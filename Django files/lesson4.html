01 • CORE CONCEPT

What is a Django View?

A Django View is Python code that receives an HTTP request, performs the required application logic, and returns an HTTP response.

Simple definition: A View is the part of Django that decides what should happen when a user visits a URL.

🔗

04 • HTTP METHODS

GET vs POST

Views commonly handle GET and POST requests differently.

GET

Retrieve Information

GET is commonly used when the browser wants to retrieve or display information.

GET 
def products(request):

    if request.method == "GET":

        return HttpResponse(
            "Product List"
        )
POST

Submit Information

POST is commonly used when the user submits information to the server.

POST 
def register(request):

    if request.method == "POST":

        return HttpResponse(
            "Processing Registration"
        )

05 • FUNCTION-BASED VIEW

Function-Based Views

The simplest type of Django View is a Function-Based View, commonly called an FBV.

views.py 
from django.http import HttpResponse


def home(request):

    return HttpResponse(
        "Welcome to ZENSUS!"
    )
Remember: A Django Function-Based View is simply a Python function that accepts a request and returns a response.

09 • DATA FLOW

Passing Data from View to Template

A view can send data to a template using a context dictionary.

views.py

def student(request):

    name = "Pradeep"

    return render(
        request,
        "student.html",
        {
            "name": name
        }
    )

17 • ERROR HANDLING

get_object_or_404()

When retrieving a database object, you often need to handle the situation where the requested object does not exist.

views.py 
from django.shortcuts import get_object_or_404
from .models import Product


def product_detail(request, id):

    product = get_object_or_404(
        Product,
        id=id
    )

    return render(
        request,
        "product.html",
        {
            "product": product
        }
    )
OBJECT EXISTS

Product Found

Django retrieves the product and sends it to the template.

OBJECT MISSING

404 Response

Django returns a 404 Not Found response.

19 • VIEW TYPES

Function-Based Views vs Class-Based Views

Django supports two major styles of implementing views.

FUNCTION-BASED VIEW 
def home(request):

    return render(
        request,
        "home.html"
    )
CLASS-BASED VIEW 
from django.views import View


class HomeView(View):

    def get(self, request):

        return render(
            request,
            "home.html"
        )
Beginner tip: Start by understanding Function-Based Views clearly. Class-Based Views become easier once the request-response cycle is understood.
20 • DEBUGGING

Common View Mistakes

✕
Forgetting request

A normal Django view should accept the request object.

✕
Forgetting return

A view must return a valid response.

✕
Wrong view name in urls.py

The URL configuration must point to an existing view.

✕
Missing context

Template variables require corresponding data from the view.

✕
Mixing too much logic

Keep database, application logic and presentation responsibilities organized.
