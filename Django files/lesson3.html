01 • CONCEPT

What is a Django App?

A Django app is a modular component of a Django project that handles a specific area of functionality.

For example, an e-commerce website could contain separate apps for users, products, orders, and payments.

👤

Users App

Handles registration, login, profiles and user-related features.

📦

Products App

Handles product information, categories and product pages.

💳

Payments App

Handles payment-related functionality and transactions.

Important: A Django project is the complete website/application, while Django apps are modular parts of that project.

05 • CONFIGURATION

Registering an App

Creating an app is not enough. Django needs to know that the app belongs to the project.

Open the project's settings.py and add the app to INSTALLED_APPS.

settings.py 
INSTALLED_APPS = [
    "django.contrib.admin",
    "django.contrib.auth",
    "django.contrib.contenttypes",
    "django.contrib.sessions",
    "django.contrib.messages",
    "django.contrib.staticfiles",

    "products",
]
Why? Registering the app allows Django to discover and use its models, migrations, configuration and other components.

07 • URL PATTERNS

Understanding path()

Django uses the path() function to define URL patterns.

Basic path() 
path("products/", views.product_home)

The first argument is the URL pattern and the second argument is the view that should handle that URL.

URL Pattern
"products/"

The browser path Django should match.

View
views.product_home

The Python function that handles the request.

08 • PROJECT URLS

Project-Level urls.py

The project's urls.py acts as the main URL directory for the website.

myproject/urls.py 
from django.contrib import admin
from django.urls import include, path

urlpatterns = [
    path("admin/", admin.site.urls),
    path("products/", include("products.urls")),
]

Notice the use of include(). It sends requests beginning with products/ to the Products app.

09 • APP URLS

App-Level urls.py

It is good practice to keep each app's routes inside that app.

Create:

products/urls.py
products/urls.py 
from django.urls import path
from . import views

urlpatterns = [
    path(
        "",
        views.product_home,
        name="product-home"
    ),
]
10 • CONNECTING URLS

How include() Works

The include() function connects the main project URL configuration to an app's URL configuration.

🌐
/products/ Browser
→
🏠
myproject/urls.py include()
→
📦
products/urls.py app routes
→
⚙️

Think of include() like delegation: The main URL file says, “Anything beginning with products/ should be handled by the Products app.”
11 • DYNAMIC ROUTING

Dynamic URL Parameters

Sometimes a URL needs to contain a changing value such as a product ID, student ID, username or article ID.

products/urls.py 
path(
    "product/<int:id>/",
    views.product_detail,
    name="product-detail"
)

This one URL pattern can handle many different URLs.

Request 1
/product/1/

id = 1

Request 2
/product/25/

id = 25

views.py 
from django.http import HttpResponse

def product_detail(request, id):

    return HttpResponse(
        f"Product ID: {id}"
    )
Important: <int:id> means Django expects an integer value and passes that value to the view as id.
12 • BEST PRACTICE

Named URLs

Django allows you to give a name to a URL pattern using name=.

Named URL 
path(
    "products/",
    views.product_home,
    name="products"
)

Instead of hard-coding URLs everywhere, Django can use the URL name to generate the correct URL.

Why use names? If the actual URL changes later, your templates and Python code can continue referring to the route by its name.

15 • DEBUGGING

Common URL Routing Mistakes

✕
Forgetting include()

The project URL configuration must connect to the app URL file.

✕
Wrong URL spelling

Check the route carefully. "products/" and "product/" are different.

✕
Missing urls.py

If your app uses its own URL configuration, create products/urls.py.

✕
Forgetting to import views

Use from . import views inside the app URL file.

✕
Incorrect dynamic parameter

Make sure your view accepts the same parameter used in the URL.

✕
Wrong view function name

Check that the function name in urls.py actually exists in views.py.

Lesson Takeaway

Django URL routing connects a browser request to the correct view. Project-level URLs organize the overall website, while app-level URLs keep each application's routes modular and manageable.
