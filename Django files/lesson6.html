What is a Django Model?

A Django model is a Python class that represents the structure of data in your application.

In simple terms:

Model = Python representation of database data.
🐍

Python Model

You define a class in models.py.

🗄️

Database Table

Django uses the model definition to create and manage the corresponding database structure.

07

Creating Your First Model

Suppose we are building a ZENSUS course platform. We want to store courses.

courses/models.py 
from django.db import models


class Course(models.Model):

    title = models.CharField(
        max_length=200
    )

    description = models.TextField()

    duration = models.IntegerField()

    price = models.DecimalField(
        max_digits=8,
        decimal_places=2
    )

    active = models.BooleanField(
        default=True
    )

    created_at = models.DateTimeField(
        auto_now_add=True
    )

Understanding the fields

title

Stores the course name.

description

Stores a longer explanation.

duration

Stores the course duration as a number.

price

Stores a decimal value.

What is a Migration?

A migration is Django's way of recording and applying changes to your database structure.

Model = what your data structure should look like.
Migration = instructions for changing the database to match that structure.
1
Write Model Define Python class
2
makemigrations Create migration file
3
migrate Apply database changes
4
Database Structure updated

Migration Commands

Step 1 — Create Migration Files

Step 2 — Apply Migrations

C:\project> python manage.py migrate

OK

makemigrations

Detects model changes and creates migration files.

migrate

Applies those migration instructions to the database.

Important:
makemigrations does not normally change the database directly.

migrate applies the migration files to the database.

What Happens When a Model Changes?

Models are not fixed forever. During development you will frequently add, remove or modify fields.

Original model

models.py 
class Student(models.Model):

    name = models.CharField(
        max_length=100
    )

    email = models.EmailField()

Add a new field

Updated models.py 
class Student(models.Model):

    name = models.CharField(
        max_length=100
    )

    email = models.EmailField()

    course = models.CharField(
        max_length=100
    )

Then run:

C:\project> python manage.py makemigrations
C:\project> python manage.py migrate
Golden rule: After changing models, remember the usual development cycle:

models.py → makemigrations → migrate

Model Relationships

Real applications contain connected data. For example, a student may enroll in courses.

👨‍🎓
Student

Stores student information.

📚
Course

Stores course information.

One-to-One

One record is connected to one other record.

OneToOneField

One-to-Many

One record can be connected to many records.

ForeignKey

Many-to-Many

Multiple records can connect to multiple records.

ManyToManyField

Example: ForeignKey

models.py 
class Course(models.Model):

    name = models.CharField(
        max_length=100
    )


class Student(models.Model):

    name = models.CharField(
        max_length=100
    )

    course = models.ForeignKey(
        Course,
        on_delete=models.CASCADE
    )
The detailed use of relationships becomes much more powerful when working with Django ORM in Lesson 07.

Common Mistakes

❌ Forgetting app registration

Make sure your app appears in INSTALLED_APPS.

❌ Forgetting makemigrations

Model changes need migration files to be generated.

❌ Forgetting migrate

Migration files are not the same as applying those changes to the database.

❌ Wrong field type

Choose a field type that matches the data you need to store.

❌ Missing max_length

Character fields normally need a maximum length.

❌ Editing migration files manually

Normally let Django generate migration files from your model changes.

Important: Do not randomly delete migration files or modify migration history just because an error appears. First understand the migration error and the current database state.

Key points

  • Models are Python classes defined in models.py.
  • Model fields define what type of data is stored.
  • Django can represent models as database tables.
  • Each database record is represented by a row.
  • Django normally provides an ID/primary key automatically when you do not define one.
  • makemigrations creates migration files.
  • migrate applies migrations to the database.
  • Models can have relationships with other models.
  • CRUD operations work with model data.
  • Django Admin can be used to manage registered models.
