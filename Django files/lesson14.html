Create the Model

Our API will manage students. First create a Django model. 

from django.db import models


class Student(models.Model):

    name = models.CharField(
        max_length=100
    )

    email = models.EmailField(
        unique=True
    )

    age = models.IntegerField()

    course = models.CharField(
        max_length=100
    )

    active = models.BooleanField(
        default=True
    )

    def __str__(self):
        return self.name

Run migrations

python manage.py makemigrations
python manage.py migrate
The model represents the database structure that our REST API will work with.

Build the List & Create API

The first endpoint will support:

GET /api/students/ List students
POST /api/students/ Create student

students/views.py

from rest_framework.views import APIView
from rest_framework.response import Response
from rest_framework import status

from .models import Student
from .serializers import StudentSerializer


class StudentListCreateAPIView(APIView):

    def get(self, request):

        students = Student.objects.all()

        serializer = StudentSerializer(
            students,
            many=True
        )

        return Response(
            serializer.data
        )


    def post(self, request):

        serializer = StudentSerializer(
            data=request.data
        )

        if serializer.is_valid():

            serializer.save()

            return Response(
                serializer.data,
                status=status.HTTP_201_CREATED
            )

        return Response(
            serializer.errors,
            status=status.HTTP_400_BAD_REQUEST
        )
06

Build the Detail API

A list endpoint works with the collection. A detail endpoint works with one specific student.

GET /api/students/1/ Get one student
PUT /api/students/1/ Replace student
PATCH /api/students/1/ Partially update student
DELETE /api/students/1/ Delete student

Student Detail API

class StudentDetailAPIView(APIView):

    def get_object(self, pk):

        try:
            return Student.objects.get(pk=pk)

        except Student.DoesNotExist:

            return None


    def get(self, request, pk):

        student = self.get_object(pk)

        if student is None:

            return Response(
                {"error": "Student not found"},
                status=status.HTTP_404_NOT_FOUND
            )

        serializer = StudentSerializer(student)

        return Response(
            serializer.data
        )


    def put(self, request, pk):

        student = self.get_object(pk)

        if student is None:

            return Response(
                {"error": "Student not found"},
                status=status.HTTP_404_NOT_FOUND
            )

        serializer = StudentSerializer(
            student,
            data=request.data
        )

        if serializer.is_valid():

            serializer.save()

            return Response(
                serializer.data
            )

        return Response(
            serializer.errors,
            status=status.HTTP_400_BAD_REQUEST
        )


    def patch(self, request, pk):

        student = self.get_object(pk)

        if student is None:

            return Response(
                {"error": "Student not found"},
                status=status.HTTP_404_NOT_FOUND
            )

        serializer = StudentSerializer(
            student,
            data=request.data,
            partial=True
        )

        if serializer.is_valid():

            serializer.save()

            return Response(
                serializer.data
            )

        return Response(
            serializer.errors,
            status=status.HTTP_400_BAD_REQUEST
        )


    def delete(self, request, pk):

        student = self.get_object(pk)

        if student is None:

            return Response(
                {"error": "Student not found"},
                status=status.HTTP_404_NOT_FOUND
            )

        student.delete()

        return Response(
            status=status.HTTP_204_NO_CONTENT
        )

API Validation

Validation prevents incorrect data from entering the database.

Field Validation

class StudentSerializer(
    serializers.ModelSerializer
):

    class Meta:

        model = Student

        fields = [
            "id",
            "name",
            "email",
            "age",
            "course",
            "active"
        ]


    def validate_age(self, value):

        if value < 16:

            raise serializers.ValidationError(
                "Student must be at least 16 years old."
            )

        return value

Object-Level Validation

def validate(self, data):

    if (
        data["course"] == "Django"
        and data["age"] < 16
    ):

        raise serializers.ValidationError(
            "Invalid student data."
        )

    return data
Never assume that frontend validation alone is enough. Backend validation is important because API requests can come from many different clients.

OK

Successful request.

201

Created

New resource created.

Invalid request data.

Unauthorized

Forbidden

Connecting a Frontend

A React or JavaScript frontend can call the Django API using fetch().

GET Example

fetch(
    "http://127.0.0.1:8000/api/students/"
)
.then(response => response.json())
.then(data => {

    console.log(data);

});

POST Example

fetch(
    "http://127.0.0.1:8000/api/students/",
    {
        method: "POST",

        headers: {
            "Content-Type": "application/json"
        },

        body: JSON.stringify({
            name: "Pradeep",
            email: "pradeep@example.com",
            age: 21,
            course: "Django",
            active: true
        })
    }
)
.then(response => response.json())
.then(data => {

    console.log(data);

});
When frontend and backend run on different origins during development, you may also need to configure CORS appropriately on the backend.

API Security

A working API is not automatically a secure API. Production APIs need authentication, permissions and careful validation.

AUTH

Authentication

Determine who is making the request.

PERM

Permissions

Determine what the authenticated user can do.

VALID

Validation

Reject invalid or unsafe input.

HTTPS

HTTPS

Protect data while it travels between client and server.

LIMIT

Throttling

Limit request rates when appropriate.

DATA

Minimal Data

Return only the data the client actually needs.

Do not place passwords, secret keys or private credentials directly inside API responses.

Common Mistakes

01

Forgot to Migrate

Run makemigrations and migrate after changing models.

02

Wrong URL

Check project urls.py and application urls.py.

03

Missing many=True

When serializing multiple model objects, use many=True.

04

Skipping Validation

Check serializer.is_valid() before saving incoming data.

05

Wrong Method

Match the client operation with the appropriate HTTP method.

06

No Error Handling

Return meaningful HTTP status codes for failed requests.

Lesson Takeaway

  • A REST API exposes backend resources through HTTP endpoints.
  • Django models represent the database data.
  • Serializers convert and validate API data.
  • API views process HTTP requests.
  • GET reads data.
  • POST creates data.
  • PUT replaces data.
  • PATCH partially updates data.
  • DELETE removes data.
  • HTTP status codes communicate the result of a request.
  • Backend validation is essential for reliable APIs.
  • A Django REST API can be consumed by React, mobile apps and other clients.
The complete architecture:

Client → URL → API View → Serializer → Model → Database → Serializer → JSON Response → Client
