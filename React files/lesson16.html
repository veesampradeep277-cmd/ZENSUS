useMemo() & Performance Optimization

Learn how React can cache expensive calculations, how dependency arrays control recalculation, why memoization is not automatically faster, and how to optimize components without sacrificing clarity.

1. What is Memoization?

Memoization is a technique for avoiding repeated work.

Memoization means remembering the result of a calculation so that the same calculation does not have to be performed again when the relevant inputs have not changed.

Simple idea:

Without memoization:
Input → Calculate → Result

With memoization:
Input → Check Cache → Reuse Result OR Calculate → Store Result
Input values
→
Dependency Check changed?
→
Cache previous result
→
Result reuse / recalculate

2. Why Performance Optimization?

React applications can perform a large amount of work during rendering.

A React component may re-render because its state changes, its parent renders, or its context changes. During a render, JavaScript calculations inside the component can run again.

Small Calculation

A simple addition or string operation usually costs very little. Memoizing it may add unnecessary complexity.

Expensive Calculation

Large filtering, sorting, parsing, or computational work may be worth optimizing when it measurably affects performance.

Frequent Rendering

An expensive calculation becomes more important when the component renders frequently.

Measurement Matters

Optimization should be based on actual performance evidence, not simply assumptions.

3. What is useMemo()?

useMemo caches the result of a calculation between renders.

Basic Syntax 
const cachedValue =
    useMemo(() => {

        return expensiveCalculation();

    }, [dependency]);

The first argument is a calculation function. The second argument is the dependency array. React can reuse the previously calculated value when the dependencies have not changed.

Important: useMemo is a performance optimization. Your component should remain correct even if the calculation were performed again.

4. Expensive Calculations

Memoization becomes useful when repeated computation has a meaningful cost.

Example: Large Calculation

Without useMemo 
function ProductList({ products, search }) {

    const filteredProducts =
        products
            .filter(product =>
                product.name
                    .toLowerCase()
                    .includes(
                        search.toLowerCase()
                    )
            )
            .sort((a, b) =>
                a.price - b.price
            );

    return (...);

}
With useMemo 
import { useMemo } from "react";

function ProductList({ products, search }) {

    const filteredProducts =
        useMemo(() => {

            return products
                .filter(product =>
                    product.name
                        .toLowerCase()
                        .includes(
                            search.toLowerCase()
                        )
                )
                .sort((a, b) =>
                    a.price - b.price
                );

        }, [products, search]);

    return (...);

}
Do not conclude that every filter or sort needs useMemo(). The optimization is useful only when the computation is sufficiently expensive and repeated rendering makes the cost meaningful.

6. Dependency Array

Dependencies tell React which reactive values the calculation depends on.

Dependency Example 
const result =
    useMemo(() => {

        return price * quantity;

    }, [price, quantity]);

If price or quantity changes, React needs to calculate the value again. If neither dependency changes, React may reuse the previously calculated result.

Initial Render

The calculation runs to obtain the initial memoized value.

Dependency Changed

The calculation runs again using the new dependency values.

Dependencies Same

React can reuse the cached calculation result.

Dependency Missing

The memoized result can become stale or the code can violate the intended dependency relationship.

7. Memoized Values

useMemo returns the calculated value—not a function.

Value vs Function 
const total =
    useMemo(() => {

        return price * quantity;

    }, [price, quantity]);

console.log(total);

// total is the calculated value
Remember:

useMemo → caches a value
useCallback → caches a function

9. When to Use useMemo()

Use it when it solves a demonstrated performance problem.

Expensive Computation

The calculation genuinely consumes noticeable CPU time.

Frequent Re-renders

The component renders often while the expensive inputs remain unchanged.

Stable Derived Data

A derived value can be reused safely until relevant dependencies change.

Large Filtering

Filtering or transforming a sufficiently large dataset repeatedly may benefit from memoization.

Large Sorting

Repeated sorting of large collections can be a meaningful optimization target.

Measured Bottleneck

Profiling identifies the calculation as a performance bottleneck.

10. When NOT to Use useMemo()

Memoization has a cost too.

Do not memoize every calculation.

For simple calculations, the overhead and complexity of memoization may provide little or no benefit.

Simple Arithmetic

const total =
    price * quantity;

Usually no memoization is needed.

Simple String Operation

const fullName =
    firstName + " " + lastName;

The calculation is typically trivial.

Premature Optimization

Adding useMemo before identifying a performance problem can make code harder to understand.

Unnecessary Dependencies

If dependencies change frequently, the calculation may run frequently anyway.

11. Performance Trade-offs

Optimization is about balancing computation, memory, complexity, and maintainability.

Factor Without Memoization With useMemo()
Calculation Can run on every render Can be reused when dependencies are unchanged
Memory No memoized result to retain React retains the memoized value
Code complexity Usually simpler Higher
Dependency management Not applicable to the calculation Important
Performance benefit None from memoization Depends on actual workload and render pattern
Professional rule: Don't ask "Can I use useMemo here?" Ask: "Is this calculation expensive enough, and does this component re-render often enough, that avoiding the calculation provides a measurable benefit?"

12. Referential Identity

Memoized values can also help maintain a stable object or array reference.

Object Example 
const options =
    useMemo(() => ({

        sortBy: "price",
        direction: "ascending"

    }), []);

JavaScript objects and arrays are reference values. Creating a new object during every render creates a new reference. useMemo can preserve a reference between renders when its dependencies remain unchanged.

This matters especially when a child component or another Hook uses reference equality to decide whether something changed. Do not memoize objects automatically; use it when reference stability is actually useful.

13. Common useMemo() Mistakes

Avoid these patterns in professional React applications.

Mistake 1 — Memoizing Everything

const answer =
    useMemo(() =>
        2 + 2,
        []
    );

This adds complexity without a meaningful computational benefit.

Mistake 2 — Missing Dependencies

const total =
    useMemo(() =>
        price * quantity,
        [price]
    );

The calculation also reads quantity, so the dependency relationship is incomplete.

Mistake 3 — Thinking useMemo Prevents Re-renders

useMemo does not prevent the component itself from rendering. It memoizes a calculation's result.

Mistake 4 — Using useMemo for Side Effects

// Wrong concept

useMemo(() => {

    fetch("/api/data");

}, []);

Side effects such as data fetching belong in the appropriate effect/event architecture, not in useMemo.

Mistake 5 — Treating useMemo as a Correctness Requirement

Your component should produce correct behavior without depending on memoization for semantic correctness.

Mistake 6 — Ignoring Measurement

If there is no meaningful performance problem, useMemo may only increase code complexity.

14. useMemo() vs useCallback()

These Hooks are related but cache different things.

Hook What it caches Typical purpose
useMemo() A calculated value Avoid repeated expensive calculations
useCallback() A function reference Keep a callback reference stable
Comparison 
// Memoized VALUE

const total =
    useMemo(() =>
        price * quantity,
        [price, quantity]
    );


// Memoized FUNCTION

const handleClick =
    useCallback(() => {

        console.log("Clicked");

    }, []);

15. Complete Real-World Example

Search and filter a large student dataset.

StudentList.jsx 
import {
    useMemo,
    useState
} from "react";

function StudentList({ students }) {

    const [search, setSearch] =
        useState("");

    const filteredStudents =
        useMemo(() => {

            return students.filter(
                student =>
                    student.name
                        .toLowerCase()
                        .includes(
                            search.toLowerCase()
                        )
            );

        }, [students, search]);

    return (
        <>

            <input
                value={search}
                onChange={e =>
                    setSearch(e.target.value)
                }
            />

            <ul>

                {filteredStudents.map(student =>
                    <li key={student.id}>
                        {student.name}
                    </li>
                )}

            </ul>

        </>
    );
}
Architecture:

User types → state changes → component renders → useMemo checks dependencies → search changed → filter runs → filtered list returned → UI renders.

If the calculation is cheap → keep the code simple.

If the calculation is expensive and repeated frequently with unchanged dependencies → useMemo may be valuable.
