Conditional Rendering

Learn how React decides what should appear on the screen. Master conditions, ternaries, logical operators, loading states, errors, authentication UI, empty states and dynamic styling.

01. What is Conditional Rendering?

Conditional rendering means displaying different UI depending on the current state, data or condition of your application.

Think about a real application:

  • A user is logged in → show Dashboard.
  • A user is logged out → show Login.
  • Data is loading → show Spinner.
  • Data failed → show Error message.
  • There are no products → show Empty State.
  • Products exist → show Product List.
THE CONDITIONAL RENDERING ENGINE
Application State isLoggedIn
→
Condition if / ?:
→
Decision true / false
→
UI what user sees
Core idea:

React does not randomly choose what to display. Your component evaluates JavaScript conditions and returns the corresponding JSX.

02. Using if Statements

The normal JavaScript if statement can be used inside a React component. 

function Dashboard({ isLoggedIn }) {

    if (isLoggedIn) {

        return <h1>Welcome back!</h1>;

    }

    return <h1>Please log in.</h1>;

}

How React evaluates it

isLoggedIn true?
→
if condition
→
YES Dashboard
When to use if?

Use it when the condition requires more logic or when you want to return an entire different component.

03. Early Returns

An early return exits a component before reaching the main JSX. 

function Profile({ user }) {

    if (!user) {

        return <Login />;

    }

    return (
        <ProfilePage user={user} />
    );

}
Why is this useful?

It keeps the main UI clean by handling exceptional or special cases before the main return.

Common pattern

if (loading) {
    return <Loading />;
}

if (error) {
    return <ErrorMessage />;
}

return <Dashboard />;

This pattern is extremely common in real React applications.

04. Ternary Operator

The ternary operator is useful when you need to choose between two UI possibilities. 

condition
    ? valueIfTrue
    : valueIfFalse

React example

function App({ isLoggedIn }) {

    return (
        <div>

            {
                isLoggedIn
                ? <Dashboard />
                : <Login />
            }

        </div>
    );

}
👋 Welcome to your Dashboard

The condition is TRUE.

Simple mental model:

condition ? showThis : showThat

05. Logical &&

The logical AND operator is useful when you want to display something only when a condition is true. 

{isAdmin && <AdminPanel />}

Meaning:

isAdmin true?
→
&& AND
→
Admin Panel rendered
Think of it as:

"If this condition is true, render the JSX."

Practical examples

{isLoggedIn && <LogoutButton />}

{cart.length > 0 && <Cart />}

{isAdmin && <AdminTools />}

06. Logical ||

The OR operator can provide a fallback value when the first value is falsy. 

const displayName =
    user.name || "Guest";

This means:

  • If user.name exists → use it.
  • Otherwise → use "Guest".
👤 Guest

Fallback value is being used.

Important:

Understand JavaScript truthy and falsy values before using && and || extensively in JSX.

07. Multiple Conditions

Real applications often have more than two possible states. 

if (score >= 90) {

    return <Excellent />;

} else if (score >= 60) {

    return <Good />;

} else {

    return <NeedsPractice />;

}

Example: Performance UI

🏆 Excellent Performance

Score: 95%

08. Nested Conditions

A nested condition means placing one conditional decision inside another. 

if (isLoggedIn) {

    if (isAdmin) {

        return <AdminDashboard />;

    }

    return <UserDashboard />;

}

return <Login />;
NESTED DECISION TREE
Logged In?
↓ YES
Admin?
YES Admin Dashboard
NO User Dashboard
Be careful:

Deeply nested conditions can become difficult to read. Consider extracting logic or components when the structure becomes complex.

09. Conditional Components

Instead of putting large amounts of JSX inside one condition, professional React applications often move UI into separate components. 

function Dashboard({ user }) {

    if (!user) {

        return <Login />;

    }

    if (user.isAdmin) {

        return <AdminDashboard />;

    }

    return <UserDashboard />;

}

Login

Displayed when authentication information is missing.

UserDashboard

Displayed for normal authenticated users.

AdminDashboard

Displayed when the user has administrative privileges.

ErrorPage

Displayed when something goes wrong.

Professional principle:

Conditions decide which component should appear; components decide how that UI is built.

13. Empty States

An empty state appears when there is no data to display. 

{items.length === 0 ? (

    <EmptyState />

) : (

    <ItemList items={items} />

)}
📭
No courses found

There is nothing to display yet.

Good empty states should:
  • Explain what happened.
  • Tell the user what they can do next.
  • Avoid leaving a completely blank interface.

14. Conditional CSS

Sometimes the condition does not decide whether an element exists. Instead, it decides how the element looks. 

<div
    className={
        isOnline
        ? "status online"
        : "status offline"
    }
>
    Status
</div>

Interactive CSS State

● User is Online
Key distinction:

Conditional rendering decides: Should this element exist?

Conditional CSS decides: How should this existing element look?

Real applications often combine several conditions.

16. Common Conditional Rendering Mistakes

❌ Confusing assignment with comparison

if (isLoggedIn = true)

Use a comparison or simply: 

if (isLoggedIn)

❌ Overusing nested ternaries

condition1
 ? condition2
   ? A
   : B
 : C

This quickly becomes difficult to read.

❌ Forgetting JavaScript truthiness

{count && <Message />}

If count is 0, understand what React will render and choose a condition appropriate for your intended UI.

❌ Making one component huge

If conditional JSX becomes massive, extract separate components.

❌ Mixing too much business logic into JSX

return (
    <div>
        {
            extremelyComplexExpression
        }
    </div>
);

Move complex decisions into variables or functions when it improves readability.

❌ Forgetting the fallback UI

Loading, error and empty states are part of a complete user experience.
