Advanced React Hooks

Go beyond useState, useEffect and useContext. Learn the advanced React hooks used for DOM synchronization, imperative APIs, accessibility, responsive rendering, performance optimization and modern concurrent UI.

useLayoutEffect useImperativeHandle useId useTransition useDeferredValue Performance Concurrent UI

1. The Advanced Hooks Map

Each advanced hook solves a different class of problem. The important skill is knowing when NOT to use one.

useLayoutEffect DOM timing
useImperativeHandle Ref API
useId Stable IDs
useTransition Non-urgent updates
useDeferredValue Deferred rendering
Core principle:

Advanced hooks are not replacements for basic React patterns. They are specialized tools for specific rendering, DOM, accessibility and performance problems.

2. `useLayoutEffect`

`useLayoutEffect` is useful when an effect must run after React has committed DOM changes but before the browser paints the updated screen.

useEffect vs useLayoutEffect

React render
DOM commit
Layout Effect
Browser paint
Normal Effect

Basic syntax

React 
import {
    useLayoutEffect,
    useRef
} from "react";

function Box(){

    const boxRef = useRef(null);

    useLayoutEffect(() => {

        const rect =
            boxRef.current.getBoundingClientRect();

        console.log(rect.width);

    }, []);

    return (
        <div ref={boxRef}>
            Measure me
        </div>
    );
}

When is it useful?

Measure DOM

Read dimensions or positions before the browser paints.

Positioning

Calculate visual placement based on actual DOM geometry.

Prevent Flicker

Synchronize a visual adjustment before the updated frame becomes visible.

Important:

Prefer `useEffect` unless you specifically need to perform layout work before the browser paints. Excessive use of `useLayoutEffect` can delay visual updates.

3. `useImperativeHandle`

`useImperativeHandle` lets a component customize the value exposed through a ref.

Parent Calls a limited method
→
Ref Public component API
→
Child Controls internal DOM

Example

Child component 
import {
    forwardRef,
    useImperativeHandle,
    useRef
} from "react";

const Input = forwardRef(
    function Input(props, ref){

        const inputRef =
            useRef(null);

        useImperativeHandle(
            ref,
            () => ({

                focus(){
                    inputRef.current.focus();
                },

                clear(){
                    inputRef.current.value = "";
                }

            }),
            []
        );

        return (
            <input ref={inputRef} />
        );
    }
);
Parent component 
function App(){

    const inputRef =
        useRef(null);

    return (
        <>

            <Input ref={inputRef} />

            <button
                onClick={() =>
                    inputRef.current.focus()
                }
            >
                Focus Input
            </button>

        </>
    );
}

Why use it carefully?

React encourages declarative data flow. An imperative ref API should therefore be small and intentional.

Good

Expose focus(), scrollTo(), play() or another narrow imperative action.

Risky

Expose the entire internal implementation of a component.

Goal

Create a small public imperative interface.

4. `useId`

`useId` generates unique IDs that are useful when connecting related elements such as labels and form controls.

Label
htmlFor=":r1:"
Input
id=":r1:"
Connection
label → input

Example

import { useId } from "react";

function PasswordField(){

    const id = useId();

    return (
        <>

            <label htmlFor={id}>
                Password
            </label>

            <input
                id={id}
                type="password"
            />

        </>
    );
}

Why not generate IDs with random numbers?

React's `useId` is designed to provide IDs that work correctly with React's rendering model, including server rendering scenarios.

Accessibility pattern:

Whenever a label, description or error message needs to be associated with a form control, a stable generated ID can make the relationship explicit.

5. `useTransition`

`useTransition` lets React treat certain state updates as non-urgent, allowing more important interactions to remain responsive.

Urgent Update

Typing into an input should remain responsive.

HIGH PRIORITY

Transition Update

A large result list can be rendered as a non-urgent update.

NON-URGENT

Basic pattern

import {
    useState,
    useTransition
} from "react";

function Search(){

    const [query, setQuery] =
        useState("");

    const [results, setResults] =
        useState([]);

    const [
        isPending,
        startTransition
    ] = useTransition();

    function handleChange(value){

        setQuery(value);

        startTransition(() => {

            setResults(
                expensiveSearch(value)
            );

        });
    }

    return (
        <>

            <input
                value={query}
                onChange={e =>
                    handleChange(e.target.value)
                }
            />

            {isPending && (
                <p>
                    Updating results...
                </p>
            )}

        </>
    );
}

Important mental model

User Input Urgent
→
State Update Immediate
→
Transition Non-urgent
→
UI Update Can be interrupted
Key idea:

A transition does not make JavaScript computation itself magically faster. It tells React that rendering a particular update is less urgent than other interactions.

6. `useDeferredValue`

`useDeferredValue` lets a component receive a deferred version of a value so that expensive rendering can lag behind urgent input.

Example

import {
    useDeferredValue,
    useState
} from "react";

function SearchPage(){

    const [query, setQuery] =
        useState("");

    const deferredQuery =
        useDeferredValue(query);

    return (
        <>

            <input
                value={query}
                onChange={e =>
                    setQuery(e.target.value)
                }
            />

            <Results
                query={deferredQuery}
            />

        </>
    );
}

Visual model

query Current value
→
deferredQuery May temporarily lag
→
Expensive UI Results

useTransition vs useDeferredValue

useTransition

Useful when you control the state update and want to mark the update as non-urgent.

useDeferredValue

Useful when you already have a value and want a deferred version of that value for expensive rendering.

7. Advanced Hook Patterns

Advanced React development is not about using more hooks. It is about combining hooks intentionally.

Custom Hook Composition

Combine multiple hooks behind a clean reusable API.

Ref + Layout Effect

Read DOM measurements when layout-sensitive behavior is required.

State + Transition

Separate urgent interactions from non-urgent rendering.

ID + Accessibility

Connect labels, controls and descriptions.

Memoization

Avoid unnecessary recalculation when it provides a measurable benefit.

Imperative API

Expose a deliberately small ref-based component interface.

Custom Hook example

function useWindowSize(){

    const [size, setSize] =
        useState({
            width: window.innerWidth,
            height: window.innerHeight
        });

    useEffect(() => {

        function update(){

            setSize({
                width: window.innerWidth,
                height: window.innerHeight
            });

        }

        window.addEventListener(
            "resize",
            update
        );

        return () => {

            window.removeEventListener(
                "resize",
                update
            );

        };

    }, []);

    return size;
}

The component using this hook does not need to know how the resize listener is implemented.

8. Hook Dependencies

Dependency arrays are one of the most common sources of subtle React bugs.

Example

useEffect(() => {

    fetchUser(userId);

}, [userId]);

The effect depends on `userId`. When `userId` changes, React can run the effect again.

Three important patterns

No dependency array

useEffect(() => {
    // ...
});

Runs after every render.

Empty array

useEffect(() => {
    // ...
}, []);

Does not re-run because of changing reactive dependencies.

Dependencies

useEffect(() => {
    // ...
}, [userId]);

Re-runs when the dependency changes.

Do not fight the dependency model.

If an effect uses a reactive value, carefully consider whether that value belongs in the dependency list and whether the effect itself is actually necessary.

9. Performance Hooks

React provides several tools that can influence rendering and calculation behavior.

useMemo

Caches the result of a calculation between renders when its dependencies remain unchanged.

useCallback

Caches a function reference between renders when its dependencies remain unchanged.

useTransition

Marks state updates as non-urgent transitions.

useDeferredValue

Allows a value used by expensive rendering to lag behind an urgent value.

Performance decision model

Measure Find the problem
→
Identify Expensive work
→
Choose Appropriate tool
→
Measure Again Verify improvement
Performance rule:

Do not automatically wrap every calculation in `useMemo` or every function in `useCallback`. Optimization has a cost. First understand the actual rendering problem.

10. Concurrent UI Concepts

Modern React can work on rendering updates in a way that allows urgent interactions to remain responsive while less urgent rendering work is processed.

Traditional mental model

Update Start
→
Render Work
→
Commit UI

Concurrent rendering mental model

Update Priority
→
Render Work Can be interrupted
→
Urgent Work Can be prioritized
→
Commit Final UI
Important terminology:

Concurrent rendering is a rendering capability rather than a promise that multiple JavaScript threads are simultaneously executing React rendering work.

11. Practical Example — Search Experience

A realistic search interface can combine several advanced React concepts.

Problem

A user types into a search box while the application needs to render a large result list. 

import {
    useDeferredValue,
    useState,
    useTransition
} from "react";

function Search(){

    const [query, setQuery] =
        useState("");

    const [results, setResults] =
        useState([]);

    const [
        isPending,
        startTransition
    ] = useTransition();

    const deferredQuery =
        useDeferredValue(query);

    function search(value){

        startTransition(() => {

            setResults(
                expensiveSearch(value)
            );

        });
    }

    function handleChange(event){

        const value =
            event.target.value;

        setQuery(value);

        search(value);

    }

    return (

        <div>

            <input
                value={query}
                onChange={handleChange}
                placeholder="Search..."
            />

            {isPending && (
                <p>
                    Updating results...
                </p>
            )}

            <Results
                query={deferredQuery}
                results={results}
            />

        </div>

    );
}

What is happening?

1. User types

The input state changes immediately.

2. React schedules work

The expensive update can be treated as less urgent.

3. Results update

The expensive interface can lag without making the input feel blocked.

Engineering lesson:

The goal is not to make every update deferred. The goal is to distinguish between work that directly responds to the user's immediate interaction and work that can safely happen afterward.

12. Common Mistakes

!
Using useLayoutEffect everywhere

Most side effects do not need layout timing. Prefer `useEffect` unless you specifically need to synchronize with layout before paint.

!
Using refs as normal state

Refs are useful for imperative values and DOM references, but changing a ref does not itself trigger a component re-render.

!
Exposing too much through useImperativeHandle

A component should expose a small intentional API rather than leaking its entire internal implementation.

!
Generating form IDs randomly

For React-controlled accessible relationships, `useId` is designed for stable unique IDs.

!
Thinking useTransition makes code faster

Transitions primarily communicate update priority to React. They do not automatically reduce the amount of computation your JavaScript performs.

!
Using every performance hook everywhere

Premature memoization can make code more complicated without producing a meaningful benefit.

!
Ignoring dependencies

Incorrect effect dependencies can produce stale values, unnecessary effects or synchronization bugs.

13. Quick Quiz

1. Which hook is specifically designed for layout-related work before browser paint?
A. useId
B. useLayoutEffect
C. useTransition
D. useDeferredValue
Answer: B — useLayoutEffect is intended for layout-sensitive effects that need to run before the browser paints.
2. What does useImperativeHandle customize?
A. A component's CSS
B. The value exposed through a ref
C. The browser URL
D. The React Router configuration
Answer: B — useImperativeHandle customizes the imperative handle exposed through a ref.
3. What is a common use case for useId?
A. Generating random passwords
B. Connecting related form elements with unique IDs
C. Fetching API data
D. Storing global state
Answer: B — useId is useful for generating unique IDs that connect related elements such as labels and inputs.
4. What does startTransition communicate to React?
A. The update is less urgent
B. The update must never render
C. The update is a network request
D. The update should always happen synchronously
Answer: A — startTransition marks state updates as non-urgent transition work.
5. What does useDeferredValue provide?
A. A deferred version of a value
B. A database connection
C. A new browser tab
D. A replacement for useState
Answer: A — useDeferredValue provides a deferred version of a value for less urgent rendering.
6. Which statement about performance hooks is most accurate?
A. Every function should always use useCallback
B. useMemo should always wrap every calculation
C. Performance optimizations should be applied based on actual rendering needs
D. useTransition makes JavaScript execution faster
Answer: C — performance tools should be used intentionally when they address an actual rendering or scheduling problem.
7. What is an important difference between useTransition and useDeferredValue?
A. useTransition marks state updates while useDeferredValue provides a deferred value
B. They are exactly the same API
C. useDeferredValue only works with CSS
D. useTransition only generates IDs
Answer: A — useTransition is used when you control an update, while useDeferredValue provides a deferred version of an existing value.
