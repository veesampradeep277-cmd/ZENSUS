Reusable Components & Patterns

Learn how professional React applications transform repeated UI, behavior, and structure into reusable components that are easier to maintain, test, scale, and understand.

1. Reusable UI

A reusable component is a component designed to work in multiple places without rewriting its internal implementation every time.

Core idea: Build the component once → configure it with props → reuse it wherever required.

2. Component Abstraction

Abstraction means hiding implementation details behind a simpler interface. A consumer should generally care about what a component does, not how its internal DOM and logic are implemented.

Without Abstraction

<button style={{ padding: "10px 18px", borderRadius: "8px", background: "#4f46e5" }} > Save </button>

Every screen repeats implementation details.

With Abstraction

<Button variant="primary"> Save </Button>

The screen communicates intent rather than styling internals.

Important: Do not abstract everything immediately. Abstraction should remove meaningful duplication or complexity. Excessive abstraction can make simple UI harder to understand.

4. The children Prop

React automatically provides the content nested between a component's opening and closing tags through the children prop.

function Card({ children }) { return ( <div className="card"> {children} </div> ); }
<Card> <h2>React Course</h2> <p> Learn React step by step. </p> </Card>
Think of children as a slot. The component provides the outer structure while the parent supplies the inner content.

children can contain many things

  • Text
  • Elements
  • Other components
  • Fragments
  • Conditionally rendered content
  • Arrays of React elements

5. Layout Components

Layout components control page structure rather than application-specific content. They provide reusable regions such as headers, sidebars, navigation areas, main content, and footers.

function DashboardLayout({ children }) { return ( <div className="dashboard-layout"> <Sidebar /> <main> <Header /> {children} </main> </div> ); }

7. Button Components

A reusable Button component should expose meaningful behavior and appearance through a clear API instead of forcing consumers to repeat implementation details.

function Button({ children, variant = "primary", size = "medium", disabled = false, onClick, type = "button" }) { return ( <button type={type} disabled={disabled} className={`button ${variant} ${size}`} onClick={onClick} > {children} </button> ); }

Primary

Secondary

Disabled

A good Button API describes intent: variant, size, disabled, loading, type and event behavior—not dozens of internal CSS implementation details.

8. Modal Components

A Modal is another excellent reusable component because many applications need dialogs for confirmation, forms, warnings, details, and authentication.

function Modal({ open, onClose, title, children }) { if (!open) { return null; } return ( <div className="backdrop"> <div className="modal"> <h2>{title}</h2> {children} <button onClick={onClose}> Close </button> </div> </div> ); }

Modal Demo

A production modal usually also considers keyboard accessibility, focus management, appropriate ARIA semantics, Escape handling, and background interaction.

9. Form Components

Forms are often built from reusable field-level components such as Input, Select, Checkbox, Textarea and FormField.

function Input({ label, name, value, onChange, type = "text", error }) { return ( <div className="field"> <label htmlFor={name}> {label} </label> <input id={name} name={name} type={type} value={value} onChange={onChange} /> {error && <small>{error}</small>} </div> ); }

10. Container Components

A Container component provides consistent layout constraints such as maximum width, horizontal spacing and responsive padding.

function Container({ children, size = "large" }) { return ( <div className={`container container-${size}`}> {children} </div> ); }
Container components are especially useful when many pages need the same content width and horizontal alignment.

11. Presentational Components

Presentational components primarily focus on displaying UI based on the props they receive. They should generally have limited application-specific state and side-effect logic.

function UserCard({ user, onSelect }) { return ( <article> <h3>{user.name}</h3> <p>{user.email}</p> <button onClick={() => onSelect(user.id)}> View Profile </button> </article> ); }

The component receives data and callbacks rather than owning the entire application workflow.

12. Logic Components

Logic-heavy components coordinate state, effects, data fetching, event handling, or application workflows.

function UserContainer() { const [users, setUsers] = useState([]); useEffect(() => { fetchUsers().then(setUsers); }, []); return ( <UserList users={users} onSelect={handleSelect} /> ); }
Modern React does not require the old strict "container vs presentational component" pattern. Hooks allow logic to be extracted into custom Hooks while UI components remain focused. Treat this as an architectural concept rather than a mandatory rule.

13. Component API Design

A component API is the public interface through which other components configure it. Good component APIs make components predictable and difficult to misuse.

API Design Principle Meaning
Clear Props Use understandable names that communicate intent.
Good Defaults Provide sensible defaults when appropriate.
Composition Use children or slots when the content needs flexibility.
Controlled Behavior Allow the parent to own important state when necessary.
Accessibility Do not hide essential accessibility behavior behind styling alone.
Predictability The same props should produce understandable behavior.

Bad API

<Button color1="#4f46e5" paddingX={18} radius={8} fontWeight={700} internalClass="btn-a" />

Better API

<Button variant="primary" size="medium" > Save </Button>
Rule: Expose meaningful decisions, not implementation details.

14. Compound Components

Compound components are a group of components designed to work together while sharing implicit state or context.

A familiar conceptual API looks like:

<Tabs> <Tabs.List> <Tabs.Tab>Overview</Tabs.Tab> <Tabs.Tab>Lessons</Tabs.Tab> <Tabs.Tab>Projects</Tabs.Tab> </Tabs.List> <Tabs.Panel> Overview content </Tabs.Panel> </Tabs>

const TabsContext = createContext(null); function Tabs({ children }) { const [active, setActive] = useState("overview"); return ( <TabsContext.Provider value={{ active, setActive }}> {children} </TabsContext.Provider> ); }
Compound components are particularly useful for tabs, menus, accordions, select controls, dialogs and other coordinated UI systems.

15. Render Props Concept

A render prop is a pattern where a component receives a function as a prop and calls that function to determine what UI should be rendered.

function MouseTracker({ render }) { const [position, setPosition] = useState({ x: 0, y: 0 }); // tracking logic... return render(position); }
Usage:
<MouseTracker render={({ x, y }) => ( <p> Mouse: {x}, {y} </p> )} />
Render props are an important React pattern to understand, but modern React often uses custom Hooks for sharing behavior when a visual wrapper is not necessary.

Render Props vs Custom Hooks

Pattern Main Idea Typical Use
Render Props Share behavior through a rendering function. Legacy or specialized component APIs.
Custom Hook Share stateful logic directly. Modern reusable behavior.
Composition Combine components to create UI. Flexible component structures.

16. Common Architecture Mistakes

1. Giant Components

One component contains layout, API calls, forms, business logic and every UI element.

2. Copy-Paste UI

The same Button, Card or Modal is implemented repeatedly.

3. Over-Abstraction

Simple UI is hidden behind multiple unnecessary abstraction layers.

4. Too Many Props

A component accepts dozens of unrelated props because its responsibility is too broad.

5. Leaky Abstraction

Consumers must understand internal implementation details to use the component correctly.

6. Premature Design Systems

Building a huge component framework before real reuse requirements are understood.

Architecture Smell

<SuperComponent user={user} theme={theme} api={api} modal={modal} form={form} table={table} sidebar={sidebar} buttonType="x" cardMode="y" ... />

Composition

<DashboardLayout> <Header /> <StatsGrid /> <ProjectCard /> <ActivityList /> </DashboardLayout>

17. Professional Component Architecture

A scalable React application usually combines multiple levels of abstraction. There is no single mandatory folder structure, but responsibilities should remain understandable.

From Small Building Blocks to Application

src/ │ ├── components/ │ ├── Button.jsx │ ├── Card.jsx │ ├── Modal.jsx │ ├── Input.jsx │ └── Container.jsx │ ├── features/ │ ├── auth/ │ ├── courses/ │ └── dashboard/ │ ├── layouts/ │ ├── MainLayout.jsx │ └── DashboardLayout.jsx │ ├── hooks/ │ ├── pages/ │ └── App.jsx
A useful boundary is: reusable UI → feature-specific UI → page composition. Do not force every component into a global components folder if it only belongs to one feature.

18. When Should You Create a Reusable Component?

1

Repeated UI

The same structure appears in multiple places.

2

Clear Responsibility

The UI represents a meaningful concept.

3

Stable API

You can describe how consumers should configure it.

Do not use "DRY" mechanically. Two pieces of code that look similar today may have different reasons to change. Prematurely combining them can create a difficult abstraction.

19. Complete Reusable UI Example

Here is a small component system combining Container, Card, Button and children.

function Container({ children }) { return ( <div className="container"> {children} </div> ); } function Card({ title, children, footer }) { return ( <article className="card"> <h2>{title}</h2> <section> {children} </section> {footer && ( <footer> {footer} </footer> )} </article> ); } function Button({ children, onClick }) { return ( <button onClick={onClick}> {children} </button> ); } function Dashboard() { return ( <Container> <Card title="React Progress" footer={ <Button> Continue Learning </Button> } > <p> Lesson 24 of the React course. </p> </Card> </Container> ); }

22. Quick Quiz

Test your understanding before moving to the next lesson.

1. What is the main purpose of a reusable React component?

Reusable components allow UI and behavior to be used in multiple places through a defined interface such as props and composition.

2. What does the React children prop represent?

The children prop represents the content nested inside a component's opening and closing tags.

3. Which pattern is especially associated with related components sharing state through context?

Compound components commonly use context or another shared mechanism so coordinated child components can work together through a declarative API.

4. What should a good component API generally expose?

A good API exposes meaningful decisions such as variant, size, content, value and behavior rather than internal implementation details.

5. Which modern React technique is commonly used to share stateful logic without requiring a rendering wrapper?

Custom Hooks allow stateful React logic to be extracted and reused across components without requiring a render-prop wrapper.
