1. What Are Custom Hooks?

A custom Hook is a JavaScript function whose name starts with use and which can use other React Hooks to encapsulate reusable stateful logic.

Simple definition:
A custom Hook lets you extract reusable React logic into a function so that multiple components can use that logic independently.

Example

function useCounter(initialValue = 0) { ``` const [count, setCount] = useState(initialValue); const increment = () => { setCount(value => value + 1); }; const decrement = () => { setCount(value => value - 1); }; return { count, increment, decrement }; ``` }

Now different components can call useCounter().

function CounterA() { ``` const { count, increment } = useCounter(); return ( <button onClick={increment}> {count} </button> ); ``` } function CounterB() { ``` const { count, increment } = useCounter(); return ( <button onClick={increment}> {count} </button> ); ``` }
Each component gets its own state. Custom Hooks share the logic, not the same state instance.

3. Hook Naming Convention

Custom Hooks should start with use.

useCounter() useFetch() useForm() useLocalStorage() useOnlineStatus() useDebounce() useAuth() useWindowSize()
The use prefix is important because it communicates that the function follows Hook rules and may call other Hooks.

Good naming

function useUserProfile() {} function useWindowSize() {} function useFetch() {}

Avoid misleading names

// These names hide the fact that the function is a Hook. function getUserData() {} function helper() {} function formManager() {}

Creating a custom Hook usually follows four steps.

Step 1 — Identify repeated behavior

Suppose several components need a counter. Instead of duplicating state and handlers, extract them.

Step 2 — Create the Hook

function useCounter() { ``` const [count, setCount] = useState(0); const increment = () => setCount(value => value + 1); const decrement = () => setCount(value => value - 1); const reset = () => setCount(0); return { count, increment, decrement, reset }; ``` }

Step 3 — Consume it

function Counter() { ``` const { count, increment, decrement, reset } = useCounter(); return ( <div> <h2>{count}</h2> <button onClick={increment}>+</button> <button onClick={decrement}>-</button> <button onClick={reset}>Reset</button> </div> ); ``` }

5. Reusing Logic

The biggest advantage of custom Hooks is that the behavior can be reused without duplicating the implementation.

useCounter()
↙
Counter A
↘
Counter B
Important: Calling the same custom Hook twice does NOT create shared state. Each Hook call creates its own state/effect lifecycle.
function Dashboard() { ``` const first = useCounter(); const second = useCounter(); ``` }

Here first.count and second.count are independent.

Concept Meaning
Shared logic Same implementation can be reused
Shared state Not automatically created by custom Hooks
Independent calls Each component/Hook call has its own Hook state

6. Custom State Logic

A custom Hook can package complex state transitions and expose a small, easy-to-use API to components.

Example — Toggle Hook

function useToggle(initial = false) { ``` const [value, setValue] = useState(initial); const toggle = () => { setValue(current => !current); }; return [value, toggle]; ``` }

Usage:

const [isOpen, toggleOpen] = useToggle();

Custom reducer logic

Custom Hooks can also hide useReducer when state transitions become more structured.

function useCart() { ``` const [state, dispatch] = useReducer(cartReducer, { items: [] }); const addItem = item => { dispatch({ type: "ADD_ITEM", payload: item }); }; return { items: state.items, addItem }; ``` }

7. Custom API Hook

API fetching is one of the most practical reasons to create custom Hooks. Instead of repeating loading, error, request, and data logic inside many components, create a reusable data-fetching abstraction.

Component
→
useFetch(url)
→
useEffect()
→
fetch()
→
data / error / loading

Basic API Hook

function useFetch(url) { ``` const [data, setData] = useState(null); const [loading, setLoading] = useState(true); const [error, setError] = useState(null); useEffect(() => { let ignore = false; async function load() { try { setLoading(true); const response = await fetch(url); if (!response.ok) { throw new Error( "Request failed" ); } const result = await response.json(); if (!ignore) { setData(result); setError(null); } } catch (err) { if (!ignore) { setError(err); } } finally { if (!ignore) { setLoading(false); } } } load(); return () => { ignore = true; }; }, [url]); return { data, loading, error }; ``` }

Using the Hook

function Users() { ``` const { data, loading, error } = useFetch( "/api/users" ); if (loading) return <p>Loading...</p>; if (error) return <p>Something went wrong.</p>; return ( <ul> {data.map(user => ( <li key={user.id}> {user.name} </li> ))} </ul> ); ``` }
The component focuses on UI. The custom Hook owns the reusable fetching behavior.

8. Custom Form Hook

Forms often contain repeated state, change handlers, validation, reset logic, and submission behavior. A custom Hook can centralize that logic.

useForm()

function useForm(initialValues) { ``` const [values, setValues] = useState(initialValues); const handleChange = event => { const { name, value } = event.target; setValues(current => ({ ...current, [name]: value })); }; const reset = () => { setValues(initialValues); }; return { values, handleChange, reset }; ``` }

Using it

const { values, handleChange, reset } = useForm({ name: "", email: "" });

9. Custom Local Storage Hook

The browser's localStorage API can persist small amounts of client-side data across page reloads. A custom Hook can combine state with storage synchronization.

Component
→
useLocalStorage()
→
React State
↔
localStorage

Basic implementation

function useLocalStorage(key, initialValue) { ``` const [value, setValue] = useState(() => { const saved = localStorage.getItem(key); return saved !== null ? JSON.parse(saved) : initialValue; }); useEffect(() => { localStorage.setItem( key, JSON.stringify(value) ); }, [key, value]); return [value, setValue]; ``` }

Usage

const [theme, setTheme] = useLocalStorage( "theme", "light" );

The custom Hook hides storage synchronization from the component.

Do not store sensitive secrets such as passwords or private authentication tokens in localStorage merely for convenience. Browser storage is accessible to JavaScript running on the page.

10. Hook Composition

One custom Hook can call another custom Hook. This is called Hook composition.

useUser()
→
useFetch()
→
useEffect()
→
API

Example

function useUser(userId) { ``` const { data, loading, error } = useFetch( `/api/users/${userId}` ); return { user: data, loading, error }; ``` }

Now the component only needs:

const { user, loading, error } = useUser(userId);
Composition lets you build larger reusable behaviors from smaller Hooks, similar to building software from modular functions.

Composition hierarchy

Component UI and presentation
useUser() Domain-specific behavior
useFetch() Reusable data fetching

11. Custom Hook Rules

Rule 1 — Start with use

function useOnlineStatus() {}

Rule 2 — Follow the Rules of Hooks

Custom Hooks can call other Hooks, but they must follow React's Hook rules.

Do not call Hooks inside:
  • if statements
  • for loops
  • while loops
  • nested functions
  • event handlers
  • arbitrary conditional branches

Correct

function useProfile() { ``` const [user, setUser] = useState(null); useEffect(() => { // effect logic }, []); return user; ``` }

Incorrect

function useProfile(enabled) { ``` if (enabled) { const [user, setUser] = useState(null); } ``` }
The order in which Hooks are called must remain consistent between renders. That is why Hooks should be called at the top level of components and custom Hooks.

13. Common Mistakes

Mistake 1 — Calling a custom Hook like a normal utility

// ❌ Avoid function calculateSomething() { ``` const value = useState(0); ``` }

If a function uses Hooks, it should follow Hook conventions and be used in a valid React component/custom-Hook context.

Mistake 2 — Conditional Hook calls

// ❌ Wrong if (loggedIn) { useUser(); }
Do not conditionally call a custom Hook if that changes the order of Hook calls.

Mistake 3 — Returning too much

A custom Hook should expose a useful API. Returning many internal implementation details can make the Hook harder to use and maintain.

Mistake 4 — Putting UI inside a Hook unnecessarily

// A Hook should normally provide behavior/data. const { data, loading, error } = useFetch(url);

The component decides how that data should be displayed.

Mistake 5 — Assuming custom Hooks share state

const first = useCounter(); const second = useCounter();

first.count and second.count are separate state values.

Mistake 6 — Making a Hook for every tiny function

Not every reusable JavaScript function needs to become a Hook. If a function does not use React state, effects, context, refs, or other Hooks, a normal utility function may be simpler.

14. Custom Hook vs Normal Function

Feature Normal Function Custom Hook
Starts with use Not required Yes
Can call React Hooks No Yes
Can manage React state Not through Hooks Yes
Reusable JavaScript calculation Excellent Usually unnecessary
Reusable stateful behavior Not the intended abstraction Excellent
Decision: If the logic is pure JavaScript, consider a normal function. If the logic needs React Hooks and reusable stateful behavior, consider a custom Hook.

17. Quick Quiz

1. What is the primary purpose of a custom Hook?
Answer: B — Custom Hooks are primarily used to extract and reuse stateful React logic.
2. What naming convention identifies a custom Hook?
Answer: B — Custom Hooks use the use prefix.
3. If two components call useCounter(), what normally happens to their state?
Answer: C — Each custom Hook call has its own Hook state. The implementation is shared, not the state instance.
4. Which Hook is especially useful for building a reusable API-fetching Hook?
Answer: A — API synchronization is commonly implemented with useEffect inside a custom data-fetching Hook.
5. Can one custom Hook call another custom Hook?
Answer: A — Custom Hooks can compose other Hooks as long as the Rules of Hooks are respected.
6. What does “shared logic ≠ shared state” mean?
Answer: B — The custom Hook implementation is reusable, but each call receives its own state and effect lifecycle.
7. When is a normal utility function usually more appropriate than a custom Hook?
Answer: A — Pure JavaScript logic that does not need React Hooks can usually remain a normal reusable function.
