01 — Core Concept

What is a Component?

A component is an independent, reusable piece of a user interface. Instead of building an entire application as one giant block, React encourages us to divide the interface into smaller pieces.

Think of Components as UI Building Blocks

A modern website may contain a navigation bar, sidebar, profile card, search box, button, dashboard card and footer. Each of these can be represented as a React component.

Core idea: A component describes a part of the UI and can be reused wherever that part of the interface is required.

Real-World Analogy

Think about a car. A car is not manufactured as one enormous indivisible object. It contains an engine, wheels, seats, dashboard and many other parts.

React applications work similarly:

Application → Components → Smaller Components → UI

03 — Why Components?

Why Does React Use Components?

♻ Reusability

Create a component once and use it multiple times.

🧩 Modularity

Large interfaces become collections of smaller manageable pieces.

🛠 Maintainability

Changes can often be isolated to the component responsible for that UI.

📦 Organization

Components give an application a clear structural architecture.

🔁 Composition

Small components can be combined to create larger interfaces.

🧪 Testing

Smaller UI units are easier to reason about and test independently.

04 — Functional Components

Functional Components

Modern React applications primarily use JavaScript functions to define components.

Welcome.jsx React Component 
function Welcome() {
    return (
        <h1>Welcome to ZENSUS</h1>
    );
}

export default Welcome;

Here:

  • Welcome is the component name.
  • The function returns JSX.
  • The JSX describes what should appear in the UI.
  • The component is exported so another file can use it.
Important: A React component is fundamentally a JavaScript function that returns something React can render, commonly JSX.

06 — Naming

Component Naming Rules

Component names should normally begin with an uppercase letter. This is not merely a style preference — React uses capitalization to distinguish user-defined components from regular HTML elements.

Name Example Typical Result
PascalCase UserProfile Recommended component naming style
camelCase userProfile Not the normal component convention
lowercase button Interpreted as an HTML-style element name
Good 
function UserProfile() {
    return <div>Profile</div>;
}
Avoid 
function userprofile() {
    return <div>Profile</div>;
}

08 — Composition

Component Composition

Composition means building a larger interface by combining smaller components. 

function Navbar() {
    return <nav>ZENSUS</nav>;
}

function Profile() {
    return <section>Profile</section>;
}

function Footer() {
    return <footer>ZENSUS 2026</footer>;
}

function App() {

    return (
        <>
            <Navbar />
            <Profile />
            <Footer />
        </>
    );
}
Composition principle: Instead of making one enormous component, combine focused components to construct the final interface.

11 — Reusability

Reusable Components

One of the biggest advantages of components is that the same component can appear in multiple places. 

function Button() {
    return <button>Learn More</button>;
}

function App() {

    return (
        <>
            <Button />
            <Button />
            <Button />
        </>
    );
}

The component definition exists once, but the component can be rendered multiple times.

Later, props will allow reusable components to receive different data while keeping the same component structure.

14 — Single Responsibility

Single Responsibility Principle

A component should ideally have a clear and focused responsibility. A component that tries to manage unrelated UI responsibilities becomes harder to understand and maintain.

❌ Too Much Responsibility

function Dashboard() {

```
// navbar
// sidebar
// profile
// course cards
// footer
// complicated logic
```

}

✓ Better Decomposition

function Dashboard() {
    return (
        <>
            <Navbar />
            <Sidebar />
            <CourseList />
            <Footer />
        </>
    );
}
Important: Single responsibility does not mean every tiny HTML element needs its own component. Extract components when doing so improves clarity, reuse, ownership, or maintainability.

16 — Exporting

Exporting Components

JavaScript modules provide different export patterns. React components are commonly exported using either a default export or a named export.

Default Export

function Button() {
    return <button>Click</button>;
}

export default Button;

Import without braces: 

import Button from "./Button";

Named Export

export function Button() {
    return <button>Click</button>;
}

Import using braces: 

import { Button } from "./Button";
17 — Default vs Named

Default Export vs Named Export

Feature Default Export Named Export
Syntax export default export
Import braces No Yes
Typical import import Button from... import { Button } from...
Names Importer can choose the local name Usually imported by its exported name
Multiple exports One default export per module Multiple named exports are possible
The important thing is consistency. A project should establish clear conventions rather than mixing export styles randomly.
18 — Organization

Professional Component Organization

As an application grows, keeping every component inside one file becomes difficult. Components can be organized into directories based on their responsibilities.

Example Project Structure 
src/
│
├── components/
│   ├── Button.jsx
│   ├── Navbar.jsx
│   ├── Sidebar.jsx
│   └── CourseCard.jsx
│
├── pages/
│   ├── Home.jsx
│   ├── Courses.jsx
│   └── Profile.jsx
│
├── App.jsx
├── main.jsx
└── index.css

components/

Reusable UI pieces such as buttons, cards, navigation elements and forms.

pages/

Larger screen-level components representing application pages.

There is no single folder structure that every React application must follow. Organization should scale with the project's complexity and team conventions.
19 — Common Mistakes

Common Component Mistakes

❌ Lowercase Component

function button() {
    return <button>Save</button>;
}

Use PascalCase for React component names.

❌ Forgetting Export

function Profile() {
    return <div>Profile</div>;
}

If another module needs the component, export it.

❌ Wrong Import Style

// Default export
export default Button;

// Wrong style import { Button } from "./Button";

Default exports are imported without braces.

❌ Forgetting the Return

function Profile() {
    <h1>Profile</h1>;
}

The JSX needs to be returned by the component.

❌ Giant Components

Putting an entire application's UI into one enormous component makes the code difficult to reason about.

Decompose large interfaces into meaningful pieces.

❌ Unnecessary Components

Creating a separate component for every tiny element can also make a project harder to navigate.

Extract components when there is a meaningful reason.
