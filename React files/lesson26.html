LESSON 26 · AUTHENTICATION

Authentication & Protected Routes

Learn how modern React applications identify users, maintain authentication state, handle login and logout, manage sessions, protect routes and communicate securely with a backend.

1. Authentication vs Authorization

These two concepts are related, but they solve different problems.

Authentication

Authentication answers: “Who are you?”


Examples:

• Login with email and password
• Sign in with Google
• Multi-factor authentication
• Session establishment

Authorization

Authorization answers: “What are you allowed to do?”


Examples:

• Student can view courses
• Instructor can create lessons
• Admin can manage users

Authentication → Authorization
User
→
Authenticate
→
Identity
→
Authorization
→
Allowed Resource
A user being authenticated does not automatically mean the user has permission to perform every action.

2. Login

A login flow normally sends credentials to a backend authentication service. The backend verifies them and establishes an authenticated session or issues tokens according to the application's authentication design.

async function login(email, password) { const response = await fetch( "/api/auth/login", { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ email, password }) } ); if (!response.ok) { throw new Error( "Login failed" ); } return response.json(); }
Login Flow
Login Form
→
Backend
→
Verify Credentials
→
Session / Tokens
Never trust the frontend to verify passwords. Password verification belongs on the server using a suitable password hashing system.

3. Signup

Signup creates a user account. A production application normally validates the submitted data on both the client and server.

async function signup( name, email, password ) { const response = await fetch( "/api/auth/signup", { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ name, email, password }) } ); if (!response.ok) { throw new Error( "Signup failed" ); } return response.json(); }
Client-side validation improves user experience. Server-side validation is still required because the client cannot be trusted.

4. Logout

Logout ends the application's authenticated session according to the authentication mechanism being used.

async function logout() { await fetch( "/api/auth/logout", { method: "POST", credentials: "include" } ); }

The frontend should then clear its authentication state and update the UI.

A good logout experience should update both:

Server-side session/token state where applicable
and
Client-side authentication state.

5. Authentication State

React needs to know whether the application currently considers the user authenticated.

Typical state may look like:

const [auth, setAuth] = useState({ status: "loading", user: null });

Possible states:

Loading

The application is checking whether an existing session is valid.

Authenticated

A valid authenticated identity is available.

Unauthenticated

No valid authenticated session is available.

6. Token Basics

A token is a credential-like value that an application can use to represent an authenticated session or authorize requests.

One common token format is JWT (JSON Web Token).

JWT Structure
Header
Payload
Signature
xxxxx.yyyyy.zzzzz

The three sections are commonly represented as:

Header

Contains metadata such as the token type and signing algorithm.

Payload

Contains claims such as subject or expiration information.

Signature

Allows the server to verify that the signed token has not been altered.

JWT payload data should not be treated as secret merely because it is inside a token. A typical JWT payload is encoded, not encrypted.

8. Refresh Tokens

A refresh token can be used by an authentication system to obtain a new access token without requiring the user to enter credentials again.

Refresh tokens are highly sensitive credentials. Production systems commonly use secure server-managed mechanisms, such as HttpOnly Secure cookies, and may use rotation and server-side revocation controls.

9. Local Storage

localStorage is a browser storage mechanism that persists data across browser sessions until it is removed.

localStorage.setItem( "theme", "dark" ); const theme = localStorage.getItem( "theme" ); localStorage.removeItem( "theme" );

Authentication and localStorage

Developers sometimes store tokens in localStorage because it is convenient. However, tokens stored there are accessible to JavaScript running in the origin. If an application has an XSS vulnerability, an attacker may be able to access such credentials.

Do not teach “localStorage = secure authentication storage.” It is convenient, but it has important security trade-offs.

10. Cookies

Cookies can be used by web applications to maintain authentication sessions. Security-sensitive cookies can use browser controls such as:

HttpOnly The cookie cannot be read by normal client-side JavaScript.
Secure The cookie is sent only over HTTPS connections.
SameSite Controls how cookies are sent in cross-site contexts and can help reduce certain CSRF risks.
Cookies do not automatically make an application secure. Cookie-based authentication also requires appropriate CSRF defenses and careful server configuration.

11. Protected Routes

A protected route decides whether a user should be shown a particular application screen based on the current authentication state.

Protected Route Decision
Request /dashboard
→
Check Auth State
→
Authenticated?

YES
→

NO

ProtectedRoute Component

import { Navigate, useLocation } from "react-router-dom"; function ProtectedRoute({ isAuthenticated, children }) { const location = useLocation(); if (!isAuthenticated) { return ( <Navigate to="/login" replace state={{ from: location.pathname }} /> ); } return children; }
This protects the frontend experience, not the backend. A user can still directly call an API, so the server must independently authenticate and authorize protected requests.

12. Auth Context

Authentication state is often needed by many components: navigation bars, dashboards, profile menus, protected routes and logout buttons. Context can make this state available without manually passing it through many component levels.

import { createContext, useContext, useState } from "react"; const AuthContext = createContext(null); export function AuthProvider({ children }) { const [user, setUser] = useState(null); const value = { user, isAuthenticated: Boolean(user), login(userData) { setUser(userData); }, logout() { setUser(null); } }; return ( <AuthContext.Provider value={value} > {children} </AuthContext.Provider> ); } export function useAuth() { return useContext( AuthContext ); }
Auth Context Architecture
AuthProvider
→
Auth State
→
useAuth()
→
Components
Context distributes authentication state to React components. It does not itself authenticate the user and is not a security boundary.

13. Redirects

Authentication commonly requires redirects in both directions.

Unauthenticated → Login

A user tries to open a protected dashboard.

return ( <Navigate to="/login" replace /> );

Authenticated → Dashboard

A signed-in user attempts to open the login page again.

if (user) { return ( <Navigate to="/dashboard" replace /> ); }

Preserving the Intended Destination

A polished application can remember where the user wanted to go before redirecting to login.

Navigate to="/login" state={{ from: location.pathname }}

After successful authentication, the application can navigate back to the original destination if appropriate.

14. Session Handling

Authentication state should not simply begin as “logged out” while the application silently checks whether a valid session already exists.

A useful model is:

Loading
→
Session Check
→
Authenticated / Guest
function AuthProvider({ children }) { const [status, setStatus] = useState("loading"); const [user, setUser] = useState(null); useEffect(() => { async function restoreSession() { try { const response = await fetch( "/api/auth/me", { credentials: "include" } ); if (!response.ok) { setUser(null); setStatus( "unauthenticated" ); return; } const userData = await response.json(); setUser(userData); setStatus( "authenticated" ); } catch { setUser(null); setStatus( "unauthenticated" ); } } restoreSession(); }, []); if (status === "loading") { return <LoadingScreen />; } return children; }
The exact session restoration mechanism depends on the backend authentication architecture. The important React concept is to represent the initial “checking” state explicitly.

19. Auth Context + React Router

The concepts from Lessons 21–25 now come together.

function App() { return ( <BrowserRouter> <AuthProvider> <Routes> <Route path="/login" element={<Login />} /> <Route path="/signup" element={<Signup />} /> <Route path="/dashboard" element={ <ProtectedRoute> <Dashboard /> </ProtectedRoute> } /> </Routes> </AuthProvider> </BrowserRouter> ); }
Notice the separation:

React Router → decides which UI should render.

Auth Context → distributes authentication state.

Backend → actually verifies identity and enforces authorization.

20. Authentication Is Not Authorization

Suppose a ZENSUS application has three roles:

Student

Can access courses and personal learning progress.

Instructor

Can create or manage assigned educational content.

Admin

Can perform administrative operations.

The frontend can conditionally render navigation, but the backend must enforce these permissions.

if (user.role === "admin") { return <AdminPanel />; } return <AccessDenied />;
Never rely on hiding a button or React route as the only authorization mechanism. The server must check permissions before performing sensitive operations.

21. Authentication Security Fundamentals

HTTPS Use HTTPS in production to protect data in transit.
Password Hashing Passwords should be handled and stored by the backend using an appropriate password hashing algorithm, never as plaintext.
Short-Lived Access Tokens Short lifetimes can reduce the useful lifetime of an exposed access token.
Refresh Token Protection Refresh credentials require stronger protection and lifecycle controls.
XSS Prevention Prevent untrusted content from becoming executable script.
CSRF Protection Cookie-based authentication needs appropriate CSRF defenses.
Server Authorization Sensitive operations must be authorized by the backend.
Session Expiration Applications should handle expired sessions predictably.
Logout Authentication state should be cleared appropriately on logout.

23. Common Authentication Mistakes

Mistake 1 — Storing Passwords in React State Permanently

Passwords should be submitted to the authentication backend and should not be treated as application state that persists after authentication.

Mistake 2 — Storing Sensitive Tokens Without Understanding the Risk

Using localStorage is convenient, but JavaScript-accessible credentials have XSS exposure considerations.

Mistake 3 — Treating ProtectedRoute as Security

A frontend route guard cannot replace backend authentication and authorization.

Mistake 4 — No Loading State

Immediately assuming “logged out” while restoring a session can cause incorrect redirects or UI flicker.

Mistake 5 — Forgetting Session Expiration

Applications need a strategy for expired or invalid authentication.

Mistake 6 — Authentication ≠ Authorization

Knowing who the user is does not determine what that user is permitted to do.

Mistake 7 — Trusting Role Information From the Client

Client-side role checks are useful for UI decisions, but the server must enforce permissions.

Mistake 8 — Sending Credentials Over Insecure Connections

Production authentication should use HTTPS.

24. Professional Authentication Decision Guide

Question Think About
Who is the user? Authentication
What can the user access? Authorization
How does the browser prove authentication? Session or token mechanism
Where should credentials be stored? Threat model + architecture + browser security controls
How does React know the user state? Auth Context / application state
How are screens protected? React Router guards for UI + backend enforcement
What happens after expiration? Session restoration / refresh / re-authentication
What happens during logout? Invalidate appropriate server-side state + clear client state

26. Quick Quiz

Test your understanding before moving to the next React lesson.

1. What does authentication answer?

Authentication answers: “Who are you?”

2. What does authorization determine?

Authorization determines what resources or operations an authenticated user is permitted to access.

3. Why is a frontend ProtectedRoute not sufficient security?

Frontend route guards control the UI. The backend must independently authenticate requests and authorize sensitive operations.

4. What is a major security consideration when storing tokens in localStorage?

JavaScript running in the origin can access localStorage. Therefore, XSS vulnerabilities can create a serious credential-exposure risk.

5. What is Auth Context mainly useful for?

Auth Context allows authentication-related application state and actions to be shared across components without manually passing them through every component level.
