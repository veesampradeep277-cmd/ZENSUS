useReducer()

Manage complex state using a predictable system of state + actions + reducer + dispatch. Learn how React turns user events into controlled state transitions.

1. What is useReducer()?

useReducer() is a React Hook used to manage state through a reducer function.

It is especially useful when state contains multiple related values or when many different actions can change the same state. 

const [state, dispatch] = useReducer(reducer, initialState);
state Current state value.
```
dispatch Sends an action describing what happened.
reducer Calculates the next state.
initialState Starting state.
```
Mental Model: Instead of directly saying “change this state,” you say “this happened.” The reducer decides how state should change.
User Event
→
dispatch(action)
→
Reducer
→
New State
→
UI Re-renders

Basic Example

import { useReducer } from "react";

function reducer(state, action) {
    if (action.type === "increment") {
        return { count: state.count + 1 };
    }

    return state;
}

function Counter() {
    const [state, dispatch] = useReducer(
        reducer,
        { count: 0 }
    );

    return (
        <button onClick={() =>
            dispatch({ type: "increment" })
        }>
            Count: {state.count}
        </button>
    );
}

2. State vs Reducer

Understanding the difference between state and reducer logic is fundamental.

Concept Purpose
State Stores the current data.
Action Describes what happened.
Reducer Calculates the next state.
Dispatch Sends an action to the reducer.
Important: A reducer does not directly update the existing state. It returns the next state.

useState vs useReducer

useState useReducer
Simple state Complex state logic
Direct setters Actions + dispatch
Logic often inside handlers Logic centralized in reducer
Easy for small components Useful for many related transitions

Rule of thumb: Don't replace every useState() with useReducer(). Choose the simpler tool when it is sufficient.

3. Reducer Function

A reducer is a JavaScript function that receives the current state and an action, then returns the next state. 

function reducer(state, action) {
    // calculate next state

    return nextState;
}

The conceptual signature is:

reducer(currentState, action) → nextState

Example

function reducer(state, action) {

    switch (action.type) {

        case "increment":
            return {
                ...state,
                count: state.count + 1
            };

        case "decrement":
            return {
                ...state,
                count: state.count - 1
            };

        default:
            return state;
    }
}
A good reducer is predictable: the same state and same action should produce the same next state.

6. Initial State

The second argument of useReducer() provides the initial state. 

const initialState = {
    count: 0,
    username: "",
    loading: false
};

const [state, dispatch] =
    useReducer(reducer, initialState);

Initial state can be a primitive, object, array, or another appropriate JavaScript value.

Object State

const initialState = {
    name: "",
    email: "",
    password: "",
    errors: {}
};

The advantage becomes clear when many related values must change according to different events.

7. State Transitions

A reducer can be understood as a state transition machine.

State A
+
Action
→
Reducer
→
State B

Example: Authentication

const initialState = {
    status: "loggedOut",
    user: null
};

function reducer(state, action) {

    switch (action.type) {

        case "login":
            return {
                status: "loggedIn",
                user: action.payload
            };

        case "logout":
            return {
                status: "loggedOut",
                user: null
            };

        default:
            return state;
    }
}

Possible transitions:

loggedOut ↓ login
```
loggedIn ↓ logout
loading ↓ success
loading ↓ error
```
Think of each action as an event and the reducer as the rulebook that determines the next state.

8. Managing Complex State

Consider a dashboard containing:

User information
Loading status
Error message
Notifications
Selected item
Filters

Managing every transition independently with many setters can make the event handlers difficult to follow.

A reducer can centralize the transition rules. 

const initialState = {
    data: [],
    loading: false,
    error: null,
    selectedId: null
};

function reducer(state, action) {

    switch (action.type) {

        case "fetchStart":
            return {
                ...state,
                loading: true,
                error: null
            };

        case "fetchSuccess":
            return {
                ...state,
                loading: false,
                data: action.payload
            };

        case "fetchError":
            return {
                ...state,
                loading: false,
                error: action.payload
            };

        case "select":
            return {
                ...state,
                selectedId: action.payload
            };

        default:
            return state;
    }
}

9. Forms with useReducer()

Forms can have many related state values:

  • name
  • email
  • password
  • validation errors
  • submitting status
  • success state

Reducer-Based Form

const initialState = {
    name: "",
    email: "",
    password: "",
    errors: {},
    submitting: false
};

function reducer(state, action) {

    switch (action.type) {

        case "fieldChange":
            return {
                ...state,
                [action.field]: action.value
            };

        case "submitStart":
            return {
                ...state,
                submitting: true
            };

        case "submitSuccess":
            return {
                ...initialState
            };

        case "setErrors":
            return {
                ...state,
                errors: action.payload,
                submitting: false
            };

        default:
            return state;
    }
}

Dispatching a Field Change

dispatch({
    type: "fieldChange",
    field: "email",
    value: e.target.value
});
The action says what happened. The reducer decides how the state changes.

10. Shopping Cart Example

A shopping cart is a classic example of state with multiple related transitions.

Possible actions:

ADD_ITEM REMOVE_ITEM INCREASE_QTY DECREASE_QTY CLEAR_CART

Cart State

const initialState = {
    items: []
};

Cart Reducer

function reducer(state, action) {

    switch (action.type) {

        case "ADD_ITEM":
            return {
                ...state,
                items: [
                    ...state.items,
                    action.payload
                ]
            };

        case "REMOVE_ITEM":
            return {
                ...state,
                items: state.items.filter(
                    item => item.id !== action.payload
                )
            };

        case "CLEAR_CART":
            return {
                ...state,
                items: []
            };

        default:
            return state;
    }
}

11. Reducer Best Practices

1. Keep reducers pure A reducer should calculate state, not perform side effects.
2. Don't mutate state Return new objects/arrays when state changes.
3. Use descriptive actions Actions should clearly communicate what happened.
4. Handle unknown actions Usually return the existing state.
5. Keep related state together Reducers are useful when multiple values change together.
6. Avoid giant reducers Split unrelated state domains when necessary.

Pure Reducer

function reducer(state, action) {

    switch (action.type) {

        case "increment":
            return {
                ...state,
                count: state.count + 1
            };

        default:
            return state;
    }
}

Do Not Perform Side Effects

Avoid API calls, timers, DOM manipulation, random side effects, or other external effects inside reducers.

Side effects belong in appropriate places such as event handlers or useEffect(), depending on the situation.

12. Common Mistakes

❌ Mistake 1 — Mutating State

state.items.push(action.payload);

return state;

This mutates the existing array.

Prefer:

return {
    ...state,
    items: [
        ...state.items,
        action.payload
    ]
};

❌ Mistake 2 — Forgetting to Return State

case "increment":
    state.count++;
    break;

A reducer must return the next state.

❌ Mistake 3 — Performing API Calls in Reducer

case "load":
    fetch("/api/users"); // ❌
    return state;

Reducers should remain pure.

❌ Mistake 4 — Unknown Action Returns undefined

default:
    return state;

Returning the current state for an unrecognized action is the normal pattern.

❌ Mistake 5 — Using useReducer for Everything

A simple boolean such as: 

const [open, setOpen] = useState(false);

usually does not need a reducer.

Don't add abstraction without a reason. useReducer is useful when the state logic benefits from explicit transitions and centralized update rules.

13. Reducer Decision Guide

Situation Typical Choice
One simple value useState
Simple independent values useState
Many related state transitions useReducer
Complex form state useReducer can help
Shopping cart useReducer can help
Complex workflow/state machine-like transitions useReducer can help

14. Complete React Example

import { useReducer } from "react";

const initialState = {
    count: 0
};

function reducer(state, action) {

    switch (action.type) {

        case "increment":
            return {
                ...state,
                count: state.count + 1
            };

        case "decrement":
            return {
                ...state,
                count: state.count - 1
            };

        case "add":
            return {
                ...state,
                count: state.count + action.payload
            };

        case "reset":
            return initialState;

        default:
            return state;
    }
}

export default function Counter() {

    const [state, dispatch] =
        useReducer(reducer, initialState);

    return (
        <div>

            <h1>Count: {state.count}</h1>

            <button onClick={() =>
                dispatch({ type: "increment" })
            }>
                +1
            </button>

            <button onClick={() =>
                dispatch({ type: "decrement" })
            }>
                -1
            </button>

            <button onClick={() =>
                dispatch({
                    type: "add",
                    payload: 5
                })
            }>
                +5
            </button>

            <button onClick={() =>
                dispatch({ type: "reset" })
            }>
                Reset
            </button>

        </div>
    );
}
Notice the separation: UI dispatches events → reducer owns transition logic → state drives UI.
