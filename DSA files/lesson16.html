Trie — The Prefix Tree

What is a Trie?

A Trie, also called a Prefix Tree, is a tree-like data structure used to store strings efficiently.

Unlike a normal Binary Search Tree, a Trie organizes data according to characters and prefixes.

Real-world analogy

Imagine the search suggestions on Google. When you type:

app|

the system can quickly find: apple, application, appointment, app.

Trie Terminology

RootStarting node
EdgeConnection between nodes
NodeStores a character
CharacterIndividual symbol
End-of-wordMarks complete word
PrefixBeginning of a word
DepthDistance from root

Why use a Trie?

  • Fast prefix searching
  • Autocomplete
  • Dictionary implementation
  • Spell checking
  • IP routing
  • Maximum XOR problems using Binary Trie

02

Trie Operations

1. Insert

Traverse character by character. If a character does not exist, create a new node.

Algorithm
  1. Start from root.
  2. Read every character.
  3. Create missing nodes.
  4. Move to the child.
  5. Mark the final node as end-of-word.

2. Search

  1. Start at root.
  2. Follow every character.
  3. If a character is missing → false.
  4. After the final character check is_end.

3. StartsWith

Used when we only want to know whether a prefix exists. 

trie.startsWith("app")

4. Delete

Delete a word carefully without removing nodes that belong to another word.

Python — Complete Trie 
class TrieNode:
    def __init__(self):
        self.children = {}
        self.is_end = False


class Trie:

    def __init__(self):
        self.root = TrieNode()

    def insert(self, word):
        node = self.root

        for ch in word:
            if ch not in node.children:
                node.children[ch] = TrieNode()

            node = node.children[ch]

        node.is_end = True

    def search(self, word):
        node = self.root

        for ch in word:
            if ch not in node.children:
                return False

            node = node.children[ch]

        return node.is_end

    def startsWith(self, prefix):
        node = self.root

        for ch in prefix:
            if ch not in node.children:
                return False

            node = node.children[ch]

        return True


trie = Trie()

trie.insert("apple")
trie.insert("app")

print(trie.search("apple"))
print(trie.search("app"))
print(trie.startsWith("ap"))

Essential Bit Tricks

Check Odd / Even

if n & 1:
    print("Odd")
else:
    print("Even")

The least significant bit determines whether a number is odd.

Check kth Bit

(n >> k) & 1

Set kth Bit

n | (1 << k)

Clear kth Bit

n & ~(1 << k)

Toggle kth Bit

n ^ (1 << k)

Remove Lowest Set Bit

n & (n - 1)
This operation removes exactly one set bit — the lowest set bit.

Check Power of Two

n > 0 and (n & (n - 1)) == 0

Count Set Bits

count = 0

while n:
    n = n & (n - 1)
    count += 1

Disjoint Set Union — DSU

What is DSU?

Disjoint Set Union is a data structure used to maintain several separate groups and efficiently determine whether two elements belong to the same group.

Core Operations

Find

Find the representative/leader of a set.

Union

Merge two sets together.

Path Compression

Make future Find operations faster.

Union by Rank

Attach the smaller tree under the larger tree.

Union by Size

Use the size of each component when merging.

Connectivity Example

1 2 3 4
Union(1,2) → Union(2,3)
1 2 3
4

Applications

  • Connected components
  • Cycle detection
  • Kruskal's Minimum Spanning Tree
  • Network connectivity
  • Number of islands
Python — DSU with Path Compression 
class DSU:

    def __init__(self, n):
        self.parent = list(range(n))
        self.size = [1] * n

    def find(self, x):

        if self.parent[x] != x:
            self.parent[x] = self.find(self.parent[x])

        return self.parent[x]

    def union(self, a, b):

        rootA = self.find(a)
        rootB = self.find(b)

        if rootA == rootB:
            return False

        if self.size[rootA] < self.size[rootB]:
            rootA, rootB = rootB, rootA

        self.parent[rootB] = rootA
        self.size[rootA] += self.size[rootB]

        return True

DSU Complexity

With path compression and union by size/rank:

≈ O(α(n)) per operation α(n) is the inverse Ackermann function and grows extremely slowly.

Segment Tree

A Segment Tree is used when we need efficient range queries together with updates.

[1..8]
[1..4]
[5..8]
[1..2]
[3..4]
[5..6]
[7..8]

Why Segment Tree?

Suppose an array changes frequently and you need to answer many range-sum or range-minimum queries.

Recomputing the whole range every time can be expensive. Segment Trees reduce query and update operations to logarithmic time.

Array
↓
Build Tree
↓
Query / Update
Build O(n)
Query O(log n)
Update O(log n)

Applications

  • Range Sum
  • Range Minimum
  • Range Maximum
  • Point Updates
  • Competitive Programming
Python — Segment Tree Range Sum 
class SegmentTree:

    def __init__(self, arr):
        self.n = len(arr)
        self.tree = [0] * (4 * self.n)
        self.arr = arr

        self.build(1, 0, self.n - 1)

    def build(self, node, left, right):

        if left == right:
            self.tree[node] = self.arr[left]
            return

        mid = (left + right) // 2

        self.build(node * 2, left, mid)
        self.build(node * 2 + 1, mid + 1, right)

        self.tree[node] = (
            self.tree[node * 2]
            + self.tree[node * 2 + 1]
        )

    def query(self, node, left, right, ql, qr):

        if qr < left or right < ql:
            return 0

        if ql <= left and right <= qr:
            return self.tree[node]

        mid = (left + right) // 2

        return (
            self.query(node * 2, left, mid, ql, qr)
            +
            self.query(node * 2 + 1, mid + 1, right, ql, qr)
        )

Fenwick Tree / Binary Indexed Tree

A Fenwick Tree is a compact data structure for maintaining prefix information with efficient updates.

i += i & -i Move upward during update
i -= i & -i Move upward during query
Update O(log n)
Query O(log n)
Space O(n)

Segment Tree vs Fenwick Tree

Feature Segment Tree Fenwick Tree
Range Sum ✓ ✓
Range Minimum ✓ Limited
Point Update ✓ ✓
Lazy Propagation ✓ ✗
Memory Higher Lower
Implementation Complex Simpler

Advanced String Algorithms

KMP

Knuth-Morris-Pratt

KMP searches for a pattern without repeatedly moving backward in the text.

  • LPS array
  • Prefix / suffix concept
  • Pattern matching
  • Complexity: O(n + m)
Z

Z Algorithm

Builds a Z-array where each position stores the length of the longest substring starting there that matches the prefix.

  • Z-array
  • Prefix matching
  • Pattern searching
  • Complexity: O(n)
RH

Rolling Hash

Converts strings or substrings into hash values to enable efficient comparisons.

  • Substring comparison
  • Hashing
  • Collision concept
