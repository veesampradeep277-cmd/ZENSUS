10 • Browser Storage

Saving Data with LocalStorage

LocalStorage allows small amounts of data to persist in the browser between page reloads. Because it stores strings, arrays and objects are normally converted using JSON.stringify() and JSON.parse().

Save 
localStorage.setItem(
    "students",
    JSON.stringify(students)
);
Read 
const students =
    JSON.parse(
        localStorage.getItem("students")
    ) || [];
Important LocalStorage is useful for learning and simple client-side persistence, but it is not a replacement for a secure production database.

POST Student 
async function createStudent(student) {

    const response =
        await fetch(
            "/api/students",
            {
                method: "POST",

                headers: {
                    "Content-Type":
                        "application/json"
                },

                body:
                    JSON.stringify(student)
            }
        );

    if (!response.ok) {
        throw new Error(
            `HTTP ${response.status}`
        );
    }

    return response.json();
}

14 • Debugging

Common Project Mistakes

Mistake 1 — Changing the array but not the UI After adding, editing or deleting a student, call your rendering function again.
Mistake 2 — Not validating input Never assume that form values are valid.
Mistake 3 — Forgetting JSON.stringify() LocalStorage stores strings, so objects need serialization.
Mistake 4 — Using array index as a permanent ID Deleting or sorting can change indexes. Prefer stable IDs.
Mistake 5 — Exposing secrets Never place private API credentials in browser JavaScript.
15 • Exam Preparation

5-Mark & 10-Mark Answers

5-Mark: Explain a JavaScript mini project.

A JavaScript mini project combines multiple JavaScript concepts to solve a practical problem. A student management application can use variables, arrays, objects, functions, DOM manipulation, events, forms and browser storage. The application accepts user input, validates it, stores student information, calculates results and dynamically updates the interface.

10-Mark: Explain the development of a Student Management System.

A Student Management System is a web application that maintains student records. The project can contain a form for entering student information, JavaScript objects for representing records, arrays for storing multiple students, functions for CRUD operations and DOM manipulation for displaying data. Search and sorting can be implemented using array methods such as filter() and sort(). LocalStorage can provide client-side persistence. In a full-stack version, the frontend can communicate with a REST API using fetch(), HTTP methods and JSON.

16 • Interview Preparation

Project Interview Questions

1. Why did you choose this project?

It combines core JavaScript concepts into a practical application and demonstrates CRUD, DOM manipulation, persistence and API integration.

2. How do you store students?

Each student can be represented as an object and multiple student objects can be stored in an array.

3. How does search work?

The search text can be normalized and filter() can be used to create a list containing matching students.

4. How does edit functionality work?

Find the student using its stable ID, update its properties, save the changed collection and render the UI again.

5. Why use stable IDs?

Array indexes can change when data is sorted or deleted. Stable IDs continue to identify the same record.

6. How does LocalStorage work?

LocalStorage stores string values in the browser. JSON.stringify() converts JavaScript data to a string, while JSON.parse() reconstructs the data.

7. How would you connect this project to Django?

The JavaScript frontend can call Django REST endpoints using fetch(), exchange JSON data and update the DOM based on the server response.

8. How would you secure the project?

Authentication and authorization should be implemented on the backend, sensitive secrets should remain server-side, and user input should be validated on the server as well as the client.

9. How would you improve performance?

Avoid unnecessary DOM work, debounce expensive search/API operations when appropriate, paginate large datasets and minimize unnecessary network requests.

10. What would you add in version 2?

Authentication, Django REST API, PostgreSQL, role-based access, charts, pagination, notifications and deployment.
