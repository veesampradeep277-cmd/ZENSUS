What Is the DOM?

DOM stands for Document Object Model.

When a browser loads an HTML document, it creates an in-memory representation of that document as a tree of objects.

Simple idea: HTML creates the structure. CSS controls the appearance. JavaScript uses the DOM to dynamically read and change that structure and its presentation.

document.title

document.body

References the body element.

document.head

References the head element.

document.URL

Returns the current document URL.

05

Selecting DOM Elements

Before changing an element, JavaScript usually needs to find it.

1. getElementById()

const title = document.getElementById("title");

console.log(title);

2. getElementsByClassName()

const cards =
    document.getElementsByClassName("card");

console.log(cards);

3. getElementsByTagName()

const paragraphs =
    document.getElementsByTagName("p");

4. querySelector()

const title =
    document.querySelector("#title");

const card =
    document.querySelector(".card");

const button =
    document.querySelector("button");

5. querySelectorAll()

const cards =
    document.querySelectorAll(".card");

cards.forEach(card => {
    console.log(card);
});
Modern recommendation: querySelector() and querySelectorAll() are extremely useful because they support CSS selectors.

07

Changing Text Content

JavaScript can change the text displayed by an element.

textContent

const heading =
    document.querySelector("h1");

heading.textContent = "Welcome to ZENSUS";

textContent treats the assigned value as text.

innerHTML

const box =
    document.querySelector(".box");

box.innerHTML =
    "<strong>Hello ZENSUS</strong>";
Security rule: Do not place untrusted user input directly into innerHTML. Prefer textContent when you only need text.
08

textContent vs innerHTML

Feature textContent innerHTML
Reads text Yes Yes, as HTML markup string
Parses HTML No Yes
Good for user text Yes Use carefully
Creates HTML structure No Yes

DOM Traversal

DOM traversal means moving through the DOM tree from one node to another.

parentElement

Moves from an element to its parent element.

children

Returns child elements.

firstElementChild

Gets the first child element.

lastElementChild

Gets the last child element.

nextElementSibling

Moves to the next sibling element.

previousElementSibling

Moves to the previous sibling element. 

const item =
    document.querySelector(".item");

console.log(item.parentElement);

console.log(item.children);

console.log(item.nextElementSibling);

When Should JavaScript Access the DOM?

If JavaScript runs before the required HTML element has been parsed, a selector may return null.

Option 1 — Put script at the end of body

<body>

    <h1 id="title">Hello</h1>

    <script src="app.js"></script>

</body>

Option 2 — DOMContentLoaded

document.addEventListener(
    "DOMContentLoaded",
    () => {

        const title =
            document.querySelector("#title");

        console.log(title);
    }
);

Option 3 — defer

<script src="app.js" defer></script>
Modern practice: External scripts commonly use defer when they need the document to be parsed before execution.

DOM and Events — The Connection

DOM manipulation becomes powerful when combined with browser events. 

const button =
    document.querySelector("#button");

button.addEventListener(
    "click",
    () => {

        document.body.classList.toggle("dark");

    }
);
Think of the relationship:

DOM = What exists on the page
Events = What happens on the page
JavaScript = What should happen in response

27

⚠️ Common DOM Mistakes

1. Wrong selector

querySelector("#box") requires an element with that ID.

2. Element is null

The script may execute before the element exists.

3. Confusing value and textContent

Form controls usually use value.

4. Misusing innerHTML

Avoid inserting untrusted content as HTML.

5. Overusing inline styles

Prefer reusable CSS classes when possible.

6. Forgetting querySelectorAll

querySelector selects only the first match.

28

DOM Performance

DOM operations can become expensive when a program performs huge numbers of reads and writes.

Good habits:
  • Cache elements you use repeatedly.
  • Avoid unnecessary DOM updates.
  • Build larger content before inserting it when appropriate.
  • Prefer event delegation for many similar interactive elements.
  • Keep rendering work separate from application logic where practical. 
// Better when reused many times

const title =
    document.querySelector("#title");

title.textContent = "One";

title.textContent = "Two";

title.textContent = "Three";
