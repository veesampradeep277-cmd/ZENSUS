🏆 Project: College Management & Placement System

Our goal is to build a relational database for an engineering college that manages students, departments, courses, companies, applications and placement results.

Project Goal: Build a database that can answer real questions such as: Which students are eligible for a company? Which department has the highest average marks? Which companies hired the most students? Which students have multiple applications?

4. Step 1 — Create Database & Tables

Start by creating the database and then build the tables in a sensible dependency order.

SQL — DATABASE 
CREATE DATABASE college_placement;

-- MySQL-style example
USE college_placement;

Departments

SQL 
CREATE TABLE departments (
    department_id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE,
    hod_name VARCHAR(100)
);

Students

SQL 
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) NOT NULL UNIQUE,
    department_id INT NOT NULL,
    marks DECIMAL(5,2) CHECK (marks BETWEEN 0 AND 100),
    graduation_year INT,

    CONSTRAINT fk_student_department
        FOREIGN KEY (department_id)
        REFERENCES departments(department_id)
);

Companies

SQL 
CREATE TABLE companies (
    company_id INT PRIMARY KEY,
    company_name VARCHAR(150) NOT NULL UNIQUE,
    package_lpa DECIMAL(6,2) CHECK (package_lpa > 0)
);

Applications

SQL 
CREATE TABLE applications (
    application_id INT PRIMARY KEY,
    student_id INT NOT NULL,
    company_id INT NOT NULL,
    status VARCHAR(30) NOT NULL DEFAULT 'Applied',

    CONSTRAINT fk_application_student
        FOREIGN KEY (student_id)
        REFERENCES students(student_id),

    CONSTRAINT fk_application_company
        FOREIGN KEY (company_id)
        REFERENCES companies(company_id),

    CONSTRAINT uq_student_company
        UNIQUE (student_id, company_id)
);

Placements

SQL 
CREATE TABLE placements (
    placement_id INT PRIMARY KEY,
    student_id INT NOT NULL,
    company_id INT NOT NULL,
    package_lpa DECIMAL(6,2) NOT NULL,

    FOREIGN KEY (student_id)
        REFERENCES students(student_id),

    FOREIGN KEY (company_id)
        REFERENCES companies(company_id)
);

7. Step 4 — JOINs

Now combine multiple tables to answer real business questions.

Students + Departments

SQL 
SELECT
    s.student_id,
    s.name,
    d.name AS department,
    s.marks
FROM students s
INNER JOIN departments d
    ON s.department_id = d.department_id;

Students + Applications + Companies

SQL 
SELECT
    s.name AS student,
    c.company_name,
    a.status
FROM applications a
JOIN students s
    ON a.student_id = s.student_id
JOIN companies c
    ON a.company_id = c.company_id;

Students Who Got Placed

SQL 
SELECT
    s.name,
    c.company_name,
    p.package_lpa
FROM placements p
JOIN students s
    ON p.student_id = s.student_id
JOIN companies c
    ON p.company_id = c.company_id
ORDER BY p.package_lpa DESC;

8. Step 5 — GROUP BY & Aggregates

Students Per Department

SQL 
SELECT
    department_id,
    COUNT(*) AS student_count
FROM students
GROUP BY department_id;

Average Marks By Department

SQL 
SELECT
    d.name AS department,
    AVG(s.marks) AS average_marks
FROM students s
JOIN departments d
    ON s.department_id = d.department_id
GROUP BY d.department_id, d.name
ORDER BY average_marks DESC;

Departments With Average Above 85

SQL 
SELECT
    d.name AS department,
    AVG(s.marks) AS average_marks
FROM students s
JOIN departments d
    ON s.department_id = d.department_id
GROUP BY d.department_id, d.name
HAVING AVG(s.marks) > 85;

9. Step 6 — Advanced SQL

Students Above Overall Average

SQL 
SELECT
    student_id,
    name,
    marks
FROM students
WHERE marks > (
    SELECT AVG(marks)
    FROM students
)
ORDER BY marks DESC;

Students Who Applied to DataCore

SQL 
SELECT name
FROM students
WHERE student_id IN (

    SELECT student_id
    FROM applications
    WHERE company_id = (
        SELECT company_id
        FROM companies
        WHERE company_name = 'DataCore'
    )

);

Students With At Least One Application

SQL 
SELECT
    s.student_id,
    s.name
FROM students s
WHERE EXISTS (

    SELECT 1
    FROM applications a
    WHERE a.student_id = s.student_id

);

10. Step 7 — Create a Placement View

A view gives users a reusable logical representation of a query.

SQL 
CREATE VIEW placement_report AS

SELECT
    s.student_id,
    s.name AS student_name,
    d.name AS department,
    c.company_name,
    p.package_lpa
FROM placements p

JOIN students s
    ON p.student_id = s.student_id

JOIN departments d
    ON s.department_id = d.department_id

JOIN companies c
    ON p.company_id = c.company_id;

Use the View

SQL 
SELECT *
FROM placement_report
ORDER BY package_lpa DESC;
Real-world use: A placement officer can use the view instead of rewriting the complicated JOIN every time.

11. Step 8 — Optimize With Indexes

Suppose the application frequently searches students by email or department.

SQL 
CREATE INDEX idx_students_department
ON students(department_id);

Composite Index

SQL 
CREATE INDEX idx_students_department_marks
ON students(department_id, marks);

Application Search

SQL 
CREATE INDEX idx_applications_student
ON applications(student_id);

CREATE INDEX idx_applications_company
ON applications(company_id);
Important: Do not create indexes on every column. Indexes improve many reads but also consume storage and add maintenance work during writes.

12. Step 9 — Transactions

Imagine a placement officer selecting a student and recording the placement. Multiple database operations should be handled safely.

Application Update status
→
Placement Insert result
→
COMMIT Save changes

START TRANSACTION;

UPDATE applications
SET status = 'Selected'
WHERE application_id = 2;

INSERT INTO placements
(
    placement_id,
    student_id,
    company_id,
    package_lpa
)
VALUES
(
    10,
    102,
    2,
    10.00
);

COMMIT;

If Something Goes Wrong

SQL 
START TRANSACTION;

UPDATE applications
SET status = 'Selected'
WHERE application_id = 2;

-- Something goes wrong

ROLLBACK;

15. Expert-Level Queries

Highest Package

SQL 
SELECT
    MAX(package_lpa) AS highest_package
FROM placements;

Average Placement Package

SQL 
SELECT
    ROUND(AVG(package_lpa), 2) AS average_package
FROM placements;

Number of Placements Per Company

SQL 
SELECT
    c.company_name,
    COUNT(p.placement_id) AS placed_students
FROM companies c
LEFT JOIN placements p
    ON c.company_id = p.company_id
GROUP BY
    c.company_id,
    c.company_name
ORDER BY placed_students DESC;

Students With Multiple Applications

SQL 
SELECT
    s.student_id,
    s.name,
    COUNT(a.application_id) AS applications
FROM students s
JOIN applications a
    ON s.student_id = a.student_id
GROUP BY
    s.student_id,
    s.name
HAVING COUNT(a.application_id) > 1;

16. CASE — Placement Classification

We can classify placement packages into useful business categories.

SQL 
SELECT
    s.name,
    p.package_lpa,

    CASE
        WHEN p.package_lpa >= 10
            THEN 'Excellent'
        WHEN p.package_lpa >= 7
            THEN 'Good'
        ELSE
            'Entry Level'
    END AS package_category

FROM placements p

JOIN students s
    ON p.student_id = s.student_id;

17. Database Testing

Never assume that a database works simply because CREATE TABLE succeeded. Test the rules deliberately.

Test 1 — Duplicate Email

SQL 
INSERT INTO students
(student_id, name, email, department_id, marks)
VALUES
(200, 'Test Student',
 'pradeep@example.com',
 1,
 80);

This should fail because email is UNIQUE.

Test 2 — Invalid Marks

SQL 
INSERT INTO students
(student_id, name, email, department_id, marks)
VALUES
(201, 'Invalid Student',
 'invalid@example.com',
 1,
 150);

The CHECK constraint should reject the value in DBMSs that enforce the specified CHECK condition.

Test 3 — Invalid Department

SQL 
INSERT INTO students
(student_id, name, email, department_id, marks)
VALUES
(202, 'Unknown Student',
 'unknown@example.com',
 999,
 80);

The FOREIGN KEY should reject a department that does not exist.

20. Interview Questions From This Project

1. Why did you separate students and departments?

To avoid unnecessary duplication and model the relationship between students and departments using a foreign key.

2. Why is applications a separate table?

A student can apply to multiple companies and a company can receive applications from multiple students. This creates a many-to-many relationship represented through a junction-style table.

3. Why did you create indexes?

To improve frequently executed searches and joins on appropriate columns while considering the additional write and storage cost.

4. Why use a view?

To provide a reusable logical representation of a complicated query and potentially simplify access to selected data.

5. Why use transactions?

To ensure related database changes are handled as a logical unit and to provide controlled COMMIT and ROLLBACK behavior.

6. What would you optimize first?

First identify actual slow queries using execution plans and workload evidence, then consider suitable indexes or query/schema changes rather than indexing everything.

24. Exam Preparation

⭐ 5-Mark Answer — Explain a SQL Project

A SQL project applies database concepts to a real-world problem. The project begins with requirement analysis and schema design, followed by table creation, constraints, data insertion and SQL queries. Advanced concepts such as JOINs, subqueries, views, indexes and transactions can then be used to improve functionality, usability, performance and data integrity.

⭐ 10-Mark Answer — Steps to Develop a Database Project

  1. Analyze the real-world requirements.
  2. Identify entities and relationships.
  3. Design the ER model.
  4. Convert the design into relational tables.
  5. Define primary and foreign keys.
  6. Add constraints for data integrity.
  7. Insert realistic test data.
  8. Develop queries using filtering, grouping and joins.
  9. Add views and indexes where justified.
  10. Use transactions for multi-step operations and test the system.
