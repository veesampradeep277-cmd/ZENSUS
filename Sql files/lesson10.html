02 • Foundation

Why do we need JOINs?

Real databases rarely store everything inside one giant table. Related information is normally separated into multiple tables.

👨‍🎓

Students

Stores student information such as student ID, name and department ID.

🏢

Departments

Stores department information such as department ID and department name.

📚

Courses

Stores courses independently while relationships connect students and courses.

Core idea

A JOIN allows SQL to retrieve related information from multiple tables by comparing values between columns.

04 • Syntax

Basic JOIN syntax

SELECT columns
FROM table1
JOIN table2
    ON table1.common_column = table2.common_column;

FROM

Specifies the starting table for the query.

JOIN

Specifies the table that should be combined with the current result.

ON

Defines the matching condition between the tables.

SELECT

Determines which columns should appear in the final result.

06 • Join Type #1

INNER JOIN

Returns only rows that have matching values in both tables. 

SELECT
    s.name,
    d.department_name
FROM students s
INNER JOIN departments d
    ON s.department_id = d.department_id;
Result

Only students whose department_id matches a department_id in the departments table are returned.

∩

Think: intersection

INNER JOIN behaves conceptually like finding the overlapping matching rows between the two tables.

07 • Join Type #2

LEFT JOIN / LEFT OUTER JOIN

Returns every row from the left table and matching rows from the right table. 

SELECT
    s.name,
    d.department_name
FROM students s
LEFT JOIN departments d
    ON s.department_id = d.department_id;
What happens when there is no match?

The left-table row remains in the result, while columns from the right table become NULL.

Student Department ID Department
Ravi 10 CSE
Anu 20 ECE
Kiran 40 NULL
08 • Join Type #3

RIGHT JOIN / RIGHT OUTER JOIN

Returns every row from the right table and matching rows from the left table. 

SELECT
    s.name,
    d.department_name
FROM students s
RIGHT JOIN departments d
    ON s.department_id = d.department_id;
Easy way to remember

LEFT JOIN → keep everything from the left table.
RIGHT JOIN → keep everything from the right table.

Practical tip

Many developers prefer LEFT JOIN because you can often rewrite a RIGHT JOIN by swapping the table order, making queries easier to read consistently.

09 • Join Type #4

FULL OUTER JOIN

Returns matching rows plus unmatched rows from both tables. 

SELECT
    s.name,
    d.department_name
FROM students s
FULL OUTER JOIN departments d
    ON s.department_id = d.department_id;
←

Left-only rows

Students with no matching department can still appear.

↔

Matching rows

Rows whose join keys match appear together.

→

Right-only rows

Departments with no matching student can still appear.

Database compatibility

FULL OUTER JOIN is not supported directly by every database system. Some systems require alternative techniques such as combining LEFT JOIN and RIGHT JOIN with UNION.

10 • Join Type #5

CROSS JOIN

Produces every possible combination of rows from two tables. 

SELECT
    s.name,
    c.course_name
FROM students s
CROSS JOIN courses c;
Cartesian Product

If table A contains 100 rows and table B contains 50 rows, a CROSS JOIN can produce 100 × 50 = 5,000 combinations.

Example

Students Courses Combinations
3 2 6
11 • Join Type #6

SELF JOIN

A table can be joined with itself when rows in the same table have relationships with other rows. 

SELECT
    e.employee_name AS employee,
    m.employee_name AS manager
FROM employees e
LEFT JOIN employees m
    ON e.manager_id = m.employee_id;
Real-world examples

Employee → Manager, Category → Parent Category, Person → Parent, Employee → Mentor.

13 • Professional SQL

Table aliases

Aliases make multi-table queries shorter and easier to read. 

SELECT
    s.name,
    d.department_name
FROM students AS s
JOIN departments AS d
    ON s.department_id = d.department_id;
Why aliases matter

When multiple tables contain columns with the same name, table aliases remove ambiguity.

14 • Critical Concept

ON vs WHERE

One of the most important concepts for writing correct JOIN queries.

ON

Defines how rows from the tables are matched. 

JOIN departments d
ON s.department_id = d.department_id

WHERE

Filters the resulting rows according to a condition. 

WHERE s.marks > 80
LEFT JOIN trap

Moving a condition from ON to WHERE can change a LEFT JOIN into behavior that resembles an INNER JOIN by filtering out rows containing NULLs from the right side. 

-- Keeps students even when their department is missing

SELECT s.name, d.department_name
FROM students s
LEFT JOIN departments d
    ON s.department_id = d.department_id
    AND d.department_name = 'CSE';
-- WHERE removes rows where d.department_name is NULL

SELECT s.name, d.department_name
FROM students s
LEFT JOIN departments d
    ON s.department_id = d.department_id
WHERE d.department_name = 'CSE';

16 • Critical Debugging

Why can JOIN create duplicate rows?

A JOIN does not guarantee one output row for every row in the first table. If one row matches multiple rows in the second table, multiple result rows can be produced. 

SELECT
    d.department_name,
    s.name
FROM departments d
JOIN students s
    ON d.department_id = s.department_id;
One-to-many relationship

One department may contain many students. Therefore, the department information can appear repeatedly — once for each matching student.

17 • Database Design

Many-to-many relationships

A many-to-many relationship is commonly implemented using a junction/bridge table.

Students

student_id, name

Enrollments

student_id, course_id

Courses

course_id, course_name 

SELECT
    s.name,
    c.course_name
FROM students s
JOIN enrollments e
    ON s.student_id = e.student_id
JOIN courses c
    ON e.course_id = c.course_id;
18 • NULL Handling

JOINs and NULL values

Remember

NULL does not mean zero, empty string or false. It represents missing/unknown information. 

SELECT
    s.name,
    d.department_name
FROM students s
LEFT JOIN departments d
    ON s.department_id = d.department_id
WHERE d.department_id IS NULL;

This is a useful pattern for finding students who do not have a matching department.

19 • Practical Pattern

Find records without a match

SELECT s.*
FROM students s
LEFT JOIN departments d
    ON s.department_id = d.department_id
WHERE d.department_id IS NULL;
Interview pattern

LEFT JOIN + WHERE right_table.key IS NULL is a common way to identify records in the left table that have no matching record in the right table.

20 • Advanced SQL

JOIN + GROUP BY + Aggregate

SELECT
    d.department_name,
    COUNT(s.student_id) AS student_count
FROM departments d
LEFT JOIN students s
    ON d.department_id = s.department_id
GROUP BY d.department_id, d.department_name
ORDER BY student_count DESC;
What does this query do?

It counts students in each department while still showing departments that currently have zero students.

21 • Combining Concepts

JOIN + ORDER BY

SELECT
    s.name,
    s.marks,
    d.department_name
FROM students s
JOIN departments d
    ON s.department_id = d.department_id
ORDER BY s.marks DESC;

The JOIN combines the information first conceptually, while ORDER BY determines the requested result ordering.

22 • Advanced Pattern

JOIN with CASE

SELECT
    s.name,
    d.department_name,
    CASE
        WHEN s.marks >= 90 THEN 'Excellent'
        WHEN s.marks >= 75 THEN 'Good'
        ELSE 'Needs Improvement'
    END AS performance
FROM students s
JOIN departments d
    ON s.department_id = d.department_id;

25 • Debugging

Common JOIN mistakes

1

Missing ON condition

Can create a huge Cartesian product or incorrect result.

2

Joining the wrong columns

Always verify the relationship between the keys.

3

Using INNER JOIN when LEFT JOIN is required

INNER JOIN removes unmatched left-side rows.

4

Filtering a LEFT JOIN incorrectly

A WHERE condition on the right table can remove NULL rows.

5

Ignoring duplicate rows

One-to-many relationships naturally produce multiple rows.

6

Not using aliases

Large JOIN queries become difficult to read and debug.

7

Accidental CROSS JOIN

Missing relationship conditions can multiply row counts.

8

Assuming every database supports every JOIN syntax

RIGHT/FULL OUTER JOIN support and syntax can vary by DBMS.

26 • Performance

JOIN performance fundamentals

⚡

Index join keys

Appropriate indexes can make joins substantially faster, especially on large tables.

🎯

Filter intelligently

Reduce unnecessary rows before expensive operations when the query and optimizer benefit from it.

📊

Inspect the plan

Use your database's EXPLAIN/EXPLAIN PLAN tools to understand how the optimizer executes the query.

Important

Do not assume an index automatically makes every JOIN fast. Database engines consider table sizes, statistics, indexes, selectivity and available execution strategies.

28 • Exam Preparation

5-Mark Answer — SQL JOIN

Define SQL JOIN and explain its types.

A SQL JOIN is used to combine related rows from two or more tables based on a related column or condition. JOINs are essential in relational databases because information is commonly distributed across normalized tables.

The major JOIN types are INNER JOIN, LEFT JOIN, RIGHT JOIN, FULL OUTER JOIN, CROSS JOIN and SELF JOIN.

INNER JOIN returns matching rows. LEFT JOIN returns all rows from the left table and matching rows from the right table. RIGHT JOIN does the opposite. FULL OUTER JOIN returns rows from both sides, including unmatched rows. CROSS JOIN returns every possible combination, while SELF JOIN joins a table with itself.

30 • Interview Preparation

JOIN interview questions

1. What is a JOIN?

A JOIN combines rows from multiple tables according to a matching condition.

2. INNER JOIN vs LEFT JOIN?

INNER JOIN returns only matching rows. LEFT JOIN keeps every row from the left table and adds matching right-side data.

3. What happens when LEFT JOIN has no match?

The left-side row remains, while selected columns from the right table are NULL.

4. What is a SELF JOIN?

A SELF JOIN joins a table to itself, typically using different aliases for the two logical copies of the table.

5. What is a CROSS JOIN?

CROSS JOIN returns the Cartesian product — every row from the first table combined with every row from the second table.

6. Why are aliases useful?

They shorten queries and remove ambiguity when several tables contain columns with the same names.

7. Can JOIN be used with GROUP BY?

Yes. A JOIN can combine related tables and GROUP BY can then aggregate the resulting rows.

8. Can a query have multiple JOINs?

Yes. A query can join three, four or many related tables, provided the relationships and conditions are correctly defined.

9. Why can a JOIN produce duplicate rows?

If a row on one side matches multiple rows on the other side, SQL returns a row for each matching combination.

10. What is the difference between ON and WHERE?

ON defines how tables are matched. WHERE filters rows from the resulting query. With outer joins, moving conditions between them can change the result.
