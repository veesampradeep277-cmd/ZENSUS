01 · Foundation

What is SELECT?

SELECT is used to retrieve data from one or more database objects such as tables and views.

Think of SELECT as asking the database a question

Suppose your database contains thousands of students. You may want to ask:

  • What are all the students?
  • What are their names?
  • Which departments exist?
  • What are their ages?
SELECT = retrieve information. It does not normally change the stored rows.

08 · DISTINCT

Removing duplicates with DISTINCT

Suppose many students belong to the same department. 

SELECT department
FROM students;

The result may contain:

department
CSE
ECE
IT
CSE

Use DISTINCT: 

SELECT DISTINCT department
FROM students;

Now each distinct department value appears once in the result.

DISTINCT removes duplicate result rows based on the selected expressions/columns.
09 · Interview concept

DISTINCT with multiple columns 

SELECT DISTINCT
    department,
    age
FROM students;

Here DISTINCT considers the combination of department + age.

DISTINCT does not mean "make every column independently unique." It removes duplicate result rows based on the complete selected combination.
10 · Readability

Column aliases with AS

An alias gives a temporary name to a column or expression in the result. 

SELECT
    name AS student_name,
    department AS branch
FROM students;

The underlying table structure is not changed.

Original column

name

Result heading

student_name

AS can often be omitted 

SELECT
    name student_name
FROM students;
Using AS is usually clearer, especially for beginners and complex expressions.
11 · Calculations

Calculations inside SELECT

SELECT can calculate values while producing the result.

Example: increase a salary by 10% 

SELECT
    name,
    salary,
    salary * 1.10 AS increased_salary
FROM employees;

The calculation changes the displayed result, not necessarily the stored salary.

SELECT expressions are excellent for reports, calculations and derived output.

13 · SELECT expressions

SELECT can also return constants 

SELECT
    'ZENSUS' AS platform,
    2026 AS year;

A SELECT statement does not always have to retrieve a table column.

It can return expressions and constants supported by the database.

14 · Database differences

SELECT without FROM

Some database systems allow expressions to be selected without referencing a table. 

SELECT
    10 + 20 AS result;

A database may return:

result
30
Exact syntax and behavior can differ by SQL dialect.

19 · Core SQL

The bigger SELECT query structure 

SELECT columns
FROM table
WHERE condition
GROUP BY columns
HAVING condition
ORDER BY columns
LIMIT number;

You do not need every clause in every query.

We will study these clauses individually throughout the upcoming SQL lessons.

The exact availability and syntax of LIMIT, TOP, FETCH and similar row-limiting features varies between database systems.
20 · Debugging

Common SELECT mistakes 

-- Wrong for retrieving table data

SELECT name;

If you intend to retrieve a table column, you normally need to specify its source using FROM.

If the column does not exist, the database normally reports an error. 

SELECT student_nam
FROM students;

SELECT * is useful for exploration, but explicit columns are often better for production code.

DISTINCT applies to the entire selected result row, not independently to each column. 

-- Wrong

SELECT
    name
    age
FROM students;

Use commas between selected expressions.

21 · Professional practice

SELECT and performance

Why avoid unnecessary columns?

Imagine a table containing 50 columns but your application only needs 3.

Less precise 

SELECT *
FROM students;

More precise 

SELECT
    name,
    department,
    cgpa
FROM students;

Selecting only the required data can improve readability and may reduce unnecessary data transfer. Actual performance depends on the database, schema, indexes, query plan and workload.
