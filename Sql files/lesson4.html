01 · Foundation

What is INSERT?

INSERT is the SQL command used to add new rows (records) to an existing table.

Think of a database table like a spreadsheet

A table contains columns and rows.

When you use INSERT, you are telling the database:

"Create a new row and put these values into these columns."
student_id name age department
101 Anil 20 CSE
102 Sneha 19 ECE

Suppose we execute: 

INSERT INTO students
    (student_id, name, age, department)
VALUES
    (103, 'Pradeep', 19, 'CSE');

The database creates one additional row.

02 · Visualization

How INSERT works

The database does not blindly store your values. It validates the row before writing it.

SQL INSERT
→
Match Columns
→
Validate Data
→
Check Constraints
→
Store Row
If every rule is satisfied → the row is inserted.
If a constraint or data rule is violated → the INSERT fails.
03 · Syntax

Basic INSERT syntax

The safest habit is to explicitly specify the columns you are inserting into.

General syntax

INSERT INTO table_name
    (column1, column2, column3)
VALUES
    (value1, value2, value3);

Example

INSERT INTO students
    (name, age, department)
VALUES
    ('Ravi', 20, 'CSE');
INSERT INTO

Specifies the table receiving the new row.

Column list

Specifies exactly which columns receive values.

VALUES

Provides the actual values being inserted.

Semicolon

Terminates the SQL statement in most environments.

04 · Best practice

Always prefer an explicit column list

✓ Recommended

INSERT INTO students
    (name, age, department)
VALUES
    ('Ravi', 20, 'CSE');

Clear, readable and safer when the table structure changes.

⚠ Possible but fragile

INSERT INTO students
VALUES
    (103, 'Ravi', 20, 'CSE');

This depends on the exact physical column order and expected number of columns.

Interview rule: Explicit column lists are generally the better production practice.
05 · Core skill

Insert a single row

Suppose we have: 

CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100),
    age INT,
    department VARCHAR(50)
);

Insert one student: 

INSERT INTO students
    (student_id, name, age, department)
VALUES
    (101, 'Anil', 20, 'CSE');

Result:

student_id name age department
101 Anil 20 CSE
06 · Efficiency

Insert multiple rows

You can insert several rows in a single statement. 

INSERT INTO students
    (student_id, name, age, department)
VALUES
    (101, 'Anil', 20, 'CSE'),
    (102, 'Sneha', 19, 'ECE'),
    (103, 'Ravi', 20, 'IT');
One INSERT statement can contain multiple VALUES rows.

Why is this useful?

  • Less repetitive SQL.
  • Useful for seed/sample data.
  • Can reduce application/database round trips.
  • Often cleaner than issuing many separate statements.
07 · Defaults

Using DEFAULT values

A column can have a predefined value that the database uses when no explicit value is supplied. 

CREATE TABLE users (
    id INT PRIMARY KEY,
    name VARCHAR(100),
    status VARCHAR(20)
        DEFAULT 'active'
);

You can explicitly request the default: 

INSERT INTO users
    (id, name, status)
VALUES
    (1, 'Pradeep', DEFAULT);

Or omit the column from the INSERT column list: 

INSERT INTO users
    (id, name)
VALUES
    (2, 'Ravi');
The exact behavior of omitted columns depends on the column definition. A default may be used, or NULL may be used if allowed, or the statement may fail.
08 · Important

NULL is not the same as "NULL"

This is one of the most common beginner mistakes.

✓ Actual NULL

INSERT INTO students
    (name, age)
VALUES
    ('Ravi', NULL);

NULL represents a missing/unknown value.

✗ String "NULL"

INSERT INTO students
    (name, age)
VALUES
    ('Ravi', 'NULL');

This attempts to store the text NULL, not SQL NULL.

09 · Data values

How different values are written

Data Typical SQL literal Example
Integer Number 19
Decimal Number 8.63
Text Single quotes 'CSE'
NULL NULL keyword NULL
Date Dialect-dependent literal/functions '2026-09-11'
Boolean Dialect-dependent TRUE
SQL dialects differ. PostgreSQL, MySQL, SQL Server, Oracle and SQLite do not have identical data-type and literal behavior. Learn the SQL standard concepts, then check your database's syntax.
10 · Generated IDs

Auto-generated / identity columns

In real applications, you usually do not manually enter every ID.

Many databases support automatically generated numeric identifiers, but the syntax differs by database system.

MySQL

Commonly uses AUTO_INCREMENT.

SQL Server

Commonly uses IDENTITY.

PostgreSQL

Supports identity columns such as GENERATED ... AS IDENTITY.

SQLite

Has its own rowid/integer primary-key behavior and AUTOINCREMENT option.

Conceptual example

INSERT INTO students
    (name, age, department)
VALUES
    ('Pradeep', 19, 'CSE');

If the ID column is configured for automatic generation, the database can generate the identifier for you.

11 · Database validation

INSERT and constraints

Constraints are rules that protect the integrity of your database.

Constraint Purpose Possible INSERT problem
PRIMARY KEY Uniquely identifies each row Duplicate ID
UNIQUE Prevents duplicate values Existing email reused
NOT NULL Requires a value Required column omitted
FOREIGN KEY Maintains relationship Referenced parent doesn't exist
CHECK Restricts allowed values Age is negative
DEFAULT Provides fallback value Usually helps omitted columns

Example: constraints in action

CREATE TABLE students (
    id INT PRIMARY KEY,
    email VARCHAR(100) UNIQUE,
    name VARCHAR(100) NOT NULL,
    age INT CHECK (age >= 17)
);

Valid INSERT

INSERT INTO students
    (id, email, name, age)
VALUES
    (1, 'a@example.com', 'Anil', 20);

Invalid INSERT: age violates CHECK

INSERT INTO students
    (id, email, name, age)
VALUES
    (2, 'b@example.com', 'Ravi', 10);
12 · Relationships

INSERT with FOREIGN KEY

Imagine two tables: 

-- Parent table

CREATE TABLE departments (
    department_id INT PRIMARY KEY,
    name VARCHAR(50)
);

-- Child table

CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100),
    department_id INT,
    FOREIGN KEY (department_id)
        REFERENCES departments(department_id)
);

First create the referenced department: 

INSERT INTO departments
    (department_id, name)
VALUES
    (10, 'Computer Science');

Then insert the student: 

INSERT INTO students
    (student_id, name, department_id)
VALUES
    (101, 'Pradeep', 10);
The value 10 must refer to a valid department according to the foreign-key rule.
13 · Advanced INSERT

INSERT ... SELECT

One of the most important advanced INSERT techniques: insert rows produced by a SELECT query.

Concept

Instead of manually providing VALUES, you can obtain the rows from another table or query. 

INSERT INTO cse_students
    (student_id, name)
SELECT
    student_id,
    name
FROM students
WHERE department = 'CSE';
Source Table
→
SELECT
→
Filter
→
INSERT
→
Target Table
The selected columns must be compatible with the target columns in number, order, and data type.
14 · Real-world example

INSERT...SELECT in a real system

Imagine an e-commerce company wants to create a table containing only active customers. 

INSERT INTO active_customers
    (customer_id, name, email)
SELECT
    customer_id,
    name,
    email
FROM customers
WHERE status = 'active';

The database reads matching rows from customers and inserts them into active_customers.

This is useful for data migration, archival, reporting tables, staging workflows and ETL processes.

16 · Debugging

Common INSERT mistakes

-- Wrong

INSERT INTO students
    (name, age, department)
VALUES
    ('Ravi', 20);

Three target columns were specified but only two values were supplied. 

-- Usually wrong

INSERT INTO students
    (name)
VALUES
    (Ravi);

Text values normally use single quotes: 'Ravi'.

NULL is the SQL null value. 'NULL' is text.

A primary-key value must uniquely identify a row. Inserting an existing key normally causes a constraint violation.

A child row cannot normally reference a nonexistent parent row when foreign-key enforcement is active.

Always make sure each value corresponds to the intended column. Explicit column lists make this much easier to reason about.

17 · Professional SQL

INSERT and transactions

In production systems, INSERT operations are often controlled using transactions. 

BEGIN;

INSERT INTO students
    (student_id, name, age)
VALUES
    (201, 'Arjun', 20);

INSERT INTO students
    (student_id, name, age)
VALUES
    (202, 'Meena', 19);

COMMIT;

COMMIT confirms the transaction. 

ROLLBACK;

ROLLBACK can undo changes made within the current transaction, subject to the database's transaction behavior.

Transaction syntax and autocommit behavior vary by database system and client.

19 · Exam preparation

5-mark answer: SQL INSERT

Definition

INSERT is a Data Manipulation Language (DML) command used to add one or more new rows into an existing database table.

Syntax

INSERT INTO table_name
    (column1, column2)
VALUES
    (value1, value2);

Example

INSERT INTO students
    (id, name, age)
VALUES
    (1, 'Ravi', 20);

Types

  1. Single-row INSERT
  2. Multiple-row INSERT
  3. INSERT with DEFAULT
  4. INSERT...SELECT

During insertion, the database checks data types and constraints such as PRIMARY KEY, UNIQUE, NOT NULL, FOREIGN KEY and CHECK.
