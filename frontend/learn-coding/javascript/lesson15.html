02 · FOUNDATION

Synchronous vs Asynchronous JavaScript

The first concept you must understand.

🧱 Synchronous

Statements execute one after another. A long-running task can prevent later code from executing. 

console.log("A");

console.log("B");

console.log("C");

Output: 

A
B
C

⚡ Asynchronous

Some operations can be scheduled to complete later while JavaScript continues executing other work. 

console.log("A");

setTimeout(() => {
    console.log("B");
}, 1000);

console.log("C");

Output: 

A
C
B
03 · WHY ASYNC?

Why do we need asynchronous JavaScript?

JavaScript is commonly used for applications that interact with external systems. Waiting for every slow operation before doing anything else would make applications feel unresponsive.

⏱

Timers

File / Database Work

Operations that may take time outside JavaScript execution.

04 · JAVASCRIPT ENGINE

The Call Stack

The Call Stack keeps track of currently executing JavaScript functions.

function first() {
    second();
}

function second() {
    console.log("Hello");
}

first();
1. Global code starts

The program begins executing.

2. first() is pushed

The function is placed on the Call Stack.

3. second() is pushed

second() is now at the top of the stack.

4. console.log executes

The message is printed.

5. Functions are popped

Execution returns back through the stack.

06 · CALLBACKS

Callbacks

A callback is a function passed to another function to be called later.

function greet(name, callback) {

    console.log("Hello " + name);

    callback();
}

function finish() {
    console.log("Finished!");
}

greet("Pradeep", finish);

Asynchronous Callback

console.log("Start");

setTimeout(() => {

    console.log("Timer finished");

}, 1000);

console.log("End");
Callback Hell Deeply nested callbacks can become difficult to read and maintain. Promises and async/await provide cleaner abstractions for many asynchronous workflows.

10 · PROMISE COMBINATORS

Promise.all, allSettled, race and any

Choose the right strategy when handling multiple asynchronous operations.

Method Behavior Useful When
Promise.all() Fulfills when all fulfill; rejects when one rejects. All results are required.
Promise.allSettled() Waits for every Promise to settle. You need success and failure results.
Promise.race() Settles when the first Promise settles. First completion determines the result.
Promise.any() Fulfills when the first Promise fulfills. Any successful result is acceptable. 
const userPromise = fetchUser();
const coursesPromise = fetchCourses();

const [user, courses] =
    await Promise.all([
        userPromise,
        coursesPromise
    ]);
Key idea If two operations are independent, starting them together can reduce total waiting time compared with awaiting each one sequentially.
11 · MODERN ASYNC

async / await

Promises become easier to read with async/await syntax.

Promise Style

getUser()
    .then(user => {
        return getCourses(user.id);
    })
    .then(courses => {
        console.log(courses);
    })
    .catch(error => {
        console.log(error);
    });

async/await Style

async function load() {

    try {

        const user = await getUser();

        const courses =
            await getCourses(user.id);

        console.log(courses);

    } catch (error) {

        console.log(error);

    }
}
Important An async function always returns a Promise. await can be used inside async functions and pauses that async function until the awaited Promise settles.
12 · RELIABILITY

Error Handling in Async Code

async function loadData() {

    try {

        const response =
            await fetch("/api/students");

        if (!response.ok) {
            throw new Error(
                "HTTP error: " + response.status
            );
        }

        const data =
            await response.json();

        console.log(data);

    } catch (error) {

        console.error(
            "Loading failed:",
            error
        );

    } finally {

        console.log("Request finished");

    }
}
Important A rejected Promise should be handled somewhere appropriate. Do not silently ignore errors.
13 · PERFORMANCE

Sequential vs Parallel Async Operations

A major real-world performance concept.

🐢 Sequential

const user =
    await getUser();

const courses =
    await getCourses();

const notifications =
    await getNotifications();

If the operations are independent, the waits may stack up.

⚡ Parallel

const [
    user,
    courses,
    notifications
] = await Promise.all([

    getUser(),
    getCourses(),
    getNotifications()

]);

Independent operations can be started together.

15 · ADVANCED CONCEPTS

Beyond the Basics

↔

Concurrency

Multiple asynchronous operations can make progress during overlapping periods.

⏳

Debouncing

Delay execution until rapid input stops, useful for search boxes and resize handlers. 

let timer;

function search(value) {

    clearTimeout(timer);

    timer = setTimeout(() => {
        console.log(value);
    }, 400);
}
🔁

Throttling

Limit how frequently a function executes during repeated events.

🚫

Cancellation

APIs such as AbortController can be used to cancel supported asynchronous operations such as fetch requests. 

const controller =
    new AbortController();

fetch("/api/data", {
    signal: controller.signal
});

controller.abort();
📦

Async Iteration

Modern JavaScript also supports async iterators and for await...of.

🧵

Web Workers

CPU-heavy JavaScript can be moved to workers so the main UI thread remains responsive.

18 · DEBUGGING

Common Async JavaScript Mistakes

❌ Forgetting await

const data = getData();

console.log(data);

If getData() returns a Promise, data is a Promise rather than the final result.

❌ Awaiting independent tasks sequentially

const a = await getA();
const b = await getB();

If A and B are independent, consider starting them together.

❌ Assuming setTimeout(0) means immediately

The callback must wait until the current synchronous work and relevant queued work allow it to run.

❌ Ignoring Promise rejection

someAsyncOperation()
    .then(result => {
        console.log(result);
    });

Handle failures appropriately with catch or try/catch.

❌ Confusing Promise.all and allSettled

Promise.all fails fast when one Promise rejects. allSettled waits for all to settle.

❌ Blocking the main thread

Asynchronous APIs do not automatically make CPU-heavy JavaScript non-blocking. Large synchronous computations can still block the main thread.

20 · INTERVIEW PREPARATION

Important Interview Questions

1. Is JavaScript synchronous or asynchronous?

JavaScript execution itself is commonly described as single-threaded and synchronous, while host environments provide asynchronous APIs and scheduling mechanisms that allow non-blocking application behavior.

2. What is the Event Loop?

The Event Loop coordinates when queued asynchronous callbacks can be processed relative to the Call Stack and microtask queue.

3. What is a Promise?

A Promise represents the eventual completion or failure of an asynchronous operation and its resulting value.

4. What are the states of a Promise?

Pending, fulfilled and rejected.

5. What is the difference between async/await and Promises?

async/await is syntax built around Promises that lets asynchronous control flow be written in a more sequential style.

6. What is a microtask?

A microtask is a higher-priority queued unit of work such as a Promise reaction callback. Microtasks are processed after the current JavaScript stack completes and before the next task is processed.

7. Promise.all vs Promise.allSettled?

Promise.all fulfills only if all input Promises fulfill and rejects when one rejects. Promise.allSettled waits for every input Promise to settle and reports each outcome.

8. Why doesn't setTimeout(fn, 0) run immediately?

The callback is scheduled for later. It must wait for the current synchronous execution to finish and for the event-loop scheduling rules to allow the callback to execute.

9. How can you run independent API calls in parallel?

const [a, b, c] =
    await Promise.all([
        getA(),
        getB(),
        getC()
    ]);

🧠 Remember These 12 Rules

1. Sync code runs now. JavaScript executes synchronous work on the Call Stack.
2. Async work finishes later. Results are scheduled through host/runtime mechanisms.
3. Promise = future result. It can be pending, fulfilled or rejected.
4. async returns a Promise. Every async function returns a Promise.
5. await works with Promises. It pauses the current async function until settlement.
6. Microtasks matter. Promise reactions are processed before the next task.
7. 0ms isn't immediate. setTimeout schedules a callback for later.
8. Handle errors. Use catch or try/catch where appropriate.
9. Independent tasks can run together. Promise.all can reduce unnecessary waiting.
10. allSettled is different. It waits for every input regardless of success/failure.
11. Async doesn't mean CPU work is free. Heavy synchronous computation can still block the main thread.
12. Think in execution order. Predict stack → microtask → task behavior.
