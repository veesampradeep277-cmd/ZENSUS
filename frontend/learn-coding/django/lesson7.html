What is ORM?

ORM stands for:

Object-Relational Mapping

It creates a connection between Python objects and relational database data.

🐍

Object

A Python representation of a database record.

🔗

Mapping

Django maps Python model objects to database structures.

🗄️

Relational Database

Data is stored in tables, rows and columns.

Instead of thinking only in terms of SQL tables, you can work with your Django models directly.
03

SQL vs Django ORM

Suppose we want all students whose course is Django.

Django ORM 
Student.objects.filter(
    course="Django"
)
SQL concept 
SELECT *
FROM student
WHERE course = 'Django';
Django ORM does not mean SQL disappears from existence. Django generates database queries behind the scenes.

all() — Get All Records

The all() method returns a QuerySet containing all records for that model.

Python 
students = Student.objects.all()

for student in students:
    print(student.name)
Student.objects is the model manager.
.all() asks Django for all records.
06

get() — Get One Record

Use get() when you expect exactly one matching object.

Python 
student = Student.objects.get(
    id=1
)

print(student.name)
Important: get() expects one matching record.

If no matching object exists, Django raises DoesNotExist.

If multiple objects match, Django raises MultipleObjectsReturned.
07

filter() — Find Matching Records

The filter() method returns all records that match the given conditions.

Filter by course 
students = Student.objects.filter(
    course="Django"
)

Multiple conditions

Multiple filters 
students = Student.objects.filter(
    course="Django",
    age=21
)
Unlike get(), filter() can return zero, one or many records.
08

exclude() — Remove Matching Records

The exclude() method returns records that do not match the specified condition.

Python 
students = Student.objects.exclude(
    course="Django"
)
Example:

If your database contains Django, Python and AI students, this query returns the students who are not enrolled in Django.
09

Field Lookups

Django provides lookup expressions for more powerful filtering.

Exact

Exact value match.

name__exact="Pradeep"

Contains

Checks whether text contains a value.

name__contains="Pra"

Starts With

Checks beginning of text.

name__startswith="P"

Greater Than

Finds values greater than another value.

age__gt=20

Less Than

Finds values below another value.

age__lt=25

Range

Finds values inside a range.

age__range=(18,25)

Example

QuerySet 
students = Student.objects.filter(
    age__gte=18
)

gte means greater than or equal to.

10

Ordering Query Results

Use order_by() when you want records in a particular order.

Ascending order

Python 
students = Student.objects.order_by(
    "name"
)

Descending order

Python 
students = Student.objects.order_by(
    "-age"
)
The minus sign - before a field means descending order.
11

values()

Sometimes you do not need complete model objects. You only need selected fields.

Python 
students = Student.objects.values(
    "name",
    "course"
)
values() returns dictionary-like data containing the fields you requested.
12

Creating Records

ORM can create database records directly through your model.

create() 
student = Student.objects.create(

    name="Pradeep",

    email="pradeep@example.com",

    age=21,

    course="Django"

)
create() creates the object and saves it to the database.

Alternative approach

save() 
student = Student(
    name="Pradeep",
    email="pradeep@example.com",
    age=21,
    course="Django"
)

student.save()
Both approaches can create records. The save() approach is useful when you want to modify the object before saving it.
13

Updating Records

Update one object

Python 
student = Student.objects.get(
    id=1
)

student.course = "Python"

student.save()

Update multiple records

QuerySet update 
Student.objects.filter(
    course="Python"
).update(
    active=False
)
Be careful when updating a QuerySet. If your filter matches many records, all matching records can be changed.
14

Deleting Records

Delete one object

Python 
student = Student.objects.get(
    id=1
)

student.delete()

Delete matching records

QuerySet delete 
Student.objects.filter(
    active=False
).delete()
Always check your filter before using delete().

A broad filter can remove more records than intended.

ORM and Relationships

ORM becomes especially powerful when models are connected through relationships.

Models 
class Course(models.Model):

    name = models.CharField(
        max_length=100
    )


class Student(models.Model):

    name = models.CharField(
        max_length=100
    )

    course = models.ForeignKey(
        Course,
        on_delete=models.CASCADE
    )

Get students of a particular course

Related query 
students = Student.objects.filter(
    course=course
)
More advanced relationship queries will become easier after you understand models, QuerySets and field lookups.

Common ORM Mistakes

❌ Confusing get() and filter()

Use get() when you expect one object. Use filter() when multiple matching objects are possible.

❌ Forgetting objects

Queries usually begin with the model manager, such as Student.objects.

❌ Wrong lookup syntax

Django lookups use double underscores, such as age__gt or name__contains.

❌ Dangerous delete()

Check your filter carefully before deleting QuerySets.

❌ Forgetting migrations

Model changes and database structure changes should be handled through migrations.

❌ Expecting get() to return a list

get() returns one model object, not a QuerySet.

Important habit: When writing a database query, first ask:

"Do I need one object, many objects, or only specific fields?"
