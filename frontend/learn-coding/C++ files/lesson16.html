1. What is File Handling?

File handling allows a program to store information permanently.

Normally, variables live in RAM while a program is running. When the program ends, their values are lost. A file lets us store data on secondary storage so it can be used later.

Core idea: Program → stream → file. The stream provides the interface through which your C++ program communicates with the file.

2. C++ File Streams

The <fstream> header provides the main file-stream classes.

📤 ofstream

Output File Stream

Used primarily for writing data to files.

ofstream out("data.txt");
out << "Hello";

📥 ifstream

Input File Stream

Used primarily for reading data from files.

ifstream in("data.txt");
string s;
in >> s;

🔄 fstream

File Stream

Can be used for both input and output.

fstream file;
file.open("data.txt",
          ios::in | ios::out);

3. File Opening Modes

Modes control what happens when a file is opened.

ModeMeaning
ios::inOpen for input/reading.
ios::outOpen for output/writing.
ios::appMove output to the end of the file; new writes are appended.
ios::ateOpen and initially position at the end; unlike app, the position can subsequently be changed.
ios::truncTruncate an existing file when opening for output, subject to the stream/open-mode rules.
ios::binaryOpen without text-mode translation; useful for binary data.
fstream file;
file.open("data.txt",
          ios::in | ios::out | ios::app);
Important: ios::app and ios::ate are not identical. app forces each output operation to the end; ate only starts at the end.

4. Writing to a File

Use an output file stream to send data from your program into a file.

Basic writing

#include <fstream>
using namespace std;

int main() {
    ofstream out("student.txt");

    out << "Name: Alex\n";
    out << "Marks: 92\n";

    out.close();
}
What happens? Opening the file creates it if appropriate. Writing sends characters into the stream. Closing releases the file resource and flushes buffered output.

Safer approach — check whether opening succeeded

ofstream out("student.txt");

if (!out.is_open()) {
    cerr << "Could not open file\n";
    return 1;
}

out << "ZENSUS C++";

5. Reading from a File

Use ifstream to retrieve stored data.

Token-by-token reading

ifstream in("student.txt");

string word;
while (in >> word) {
    cout << word << '\n';
}

Formatted extraction skips whitespace and reads tokens separated by whitespace.

Line-by-line reading

ifstream in("student.txt");

string line;
while (getline(in, line)) {
    cout << line << '\n';
}

getline preserves spaces inside each line and stops at the newline delimiter.

Best EOF pattern: prefer while (getline(in, line)) or while (in >> value). Do not write while (!in.eof()) to control the read loop.

7. getline() and Mixed Input

A very common beginner problem is mixing formatted input with line input.

int age;
string name;

cin >> age;
getline(cin >> ws, name);

getline(cin, name) reads the remaining characters up to newline. After cin >> age, the newline remains in the input buffer. Using std::ws consumes leading whitespace before getline.

Important: this is an input-stream issue, not a special file-handling rule. The same principle applies when mixing >> and getline() with file streams.

8. File Position Pointers

Random access lets you move to a specific location instead of reading from the beginning every time.

get pointer — reading position

ifstream in("data.txt");

in.seekg(5);

char ch;
in.get(ch);

seekg() changes the input/get position. tellg() reports it.

put pointer — writing position

fstream file("data.txt",
             ios::in | ios::out);

file.seekp(5);
file.put('X');

seekp() changes the output/put position. tellp() reports it.

// Examples of positioning
in.seekg(0, ios::beg);
in.seekg(10, ios::cur);
in.seekg(0, ios::end);
Remember: g = get (input), p = put (output).

9. Text Files vs Binary Files

Choose the representation based on your data and requirements.

📝 Text file

Human-readable characters, such as students.txt.

ofstream out("data.txt");
out << 123 << '\n';
out.close();

Easy to inspect, debug and exchange with people/tools.

💾 Binary file

Stores raw byte representations. Use ios::binary.

ofstream out("data.bin",
             ios::binary);

int x = 123;
out.write(
    reinterpret_cast<const char*>(&x),
    sizeof(x)
);

Useful for compact/raw data formats, but binary representation is not automatically portable across all machines, compilers or program versions.

Advanced caution: blindly writing an object with reinterpret_cast is not a general-purpose serialization method. Objects containing pointers, virtual functions, padding-sensitive layouts or non-trivial invariants should not simply be dumped to disk and expected to work later.

10. Storing Objects — Serialization Basics

Real applications often need to convert object state into a storable format.

Simple text serialization

struct Student {
    string name;
    int age;
    double marks;
};

Student s{"Alex", 20, 91.5};

ofstream out("student.txt");
out << s.name << '\n'
    << s.age << '\n'
    << s.marks << '\n';
Student s;

ifstream in("student.txt");
getline(in, s.name);
in >> s.age >> s.marks;
Professional idea: serialization means converting program state into a format that can be stored or transmitted and later reconstructed. Text, CSV, JSON and carefully designed binary formats are common approaches.

11. File Errors & Stream States

Robust programs must detect failed opens, invalid operations and end-of-input.

good()

No error flags are currently set.

eof()

The end-of-file condition has been reached.

fail()

A recoverable operation failed, such as formatted extraction failure.

bad()

A serious I/O error has occurred.

ifstream in("data.txt");

if (!in) {
    cerr << "Failed to open file\n";
    return 1;
}

string line;
while (getline(in, line)) {
    // process line
}

if (in.bad()) {
    cerr << "Serious I/O error\n";
}
Key distinction: reaching EOF is a normal condition while reading. A failed formatted conversion can set failbit. Check the stream after the operation you care about.

13. Practical File-Handling Patterns

Reusable patterns you will see in projects.

Pattern 1 — Read every line

ifstream in("data.txt");
string line;

while (getline(in, line)) {
    cout << line << '\n';
}

Pattern 2 — Count lines

ifstream in("data.txt");
string line;
int lines = 0;

while (getline(in, line))
    ++lines;

Pattern 3 — Count words

ifstream in("data.txt");
string word;
long long count = 0;

while (in >> word)
    ++count;

Pattern 4 — Append a log

ofstream log("app.log", ios::app);

log << "Application started\n";

Pattern 5 — Read numeric data

ifstream in("marks.txt");

double x, sum = 0;
int n = 0;

while (in >> x) {
    sum += x;
    ++n;
}

Pattern 6 — RAII

{
    ofstream out("data.txt");
    out << "Hello";
} // stream closes automatically

Prefer automatic resource management. Explicit close is available, but streams also close when their objects are destroyed.

15. Common Mistakes

Avoid these before interviews and projects.

❌ Wrong EOF loop

Do not use while (!file.eof()) as the normal read condition.

// Prefer:
while (getline(file, line)) {
    ...
}

❌ Not checking open

A file may fail to open because of a wrong path, permissions or other I/O conditions.

❌ Accidentally truncating

Opening an output file with truncating behavior can replace existing content. Use ios::app when you intend to append.

❌ Confusing app and ate

app forces writes to the end; ate starts at the end but permits repositioning.

❌ Blind binary object dumping

Raw object bytes are not a portable serialization format for arbitrary C++ objects.

❌ Forgetting mixed-input rules

Mixing >> and getline() requires understanding the newline/whitespace left in the stream.

17. Interview Questions

Click to reveal the answer.

ifstream vs ofstream? +
ifstream is primarily used for input from a file; ofstream is primarily used for output to a file.
What is fstream? +
fstream is a file stream class that supports input and output operations, depending on how the stream is opened.
Why should you avoid while(!file.eof())? +
EOF becomes set after an attempted read reaches the end. The failed read may therefore cause you to process invalid/stale data. Put the read operation directly in the loop condition instead.
What is ios::app? +
It opens a file in append mode so output is directed to the end of the file.
app vs ate? +
app positions output at the end for each output operation. ate initially positions the file position at the end, but the position can later be changed.
What are seekg and seekp? +
seekg changes the input/get position; seekp changes the output/put position.
What is serialization? +
Serialization converts program state into a storable/transmittable representation so it can later be reconstructed.
Why is a virtual destructor relevant to file handling? +
It is not specifically a file-handling feature. It matters when file-owning resources are managed through polymorphic base pointers. The broader principle is safe resource lifetime management.

🚀 Mini Project — Student Record Manager

Build a console application that persists student records in a file.

struct Student {
    string name;
    int roll;
    double marks;
};

void save(const Student& s) {
    ofstream out("students.txt", ios::app);

    if (!out) {
        cerr << "File error\n";
        return;
    }

    out << s.roll << ','
        << s.name << ','
        << s.marks << '\n';
}
