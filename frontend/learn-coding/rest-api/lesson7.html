API Endpoints & URL Structure

Learn how REST APIs identify resources using URLs and endpoints. Understand base URLs, paths, path parameters, query parameters, API versioning and clean REST URL design.

01

What is an API Endpoint?

An API endpoint is a specific URL through which a client can communicate with a particular resource or operation provided by an API.

Simple definition:

An endpoint is a specific address where an API provides access to a particular resource.
Example Endpoint 
https://api.example.com/students/

In this example, the endpoint can represent a collection of students.

Client
→
API Endpoint
→
Student Resource
02

What is a URL?

A URL stands for Uniform Resource Locator. It identifies the location of a resource on a network.

Example URL 
https://api.zensus.com/v1/students/101/

A URL can contain several important parts.

https://

Protocol used to communicate securely with the server.

api.zensus.com

Domain or host where the API is available.

/v1/

API version.

/students/101/

Resource path identifying a student.

03

Base URL

The base URL is the common starting part of an API's URLs.

Base URL 
https://api.zensus.com/

Endpoints are built by adding resource paths to the base URL.

Base URL Resource Path Complete Endpoint
https://api.zensus.com /students/ https://api.zensus.com/students/
https://api.zensus.com /courses/ https://api.zensus.com/courses/
https://api.zensus.com /teachers/ https://api.zensus.com/teachers/
04

Resources

In REST APIs, URLs generally represent resources. A resource can be a collection or an individual item.

👨‍🎓

Students

/students/

Represents the student collection.

📚

Courses

/courses/

Represents the course collection.

📝

Assignments

/assignments/

Represents assignments.

Collection vs Individual Resource:

/students/ → collection of students

/students/101/ → one specific student
05

URL Path

The path identifies which resource the client wants to access.

https://api.zensus.com/students/101?course=python

Base

https://api.zensus.com

Resource

/students

ID

/101

Query

?course=python

06

What are URL Parameters?

Parameters allow the client to provide additional information to the API.

🎯

Path Parameter

Identifies a specific resource.

/students/101/
🔎

Query Parameter

Filters, searches or modifies a request.

?course=python
The most important difference is:

Path parameter → usually identifies which resource.

Query parameter → usually controls how the collection is filtered, searched, sorted or paginated.
07

Path Parameters

A path parameter is a dynamic value included directly inside the URL path.

Collection 
GET /students/
Specific Student 
GET /students/101/

Here, 101 is the identifier of the requested student.

GET /students/{id}/

The {id} part is dynamic.

Examples 
/students/101/
/students/102/
/students/103/
08

Query Parameters

Query parameters are added after a ? in the URL. They are commonly used for filtering, searching, sorting and pagination.

Filtering 
GET /students/?course=python
Search 
GET /students/?search=pradeep
Pagination 
GET /students/?page=2

Multiple Query Parameters

Multiple Parameters 
GET /students/?course=python&page=2&limit=10

The first query parameter starts after ?. Additional parameters are separated using &.

09

Path + Query Parameters

Path parameters and query parameters can be used together.

Example 
GET /students/101/courses/?page=2

Here:

  • 101 identifies a specific student.
  • courses identifies the related resource.
  • ?page=2 is a query parameter.
/students/101/courses/?page=2
A useful mental model:

Path → "Which resource?"

Query → "How should I retrieve it?"
10

Endpoints & HTTP Methods

The same endpoint can perform different operations depending on the HTTP method.

Method Endpoint Typical Meaning
GET /students/ Get students
POST /students/ Create a student
GET /students/101/ Get student 101
PUT /students/101/ Replace student 101
PATCH /students/101/ Partially update student 101
DELETE /students/101/ Delete student 101
Important:

The endpoint identifies the resource. The HTTP method describes the intended operation.
11

API Versioning

APIs may evolve over time. Versioning helps developers maintain different versions while reducing the risk of breaking existing clients.

Version 1 
https://api.zensus.com/v1/students/
Version 2 
https://api.zensus.com/v2/students/

The exact versioning strategy depends on the API design and organization. A common approach is including the version in the URL path.

12

Good REST URL Design

✓

Use Nouns

Represent resources using nouns.

/students/
✓

Use Consistent Naming

Keep resource naming predictable.

/students/
✓

Use IDs for Items

Identify individual resources clearly.

/students/101/
✓

Use Query Parameters

Use queries for filtering and searching.

?course=python

Prefer Resource-Oriented URLs

Recommended Style 
GET    /students/
GET    /students/101/
POST   /students/
PATCH  /students/101/
DELETE /students/101/
Avoid putting the operation itself into every URL when the HTTP method can express the operation.

For example, instead of designing: /getStudents/ use a resource-oriented endpoint such as: /students/ with the appropriate HTTP method.

Practice Challenge

Design REST API endpoints for an online learning platform. The platform has:

  • Students
  • Courses
  • Lessons
  • Assignments

Try to design endpoints for:

Requirement Your Endpoint
Get all students /students/
Get student 101 /students/101/
Get all courses /courses/

Start by identifying the resource. Then decide whether you need a collection, a specific item, or a query parameter.

Lesson Takeaway

  • An API endpoint is a specific URL used to access an API resource.
  • A URL identifies the location of a resource.
  • The base URL is the common starting point of an API.
  • REST APIs commonly organize URLs around resources such as /students/ and /courses/.
  • A collection can be represented by /students/.
  • A specific resource can be represented by /students/101/.
  • Path parameters usually identify a specific resource.
  • Query parameters are commonly used for filtering, searching, sorting and pagination.
  • Multiple query parameters can be combined using &.
  • The HTTP method and endpoint work together to describe an API operation.
  • API versioning can help manage changes over time.
  • Good REST URLs are predictable, consistent and resource-oriented.
