Testing REST APIs with Postman

Learn how to test REST APIs without building a frontend first. You will learn requests, HTTP methods, parameters, headers, JSON bodies, authentication, environments, collections, automated tests, debugging and a complete Student API workflow.

01

What is Postman?

Postman is a tool used to build, send, inspect and test HTTP requests to APIs.

It allows developers to communicate directly with an API without first creating a frontend application.

Developer
→
Postman
→
REST API
→
Backend
→
Database
Simple definition: Postman is an API testing and development tool that lets you send HTTP requests and inspect API responses.

Example

Suppose your API provides:

API Endpoint 
GET http://localhost:8000/api/students/

You can enter this endpoint into Postman and send the request. You can then inspect the returned status code, headers and JSON body.

Query Parameters

Query parameters allow a client to provide optional information after the question mark in a URL.

Example

URL 
GET /students/?course=python

The parameter is:

Query Parameter 
course = python

Multiple Parameters

URL 
GET /students/?course=python&page=2&limit=10

Postman Params Tab

Instead of manually typing the query string, you can add key-value pairs in the Params section.

Key Value
course python
page 2
limit 10

Sending a JSON Request Body

POST, PUT and PATCH requests often contain data in the request body.

Example JSON

JSON 
{
    "name": "Pradeep",
    "email": "pradeep@example.com",
    "age": 21,
    "course": "REST API"
}

Postman Configuration

  1. Select Body.
  2. Select raw.
  3. Choose JSON as the format.
  4. Enter the JSON data.
  5. Click Send.

Expected Request

HTTP 
POST /api/students/

Content-Type: application/json

{
    "name": "Pradeep",
    "email": "pradeep@example.com",
    "age": 21,
    "course": "REST API"
}
The JSON must be valid. Missing quotes, commas or braces can cause the server to reject the request.

Postman Variables

Variables prevent you from repeatedly typing values such as API base URLs, IDs and tokens.

Without Variables

Repeated URL 
http://localhost:8000/api/students/

http://localhost:8000/api/students/101/

http://localhost:8000/api/students/102/

With Variables

Variable Usage 
{{baseUrl}}/api/students/

{{baseUrl}}/api/students/{{studentId}}/

Example Variables

Variable Example Value
baseUrl http://localhost:8000
studentId 101
accessToken your-token-value
Variables make API collections easier to reuse across different servers and environments.

Writing Tests in Postman

Postman can run JavaScript-based tests against API responses.

Example: Check Status Code

Postman Test 
pm.test(
    "Status code is 200",
    function () {

        pm.response.to.have
            .status(200);

    }
);

Example: Check Response Property

Postman Test 
pm.test(
    "Response contains student",
    function () {

        const data =
            pm.response.json();

        pm.expect(data).to.have
            .property("students");

    }
);

Common Postman Errors & Troubleshooting

Error Possible Cause What to Check
404 Not Found Incorrect endpoint URL and route
400 Bad Request Invalid input JSON/body/parameters
401 Unauthorized Missing/invalid authentication Token or credentials
403 Forbidden Insufficient permission User role/permissions
405 Method Not Allowed Wrong HTTP method GET/POST/PUT/etc.
422 Unprocessable Content Validation problem Request fields
500 Server Error Backend exception Server logs
Connection refused Server not running Start backend

Debugging Checklist

  1. Check whether the backend server is running.
  2. Check the API base URL.
  3. Check the endpoint path.
  4. Check the HTTP method.
  5. Check query parameters.
  6. Check request headers.
  7. Check authentication.
  8. Check JSON syntax.
  9. Check required fields.
  10. Check backend logs.
Do not immediately assume the API is broken. First inspect the request URL, method, headers, body and response status.

Lesson Takeaway

  • Postman allows developers to test REST APIs directly.
  • You can test GET, POST, PUT, PATCH and DELETE requests.
  • Request URLs can contain path parameters and query parameters.
  • Headers can contain information such as Content-Type and Authorization.
  • POST, PUT and PATCH requests can send JSON data in the request body.
  • Postman displays the response status, headers, body and other response information.
  • Authentication can be tested by sending the appropriate credentials or access tokens.
  • Variables allow requests to be reused across different environments.
  • Collections organize related API requests.
  • Postman tests can automatically verify response behavior.
  • API errors should be analyzed using the status code, response body, request configuration and server logs.
