1. Introduction to C

First understand what C does.

What is C?

C is a general-purpose programming language designed for efficient, low-level and systems-oriented programming. It is used in areas such as operating systems and embedded systems.

Why learn C?

C teaches core programming ideas and gives you a strong understanding of memory, data representation, control flow and algorithms.

How a C program runs

Think: source code → compiler → object/machine code → linker → executable → CPU executes it.

Memory trick: Write → Translate → Build → Run. You write C; the toolchain translates it; the linker builds the executable; the computer runs it.

2. History of C & Who Invented It?

Understand where C came from and why it became so important.

INVENTOR

Dennis Ritchie

Dennis M. Ritchie developed the C programming language at Bell Laboratories. W3Schools describes C as being created by Dennis Ritchie at Bell Labs in 1972, while GeeksforGeeks similarly identifies Ritchie and Bell Laboratories in 1972.

PURPOSE

Built for UNIX

C was developed alongside the early UNIX operating system. It was designed as a practical system programming language that could provide efficient, low-level control while being easier to work with than assembly language.

ANCESTORS

BCPL → B → C

C evolved from earlier languages. BCPL influenced B, developed by Ken Thompson, and Dennis Ritchie then developed C from B by adding types and other important features.

A Short Timeline

PeriodWhat happened
1969–1973C emerged during the early development of UNIX at Bell Laboratories.
1972The most creative period of C's development occurred; this is the year commonly associated with the creation of C.
1973UNIX was largely rewritten in C, demonstrating that C could be used effectively for system software.
1978Dennis Ritchie and Brian Kernighan published The C Programming Language, commonly known as the K&R book.
1989–1990C was standardized as ANSI C (C89) and then adopted internationally as ISO C (C90).
Remember: C was not created in isolation. It evolved from BCPL through B and was developed to make UNIX and other system software practical to write efficiently.

Why C Became So Influential

C combines efficiency, portability and relatively low-level control over memory and hardware. Its syntax and ideas also influenced many later programming languages. That is why learning C remains useful for understanding programming fundamentals, memory and systems programming.

8. Pointers — Understand Memory Visually

The key idea: a pointer stores an address.

int x = 10;
int *p = &x;

printf("%d\\n", x);   // value
printf("%p\\n", (void*)p); // address
printf("%d\\n", *p);  // value at address
xvariable10
Address&x0x1000
ppointer0x1000
&x means “address of x”. *p means “value stored at the address held by p”.

9. Dynamic Memory

Request memory while the program is running.

malloc()

Allocates a block of memory; the contents are not initialized.

calloc()

Allocates memory for multiple elements and initializes the allocated bytes to zero.

realloc()

Changes the size of a previously allocated memory block.

free()

Releases dynamically allocated memory when it is no longer needed.

int *a = malloc(5 * sizeof(int));

if (a != NULL) {
    a[0] = 10;
    free(a);
}
Golden rule: memory you allocate dynamically should be released with free() when you are finished with it.

10. Structures, Unions & Enums

Group and represent related information.

struct Student {
    char name[30];
    int age;
    float marks;
};

struct Student s = {"Raju", 20, 85.5f};

Structure

Different members can exist together, and each member has its own storage within the object.

Union

Members share the same memory location; typically only one member's stored value is meaningfully used at a time.

enum

Gives names to a set of integer constants, improving readability.

typedef

Creates an alias for a type, often making declarations easier to read.

14. Most Common C Mistakes

Small mistakes every beginner can make — learn to spot them early.

BEGINNER

1. Missing semicolon

Most C statements end with ;. Forgetting it commonly causes a compiler error.

// Wrong
int age = 20

// Correct
int age = 20;
SYNTAX

2. Using = instead of ==

= assigns a value, while == compares two values. Mixing them up can produce unexpected results.

// Comparison
if (age == 18) {
    printf("18");
}
POINTERS

3. Confusing & and *

&x means the address of x. *p accesses the value at the address stored in p.

int x = 10;
int *p = &x;

printf("%d", *p);
ARRAYS

4. Going outside an array

If an array has 5 elements, valid indexes are 0 through 4. Accessing array[5] is outside the array.

int marks[5];

// Correct indexes
marks[0] = 70;
marks[4] = 90;
STRINGS

5. Forgetting the string terminator

C strings use the null character '\0' to mark the end. Leave enough space when creating a character array for a string.

char name[] = "Raju";

// The compiler includes '\0'
// automatically for this string literal.
MEMORY

6. Forgetting free()

Memory allocated dynamically with malloc(), calloc() or realloc() should be released with free() when it is no longer needed.

int *p = malloc(5 * sizeof(int));

// use p...
free(p);
INPUT

7. Ignoring input-related details

Pay attention to the format specifier and the address passed to scanf(). For ordinary variables, scanf() generally needs their address.

int age;
scanf("%d", &age);
LOOPS

8. Creating an infinite loop

Make sure a loop's condition can eventually become false, and update the variable controlling the loop.

for (int i = 0; i < 5; i++) {
    printf("%d ", i);
}
TYPES

9. Using the wrong format specifier

The format string should match the type being printed. For example, %d is commonly used with int, while %c is used with a character.

int age = 20;
char grade = 'A';

printf("%d %c", age, grade);
FUNCTIONS

10. Returning the wrong thing

Check the function's return type and make sure the returned value matches what the function promises to return.

int add(int a, int b) {
    return a + b;
}
LOGIC

11. Off-by-one errors

Loop boundaries are a common source of bugs. Carefully check whether you need < or <=.

for (int i = 0; i < 5; i++) {
    // runs 5 times: 0,1,2,3,4
}
DEBUGGING

12. Ignoring compiler warnings

A program compiling successfully does not always mean it is correct. Read warnings and test your program with different inputs.

Beginner checklist: Check semicolons → types → format specifiers → array indexes → conditions → pointer usage → allocated memory → compiler warnings.

Debug Like a Programmer

When something goes wrong, don't immediately rewrite the whole program. First reproduce the problem, read the compiler message, identify the smallest suspicious section, inspect the values, make one change, and test again.
