Git Repository & Git Init

Learn what a Git repository is, how Git stores project history, how to initialize a repository using git init, and how to check whether your project is being tracked by Git.

Git Repository git init .git Git Status
01 — Foundation

What Is a Git Repository?

A Git repository is a project folder that Git manages and tracks.

Once a folder becomes a Git repository, Git can keep track of changes made to files and maintain a history of those changes.

Simple definition: A Git repository is a folder containing your project and Git's information required to track the project's history.

01

Project Files

Your HTML, CSS, Python, JavaScript and other project files.

02

Git Data

Git stores information needed to track versions and history.

03

History

Commits allow you to record meaningful versions of your project.

02 — Core Concept

The Three Main Areas of Git

Before using git init, it is useful to understand the basic areas through which Git tracks your files.

Working Directory Your actual project files
→
Staging Area Changes selected for commit
→
Repository Committed project history

1. Working Directory

This is the folder where you create and edit your project files.

For example, you may create:

  • index.html
  • style.css
  • script.js

2. Staging Area

The staging area contains changes that you have selected for the next commit.

You normally add files to the staging area using git add.

3. Repository

The repository stores committed versions of your project. You create a commit using git commit.

03 — Git Command

What Is git init?

git init is used to initialize a Git repository.

It tells Git:

"Start managing this folder as a Git repository."

Terminal 
git init

After running this command, Git creates a hidden directory named .git.

Important: Running git init does not upload your project to GitHub. It creates a local Git repository.

05 — Behind the Scenes

The .git Folder

When you run git init, Git creates a hidden directory called .git.

📁 my-project/
📁 .git/
📄 index.html
📄 style.css
📄 script.js

The .git directory contains Git's internal repository information.

It is what makes the folder a Git repository.

Do not manually modify files inside .git. Git manages these files automatically.

What does .git contain?

HEAD

Helps Git identify the currently checked-out branch/reference.

config

Contains repository-specific Git configuration.

objects

Stores Git's internal objects representing project data.

refs

Stores references such as branches and tags.

You do not need to memorize the internal structure at this stage. Git commands manage it for you.

06 — Check Your Repository

Using git status

The git status command tells you the current state of your repository.

Terminal 
git status

Immediately after initialization, you may see output similar to:

Example Output 
On branch main

No commits yet

nothing to commit (create/copy files and use "git add" to track)

This means Git recognizes the current folder as a repository, but there are no commits yet.

Remember: git status is one of the most useful commands in everyday Git work.

07 — Important Difference

Local Repository vs Remote Repository

A Git repository can exist on your own computer and can also be connected to a remote hosting service such as GitHub.

L

Local Repository

Exists on your computer. Created using git init.

R

Remote Repository

A repository hosted online, for example on GitHub.

↔

Connection

Git can connect your local repository to a remote repository.

Your Computer Local repository
↔
GitHub Remote repository

Important: git init does not create a GitHub repository. It only initializes Git locally.

08 — Workflow

Git Repository Lifecycle

A basic Git workflow can be understood as a sequence of stages.

Create Folder Project starts
→
git init Initialize Git
→
Edit Files Make changes
→
git add Stage changes
→
git commit Save version

Later, you can connect the local repository to GitHub and push your commits to the remote repository.

10 — Important File

Introduction to .gitignore

Some files should not be tracked by Git.

Examples include:

  • Temporary files
  • Operating system files
  • Build files
  • Environment files containing secrets
  • Large generated files

Git provides a special file called .gitignore.

.gitignore 
node_modules/
.env
__pycache__/
*.log

The patterns in this file tell Git which files or directories should normally be ignored.

Never commit passwords, API keys, private credentials, or other secrets into a public repository.

11 — Troubleshooting

Common Git Repository Mistakes

Wrong Folder

Running git init in the wrong directory can create an unwanted repository.

Nested Repositories

Accidentally initializing Git inside another Git repository can cause confusing project structures.

Deleting .git

Deleting the .git directory removes the repository metadata and history.

Wrong GitHub Assumption

git init does not automatically upload anything to GitHub.

Helpful habit: Before running Git commands, use pwd or your terminal's current-path information to confirm where you are.

Lesson Takeaway

  • A Git repository is a project managed by Git.
  • git init initializes a Git repository.
  • Git creates a hidden .git directory.
  • git status shows the current repository state.
  • A local repository exists on your computer.
  • A remote repository can be hosted on services such as GitHub.
  • .gitignore helps prevent unwanted files from being tracked.
  • The basic Git flow is: Working Directory → Staging Area → Repository.
