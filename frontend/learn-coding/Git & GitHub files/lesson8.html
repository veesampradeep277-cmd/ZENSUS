GitHub Repositories & Remote Connections

Learn how GitHub stores repositories online, understand the difference between local and remote repositories, and connect your local Git project to GitHub using remote URLs.

1. Git vs GitHub

Git and GitHub are related, but they are not the same thing.

Git

Git is a distributed version control system used to track changes in source code.

It runs on your computer.

GitHub

GitHub is an online platform that hosts Git repositories and provides collaboration features.

Connection

Git can connect your local repository to a remote repository hosted on GitHub.

Simple idea: Git manages your project history. GitHub can store and collaborate on that Git repository online.

2. What Is GitHub?

GitHub is a web-based platform used by developers to host, manage, share, and collaborate on Git repositories.

A GitHub repository can contain:

  • Source code
  • README files
  • Documentation
  • Issues
  • Branches
  • Pull requests
  • Project configuration files

3. What Is a GitHub Repository?

A GitHub repository is an online project space that stores a Git repository.

For example, you might create:

github.com/your-username/student-management-system

Inside the repository you may find:

  • Code — project source files
  • Branches — different development lines
  • Commits — project history
  • Issues — tasks and bugs
  • Pull Requests — proposed code changes

4. Local Repository vs Remote Repository

This distinction is extremely important.

Local Repository Remote Repository
Exists on your computer Exists on a remote server
Managed by Git Often hosted by GitHub, GitLab, etc.
Can work without internet Usually accessed over a network
Contains project history Contains a copy of the repository history
Important: Your local repository and GitHub repository are separate repositories that can exchange Git data.

5. Creating a GitHub Repository

A common workflow begins by creating an empty repository on GitHub.

Typical information

  • Repository name
  • Description
  • Public or private visibility
  • Optional README
  • Optional .gitignore
For learning the local-to-remote workflow, creating an empty GitHub repository first can make the connection steps easier to understand.

Example repository

student-management-system

After creating it, GitHub provides a repository URL that can be used as the remote address.

6. What Is a Remote?

In Git, a remote is a named reference to another repository.

Your local Git repository can have one or more remotes.

remote: origin
URL: https://github.com/username/project.git

The remote name is a convenient label. It lets Git refer to a long repository URL using a short name.

7. Understanding origin

origin is the conventional name Git uses for the primary remote repository when a remote is added.

For example: 

git remote add origin https://github.com/username/project.git

Here:

  • git remote → work with remote repositories
  • add → add a new remote
  • origin → name given to the remote
  • The URL → location of the remote repository
Remember: origin is a name, not a special GitHub URL. You could technically use another name.

8. Connecting a Local Repository to GitHub

Suppose you already have a local Git repository. 

git init

Now connect it to GitHub: 

git remote add origin https://github.com/username/project.git

The local repository now knows where the remote repository is.

→
origin Remote name

9. Checking Remote Connections

Use: 

git remote -v

Example output: 

origin  https://github.com/username/project.git (fetch)
origin  https://github.com/username/project.git (push)

Why are there fetch and push URLs?

  • fetch — URL Git uses to retrieve repository data.
  • push — URL Git uses to send your local commits.
In many normal configurations, the fetch and push URLs are the same.

10. Getting the Remote URL

You can also use: 

git remote get-url origin

Git will display the URL associated with origin.

List only remote names 

git remote

Example: 

origin

11. Connecting Through HTTPS

One common way to connect Git to GitHub is through HTTPS.

Example: 

git remote add origin https://github.com/username/project.git

HTTPS connections are easy to understand because the remote is represented by a normal web-style URL.

Authentication note: When GitHub requires authentication for Git operations, you should use GitHub's supported authentication mechanisms. Do not place passwords or sensitive credentials directly inside repository URLs or source code.

12. Connecting Through SSH

SSH is another common way to authenticate Git operations with GitHub.

An SSH remote may look like: 

git@github.com:username/project.git

You can add it as: 

git remote add origin git@github.com:username/project.git

HTTPS

Uses an HTTPS repository URL.

SSH

Uses SSH keys configured for GitHub.

Both

Can connect your local Git repository to GitHub.

You do not need to master SSH configuration yet. The important concept is that GitHub supports different ways of authenticating remote Git operations.

13. Changing a Remote URL

If a remote already exists and you need to change its URL, use: 

git remote set-url origin https://github.com/username/new-project.git

Verify it with: 

git remote -v

14. Removing a Remote

If you no longer want a remote connection: 

git remote remove origin

This removes the remote reference from your local repository.

Removing a remote does not delete the GitHub repository. It only removes the local connection information.

15. Complete Local-to-GitHub Workflow

Let's connect a brand-new local project to a GitHub repository.

Step 1 — Create project folder 

mkdir student-management
cd student-management

Step 2 — Initialize Git 

git init

Step 3 — Create project files 

index.html
style.css
script.js

Step 4 — Stage the files 

git add .

Step 5 — Create the first commit 

git commit -m "Initial commit"

Step 6 — Add GitHub as a remote 

git remote add origin https://github.com/username/student-management.git

Step 7 — Verify the remote 

git remote -v
At this point, your local repository knows about the GitHub repository. Sending commits to the remote is the subject of the next lesson.

18. Common Mistakes

Mistake 1 — Thinking Git and GitHub are the same

Git is the version control system. GitHub is an online platform that hosts Git repositories.

Mistake 2 — Using the wrong repository URL

Check the repository address carefully before adding it.

Mistake 3 — Adding origin twice

If origin already exists, running git remote add origin ... again can produce an error.

Check first: 

git remote -v

Mistake 4 — Confusing remote connection with uploading

Adding a remote only tells Git where the remote repository is. It does not by itself upload your commits.

Mistake 5 — Putting secrets in a repository

Never commit passwords, API keys, private tokens, database credentials, or other sensitive secrets into your Git repository.

22. Lesson Takeaway

GitHub provides a remote location where Git repositories can be hosted and shared. Git can connect your local repository to that remote using a remote URL.

  • Git is a version control system.
  • GitHub is a platform for hosting and collaborating on Git repositories.
  • A local repository exists on your computer.
  • A remote repository exists on another system or service.
  • origin is the conventional name for the primary remote.
  • git remote add origin URL connects a local repository to a remote.
  • git remote -v displays remote URLs.
  • git remote get-url origin displays the URL for origin.
  • git remote set-url changes a remote URL.
  • git remote remove removes a remote reference.
  • Adding a remote does not automatically upload commits.
  • Never store passwords, API keys, or other secrets in your repository.
