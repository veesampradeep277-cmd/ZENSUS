CSS Transitions

Learn how to transform instant CSS state changes into smooth, controlled interface experiences. Master duration, timing functions, delays, multiple transitions, cubic-bezier curves, and professional UI interactions.

What is a CSS Transition?

A transition controls how a CSS property changes from one value to another over time.

Without a transition

CSS normally changes a property immediately when a new state becomes active.

Instant Change

Smooth Change

/* Without transition */ .button:hover { transform: scale(1.08); } /* With transition */ .button { transition: transform 0.4s ease; } .button:hover { transform: scale(1.08); }

How the Browser Thinks

A transition is essentially a controlled interpolation between two computed states.

Example: A button starts with background: blue. On hover it becomes background: purple. With a transition, the browser calculates intermediate visual states between those values.

CSS Transition Syntax

selector { transition: property duration timing-function delay; }

Full Example

.card { transition: transform 0.4s ease 0s; } .card:hover { transform: translateY(-8px); }
Remember the order:

Property → Duration → Timing Function → Delay

transition-property

Determines which CSS property should transition.

You can transition a specific property instead of asking the browser to transition everything.

.box { transition-property: transform; }

Common examples:

transition-property: transform; transition-property: opacity; transition-property: background-color; transition-property: width; transition-property: color; transition-property: transform, opacity;

transition-duration

Controls how long the transition takes.

Fast

0.15s – 0.25s

Useful for buttons, hover states and micro-interactions.

Medium

0.3s – 0.5s

Useful for cards, menus and component movement.

Slow

0.8s+

Useful for demonstrations, visual storytelling and special effects.

.box { transition-duration: 0.5s; }

transition-delay

Delay starts the transition after a specified amount of time.

Hover the box → each element starts at a different time.
.item { transition: transform 0.7s ease; } .item:nth-child(1) { transition-delay: 0s; } .item:nth-child(2) { transition-delay: 0.15s; } .item:nth-child(3) { transition-delay: 0.3s; } .item:nth-child(4) { transition-delay: 0.45s; }

Multiple Transitions

Different properties can have different transition configurations.

ZENSUS CARD

Hover me

.card { transition: transform 0.45s ease, box-shadow 0.45s ease, border-color 0.45s ease, background-color 0.45s ease; }
This is usually better than blindly using transition: all because you explicitly define the properties that should animate.

cubic-bezier()

Create custom timing curves beyond the built-in timing functions.

Hover the area to see the custom spring-like curve.
.box { transition: left 1.5s cubic-bezier( 0.68, -0.55, 0.27, 1.55 ); }
Think of cubic-bezier as a speed curve.
It doesn't directly specify where the element moves. It specifies how quickly the transition progresses from start to finish.

steps()

Instead of continuously interpolating a value, steps() divides the transition into discrete jumps.

Hover → notice the movement happens in visible steps.
.box { transition: left 2s steps(5); }

This technique can be useful for sprite animation, counters, progress-like effects and intentionally discrete motion.

What are transitions? ▼
Transitions describe how CSS property values change over a period of time rather than changing instantly.
Are transitions animations? ▼
They are related but different CSS mechanisms. A transition generally describes a change between two states, while CSS animations can define multiple keyframes.

Transition Performance

Prefer

transform opacity

These properties are commonly suitable for smooth UI motion because they can often be handled efficiently by the browser.

Be Careful

width height top left

Layout-affecting properties can cause additional browser work. Use them deliberately, especially in large or complex interfaces.

Avoid blindly writing:

transition: all 0.3s ease;

Explicitly listing the properties you intend to transition often makes your CSS more predictable.
Accessibility: Users who request reduced motion should not be forced to experience large or unnecessary movement. This lesson includes a prefers-reduced-motion rule.

Common Transition Mistakes

❌ Mistake 1

Putting transition only inside :hover.

.button:hover { transition: transform 0.3s; }

The reverse state may not transition as expected. Usually place the transition on the base element.

❌ Mistake 2

Using extremely long durations for normal UI.

transition: transform 5s;

A five-second button interaction usually feels disconnected from the user's action.

❌ Mistake 3

Animating every property unnecessarily.

transition: all 0.5s;

Explicit property lists provide better control.

❌ Mistake 4

Forgetting focus states.

Keyboard users also need clear interaction feedback.
