01 • Foundations

What is a Binary Search Tree?

A Binary Search Tree is a special type of Binary Tree that maintains an ordering rule.

A Binary Search Tree (BST) is a binary tree in which values are arranged according to a specific ordering property.

Core idea: For every node:

Left subtree values < Node value < Right subtree values

Why do we need a BST?

A normal binary tree does not guarantee that values are ordered. A BST uses ordering to eliminate unnecessary branches while searching.

🔍

Fast Search

In a balanced BST, search can take approximately O(log n).

➕

Easy Insertion

New values can be placed according to the ordering property.

🗑️

Structured Deletion

Nodes can be deleted while preserving BST ordering.

02 • Comparison

Binary Tree vs Binary Search Tree

This distinction is extremely important in interviews.

Feature Binary Tree Binary Search Tree
Children At most 2 At most 2
Ordering No required ordering Maintains ordering
Search Usually O(n) O(h)
Inorder traversal Not necessarily sorted Sorted order
Insertion No BST rule Uses ordering rule
Deletion Depends on application Must preserve BST property
Remember: Every BST is a Binary Tree, but every Binary Tree is not a BST.
03 • Core Rule

The BST Property

Everything in a BST is built around this one rule.

For every node

Left < Root < Right

All values in the left subtree must be smaller than the node, while values in the right subtree must be greater.

Example

Node = 50

Left side: 10, 20, 30, 40
Right side: 60, 70, 80, 90

Important: The rule applies to the entire subtree

A common beginner mistake is checking only the immediate left and right children.

Example:

If 30 is inside the right subtree of 50, then 30 violates the BST rule even if it is smaller than its immediate parent.

05 • Construction

How is a BST Constructed?

BSTs are commonly constructed by repeatedly inserting values according to the BST rule.

Example sequence

50 30 70 20 40 60 80

Step-by-step

Step 1

Insert 50.
Tree is empty, so 50 becomes root.
Step 2

Insert 30.
30 < 50 → move left.
Step 3

Insert 70.
70 > 50 → move right.
Step 4

Insert 20.
20 < 50 → left.
20 < 30 → left again.

Python Node structure

Python BST Node 
class Node:
    def __init__(self, key):
        self.key = key
        self.left = None
        self.right = None
06 • Core Operation

Searching in a BST

Search is one of the biggest advantages of a BST.

Search for 60

Start at 50.

60 > 50
Move right.

Current node = 70

60 < 70
Move left.

Current node = 60

🎯 Found!

Search algorithm

Start
↓
Is node NULL?
↓
key == node.key?
↓
key < node.key → LEFT
↓
key > node.key → RIGHT
↓
Found / Not Found

Python implementation

Python Search 
def search(root, key):

    if root is None:
        return False

    if root.key == key:
        return True

    if key < root.key:
        return search(root.left, key)

    return search(root.right, key)
07 • Core Operation

Insertion in a BST

Insertion follows exactly the same comparisons used during search.

Insert 65

  1. Compare with 50.
  2. 65 > 50 → go right.
  3. Compare with 70.
  4. 65 < 70 → go left.
  5. Compare with 60.
  6. 65 > 60 → go right.
  7. Empty position found.
  8. Insert 65.

Insertion principle

Compare → Move → Compare → Insert
The new node is always inserted at a leaf position.

Python implementation

Python Insert 
def insert(root, key):

    if root is None:
        return Node(key)

    if key < root.key:
        root.left = insert(root.left, key)

    elif key > root.key:
        root.right = insert(root.right, key)

    return root
Duplicate values: BST implementations must define how duplicates are handled. One common convention is to ignore duplicates; another is to consistently place them on one chosen side.
08 • Traversals

BST Traversals

BSTs support all standard binary-tree traversals, but inorder traversal has a special property.

PREORDER

Root → Left → Right

50 → 30 → 20 → 40 → 70 → 60 → 80

Useful for copying or serializing a tree.

INORDER

Left → Root → Right

20 → 30 → 40 → 50 → 60 → 70 → 80

⭐ In a valid BST, inorder traversal produces values in sorted order.

POSTORDER

Left → Right → Root

20 → 40 → 30 → 60 → 80 → 70 → 50

Useful when processing children before parents.

LEVEL ORDER

BFS by levels

50 → 30 → 70 → 20 → 40 → 60 → 80

Uses a queue and processes nodes level by level.

Interview fact: If you are given a BST and asked to output elements in sorted order, think: INORDER TRAVERSAL.
09 • Fundamental Pattern

Finding Minimum and Maximum

BST ordering makes these operations extremely simple.

Minimum Value

Keep moving LEFT

The smallest value in a BST is the leftmost node.

Example → minimum = 20

Maximum Value

Keep moving RIGHT

The largest value in a BST is the rightmost node.

Example → maximum = 80

Python

Python Minimum 
def find_min(root):

    current = root

    while current.left is not None:
        current = current.left

    return current.key
10 • Advanced Core Operation

Deletion in a BST

Deletion is one of the most important BST interview topics.

CASE 1

Leaf Node

The node has no children.

Simply remove it.
CASE 2

One Child

Replace the deleted node with its only child.

Connect parent directly to child.
CASE 3

Two Children

Replace the node using its inorder successor or inorder predecessor.

Most important deletion case.

Case 1 — Delete a Leaf

Suppose we delete 20.

20 has no children.

Therefore: remove 20 directly.

Case 2 — Delete a Node with One Child

Suppose a node has only a right child.

Parent
↓
Deleted Node
↓
Child

Connect: Parent → Child

Case 3 — Delete a Node with Two Children

Suppose we want to delete 50.

We cannot simply remove 50 because it has both left and right subtrees.

Use inorder successor

The inorder successor is the smallest value in the node's right subtree.

Successor = Minimum of Right Subtree

Python deletion

Python Delete 
def delete(root, key):

    if root is None:
        return root

    if key < root.key:
        root.left = delete(root.left, key)

    elif key > root.key:
        root.right = delete(root.right, key)

    else:

        # Case 1 and Case 2

        if root.left is None:
            return root.right

        if root.right is None:
            return root.left

        # Case 3

        successor = root.right

        while successor.left is not None:
            successor = successor.left

        root.key = successor.key

        root.right = delete(root.right, successor.key)

    return root
11 • Interview Concept

Inorder Predecessor & Successor

These concepts appear frequently in BST problems.

Inorder Predecessor

Largest value smaller than X

It is the value immediately before X in sorted inorder order.

For 50:

Predecessor = 40

Inorder Successor

Smallest value greater than X

It is the value immediately after X in sorted inorder order.

For 50:

Successor = 60
Shortcut: In the sorted sequence:

20, 30, 40, 50, 60, 70, 80

Previous value → predecessor
Next value → successor
12 • Problem Solving

How to Validate a BST

Checking only the immediate children is not enough.

The wrong approach

Check:
left child < root
right child > root

❌ This can fail because the BST property applies to the entire subtree.

The correct idea — Range Validation

Every node must remain inside an allowed range.

minRange < node < maxRange
Start with:
(-∞, +∞)

Move left:
(min, current)

Move right:
(current, max)

Python implementation

Python Validate BST 
def is_valid_bst(root):

    def check(node, low, high):

        if node is None:
            return True

        if not (low < node.key < high):
            return False

        return (
            check(node.left, low, node.key)
            and
            check(node.right, node.key, high)
        )

    return check(root, float("-inf"),
                  float("inf"))
13 • Recursion

Recursive Thinking in BST

BST operations become much easier when you understand the recursive structure.

Think in terms of smaller BSTs

The left subtree is itself a BST. The right subtree is also a BST.

Recursive pattern:

Current node decides the direction.

Smaller → left
Greater → right
Equal → current node
1

Base Case

Node is NULL or target is found.

2

Decision

Compare target with current value.

3

Recursive Call

Continue into only one subtree.

14 • Complexity

BST Time Complexity

The height of the tree controls the running time.

Operation Average Worst Case
Search O(log n) O(n)
Insertion O(log n) O(n)
Deletion O(log n) O(n)
Minimum O(log n) O(n)
Maximum O(log n) O(n)
Important: BST operations are actually O(h), where h is the height of the tree.

Balanced BST: h ≈ log n
Skewed BST: h ≈ n

16 • Avoid These

Common BST Mistakes

These mistakes appear frequently in beginner implementations.

!
Confusing Binary Tree with BST

A BST has an ordering property; a normal binary tree does not necessarily have one.

!
Checking only immediate children

BST validation must consider the entire subtree.

!
Assuming BST is always O(log n)

A badly skewed BST can become O(n).

!
Forgetting the two-child deletion case

Use inorder successor or predecessor to preserve ordering.

!
Ignoring duplicate policy

Decide how duplicate values are handled before implementing the BST.

18 • Test Yourself

BST Mastery Quiz

Test your understanding before moving to advanced trees.

1. What is the defining property of a BST?

Correct: A BST maintains an ordering relationship between each node and its subtrees.

2. What traversal gives sorted order in a BST?

Correct: Inorder traversal of a valid BST produces values in sorted order.

3. What is the worst-case search complexity of a BST?

Correct: A skewed BST can have height n, making search O(n).

4. Where is the minimum value in a BST?

Correct: Keep moving left until no more left child exists.

5. How do you usually delete a node with two children?

Correct: The successor or predecessor allows the BST ordering to be preserved.
