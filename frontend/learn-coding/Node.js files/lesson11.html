What is REST?

Representational State Transfer

REST stands for Representational State Transfer.

REST is a style for designing networked applications. REST APIs commonly expose application data as resources that clients can access through standard HTTP operations.

For example, imagine an application that manages students. Instead of creating completely different technologies for every operation, we can expose a student resource:

Client Browser / Mobile App
↔
REST API /api/students
Important: REST is an architectural style, not a programming language or library. Express.js can be used to build REST-style APIs.
03

What is an API?

Application Programming Interface

An API is an interface that allows different software systems to communicate with each other.

Example

A frontend application may need a list of users. Instead of directly accessing the database, it sends a request to the backend API.

Frontend React / Browser
→
HTTP Request GET /api/users
→
Express API Route Handler
→
JSON Response 200 OK

The frontend does not need to know how the backend stores the users. It only needs to understand the API contract.

04

What is a REST API?

Combining HTTP, resources and REST principles

A REST API typically uses:

  • Resources such as users, products and orders.
  • URLs to identify resources.
  • HTTP methods to describe operations.
  • JSON to represent data.
  • HTTP status codes to describe outcomes.
Example Resource 
/api/users

/api/users/42

/api/products

/api/orders/1001
A good REST API usually models URLs around resources, while HTTP methods describe what should happen to those resources.

Add new data

READ

Retrieve data

Modify data

Remove data

CREATE

Add a new resource to the system. In REST APIs this is commonly implemented using POST.

07

HTTP Methods & CRUD

Mapping operations to HTTP verbs

CRUD HTTP Method Example Purpose
Create POST POST /api/users Create a resource.
Read GET GET /api/users Retrieve resources.
Update PUT PUT /api/users/5 Replace a resource.
Update PATCH PATCH /api/users/5 Partially update a resource.
Delete DELETE DELETE /api/users/5 Delete a resource.
PUT vs PATCH: PUT is generally used to replace the representation of a resource, while PATCH is used for a partial modification.

REST API Status Codes

Communicate the result of an operation

Status Meaning Typical REST Usage
200 OK Successful read or update.
201 Created Successful resource creation.
204 No Content Successful operation without a response body.
400 Bad Request Invalid client input.
401 Unauthorized Authentication is required or invalid.
403 Forbidden Access is not permitted.
404 Not Found Resource does not exist.
409 Conflict Request conflicts with current resource state.
500 Internal Server Error Unexpected server-side problem.

JSON in REST APIs

The common data representation used between frontend and backend

JSON stands for JavaScript Object Notation. It provides a lightweight structure for representing objects, arrays, strings, numbers, booleans and null values.

JSON Data 
{
  "id": 101,
  "name": "Priya",
  "email": "priya@example.com",
  "active": true
}

In Express, express.json() parses incoming JSON request bodies.

Reading JSON Body 
app.use(express.json());

app.post("/users", (req, res) => {

12

READ — GET Requests

Retrieve resources from the API

Get all users

GET /api/users 
app.get("/api/users", (req, res) => {

  res.json(users);

});

Get one user

GET /api/users/:id 
app.get("/api/users/:id", (req, res) => {

  const id = Number(req.params.id);

  const user = users.find(
    user => user.id === id
  );

  if (!user) {
    return res.status(404).json({
      message: "User not found"
    });
  }

  res.json(user);

});
GET should retrieve data. It should not normally be used to create or modify a resource.
13

CREATE — POST Requests

Create a new resource

POST is commonly used when the client wants the server to create a new resource in a collection.

POST /api/users 
app.post("/api/users", (req, res) => {

  const newUser = {
    id: users.length + 1,
    name: req.body.name,
    email: req.body.email
  };

  users.push(newUser);

  res.status(201).json(newUser);

});

Client sends

{ "name": "Arun", "email": "arun@example.com" }

Server returns

{ "id": 3, "name": "Arun", "email": "arun@example.com" }
14

UPDATE — PUT Requests

Replace a resource representation

PUT is commonly used when the client sends a new representation for an existing resource.

PUT /api/users/:id 
app.put("/api/users/:id", (req, res) => {

  const id = Number(req.params.id);

  const index = users.findIndex(
    user => user.id === id
  );

  if (index === -1) {
    return res.status(404).json({
      message: "User not found"
    });
  }

  users[index] = {
    id,
    name: req.body.name,
    email: req.body.email
  };

  res.json(users[index]);

});
PUT generally represents replacement of the resource representation. If your API only needs to change selected fields, PATCH is usually more appropriate.
15

PARTIAL UPDATE — PATCH

Change only selected fields

PATCH /api/users/:id 
app.patch("/api/users/:id", (req, res) => {

  const id = Number(req.params.id);

  const user = users.find(
    user => user.id === id
  );

  if (!user) {
    return res.status(404).json({
      message: "User not found"
    });
  }

  if (req.body.name !== undefined) {
    user.name = req.body.name;
  }

  if (req.body.email !== undefined) {
    user.email = req.body.email;
  }

  res.json(user);

});

For example, the client can send only:

{ "name": "Updated Name" }

The existing email can remain unchanged.

16

DELETE Requests

Remove a resource

DELETE /api/users/:id 
app.delete("/api/users/:id", (req, res) => {

  const id = Number(req.params.id);

  const index = users.findIndex(
    user => user.id === id
  );

  if (index === -1) {
    return res.status(404).json({
      message: "User not found"
    });
  }

  users.splice(index, 1);

  res.json({
    message: "User deleted successfully"
  });

});
Always check whether the resource exists before deleting it. Returning 404 for a missing resource gives the client a clear result.

Complete CRUD REST API

A working Express example

The following example combines all four CRUD operations into one small Express application.

server.js — Complete CRUD API 
const express = require("express");

const app = express();

app.use(express.json());

let users = [
  {
    id: 1,
    name: "Asha",
    email: "asha@example.com"
  },
  {
    id: 2,
    name: "Ravi",
    email: "ravi@example.com"
  }
];


/* =========================
   READ - ALL USERS
========================= */

app.get("/api/users", (req, res) => {

  res.status(200).json(users);

});


/* =========================
   READ - ONE USER
========================= */

app.get("/api/users/:id", (req, res) => {

  const id = Number(req.params.id);

  const user = users.find(
    user => user.id === id
  );

  if (!user) {
    return res.status(404).json({
      message: "User not found"
    });
  }

  res.status(200).json(user);

});


/* =========================
   CREATE USER
========================= */

app.post("/api/users", (req, res) => {

  const { name, email } = req.body;

  if (!name || !email) {
    return res.status(400).json({
      message: "Name and email are required"
    });
  }

  const newUser = {
    id: users.length
      ? Math.max(...users.map(user => user.id)) + 1
      : 1,
    name,
    email
  };

  users.push(newUser);

  res.status(201).json(newUser);

});


/* =========================
   REPLACE USER
========================= */

app.put("/api/users/:id", (req, res) => {

  const id = Number(req.params.id);

  const index = users.findIndex(
    user => user.id === id
  );

  if (index === -1) {
    return res.status(404).json({
      message: "User not found"
    });
  }

  const { name, email } = req.body;

  if (!name || !email) {
    return res.status(400).json({
      message: "Name and email are required"
    });
  }

  users[index] = {
    id,
    name,
    email
  };

  res.status(200).json(users[index]);

});


/* =========================
   PARTIAL UPDATE
========================= */

app.patch("/api/users/:id", (req, res) => {

  const id = Number(req.params.id);

  const user = users.find(
    user => user.id === id
  );

  if (!user) {
    return res.status(404).json({
      message: "User not found"
    });
  }

  if (req.body.name !== undefined) {
    user.name = req.body.name;
  }

  if (req.body.email !== undefined) {
    user.email = req.body.email;
  }

  res.status(200).json(user);

});


/* =========================
   DELETE USER
========================= */

app.delete("/api/users/:id", (req, res) => {

  const id = Number(req.params.id);

  const index = users.findIndex(
    user => user.id === id
  );

  if (index === -1) {
    return res.status(404).json({
      message: "User not found"
    });
  }

  users.splice(index, 1);

  res.status(200).json({
    message: "User deleted successfully"
  });

});


/* =========================
   404 HANDLER
========================= */

app.use((req, res) => {

  res.status(404).json({
    message: "Route not found"
  });

});


/* =========================
   SERVER
========================= */

app.listen(3000, () => {

  console.log(
    "REST API running at http://localhost:3000"
  );

});
This API now supports: GET, POST, PUT, PATCH and DELETE for the users resource.

Organizing CRUD Routes

Using Express Router for scalable APIs

As an application grows, keeping every route inside server.js becomes difficult.

Express provides express.Router() to split routes into separate modules.

Project structure

Project Structure 
my-api/
│
├── server.js
│
├── routes/
│   └── users.js
│
├── controllers/
│   └── userController.js
│
└── package.json

routes/users.js

User Router 
const express = require("express");

const router = express.Router();

router.get("/", (req, res) => {

  res.json({
    message: "All users"
  });

});

router.get("/:id", (req, res) => {

  res.json({
    id: req.params.id
  });

});

router.post("/", (req, res) => {

  res.status(201).json({
    message: "User created"
  });

});

module.exports = router;

server.js

Mounting Router 
const express = require("express");

const userRoutes =
  require("./routes/users");

const app = express();

app.use(express.json());

app.use(
  "/api/users",
  userRoutes
);

app.listen(3000);
Because the router is mounted at /api/users, router.get("/") becomes: GET /api/users

RESTful API Design Principles

Design APIs that are easy to understand

Use nouns for resources

Prefer: /api/users instead of: /api/getUsers.

Use HTTP methods

Let GET, POST, PUT, PATCH and DELETE communicate the intended operation.

Use consistent URLs

Keep naming and URL structures predictable throughout the API.

Return meaningful status codes

Clients should be able to understand whether an operation succeeded or failed.

Validate input

Never blindly trust client-provided body, route parameters or query values.

Keep responses consistent

Consistent response structures make frontend integration easier.

Good vs poor endpoint design

Less RESTful Resource-oriented
/getUsers GET /api/users
/createUser POST /api/users
/deleteUser/5 DELETE /api/users/5
/updateUser/5 PATCH /api/users/5

Filtering, Searching & Pagination

Using query parameters with REST APIs

Query parameters are useful when the client wants to filter, search, sort or paginate a collection.

Example URL 
GET /api/products?category=books&page=2&limit=10

Reading query parameters

Express Query Parameters 
app.get("/api/products", (req, res) => {

  const {
    category,
    page,
    limit
  } = req.query;

  res.json({
    category,
    page,
    limit
  });

});
Remember: req.params is for values embedded in the route path, req.query is for query-string values, and req.body is for request body data after the appropriate body parser middleware is registered.
22

Common REST API Mistakes

Problems beginners frequently make

GET is intended for retrieving representations. Use an appropriate modifying method such as POST, PUT, PATCH or DELETE for state-changing operations.
APIs should use appropriate HTTP status codes so clients can distinguish successful requests from validation, authorization, missing-resource and server errors.
If your endpoint expects JSON request bodies, register express.json() before the routes that need it.
A route parameter is client input. Validate it before using it for database queries or other operations.
As an API grows, separate routes, controllers, services, middleware and data-access logic into appropriate modules.

Interview Questions

Important REST API and CRUD questions

REST stands for Representational State Transfer. It is an architectural style for designing networked applications around resources and standard HTTP operations.
A REST API is an API designed using REST-style principles, commonly exposing resources through URLs and operating on them with HTTP methods.
CRUD means Create, Read, Update and Delete.
PUT is generally used to replace a resource representation, while PATCH is intended for partial modifications.
It contains route parameters captured from a route such as /users/:id.
It contains query-string parameters such as ?page=2&limit=10.
It contains parsed request body data when the appropriate body parsing middleware, such as express.json(), is configured.
201 Created indicates that a request successfully resulted in the creation of a resource.
Resource-oriented URLs separate the resource identity from the operation. HTTP methods then communicate the operation.
Define resource routes using GET, POST, PUT/PATCH and DELETE, parse request bodies when needed, validate input, perform the required data operation and return appropriate status codes and JSON responses.
