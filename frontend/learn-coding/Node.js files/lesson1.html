What is Node.js?

The fundamental idea behind Node.js

Node.js is a JavaScript runtime environment that allows JavaScript code to execute outside a web browser.

Traditionally, JavaScript was primarily associated with web browsers. Node.js made it possible to use JavaScript for server-side applications, APIs, command-line tools, automation, real-time applications and backend systems.

Simple Definition

Node.js = JavaScript runtime + V8 engine + Node APIs + asynchronous I/O system

02

Why was Node.js created?

Understanding the problem Node.js addressed

Before Node.js

JavaScript was mainly executed inside browsers. Backend systems commonly used technologies such as PHP, Java, Python, Ruby and C#.

Browser JavaScript

Primarily used to make web pages interactive.

  • DOM manipulation
  • Events
  • Forms
  • Animations

Traditional Server Model

Many server architectures used a thread/process for handling incoming work.

  • Request handling
  • Database operations
  • File operations
  • Response generation

The key idea

Node.js was designed around an asynchronous, event-driven model that can efficiently handle many I/O-oriented operations.

The Event Loop

The central concept behind asynchronous Node.js programming

The event loop allows Node.js to coordinate asynchronous operations without requiring JavaScript application code to block while waiting for I/O operations to finish.

Tasks

Request
File I/O
Network I/O
EVENT

Important idea

Node.js does not mean that every operation is executed by a single physical CPU thread. The JavaScript execution model is centered around one main event-loop thread, while certain operations can be handled by the operating system or libuv's worker pool.

08

Non-Blocking I/O

Why asynchronous operations matter

Blocking approach

Imagine the server starts a slow file operation and waits until the operation finishes before continuing with other work.

Blocking-style example 
const fs = require("fs");

const data = fs.readFileSync("data.txt");

console.log(data.toString());

console.log("Next task");
Output waits for the file operation to complete.

Asynchronous approach

Asynchronous example 
const fs = require("fs");

fs.readFile("data.txt", (error, data) => {

    if (error) {
        console.error(error);
        return;
    }

    console.log(data.toString());

});

console.log("Next task");
Next task
...
File result when the operation completes

Single-Threaded Model

What does "single-threaded" actually mean?

Node.js JavaScript execution is primarily handled by a single main thread. This design simplifies many programming tasks because JavaScript code does not normally require developers to manually coordinate multiple application threads.

Main JavaScript Thread

Executes JavaScript code and coordinates the event loop.

Other Resources

Operating-system facilities and libuv's worker pool can perform certain asynchronous operations outside the main JavaScript execution path.

Advantages of Node.js

Why developers use it

  • JavaScript can be used across frontend and backend.
  • Asynchronous APIs are well suited to I/O-heavy applications.
  • Large ecosystem through npm.
  • Excellent support for HTTP and API development.
  • Useful for real-time applications.
  • Fast startup and lightweight application processes for many workloads.
  • Large developer community and ecosystem.
17

Limitations of Node.js

Knowing when the technology is not the right fit

  • CPU-heavy JavaScript work can block the main event-loop thread.
  • Developers need to understand asynchronous programming.
  • Long-running synchronous operations can reduce responsiveness.
  • Large applications require good project architecture and dependency management.
  • Performance depends on workload, architecture and implementation rather than the runtime alone.
18

When Should You Use Node.js?

Choose technology based on the workload

Node.js can be a strong fit for:

  • REST APIs
  • Backend services
  • Real-time applications
  • Streaming applications
  • Web applications
  • Microservices
  • CLI applications
  • Developer tools

Be careful with CPU-heavy tasks

Heavy synchronous CPU work can block the JavaScript event-loop thread. For such workloads, developers may use worker threads, separate services, native modules, queues or other architectural approaches.

Interview Questions

Important questions for backend interviews

1. What is Node.js?
Node.js is a JavaScript runtime environment that allows JavaScript to execute outside the browser. It is built around Google's V8 JavaScript engine and provides APIs for server-side and system-level tasks.
2. Is Node.js a programming language?
No. JavaScript is the programming language. Node.js is a runtime environment for executing JavaScript outside the browser.
3. What is V8?
V8 is Google's open-source JavaScript engine. Node.js embeds V8 to parse and execute JavaScript.
4. What is the Event Loop?
The Event Loop coordinates asynchronous operations and determines when callbacks and other scheduled work can be processed by the JavaScript execution environment.
5. Is Node.js single-threaded?
JavaScript execution in Node.js primarily occurs on one main thread, but Node.js can use operating-system asynchronous facilities and libuv's worker pool for certain operations.
6. What is non-blocking I/O?
It means an application does not have to synchronously wait for an I/O operation to finish before continuing with other work.
7. What is libuv?
libuv is a cross-platform library that provides asynchronous I/O capabilities and infrastructure used by Node.js.
8. Why is Node.js popular for APIs?
Node.js provides built-in networking capabilities and an asynchronous programming model that works well for many I/O-oriented backend services.
