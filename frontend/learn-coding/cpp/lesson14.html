01 · Foundation

What is Polymorphism?

"Poly" means many and "morph" means forms.

P

Simple Definition

Polymorphism is the ability of the same interface, function name or operation to behave differently depending on the situation or object.

∞

Real-World Analogy

A person may act as a student, employee or customer depending on the context. One person, multiple roles.

Core idea: Same interface → different behavior.
Animated Visualization

One Interface → Many Forms

Animal::sound() Common Interface
↓

Cat sound() → Meow
Cow sound() → Moo
02 · Classification

Types of Polymorphism

01

Compile-Time Polymorphism

The compiler determines which function or operation to use during compilation.


  • Function overloading
  • Operator overloading
  • Templates are another form of compile-time polymorphic programming
02

Runtime Polymorphism

The function implementation is selected at runtime through virtual dispatch.


  • Virtual functions
  • Function overriding
  • Base references/pointers
03 · Compile-Time

Compile-Time Polymorphism

The compiler decides which overloaded function matches the call.

compile-time.cpp 
class Calculator {

public:

    int add(int a, int b) {
        return a + b;
    }

    double add(double a, double b) {
        return a + b;
    }

};

int main() {

    Calculator c;

    cout << c.add(2, 3) << '\n';

    cout << c.add(2.5, 3.5);

}
Decision: add(2,3) matches the integer version. add(2.5,3.5) matches the double version.
04 · Function Overloading

Function Overloading

Multiple functions have the same name but different parameter lists.

function-overloading.cpp 
class Print {

public:

    void show(int x) {
        cout << "Integer";
    }

    void show(double x) {
        cout << "Double";
    }

    void show(string x) {
        cout << "String";
    }

};

int main() {

    Print p;

    p.show(10);
    p.show(5.5);
    p.show("Hello");

}
Important: Function overloading cannot be based only on the return type.
Function Parameter List Overload?
show(int) int Yes
show(double) double Yes
show(int, int) two ints Yes
show(int) with different return type same No
05 · Operator Overloading

Operator Overloading

Give operators meaningful behavior for user-defined types.

operator-overloading.cpp 
class Point {

public:

    int x;
    int y;

    Point(int a, int b)
        : x(a), y(b) {}

    Point operator+(const Point& other) {

        return Point(
            x + other.x,
            y + other.y
        );
    }
};

int main() {

    Point p1(2, 3);
    Point p2(4, 5);

    Point p3 = p1 + p2;

    cout << p3.x << " "
         << p3.y;

}
Meaning: The expression p1 + p2 calls the overloaded operator+.
Operator Rules

What Cannot Be Changed?

You cannot create new operators

Operator overloading only changes the behavior of existing operators.

You cannot change precedence

Operator precedence and associativity remain unchanged.

At least one operand must be user-defined

You cannot redefine operators only for built-in types.

Some operators cannot be overloaded

Examples include ::, ., .*, ?: and sizeof.

06 · Runtime Polymorphism

Runtime Polymorphism

The actual object determines which overridden virtual function executes.

runtime.cpp 
class Animal {

public:

    virtual void sound() {
        cout << "Animal sound\n";
    }
};

class Dog : public Animal {

public:

    void sound() override {
        cout << "Dog barks\n";
    }
};

int main() {

    Dog d;

    Animal* ptr = &d;

    ptr->sound();

}
Output: Dog barks because sound() is virtual and the actual object is a Dog.
07 · Virtual Functions

Virtual Functions

The virtual keyword enables dynamic dispatch through a base pointer or reference. 

class Shape {

public:

    virtual void draw() {
        cout << "Drawing Shape";
    }
};

class Circle : public Shape {

public:

    void draw() override {
        cout << "Drawing Circle";
    }
};

Without virtual

A base pointer calling a non-virtual function uses static binding based on the pointer/reference type.

With virtual

A base pointer/reference can dispatch to the derived override according to the actual object.

08 · Best Practice

The override Keyword 

class Animal {

public:

    virtual void sound() {
        cout << "Animal";
    }
};

class Dog : public Animal {

public:

    void sound() override {
        cout << "Dog";
    }
};
Why use override? It asks the compiler to verify that the derived function really overrides a virtual base function.
09 · Abstraction

Pure Virtual Function

A pure virtual function defines an interface requirement. 

class Shape {

public:

    virtual void draw() = 0;
};
Meaning: = 0 makes the function pure virtual. A class containing a pure virtual function is abstract.
10 · Abstract Classes

Abstract Classes

Abstract classes provide interfaces that derived classes can implement. 

class Shape {

public:

    virtual double area() const = 0;

    virtual ~Shape() = default;
};

class Circle : public Shape {

private:

    double radius;

public:

    Circle(double r)
        : radius(r) {}

    double area() const override {

        return 3.14159 *
               radius *
               radius;
    }
};
Important: You cannot create an object directly from an abstract class.

Shape s; → Error.
Interface Thinking

Interface-Style Design in C++ 

class Payment {

public:

    virtual void pay(double amount) = 0;

    virtual ~Payment() = default;
};

class UPI : public Payment {

public:

    void pay(double amount) override {

        cout << "Paid using UPI";
    }
};

class Card : public Payment {

public:

    void pay(double amount) override {

        cout << "Paid using Card";
    }
};

This allows client code to work with the common Payment interface without depending on one concrete payment type.

12 · Important

Object Slicing 

class Animal {

public:

    virtual void sound() {}
};

class Dog : public Animal {

public:

    void sound() override {}
};

Dog dog;

Animal animal = dog;

When a derived object is copied into a base object by value, the derived-specific portion is sliced away.

Better for polymorphism: Use references or pointers. 
Animal& ref = dog;
13 · Casting

Upcasting and Downcasting

Upcasting

Derived → Base. Safe and implicit with public inheritance. 

Dog dog;

Animal* animal = &dog;

Downcasting

Base → Derived. Requires care. 

Animal* animal = &dog;

Dog* dogPtr =
    dynamic_cast<Dog*>(animal);
Warning: Never blindly assume a Base object is a particular Derived object. dynamic_cast can perform a checked downcast when the base is polymorphic.
14 · Interview Essential

Virtual Destructor 

class Base {

public:

    virtual ~Base() = default;
};

class Derived : public Base {

public:

    ~Derived() {
        cout << "Derived destroyed";
    }
};
Rule: If a class is intended to be used polymorphically and an object may be destroyed through a base pointer, give the base class a virtual destructor.

Avoid These

Common Polymorphism Mistakes

❌ Same name ≠ overriding

A derived function does not automatically create runtime polymorphism. The base function should be virtual for dynamic dispatch.

❌ Overloading by return type

Two functions cannot be overloaded only because their return types differ.

❌ Forgetting override

Using override lets the compiler detect accidental signature mismatches.

❌ Creating abstract objects

A class with a pure virtual function is abstract and cannot be instantiated directly.

❌ Object slicing

Passing polymorphic objects by value can lose the derived portion.

❌ Non-virtual destructor

Polymorphic base classes commonly need virtual destructors.

16 · Exam Preparation

5-Mark Answer

Define polymorphism. Explain its types.

Polymorphism is an OOP feature in which the same interface can exhibit different behaviors. The word polymorphism means "many forms".


C++ supports two major forms:

  • Compile-time polymorphism: achieved mainly through function overloading and operator overloading.
  • Runtime polymorphism: achieved using inheritance, virtual functions and overriding.

Mini Project

Payment Processing System

A practical runtime-polymorphism example.

payment-system.cpp 
#include <iostream>

using namespace std;

class Payment {

public:

    virtual void pay(double amount) = 0;

    virtual ~Payment() = default;
};

class UPI : public Payment {

public:

    void pay(double amount) override {

        cout << "UPI payment: ₹"
             << amount << '\n';
    }
};

class Card : public Payment {

public:

    void pay(double amount) override {

        cout << "Card payment: ₹"
             << amount << '\n';
    }
};

class Cash : public Payment {

public:

    void pay(double amount) override {

        cout << "Cash payment: ₹"
             << amount << '\n';
    }
};

void processPayment(
    Payment& payment,
    double amount
) {

    payment.pay(amount);
}

int main() {

    UPI upi;
    Card card;
    Cash cash;

    processPayment(upi, 500);
    processPayment(card, 1000);
    processPayment(cash, 250);

    return 0;
}
What this demonstrates: abstract class → pure virtual function → inheritance → overriding → runtime polymorphism → virtual destructor → common interface.
