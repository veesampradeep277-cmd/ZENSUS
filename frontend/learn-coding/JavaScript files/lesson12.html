1. What Is an Event?

An event is something that happens in the browser and can trigger JavaScript code.

Think of a website like a responsive system

The user performs an action → the browser detects it → JavaScript receives an event → your function executes → the page changes.

👤 User Action
→
🌐 Browser
→
⚡ Event
→
🧠 JavaScript
→
🎨 UI Update

Examples of events

  • User clicks a button.
  • User presses a keyboard key.
  • User moves the mouse.
  • User enters text into an input.
  • User submits a form.
  • An element receives focus.
  • The page finishes loading.

Real-world analogy

Imagine a doorbell.

Pressing the button is the event.

The bell ringing is the event handler.

JavaScript works in a similar way:

Action → Event → Handler → Result

2. addEventListener()

The modern and recommended way to attach event behavior to elements.

Basic syntax

JavaScript 
element.addEventListener("event", function() {
    // code to execute
});
Example 
const button = document.querySelector("#myButton");

button.addEventListener("click", function() {
    console.log("Button clicked!");
});
Why use addEventListener()?

It keeps JavaScript separate from HTML, allows multiple listeners for the same event and provides options for advanced event handling.

Multiple listeners 
button.addEventListener("click", function() {
    console.log("First listener");
});

button.addEventListener("click", function() {
    console.log("Second listener");
});

4. Mouse Events

Mouse events allow your page to react to pointer interaction.

Event Meaning Typical Use
click Element is clicked Buttons
dblclick Double click occurs Editing / zooming
mousedown Mouse button is pressed Drag systems
mouseup Mouse button is released Drag systems
mouseenter Pointer enters element Hover effects
mouseleave Pointer leaves element Tooltips
mousemove Pointer moves Drawing / tracking
Mouse example 
const card = document.querySelector(".card");

card.addEventListener("mouseenter", () => {
    console.log("Mouse entered");
});

card.addEventListener("mouseleave", () => {
    console.log("Mouse left");
});

card.addEventListener("click", () => {
    console.log("Card clicked");
});

5. Keyboard Events

Keyboard events are essential for search boxes, games, forms, shortcuts and accessibility.

keydown

Fires when a key is pressed down.

keyup

Fires when a key is released.

Keyboard example 
document.addEventListener("keydown", (event) => {

    console.log("Key:", event.key);

    if (event.key === "Enter") {
        console.log("Enter pressed");
    }

});
event.key vs event.code

event.key describes the character or key value, while event.code describes the physical keyboard key.

Keyboard shortcut 
document.addEventListener("keydown", (event) => {

    if (event.ctrlKey && event.key.toLowerCase() === "s") {

        event.preventDefault();

        console.log("Custom save shortcut");

    }

});

7. The Event Object

Every event listener can receive an event object containing useful information about what happened.

Event object 
button.addEventListener("click", (event) => {

    console.log(event);

});

event.target

The element where the event originated. 

button.addEventListener("click", (event) => {
    console.log(event.target);
});

event.currentTarget

The element whose listener is currently running. 

button.addEventListener("click", (event) => {
    console.log(event.currentTarget);
});
Important interview concept

target and currentTarget can be different when event propagation is involved.

8. preventDefault()

Some browser actions happen automatically. You can cancel the default action when your application needs custom behavior.

Prevent form submission 
form.addEventListener("submit", (event) => {

    event.preventDefault();

    console.log("Browser submission stopped");

});

Common uses

  • Custom form validation
  • Single-page applications
  • Custom links
  • Drag-and-drop behavior
  • Keyboard shortcuts

Remember

preventDefault() stops the browser's default action.

It does not automatically stop event propagation.

9. Event Bubbling & Capturing

Events do not simply stay inside the element where they occur. They travel through the DOM event path.

Event propagation has three conceptual phases

1. Capturing
→
2. Target
→
3. Bubbling
OUTER ELEMENT
MIDDLE ELEMENT
CLICK ME
Click the inner box to observe propagation.

Event Bubbling

The event moves from the target upward through ancestor elements. 

parent.addEventListener("click", () => {
    console.log("Parent");
});

Event Capturing

A listener can run during the capturing phase before the event reaches the target. 

parent.addEventListener(
    "click",
    () => {
        console.log("Capturing");
    },
    true
);
stopPropagation()

Use event.stopPropagation() when you intentionally need to stop an event from continuing through the propagation path.

10. Event Delegation

Event delegation uses event bubbling to handle events from many child elements using one listener on a parent.

Without delegation

items.forEach(item => {

    item.addEventListener("click", () => {
        console.log("Clicked");
    });

});

With delegation 

list.addEventListener("click", (event) => {

    if (event.target.matches(".item")) {
        console.log("Clicked:", event.target.textContent);
    }

});
Why is delegation useful?

It can reduce the number of listeners and is especially useful for dynamic lists where elements are added later.

13. Real-World Form Event System

A common application pattern: listen for submit, validate the input and provide feedback.

✓ Form submitted successfully!
Typical form event pattern 
form.addEventListener("submit", (event) => {

    event.preventDefault();

    const name = nameInput.value.trim();
    const email = emailInput.value.trim();

    if (!name || !email) {
        return;
    }

    console.log("Form is valid");

});

14. Understanding this in Event Handlers

In a traditional event listener function, this commonly refers to the element on which the listener was registered. 

button.addEventListener("click", function() {

    console.log(this);

});

Arrow functions do not create their own this. 

button.addEventListener("click", () => {

    console.log(this);

});

15. Common Mistakes

❌ Calling the function immediately

Avoid: 

button.addEventListener(
    "click",
    showMessage()
);

Prefer: 

button.addEventListener(
    "click",
    showMessage
);

❌ Using the wrong event name

Event names are specific. For example, click is correct, not onclick when using addEventListener().

❌ Forgetting preventDefault()

Forms may reload or navigate when their default behavior is not intentionally controlled.

❌ Confusing target and currentTarget

This becomes especially important with nested elements and event delegation.

❌ Adding too many listeners

For large dynamic lists, consider event delegation.

❌ Ignoring keyboard accessibility

Interactive interfaces should not depend only on mouse events.

16. Event Performance & Best Practices

Use event delegation

Useful for large or dynamically changing lists.

Do not overuse mousemove

mousemove can fire many times. Expensive work should be minimized or throttled when necessary.

Keep handlers focused

Event handlers should perform a clear task instead of becoming huge blocks of application logic.

Think about accessibility

Use semantic HTML and ensure keyboard users can operate important controls.
