02 • Fundamentals

What is an API?

API stands for Application Programming Interface.

Simple definition

An API is a defined way for one software system to communicate with another software system.

Think of an API as a waiter 🍽️ You are the client. The kitchen is the server. The waiter takes your request to the kitchen and brings the response back to you.
🖥️

Client

The application making the request. Example: browser, mobile application or React app.

⚙️

Server

The system receiving the request and producing a response.

🔗

API

The communication contract between client and server.

🗄️

Database

Stores application data such as students, products, users and orders.

04 • HTTP

Understanding HTTP

HTTP stands for HyperText Transfer Protocol. It defines how clients and servers communicate over a network.

HTTP vs HTTPS HTTPS is HTTP protected by encryption using TLS. Production applications should use HTTPS.
📤

Request

Sent by the client.

🖥️

Processing

Server handles the request.

📥

Response

Server sends data back.

05 • HTTP Methods

HTTP Request Methods

The HTTP method tells the server what operation the client wants.

GET READ
Retrieve existing data.

Example: Get all students.
POST CREATE
Send data to create a new resource.

Example: Create a student.
PUT REPLACE
Replace a resource representation.
PATCH PARTIAL
Modify part of an existing resource.
DELETE REMOVE
Delete an existing resource.
HEAD METADATA
Similar to GET but normally without a response body.
HTTP methods example
GET     /api/students
POST    /api/students
GET     /api/students/42
PUT     /api/students/42
PATCH   /api/students/42
DELETE  /api/students/42

11 • JavaScript API

Fetch API

JavaScript provides fetch() for making HTTP requests.

Basic GET request

async function getStudents() {

    const response = await fetch(
        "https://api.example.com/students"
    );

    if (!response.ok) {
        throw new Error("Request failed");
    }

    const data = await response.json();

    console.log(data);
}

getStudents();

POST request

const student = {
    name: "Pradeep",
    course: "CSE"
};

const response = await fetch(
    "https://api.example.com/students",
    {
        method: "POST",

        headers: {
            "Content-Type": "application/json"
        },

        body: JSON.stringify(student)
    }
);

const data = await response.json();

console.log(data);
Important fetch() detail fetch() rejects its promise for many network-level failures, but an HTTP error such as 404 or 500 does not automatically reject the promise. Check response.ok yourself.

13 • Browser Security

CORS

Cross-Origin Resource Sharing

Browsers enforce the same-origin policy. CORS is a mechanism that allows a server to declare which cross-origin browser requests are permitted.

Frontend
localhost:3000
→
API
api.example.com
→
CORS Headers 
Access-Control-Allow-Origin: https://example.com
Important CORS is primarily a browser-enforced cross-origin mechanism. It is not a replacement for authentication or authorization, and CORS errors should normally be fixed on the server/API configuration rather than by disabling browser security.
14 • Security

API Authentication

🔑

API Key

A key identifying or authorizing an application. Never expose sensitive server-side secrets.

🎫

Bearer Token

A token sent in the Authorization header.

👤

Session

Server-managed authenticated session.

🪪

OAuth

A standardized authorization framework commonly used for delegated access. 

fetch("/api/profile", {
    headers: {
        "Authorization": "Bearer YOUR_TOKEN"
    }
});
Security rule Never put private API secrets directly into frontend code. Anything shipped to a browser can potentially be inspected by users.
15 • Advanced Concepts

Production API Concepts

Pagination

Instead of returning thousands of records at once, APIs return smaller pages. 

/students?page=2&limit=20

Filtering

Return only matching resources.

/students?course=CSE

Sorting

Control result ordering.

/students?sort=name

Rate Limiting

Limits how many requests a client can make during a specified period.

API Versioning

Allows APIs to evolve without unexpectedly breaking clients.

/api/v1/students
/api/v2/students

Timeouts

Prevent an application from waiting indefinitely for a slow network operation.

17 • Real JavaScript

Professional Fetch Pattern

async function fetchStudents() {

    try {

        const response = await fetch("/api/students");

        if (!response.ok) {
            throw new Error(
                `HTTP error: ${response.status}`
            );
        }

        const students = await response.json();

        return students;

    } catch (error) {

        console.error(
            "Failed to fetch students:",
            error
        );

        throw error;
    }
}
Professional pattern Request → Check response → Parse data → Update UI → Handle errors → Show loading/error states.

20 • Avoid These

Common API Mistakes

01. Assuming fetch rejects on 404

Check response.ok or the status code.

02. Forgetting JSON.stringify()

When sending JSON, serialize the JavaScript object.

03. Forgetting Content-Type

Tell the server what format the request body uses.

04. Exposing secret API keys

Never assume frontend code can hide a secret.

05. Confusing authentication with authorization

Authentication asks who you are; authorization asks what you are allowed to do.

06. Ignoring loading states

Users should know when an API request is in progress.

07. Ignoring empty states

An empty result is different from an API failure.

08. Sending unlimited requests

Use pagination, caching, debouncing or appropriate rate controls.

09. Using DELETE/PUT/PATCH incorrectly

Understand the semantics expected by the API contract.

21 • Exam Preparation

5-Mark & 10-Mark Answers

5-Mark Question: What is an API?

An API, or Application Programming Interface, is a defined interface that allows software applications to communicate. In web development, APIs commonly use HTTP requests to allow a client application to communicate with a server. The client sends a request containing information such as a URL, method, headers and sometimes a request body. The server processes the request and returns an HTTP response, often containing JSON data.

10-Mark Question: Explain REST API communication.

A REST API is an API designed according to REST architectural principles. Resources are represented through URLs and HTTP methods are used to perform operations on those resources. GET is commonly used to retrieve data, POST to create, PUT/PATCH to update, and DELETE to remove resources. The server responds with an HTTP status code and may return a representation such as JSON.

22 • Interview Preparation

API Interview Questions

1. What is an API?

An interface that defines how software components communicate.

2. What is a REST API?

An API designed around REST architectural principles, commonly using resources and HTTP methods.

3. Difference between GET and POST?

GET is commonly used to retrieve resources, while POST is commonly used to submit data for creating a resource or triggering server-side processing.

4. PUT vs PATCH?

PUT generally replaces a resource representation; PATCH applies a partial modification.

5. What is JSON?

A text-based structured data format commonly used for exchanging data between applications.

6. What does 404 mean?

The requested resource could not be found.

7. What does 401 mean?

The request lacks valid authentication credentials or authentication failed.

8. What is CORS?

A browser security mechanism that allows servers to specify which cross-origin browser requests are permitted.

9. What is response.ok?

A boolean indicating whether the HTTP response status is in the successful 200–299 range.

10. Does fetch reject for HTTP 404?

Normally no. A 404 produces a fulfilled Response promise; application code should inspect response.ok/status.

11. Why use API versioning?

To allow an API to evolve while giving existing clients a stable contract.

12. What is pagination?

Dividing a large result set into smaller pages.

13. What is authentication?

Verifying the identity or credentials of a user or system.

14. What is authorization?

Determining what an authenticated identity is allowed to access or perform.

15. Why should API keys not be exposed in frontend code?

Browser-delivered code can be inspected. A secret embedded in frontend JavaScript cannot be treated as confidential.
