SORTING FUNDAMENTALS

What does “sorting” actually mean?

Definition

Sorting rearranges elements into a chosen order, usually ascending or descending. The important DSA question is not only “Can I sort it?” but “How should I sort it under these constraints?”

BEFORE

→
AFTER

Comparison-based sorting

Algorithms determine order by comparing elements, such as a[i] > a[j].

  • Bubble Sort
  • Selection Sort
  • Insertion Sort
  • Merge Sort
  • Quick Sort
  • Heap Sort

Non-comparison sorting

Algorithms use properties of the values instead of comparing every pair.

  • Counting Sort
  • Radix Sort
  • Bucket Sort
Core idea: A sorting algorithm is a sequence of decisions that gradually creates a known sorted region or reduces the problem into smaller pieces.

PATTERN 01 • BUBBLE SORT

Adjacent comparison → largest element bubbles right

RECOGNIZE

If the logic repeatedly compares neighboring elements and swaps them when out of order, think Bubble Sort.

See the invariant

After one complete pass, the largest unsorted element reaches the right side.

51428
COMPARE 5 & 1→SWAP→COMPARE 5 & 4→SWAP

Idea

  1. Start at the left.
  2. Compare adjacent elements.
  3. Swap if left > right.
  4. Repeat until the unsorted region disappears.

Why does it work?

Large values move right one swap at a time. Each pass places one maximum element in its final position.

Python • Optimized Bubble Sort
def bubble_sort(arr):
    n = len(arr)

    for i in range(n - 1):
        swapped = False

        for j in range(n - 1 - i):
            if arr[j] > arr[j + 1]:
                arr[j], arr[j + 1] = arr[j + 1], arr[j]
                swapped = True

        if not swapped:
            break

    return arr
1swapped = False detects whether this pass made progress.
2n - 1 - i avoids the already-sorted suffix.
3The comparison is local: only neighbors are examined.
4The swap exchanges two adjacent values that are in the wrong order.

Dry run: [5, 1, 4, 2, 8]

Compare 5,1[1,5,4,2,8]
Compare 5,4[1,4,5,2,8]
Compare 5,2[1,4,2,5,8]
Compare 5,8[1,4,2,5,8]

⚠ Common mistake

Forgetting n - 1 - i is not a correctness disaster, but it repeats comparisons unnecessarily. Forgetting the swapped optimization loses the O(n) best case.

Python • Selection Sort
def selection_sort(arr):
    n = len(arr)

    for i in range(n - 1):
        min_index = i

        for j in range(i + 1, n):
            if arr[j] < arr[min_index]:
                min_index = j

        if min_index != i:
            arr[i], arr[min_index] = arr[min_index], arr[i]

    return arr

PATTERN 03 • INSERTION SORT

Take one element → shift → insert into sorted prefix

Python • Insertion Sort
def insertion_sort(arr):
    for i in range(1, len(arr)):
        key = arr[i]
        j = i - 1

        while j >= 0 and arr[j] > key:
            arr[j + 1] = arr[j]
            j -= 1

        arr[j + 1] = key

    return arr
Why key?

The key is the value we temporarily remove from the unsorted region.

Why shift instead of swap?

Shifting moves a whole block efficiently and leaves one final write for the key.

Why j = i - 1?

The element immediately before the key is the last element of the sorted prefix.

BestO(n)
AverageO(n²)
WorstO(n²)
Extra SpaceO(1)
StableYes
In-placeYes
Interview clue: Insertion Sort is especially useful when the input is already nearly sorted or when elements arrive incrementally.

1Split

Keep dividing until each piece has one element.

2Compare

Compare the first unused element of each half.

3Merge

Copy the smaller element into the result.

4Combine

Repeat until the whole array is rebuilt in order.

Python • Merge Sort
def merge_sort(arr):
    if len(arr) <= 1:
        return arr

    mid = len(arr) // 2
    left = merge_sort(arr[:mid])
    right = merge_sort(arr[mid:])

    return merge(left, right)


def merge(left, right):
    result = []
    i = j = 0

    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1

    result.extend(left[i:])
    result.extend(right[j:])
    return result

PATTERN 05 • QUICK SORT

Choose a pivot → partition → recurse on both sides

RECOGNIZE: The problem revolves around a pivot and placing smaller values on one side and larger values on the other.
9375281
LESS THAN 5← PIVOT = 5 →GREATER THAN 5
[3,2,1]5[9,7,8]
Python • Quick Sort with Lomuto Partition
def quick_sort(arr, low, high):
    if low < high:
        pivot_index = partition(arr, low, high)
        quick_sort(arr, low, pivot_index - 1)
        quick_sort(arr, pivot_index + 1, high)


def partition(arr, low, high):
    pivot = arr[high]
    i = low

    for j in range(low, high):
        if arr[j] <= pivot:
            arr[i], arr[j] = arr[j], arr[i]
            i += 1

    arr[i], arr[high] = arr[high], arr[i]
    return i
PivotChoose a value around which the array will be partitioned.
iMarks the next position where a value ≤ pivot should go.
jScans the current partition.
Final swapPlaces the pivot between the smaller and larger regions.
BestO(n log n)
AverageO(n log n)
WorstO(n²)
Extra StackO(log n) avg.
StableNo
In-placeUsually

⚠ Why can Quick Sort become O(n²)?

If every partition is extremely unbalanced — for example, repeatedly choosing the smallest or largest element as pivot — recursion becomes almost linear.

Common improvement: randomized pivot selection or a good pivot strategy.

PATTERN 06 • HEAP SORT

Build a max heap → move maximum to the end → heapify

RECOGNIZE: When you need repeated access to the maximum/minimum and want a guaranteed O(n log n) comparison sort with O(1) auxiliary array space.

For a max heap: every parent ≥ its children.

left child = 2i + 1 right child = 2i + 2 parent = (i - 1) // 2
Python • Heap Sort
def heap_sort(arr):
    n = len(arr)

    def heapify(size, root):
        largest = root
        left = 2 * root + 1
        right = 2 * root + 2

        if left < size and arr[left] > arr[largest]:
            largest = left

        if right < size and arr[right] > arr[largest]:
            largest = right

        if largest != root:
            arr[root], arr[largest] = arr[largest], arr[root]
            heapify(size, largest)

    # Build max heap
    for i in range(n // 2 - 1, -1, -1):
        heapify(n, i)

    # Extract maximum one by one
    for end in range(n - 1, 0, -1):
        arr[0], arr[end] = arr[end], arr[0]
        heapify(end, 0)

    return arr

Python • Counting Sort for non-negative integers
def counting_sort(arr):
    if not arr:
        return arr

    maximum = max(arr)
    count = [0] * (maximum + 1)

    for value in arr:
        count[value] += 1

    index = 0
    for value, frequency in enumerate(count):
        for _ in range(frequency):
            arr[index] = value
            index += 1

    return arr
TimeO(n + k)
SpaceO(k)
Stable?Basic version no
Best whenk is manageable

k = range of values. If values range from 1 to 10⁹ for only 100 elements, a huge count array is usually a poor choice.

Radix Sort

Python • LSD Radix Sort for non-negative integers
def radix_sort(arr):
    if not arr:
        return arr

    maximum = max(arr)
    place = 1

    while maximum // place > 0:
        counting_by_digit(arr, place)
        place *= 10

    return arr


def counting_by_digit(arr, place):
    output = [0] * len(arr)
    count = [0] * 10

    for value in arr:
        digit = (value // place) % 10
        count[digit] += 1

    for i in range(1, 10):
        count[i] += count[i - 1]

    for i in range(len(arr) - 1, -1, -1):
        digit = (arr[i] // place) % 10
        output[count[digit] - 1] = arr[i]
        count[digit] -= 1

    for i in range(len(arr)):
        arr[i] = output[i]
TimeO(d(n + b))
SpaceO(n + b)

bbase, e.g. 10

COMMON MISTAKES

Where students usually lose marks

01

Confusing stable with in-place

They describe different properties. Stability concerns equal-key ordering; in-place concerns auxiliary memory.

02

Memorizing Quick Sort pointers

Understand the partition invariant first: what does the pointer region already guarantee?

03

Ignoring constraints

O(n+k) is not automatically better if k is enormous.

04

Calling every O(n log n) sort identical

Merge, Quick, and Heap have different memory, stability, and worst-case behavior.

05

Forgetting duplicates

Partition logic, stability, and equality conditions can change behavior when duplicate values exist.

06

Not tracing the base case

Merge and Quick Sort are recursive. Always state exactly when recursion stops.
