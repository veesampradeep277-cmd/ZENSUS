What is Recursion?

🔁

A function solving a smaller version of itself

Recursion is a programming technique where a function calls itself to solve a smaller or simpler version of the same problem.

Every recursive solution must eventually reach a condition where it stops calling itself. This is called the base case.

🪆
REAL-WORLD ANALOGY

Russian Dolls

Imagine opening a Russian doll. Inside it is another doll, and inside that is another one. You continue until you reach the smallest doll.

Big Doll → Smaller Doll → Smallest Doll → STOP
Every recursive function needs
1 Base Case

When should recursion stop?

2 Recursive Case

How does the problem become smaller?

3 Progress

Does every call move toward the base case?

03
THE TWO MOST IMPORTANT PARTS

Base Case & Recursive Case

🛑
PART 01

Base Case

The condition that tells the recursive function: “Stop calling yourself.” 

if n == 0:
    return
❌ Without a valid base case, recursion can continue indefinitely and cause a stack overflow.
🔄
PART 02

Recursive Case

The part where the function calls itself using a smaller or simpler input. 

return n * factorial(n - 1)
✓ The recursive call must move toward the base case.
⭐ ZENSUS GOLDEN RULE

If you cannot clearly explain your base case, you probably do not understand your recursion yet.

03
TWO CHOICES

Include / Exclude

⭐ MUST KNOW

🧠 Recognize this pattern

At every element, you have two possibilities: take it or skip it.

Element → Include + Exclude

Common problems

  • Subsets
  • Subsequences
  • Subset Sum
  • 0/1 Knapsack thinking
[]
1
INCLUDE
[1]
EXCLUDE
[]

Example: Generate all subsets

def subsets(nums):

    result = []

    def backtrack(index, path):

        if index == len(nums):
            result.append(path.copy())
            return

        # Include nums[index]
        path.append(nums[index])
        backtrack(index + 1, path)

        # Undo include
        path.pop()

        # Exclude nums[index]
        backtrack(index + 1, path)

    backtrack(0, [])
    return result
🔍 Dry Run: [1, 2]
[]
[1] []
[1,2] [1] [2] []

Every element creates exactly two branches: include and exclude.

Time: O(2ⁿ) Space: O(n) recursion depth

Example: Recursive Binary Search

def binary_search(arr, low, high, target):

    if low > high:
        return -1

    mid = (low + high) // 2

    if arr[mid] == target:
        return mid

    elif target < arr[mid]:
        return binary_search(
            arr, low, mid - 1, target
        )

    else:
        return binary_search(
            arr, mid + 1, high, target
        )

THE BIG IDEA

What is Backtracking?

↩

Backtracking = Explore possibilities + Undo choices

Backtracking is a problem-solving technique that explores possible choices and abandons a choice as soon as it becomes impossible or invalid.

It is often implemented using recursion. The important addition is that we maintain a changing state and undo our choices when returning from recursion.

01 CHOOSE Make a decision
→
02 CHECK Is it valid?
→
03 EXPLORE Recurse deeper
→
04 UNDO Restore state
MASTER TEMPLATE

The Backtracking Skeleton

CORE 
def backtrack(state):

    # 1. Base case
    if is_complete(state):
        save_solution(state)
        return

    # 2. Try every possible choice
    for choice in choices:

        # 3. Check constraint
        if not valid(choice, state):
            continue

        # 4. Choose
        make_choice(choice, state)

        # 5. Explore
        backtrack(state)

        # 6. Undo
        undo_choice(choice, state)

Recursion vs Backtracking

Recursion Backtracking
Core idea Function calls itself Explore choices and undo
State May or may not change Usually maintained explicitly
Choices Not necessarily multiple Usually multiple possibilities
Pruning Not essential Very important
Examples Factorial, Tree Traversal N-Queens, Sudoku, Subsets

Example — Combination Sum

def combination_sum(start, target, path):

    if target == 0:
        result.append(path.copy())
        return

    for i in range(start, n):

        if nums[i] > target:
            break

        path.append(nums[i])

        combination_sum(
            i,
            target - nums[i],
            path
        )

        path.pop()

CONSTRAINTS

Constraint + Pruning

Reject invalid choices as early as possible. This prevents entire branches from being explored.

Start
Valid ✓ Explore
Invalid ✕ PRUNE
Continue ↓
⚡ WHY PRUNING MATTERS

Without pruning, the algorithm may explore huge numbers of impossible states. A good backtracking solution detects failure early and immediately returns.

Example — N-Queens Safety Check

def is_safe(row, col):

    # Check previous rows
    for r in range(row):

        c = board[r]

        # Same column
        if c == col:
            return False

        # Same diagonal
        if abs(c - col) == abs(r - row):
            return False

    return True

def dfs(r, c):

    if outside_grid(r, c):
        return False

    if visited[r][c]:
        return False

    # Mark
    visited[r][c] = True

    # Explore neighbors
    for dr, dc in directions:

        if dfs(r + dr, c + dc):
            return True

    # Undo / unmark
    visited[r][c] = False

    return False

Example — Palindrome Partitioning

def partition(start, path):

    if start == len(s):
        result.append(path.copy())
        return

    for end in range(start + 1, len(s) + 1):

        part = s[start:end]

        if is_palindrome(part):

            path.append(part)

            partition(end, path)

            path.pop()

How to Recognize the Pattern

Before writing code, ask what the problem is actually asking you to do.

Problem Clue Think About Pattern
“Generate all subsets” Two choices per element Include / Exclude
“Generate all subsequences” Take / Skip Include / Exclude
“Generate all permutations” Every item can occupy every position Pick / Mark / Unmark
“Find all combinations” Try multiple choices Loop + Recursion

LEARN FROM FAILURES

Common Mistakes

01

No Base Case

The function keeps calling itself forever. 

def wrong(n):
    return wrong(n - 1)
✓ Always define a stopping condition.
02

No Progress

The recursive call receives the same state repeatedly. 

solve(n)
✓ Every call should move toward termination.
03

Forgetting Undo

A previous choice remains in the path and corrupts future solutions.

✓ If you modify shared state, restore it after recursion.
04

Saving the Same List

Appending a mutable path directly can cause all solutions to reference the same list. 

result.append(path.copy())
✓ Save a copy of the current state.
05

Pruning Too Late

Exploring an impossible branch wastes time.

✓ Check constraints as early as possible.
06

Confusing Recursion With Backtracking

Recursion alone does not automatically mean backtracking.

✓ Backtracking usually means explore choices + restore state.

ANALYZE YOUR SOLUTION

Time & Space Complexity

📈

Linear Recursion

O(n)

One recursive call per level.

🌳

Binary Recursion

O(2ⁿ)

Each state may produce two branches.

🔀

Permutations

O(n × n!)

There are n! possible arrangements.

♛

N-Queens

Exponential

Constraints and pruning reduce practical search.

Important:

Backtracking often has exponential worst-case complexity because it explores combinations of choices. The goal is not always to eliminate exponential complexity; it is to eliminate unnecessary branches through pruning and good state design.
