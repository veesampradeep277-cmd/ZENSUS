01 · FOUNDATION

What Is the <input> Element?

The <input> element is an HTML form control used to allow users to enter, select or provide information.

Its behavior is controlled mainly by the type attribute.

HTML 
<input type="text">

Important Concept

The same <input> element can behave completely differently depending on its type.

14 · HIDDEN DATA

type="hidden"

A hidden input is not displayed to the user, but its value can be included in submitted form data.

HTML

    type="hidden"
    name="courseId"
    value="HTML-009"
>

Important Security Rule

Hidden does not mean trusted or secure. Users can inspect and modify client-side data. Never use hidden inputs as a security boundary.

17 · STATE

readonly vs disabled

readonly

The user generally cannot edit the value, but the control remains usable and its value can participate in normal form submission.

disabled

The control is disabled and is not normally included in form submission.

HTML 
<input
    type="text"
    name="studentId"
    value="ZENSUS-1001"
    readonly
>

<input
    type="text"
    name="lockedField"
    value="Unavailable"
    disabled
>
18 · PATTERN VALIDATION

pattern Attribute

The pattern attribute allows you to specify a regular-expression constraint for supported text-like input types.

HTML 
<label for="studentCode">
    Student Code
</label>

<input
    type="text"
    id="studentCode"
    name="studentCode"
    pattern="[A-Z]{3}[0-9]{4}"
    placeholder="ABC1234"
    required
>

Example

The pattern above expects three uppercase letters followed by four digits.

23 · ACCESSIBILITY

Accessible Input Elements

  1. Use a visible <label> for important inputs.
  2. Connect label for with input id.
  3. Use the correct input type.
  4. Do not rely only on placeholder text.
  5. Provide meaningful error messages.
  6. Ensure keyboard users can operate the form.
  7. Group related radio buttons and checkboxes.

24 · DEBUGGING

Common Input Mistakes

❌ No label

Users may not know what information the input expects.

❌ Missing name

The expected field may not be included in normal form submission.

❌ Wrong input type

Using text for every field can reduce validation and mobile usability.

❌ Placeholder as label

Placeholder disappears while typing.

❌ Trusting hidden fields

Hidden values can be modified by users.

❌ Client validation only

Server-side validation is still required for untrusted input.

27 · EXAM PREPARATION

5-Mark Answer

Explain the HTML <input> Element

The HTML <input> element is used to create interactive controls that allow users to enter or select information.

Its behavior is determined mainly by the type attribute. Common types include text, email, password, number, date, checkbox, radio, file, range and color.

Important attributes include name, id, value, placeholder, required, min, max, step, minlength, maxlength, pattern, readonly and disabled.

28 · EXAM PREPARATION

10-Mark Answer

The HTML <input> element is one of the most important form elements. It allows websites to collect information from users.


The behavior of the input is controlled using the type attribute. Common input types include text, email, password, number, tel, url, search, date, time, checkbox, radio, file, range, color, hidden, submit and reset.


The name attribute identifies the field during form submission, while id identifies the element within the document. The value attribute represents its value.


Input validation can be implemented using required, min, max, step, minlength, maxlength and pattern. These features improve the user experience, but server-side validation remains necessary.


Accessible inputs should use appropriate labels, logical grouping, clear instructions and useful error messages.

29 · INTERVIEW PREPARATION

HTML Input Interview Questions

1. What is the <input> element?

It is an HTML form control used to collect or select user input.

2. What does the type attribute do?

It determines the behavior and user interface of the input control.

3. What is the difference between text and email?

Email provides email-oriented browser behavior and validation, while text is general-purpose.

4. What is the purpose of name?

It identifies a form field in submitted data.

5. What is the purpose of id?

It uniquely identifies an element within the document and can connect a label to that input.

6. Why is the label element important?

It gives users and assistive technologies a clear accessible name for the control.

7. Difference between radio and checkbox?

Radio buttons are normally used for one choice in a group. Checkboxes allow independent choices.

8. What is readonly?

It prevents normal editing while keeping the control usable.

9. What is disabled?

It makes a control unavailable for interaction and normally excludes it from form submission.

10. What is pattern?

Pattern defines a regular-expression constraint for supported input values.

11. What is autocomplete?

It provides browser hints about autofill behavior.

12. What is accept?

It provides a hint about which file types should be offered by a file picker.

13. Is hidden input secure?

No. Users can inspect and modify client-side values.

14. Is HTML validation enough for security?

No. Server-side validation is required because client-side validation can be bypassed.
