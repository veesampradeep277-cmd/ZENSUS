01 · Foundation

What Is an HTML Form?

An HTML form is a section of a webpage used to collect information from a user.

Examples include login forms, registration forms, contact forms, search boxes, payment forms, feedback forms and application forms.

Form Anatomy

A professional form connects a visible label with a form control and gives that control a name.

<input>

05 · Accessibility

Labels: Never Leave Users Guessing

A <label> tells users what information a form control expects.

The for attribute should match the input's id.

HTML 
<label for="email">Email Address</label>

<input
    type="email"
    id="email"
    name="email"
>

Why this matters

Labels improve usability, accessibility, keyboard interaction and screen-reader support.

07 · User Experience

Placeholder vs Label

❌ Placeholder is not a label

Placeholder text disappears when users begin entering information.

✅ Use a real label

Labels remain available and provide persistent context.

    id="phone"

>

13 · Validation

HTML Form Validation

Validation helps prevent incomplete or incorrectly formatted input before submission.

Attribute Purpose
required Field must contain a value.
minlength Minimum number of characters.
maxlength Maximum number of characters.
min Minimum numeric/date value.
max Maximum numeric/date value.
step Allowed increment between values.
pattern Pattern that the value should match.
HTML 
<label for="username">Username</label>

<input
    type="text"
    id="username"
    name="username"
    required
    minlength="4"
    maxlength="20"
>

<label for="age">Age</label>

<input
    type="number"
    id="age"
    name="age"
    min="18"
    max="60"
    required
>
14 · Submission

GET vs POST

GET

Form data is generally appended to the URL as query parameters.

Example: ?course=python&level=beginner

POST

Form data is sent in the request body rather than being appended to the URL.

Common for registration, login and data creation.

HTML 
<form action="/search" method="get">

    <input
        type="search"
        name="query"
    >

    <button type="submit">
        Search
    </button>

</form>


<form action="/register" method="post">

    <input
        type="text"
        name="username"
    >

    <button type="submit">
        Register
    </button>

</form>

Important

Never treat GET or POST alone as a security mechanism. Sensitive applications should use HTTPS and proper server-side security controls.

15 · File Uploads

File Uploads & enctype

When uploading files, a form commonly uses multipart/form-data.

HTML 
<form
    action="/upload"
    method="post"
    enctype="multipart/form-data"
>

    <label for="resume">Upload Resume</label>

    <input
        type="file"
        id="resume"
        name="resume"
        accept=".pdf,.doc,.docx"
    >

    <button type="submit">
        Upload
    </button>

</form>

Security Rule

The accept attribute is only a user-interface hint. A server must still validate file type, size and content.

22 · Avoid These

Common Form Mistakes

❌ Missing labels

Every important form control should have an accessible name.

❌ Missing name

A control without an appropriate name may not provide the expected submitted field.

❌ Using placeholder as label

Placeholder text should not replace persistent labels.

❌ No server validation

Browser validation can be bypassed. Validate again on the server.

❌ Password through GET

Sensitive information should not be placed in URLs.

❌ Unclear error messages

Tell users what went wrong and how they can fix it.

23 · Security

Form Security Basics

HTTPS

Use HTTPS to protect data while it travels between browser and server.

Server Validation

Never trust browser validation alone. Validate data on the server.

XSS Protection

Safely encode and sanitize untrusted data before rendering it as HTML.

CSRF Protection

State-changing requests should use appropriate CSRF protections.

24 · Accessibility

Accessible Forms

  1. Use a real label for every form control.
  2. Use clear and descriptive labels.
  3. Group related controls with fieldset and legend.
  4. Ensure the form can be operated using a keyboard.
  5. Provide understandable error messages.
  6. Do not depend only on color to communicate errors.
  7. Use appropriate input types.
  8. Use autocomplete where appropriate.

26 · Exam Preparation

5-Mark Answer

Explain HTML Forms

HTML forms are used to collect user information through controls such as text fields, email fields, passwords, radio buttons, checkboxes, select menus, text areas and buttons.

The <form> element defines the form. The action attribute specifies where data is sent and the method attribute specifies how the data is submitted.

Labels improve accessibility, while attributes such as required, minlength, maxlength, min, max and pattern provide client-side validation.

27 · Exam Preparation

10-Mark Answer

HTML forms provide a structured way to collect information from users and send it to a server for processing.


A form is created using the <form> element. Important attributes include action and method. Form controls include <input>, <textarea>, <select>, <option> and <button>.


The input element supports many types such as text, email, password, number, date, file, checkbox, radio, range and submit.


Labels should be associated with controls using the for and id attributes. Validation can be performed using required, minlength, maxlength, min, max, step and pattern.


GET normally places submitted parameters in the URL, while POST sends form data in the request body. File uploads commonly use multipart/form-data.


Professional forms should provide clear labels, accessible grouping, useful error messages, keyboard support, client-side validation and server-side validation.

28 · Interview Preparation

HTML Forms Interview Questions

1. What is an HTML form?

An HTML form is a section of a webpage used to collect user input and submit it for processing.

2. What is the purpose of the form element?

It groups form controls and defines how their data is submitted.

3. What is the difference between id and name?

id identifies an element within the document, while name identifies the field in submitted form data.

4. Why are labels important?

Labels improve usability and accessibility and provide a clear name for form controls.

5. What is the difference between GET and POST?

GET generally sends parameters through the URL, while POST sends data in the request body.

6. What is required?

required indicates that the user must provide a value before normal browser submission.

7. What is the difference between radio and checkbox?

Radio buttons are generally used for one choice within a group, while checkboxes allow independent selections.

8. What is fieldset?

Fieldset groups related form controls.

9. What is legend?

Legend provides a caption for a fieldset.

10. What is enctype?

enctype specifies how form data is encoded before submission. File uploads commonly use multipart/form-data.

11. What is client-side validation?

Validation performed in the browser before the request is normally submitted.

12. Why is server-side validation still required?

Browser-side checks can be bypassed, so the server must independently validate untrusted input.

13. What is datalist?

Datalist provides suggested values for an input while allowing the user to enter a value.

14. What is autocomplete?

It provides hints about whether and how the browser may autofill form controls.
