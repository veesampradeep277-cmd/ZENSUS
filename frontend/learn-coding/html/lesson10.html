02

What Is Semantic HTML?

HTML elements that describe the meaning of their content.

Semantic HTML means choosing HTML elements according to what the content actually represents.

For example, a navigation menu should use <nav>, the primary content should use <main>, and an independent article can use <article>.

💡 Think Like This

Semantic HTML answers the question: “What is this content?” rather than only: “How should this content look?”

❌ Non-Semantic

A generic container gives little information about its purpose.

HTML 
<div class="header">
    Website Logo
</div>

<div class="navigation">
    Home
    Courses
    About
</div>

✅ Semantic

The element itself communicates its purpose.

HTML 
<header>
    Website Logo
</header>

<nav>
    Home
    Courses
    About
</nav>

04

Core Semantic Elements

These are the most important structural elements you should know.

<header>

Header

Introductory content, branding, heading or navigation for a page or section.

<nav>

Navigation

Contains major navigation links.

<main>

Main

Contains the dominant content of the document.

<section>

Section

Represents a thematic grouping of content.

<article>

Article

Represents self-contained content that could stand independently.

<aside>

Aside

Contains content indirectly related to the surrounding content.

<footer>

Footer

Contains closing information such as copyright or related links.

<figure>

Figure

Groups self-contained media or illustrations.

<details>

Details

Creates an expandable disclosure component.

05

<header> — Page Introduction

Defines introductory content for a page or section.

A <header> can contain a logo, heading, introductory text or navigation.

header-example.html 
<header>
    <h1>ZENSUS</h1>
    <p>Learn. Build. Grow.</p>
</header>

Important

A page can contain multiple headers because a section or article may have its own header.

06

<nav> — Navigation

Represents a major set of navigation links.

navigation.html 
<nav aria-label="Main navigation">
    <a href="index.html">Home</a>
    <a href="courses.html">Courses</a>
    <a href="problems.html">Coding Problems</a>
    <a href="contact.html">Contact</a>
</nav>

Accessibility Tip

If a page has multiple navigation regions, use aria-label to distinguish them when appropriate.

07

<main> — Main Content

Represents the dominant content of the document.

main.html 
<main>

    <h1>Python Programming</h1>

    <p>
        Learn Python from beginner to advanced level.
    </p>

</main>

⚠️ Important Rule

A document should normally have one main content region. Do not use multiple unrelated <main> elements to divide a page.

08

Section vs Article vs Div

One of the most important semantic HTML concepts.

Element Purpose Typical Usage
<section> Thematic grouping Features, topics, chapters
<article> Self-contained content Blog post, news item, forum post
<div> Generic container Styling/layout when no semantic element fits

Section

Think: “A chapter of my page.”

Article

Think: “This content can stand alone.”

Div

Think: “I need a generic container.”

09

<article> — Independent Content

Content that could potentially be distributed independently.

article.html 
<article>

    <header>
        <h2>How Python Lists Work</h2>
    </header>

    <p>
        Python lists store multiple values in a single collection.
    </p>

    <footer>
        Written by ZENSUS
    </footer>

</article>

Examples include blog posts, news articles, product cards, forum posts and independent learning lessons.

10

<aside> — Related Content

Content that is related to, but not central to, the main content.

aside.html 
<aside>

    <h3>Related Topics</h3>

    <ul>
        <li>Python Variables</li>
        <li>Python Functions</li>
        <li>Python Lists</li>
    </ul>

</aside>

A sidebar is a common visual use of <aside>, but its meaning is broader than simply “right side of the page.”

11

<footer> — Closing Information

Represents footer information for a page or section.

footer.html 
<footer>

    <p>
        © 2026 ZENSUS. All rights reserved.
    </p>

    <a href="privacy.html">Privacy Policy</a>

</footer>

A footer can appear for the entire page or inside an article.

12

<figure> & <figcaption>

Semantic grouping for media and its description.

figure.html 
<figure>

    <img
        src="architecture.png"
        alt="Semantic HTML page structure"
    >

    <figcaption>
        Semantic structure of a modern webpage.
    </figcaption>

</figure>

Why use figure?

It communicates that the media and caption form a meaningful, self-contained unit.

Complete Semantic HTML Structure

This is the pattern you should remember.

        <a href="#">Courses</a>
        <a href="#">Problems</a>

    <main>

        <section>

            <h2>Featured Courses</h2>

            <article>
                <h3>Python Programming</h3>
                <p>
                    Learn Python from beginner to advanced.
                </p>
            </article>

        </section>

        <aside>
            Related learning resources
        </aside>

    </main>

    <footer>
        <p>© 2026 ZENSUS</p>
    </footer>

</body>

</html>

Semantic HTML + Heading Hierarchy

Semantic page structure should work together with proper headings.

good-heading-structure.html 
<main>

    <h1>Python Programming</h1>

    <section>

        <h2>Python Basics</h2>

        <article>
            <h3>Variables</h3>
        </article>

        <article>
            <h3>Data Types</h3>
        </article>

    </section>

    <section>

        <h2>Advanced Python</h2>

        <h3>Decorators</h3>

    </section>

</main>

⚠️ Don't use headings only for visual size

If you want text to look larger, use CSS. Do not choose an <h2> instead of <h3> simply because it looks better.

23

Common Semantic HTML Mistakes

Avoid these mistakes when building professional websites.

❌ Div Everywhere

Using <div> for every page region removes useful structural meaning.

❌ Fake Buttons

Using a generic element as a button when a real <button> is appropriate.

❌ Fake Navigation

Creating navigation without meaningful navigation structure.

❌ Wrong Element for Styling

Choosing semantic elements only because their default browser style looks convenient.

❌ Missing Main

Failing to identify the primary content of the document.

❌ Random Headings

Using heading levels based only on font size.

24

Semantic HTML Best Practices

Follow these rules when writing production-quality HTML.

  • Choose HTML elements based on meaning.
  • Use one clear primary <main> region.
  • Use <nav> for major navigation areas.
  • Use <article> for self-contained content.
  • Use <section> for meaningful thematic groups.
  • Use <aside> for supporting content.
  • Maintain logical heading hierarchy.
  • Use CSS for visual styling rather than incorrect semantic elements.
  • Use accessible labels and meaningful link text.
  • Use semantic HTML before adding ARIA when native HTML already provides the required semantics.

Semantic HTML and SEO

Semantic structure can help search engines understand page content.

Clear Content

Search systems can better understand the relationship between headings and content.

Structured Page

26

5-Mark Exam Answer

Write this structure in your exam when asked about Semantic HTML.

Semantic HTML

Semantic HTML is the practice of using HTML elements that clearly describe the meaning and purpose of their content. Examples include <header>, <nav>, <main>, <section>, <article>, <aside> and <footer>.

Semantic HTML improves code readability, accessibility and document structure. It helps assistive technologies identify important page regions and allows developers to understand the structure more easily.

27

10-Mark Exam Answer

A detailed answer for university examinations.

Explain Semantic HTML with examples

Semantic HTML refers to using HTML elements according to the meaning and purpose of the content they contain. Unlike generic elements such as <div>, semantic elements communicate structural information.

Important semantic elements include <header> for introductory content, <nav> for navigation, <main> for the primary content, <section> for thematic groups, <article> for independent content, <aside> for related content and <footer> for closing information.

Semantic HTML improves accessibility because assistive technologies can use structural information to help users navigate the document. It also improves code readability and maintainability.

Semantic structure can also help search engines understand the relationship between different parts of a document.

Therefore, semantic HTML is an important foundation for creating professional, accessible and maintainable websites.

Interview Questions

14 important Semantic HTML interview questions.

1. What is Semantic HTML?
Semantic HTML uses elements that communicate the meaning and purpose of their content.
2. Why is Semantic HTML important?
It improves structure, accessibility, maintainability and can help search engines understand the document.
3. What is the difference between div and section?
A section represents a meaningful thematic grouping, while div is a generic container with no semantic meaning.
4. What is the purpose of main?
The main element represents the dominant content of the document.
5. What is an article?
An article represents self-contained content that could potentially be distributed or understood independently.
6. What is aside used for?
Aside represents content related to the surrounding content but not part of its central flow.
7. Can a page contain multiple header elements?
Yes. Headers can belong to the overall page or individual sections/articles.
8. Can a page contain multiple nav elements?
Yes. Multiple navigation regions can exist when appropriate. They can be distinguished with accessible labels.
9. What is the purpose of footer?
Footer provides closing information for a page or section.
10. Does semantic HTML improve SEO?
Semantic structure can help search engines interpret page content, but semantic HTML alone does not guarantee ranking improvements.
11. What is a landmark?
A landmark is an important page region that assistive technologies can use for navigation, such as navigation and main content.
12. What is figure used for?
Figure groups self-contained media or content, often together with a figcaption.
13. What are details and summary?
They provide a native expandable disclosure interface.
14. Should div never be used?
No. Div is useful when no appropriate semantic element exists, especially for generic styling or layout containers.
