01 · Foundation

Why Asynchronous JavaScript?

A Node.js application often performs operations that take time: reading files, querying databases, communicating with APIs, waiting for timers or receiving network requests. Instead of making JavaScript wait for every operation, Node.js uses an asynchronous programming model.

01

Responsive Execution

Long-running operations can be handled without unnecessarily stopping the JavaScript execution flow.

02

I/O Operations

File systems, databases, networks and other input/output operations are common places where asynchronous behavior becomes important.

03

Event-Driven Architecture

Node.js uses an event-driven model in which operations can complete later and trigger callbacks or other continuation mechanisms.

Core idea: Start an operation → allow other JavaScript work to continue → receive the result later → continue processing it.
02 · Core Concept

Synchronous vs Asynchronous

The difference is mainly about when JavaScript can continue to the next piece of work.

Synchronous

Operations are executed in sequence. If one operation blocks execution, later JavaScript statements wait. 

console.log("A");

const result =
    readFileSynchronously();

console.log("B");

Conceptually: A → wait → operation → B

Asynchronous

An operation can begin and complete later. JavaScript can continue with other work. 

console.log("A");

readFileAsync(() => {
    console.log("File ready");
});

console.log("B");

Typical output: A → B → File ready

03 · Node.js Behavior

Blocking vs Non-Blocking

In Node.js, non-blocking I/O allows the JavaScript thread to continue processing while an I/O operation is being handled.

B

Blocking

JavaScript execution cannot continue past a blocking operation until that operation finishes.

NB

Non-Blocking

JavaScript can continue processing while the asynchronous operation is handled elsewhere.

I/O

Typical Example

Reading a file asynchronously lets your application continue with other JavaScript work while waiting for the file operation.

Node.js — asynchronous file example 
const fs = require("fs");

console.log("1. Start");

fs.readFile(
    "data.txt",
    "utf8",
    (err, data) => {

        if (err) {
            console.log(err);
            return;
        }

        console.log(data);
    }
);

console.log("2. Continue");

06 · The Original Pattern

Callbacks

A callback is a function passed to another function so that it can be called later, often after an asynchronous operation completes.

callback-example.js 
function getData(callback) {

    setTimeout(() => {

        const data =
            { name: "ZENSUS" };

        callback(data);

    }, 1000);
}


getData((data) => {

    console.log(data);

});
+

Simple Idea

The callback executes after the asynchronous operation has completed.

−

Nested Callbacks

Multiple dependent callbacks can become deeply nested and difficult to maintain.

!

Error Handling

Node.js commonly uses the error-first callback convention: callback(error, result).

Error-first callback pattern 
fs.readFile("data.txt", "utf8",
    (err, data) => {

        if (err) {
            console.error(err);
            return;
        }

        console.log(data);
    }
);
07 · Modern Asynchronous Control

Promises

A Promise represents the eventual completion or failure of an asynchronous operation.

01

Pending

The asynchronous operation has started, but the result is not available yet.

02

Fulfilled

The operation completed successfully. The Promise now contains a successful result.

03

Rejected

The operation failed. The Promise contains a reason for the failure.

Promise example 
const promise = new Promise(
    (resolve, reject) => {

        setTimeout(() => {

            const success = true;

            if (success) {
                resolve("Data received");
            } else {
                reject("Request failed");
            }

        }, 1000);
    }
);


promise
    .then(result => {
        console.log(result);
    })
    .catch(error => {
        console.log(error);
    });
08 · Modern Syntax

async / await

async/await provides a cleaner way to write Promise-based asynchronous code. An async function always returns a Promise.

async-await-example.js 
function getData() {

    return Promise.resolve(
        "Student data"
    );
}


async function loadData() {

    try {

        const data =
            await getData();

        console.log(data);

    } catch (error) {

        console.error(error);

    }
}


loadData();
Remember: await pauses the execution of the surrounding async function until the Promise settles. It does not freeze the entire Node.js process.
09 · Evolution

Callback → Promise → async/await

These are different approaches for structuring asynchronous operations. Modern Node.js code commonly uses Promises and async/await.

01

Callbacks

Functions are passed as callbacks and invoked when an operation completes.

02

Promises

Represent future success or failure and can be composed using then(), catch() and finally().

03

async / await

Provides a more sequential-looking syntax over Promise-based asynchronous operations.

10 · Timers

Timers in Node.js

Timers schedule callbacks. They do not guarantee that the callback executes at an exact wall-clock moment.

setTimeout()

Schedules a callback after at least the specified delay, subject to event-loop scheduling. 

setTimeout(() => {
    console.log("Done");
}, 1000);

setInterval()

Repeatedly schedules a callback at approximately the requested interval until cleared. 

setInterval(() => {
    console.log("Tick");
}, 1000);

setImmediate()

Schedules a callback for a later phase of the Node.js event loop. 

setImmediate(() => {
    console.log("Immediate");
});
Interview point: A timer delay is not a promise of exact execution time. The callback runs when the event loop reaches the appropriate scheduling point and the call stack is available.
11 · Node-Specific Scheduling

process.nextTick()

Node.js provides process.nextTick() for scheduling a callback to run after the current operation completes but before the event loop continues to later phases.

nexttick-example.js 
console.log("Start");

process.nextTick(() => {
    console.log("nextTick");
});

console.log("End");
Typical output: Start → End → nextTick

Excessive recursive use of nextTick can prevent the event loop from reaching other scheduled work, so it should be used carefully.
12 · Reliability

Error Handling in Async Code

Correct asynchronous error handling is essential in production Node.js applications.

✓ try / catch with await

try {

    const data =
        await getData();

} catch (error) {

    console.error(error);

}

✓ Promise catch()

getData()
    .then(data => {
        console.log(data);
    })
    .catch(error => {
        console.error(error);
    });
Common mistake: Forgetting to handle a rejected Promise can lead to unhandled rejection problems. Always decide how failures should be handled at the appropriate application boundary.

Real-World Example

14 · Interview Preparation

Node.js Async Interview Questions

What is asynchronous programming? +
It is a programming model where an operation can begin and complete later, allowing other work to proceed instead of waiting synchronously for the operation to finish.
What is the event loop? +
The event loop coordinates JavaScript execution with asynchronous callbacks and other scheduled work, allowing Node.js to handle many I/O operations without blocking the JavaScript execution thread for each one.
What is a callback? +
A callback is a function passed to another function so it can be invoked later, often after an asynchronous operation completes.
What is a Promise? +
A Promise represents the eventual completion or failure of an asynchronous operation.
What does async mean? +
An async function always returns a Promise and allows await to be used inside the function body.
What does await do? +
await waits for a Promise to settle within an async function. It suspends that async function's continuation while allowing the Node.js process to handle other work.
Does await block Node.js? +
No. await suspends the async function's continuation; it does not freeze the entire Node.js process.
Why is asynchronous programming important in Node.js? +
Node.js applications frequently perform I/O operations. Asynchronous APIs allow the application to continue handling other work instead of waiting synchronously for every I/O operation.
