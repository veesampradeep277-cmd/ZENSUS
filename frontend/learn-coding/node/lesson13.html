02 • Core Concept

What Is Authentication?

Authentication is the process of verifying who a user is.

For example, when you log into a website using an email and password, the server checks whether those credentials belong to a valid account.

Simple Question Authentication answers: "Who are you?"
👤

Identity

The user claims an identity, usually through an email, username, or other identifier.

🔑

Credentials

The user proves their identity using a password, token, passkey, or another authentication factor.

✅

Verification

The server verifies the provided credentials.

03 • Access Control

Authentication vs Authorization

These two terms are closely related but mean different things.

🔐

Authentication

Determines who the user is.


Example: "This is user Asha."

🛡️

Authorization

Determines what the authenticated user is allowed to do.


Example: "Asha is an administrator and can delete users."

Easy way to remember Authentication = Who are you? Authorization = What are you allowed to do?

05 • Password Security

Why Passwords Must Be Protected

Imagine a database contains:

❌ Unsafe database 
{
  "email": "asha@example.com",
  "password": "Asha123"
}

If an attacker gains access to the database, the actual password is immediately exposed.

Instead, applications should store a password hash.

✓ Safer representation 
{
  "email": "asha@example.com",
  "password": "$2b$12$..."
}
Never do this Never store passwords directly in MongoDB, PostgreSQL, files, or JavaScript variables as plain text.
06 • Password Hashing

Hashing with bcrypt

A password hash is produced by a one-way password hashing function. The purpose is to make recovering the original password from the stored value computationally difficult.

In Node.js applications, bcrypt is a commonly taught password-hashing library.

07 • Token Authentication

What Is JWT?

JWT stands for JSON Web Token.

A JWT is a compact token format that can carry claims between parties. It is commonly used in web applications as part of token-based authentication.

Important Security Concept A JWT is generally signed, not automatically encrypted. Its payload should not contain sensitive secrets merely because it is inside a JWT.

A simplified JWT looks like:

JWT Example Structure
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9 . eyJzdWIiOiIxMjMiLCJyb2xlIjoiYWRtaW4ifQ . SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c

08 • JWT Anatomy

Header, Payload & Signature

①

Header

Contains information such as the token type and signing algorithm.

②

Payload

Contains claims such as user ID, role, issuer, or expiration.

③

Signature

Helps verify that the token was signed with the expected secret or key.

Example Payload

JWT payload 
{
  "sub": "665ab123...",
  "role": "admin",
  "iat": 1720000000,
  "exp": 1720003600
}

Common claims include:

Claim Meaning
sub Subject, often the user identifier.
iat Issued-at time.
exp Expiration time.
iss Issuer.
aud Audience.

Protect JWT secrets Never commit your production JWT secret into a public Git repository. Store secrets using environment variables or an appropriate secret management system.
11 • Verification

Verifying a JWT

When a client accesses a protected API, the server needs to verify the token before allowing the request to continue.

verify-token.js 
const jwt = require("jsonwebtoken");

try {
  const decoded = jwt.verify(
    token,
    process.env.JWT_SECRET
  );

  console.log(decoded);

} catch (error) {
  console.log("Invalid or expired token");
}

Verification checks the token against the expected signing key and validates relevant registered claims such as expiration.

12 • Middleware

Authentication Middleware

Instead of repeating JWT verification inside every protected route, create reusable middleware.

middleware/auth.js 
const jwt = require("jsonwebtoken");

function authenticateToken(req, res, next) {

  const authHeader =
    req.headers.authorization;

  if (!authHeader) {
    return res.status(401).json({
      message: "Authentication required"
    });
  }

  const token =
    authHeader.split(" ")[1];

  if (!token) {
    return res.status(401).json({
      message: "Token missing"
    });
  }

  try {

    const decoded =
      jwt.verify(
        token,
        process.env.JWT_SECRET
      );

    req.user = decoded;

    next();

  } catch (error) {

    return res.status(401).json({
      message: "Invalid or expired token"
    });

  }
}

module.exports = authenticateToken;

Authorization Header

HTTP Request 
Authorization: Bearer YOUR_JWT_TOKEN
What does Bearer mean? The client is presenting a token as the credential used to access the protected resource.

14 • Token Storage

Cookies, Tokens & Security

After authentication, an application needs a way to maintain authenticated state between requests.

One common approach is to use cookies.

Important Cookie Flags

🔒

HttpOnly

Prevents JavaScript running in the browser from directly reading the cookie.

🛡

Secure

Sends the cookie over HTTPS connections.

🌐

SameSite

Controls how cookies are sent in cross-site contexts.

Example Cookie

Express 
res.cookie("token", token, {
  httpOnly: true,
  secure: true,
  sameSite: "lax",
  maxAge: 15 * 60 * 1000
});
HTTPS matters The Secure cookie flag is intended for secure HTTPS transport. Local development setups may require different configuration.
15 • Authentication Models

Sessions vs JWT

Feature Session-based JWT-based
State Session state is typically maintained server-side. Token carries signed claims.
Client Usually receives a session identifier. Receives/presents a token.
Revocation Can be straightforward by invalidating server session. Often requires additional design such as short expiry, rotation, or a revocation strategy.
Scaling May require shared session storage in distributed systems. Can reduce server-side session state for access tokens, but introduces other security and lifecycle concerns.
Use case Traditional web applications. APIs and distributed applications can use tokens.
Important JWT is not automatically "more secure" than sessions. Security depends on how either mechanism is designed and implemented.

17 • Threat Awareness

Common Web Security Attacks

XSS

Cross-Site Scripting

An attacker attempts to inject executable content into a web page that other users may load.

Defense

Proper output encoding, safe rendering, input validation, Content Security Policy, and secure framework practices.

CSRF

Cross-Site Request Forgery

A malicious site attempts to cause a user's browser to perform an unwanted authenticated action.

Defense

SameSite cookies, CSRF tokens where appropriate, origin checks, and correct application design.

Brute Force

Password Guessing

An attacker repeatedly tries credentials against an authentication endpoint.

Defense

Rate limiting, strong password policies, account protection, monitoring, and MFA where appropriate.

Injection

Malicious Input

Specially crafted input attempts to manipulate a database query or command.

Defense

Use safe query APIs, validation, least privilege, and avoid constructing commands or queries unsafely from strings.

Credential Theft

Stolen Credentials

Passwords, tokens, or session identifiers may be stolen through phishing, malware, unsafe storage, or application vulnerabilities.

Defense

HTTPS, secure cookies, short token lifetimes where appropriate, MFA, secure storage, and careful logging.

Data Exposure

Excessive API Data

An API may accidentally return passwords, internal fields, secrets, or unnecessary private information.

Defense

Explicit response fields, DTOs/serializers, schema controls, and careful API design.

19 • Abuse Prevention

Rate Limiting

Rate limiting restricts how frequently a client can call an endpoint during a given period.

It is especially useful for sensitive endpoints such as:

  • Login
  • Password reset
  • OTP verification
  • Account creation
  • Expensive API operations

Example Package

Terminal 
npm install express-rate-limit
server.js 
const rateLimit =
  require("express-rate-limit");

const loginLimiter =
  rateLimit({
    windowMs: 15 * 60 * 1000,
    limit: 10,
    message: {
      message: "Too many login attempts"
    }
  });

app.use(
  "/api/login",
  loginLimiter
);

Authentication Middleware

middleware/auth.js 
const jwt = require("jsonwebtoken");

function authenticateToken(req, res, next) {

  const authHeader =
    req.headers.authorization;

  if (!authHeader) {
    return res.status(401).json({
      message: "Authentication required"
    });
  }

  const [scheme, token] =
    authHeader.split(" ");

  if (scheme !== "Bearer" || !token) {
    return res.status(401).json({
      message: "Invalid authorization header"
    });
  }

  try {

    const decoded =
      jwt.verify(
        token,
        process.env.JWT_SECRET
      );

    req.user = decoded;

    next();

  } catch (error) {

    return res.status(401).json({
      message: "Invalid or expired token"
    });

  }
}

module.exports =
  authenticateToken;

Complete Server

server.js 
require("dotenv").config();

const express = require("express");
const mongoose = require("mongoose");
const bcrypt = require("bcrypt");
const jwt = require("jsonwebtoken");
const helmet = require("helmet");
const rateLimit =
  require("express-rate-limit");

const User = require("./models/User");

const authenticateToken =
  require("./middleware/auth");

const app = express();

/* =========================
   GLOBAL MIDDLEWARE
========================= */

app.use(helmet());
app.use(express.json());

/* =========================
   DATABASE
========================= */

mongoose
  .connect(process.env.MONGODB_URI)
  .then(() => {
    console.log("MongoDB connected");
  })
  .catch((error) => {
    console.error(
      "MongoDB connection failed:",
      error
    );
  });

/* =========================
   LOGIN RATE LIMIT
========================= */

const loginLimiter =
  rateLimit({
    windowMs: 15 * 60 * 1000,
    limit: 10,
    message: {
      message: "Too many login attempts"
    }
  });

/* =========================
   REGISTER
========================= */

app.post(
  "/api/register",
  async (req, res) => {

    try {

      const {
        name,
        email,
        password
      } = req.body;

      if (
        !name ||
        !email ||
        !password
      ) {
        return res.status(400).json({
          message:
            "Name, email and password are required"
        });
      }

      if (password.length < 8) {
        return res.status(400).json({
          message:
            "Password must contain at least 8 characters"
        });
      }

      const existingUser =
        await User.findOne({ email });

      if (existingUser) {
        return res.status(409).json({
          message: "User already exists"
        });
      }

      const hashedPassword =
        await bcrypt.hash(
          password,
          12
        );

      const user =
        await User.create({
          name,
          email,
          password: hashedPassword
        });

      res.status(201).json({
        message:
          "Registration successful",
        user: {
          id: user._id,
          name: user.name,
          email: user.email,
          role: user.role
        }
      });

    } catch (error) {

      res.status(500).json({
        message:
          "Registration failed"
      });

    }

  }
);

/* =========================
   LOGIN
========================= */

app.post(
  "/api/login",
  loginLimiter,
  async (req, res) => {

    try {

      const {
        email,
        password
      } = req.body;

      if (!email || !password) {
        return res.status(400).json({
          message:
            "Email and password are required"
        });
      }

      const user =
        await User.findOne({ email });

      if (!user) {
        return res.status(401).json({
          message:
            "Invalid credentials"
        });
      }

      const passwordMatch =
        await bcrypt.compare(
          password,
          user.password
        );

      if (!passwordMatch) {
        return res.status(401).json({
          message:
            "Invalid credentials"
        });
      }

      const token =
        jwt.sign(
          {
            sub: user._id.toString(),
            role: user.role
          },
          process.env.JWT_SECRET,
          {
            expiresIn: "15m"
          }
        );

      res.status(200).json({
        message:
          "Login successful",
        token
      });

    } catch (error) {

      res.status(500).json({
        message:
          "Login failed"
      });

    }

  }
);

/* =========================
   PROTECTED PROFILE
========================= */

app.get(
  "/api/profile",
  authenticateToken,
  async (req, res) => {

    try {

      const user =
        await User.findById(
          req.user.sub
        ).select(
          "-password"
        );

      if (!user) {
        return res.status(404).json({
          message:
            "User not found"
        });
      }

      res.status(200).json({
        user
      });

    } catch (error) {

      res.status(500).json({
        message:
          "Failed to load profile"
      });

    }

  }
);

/* =========================
   ADMIN AUTHORIZATION
========================= */

app.get(
  "/api/admin",
  authenticateToken,
  async (req, res) => {

    if (req.user.role !== "admin") {
      return res.status(403).json({
        message:
          "Admin access required"
      });
    }

    res.json({
      message:
        "Welcome to the admin area"
    });

  }
);

/* =========================
   SERVER
========================= */

app.listen(
  3000,
  () => {
    console.log(
      "Server running on port 3000"
    );
  }
);

24 • Debugging

Common Authentication Mistakes

❌ Storing Plain Passwords

Never save the original password in the database.

❌ Putting Password in JWT

JWT payloads should not contain passwords or unnecessary secrets.

❌ Never Expiring Tokens

Consider appropriate expiration and token lifecycle strategies.

❌ Trusting req.body

Client input is untrusted and must be validated.

❌ Checking Authentication Only

A logged-in user may still not have permission for a particular resource.

❌ Hard-Coded JWT Secret

Keep production secrets outside the source code.

❌ Returning Passwords

Explicitly exclude password fields from API responses.

❌ No Rate Limiting

Login endpoints can become targets for automated guessing.
