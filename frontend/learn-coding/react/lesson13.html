APIs & Data Fetching

Learn how React applications communicate with backend servers, request data, send data, handle asynchronous operations, manage loading/error/success states, and securely work with APIs.

01. What is an API?

API stands for Application Programming Interface. It provides a defined way for one software system to communicate with another.

In a web application, the frontend commonly communicates with a backend through HTTP requests.

REAL-WORLD API FLOW
React UI User interaction
→
HTTP Request GET / POST...
→
Backend API Server
→
Database Data
→
JSON Response Data returned
→
React UI Render
Simple mental model:

React does not directly "talk to the database" in a normal architecture. React talks to an API. The backend decides how to access and protect the database.

02. REST APIs

REST stands for Representational State Transfer. A REST-style API commonly represents resources through URLs and uses HTTP methods to describe operations on those resources.

Example Resource

/api/students

A particular student could be represented as: 

/api/students/42
RESOURCE-BASED API
/students collection
→
GET read students
→
POST create student

/students/42 single resource
→

→

→

04. GET Request

GET is commonly used to retrieve data. 

fetch("https://api.example.com/students");

GET with React

import { useEffect, useState } from "react";

function Students(){

    const [students, setStudents] =
        useState([]);

    useEffect(() => {

        fetch("/api/students")
            .then(response => response.json())
            .then(data => {
                setStudents(data);
            });

    }, []);

    return (
        <div>
            {students.map(student => (
                <p key={student.id}>
                    {student.name}
                </p>
            ))}
        </div>
    );
}

The previous lesson introduced useEffect(). Here it becomes practical: the Effect can synchronize the component with remote data.

05. POST Request

POST is commonly used to send data to a server to create a new resource. 

fetch("/api/students", {

    method: "POST",

    headers: {
        "Content-Type":
            "application/json"
    },

    body: JSON.stringify({
        name: "Pradeep",
        course: "CSE"
    })

});
Important:

JavaScript objects are not automatically transmitted as JSON. Use JSON.stringify() when sending a JSON request body, and use response.json() to parse a JSON response.

06. PUT Request

PUT is commonly used when the client intends to replace the representation of a resource. 

fetch("/api/students/42", {

    method: "PUT",

    headers: {
        "Content-Type":
            "application/json"
    },

    body: JSON.stringify({

        name: "Pradeep",
        course: "CSE",
        year: 3

    })

});
PUT vs PATCH:

Exact server semantics depend on the API design, but PUT is commonly used for a complete replacement while PATCH is used for a partial modification.

07. PATCH Request

PATCH is commonly used when only part of a resource needs to change. 

fetch("/api/students/42", {

    method: "PATCH",

    headers: {
        "Content-Type":
            "application/json"
    },

    body: JSON.stringify({

        year: 3

    })

});

Only the specified field is being requested for modification. The exact behavior is determined by the backend API.

08. DELETE Request

DELETE is used to request removal of a resource. 

fetch("/api/students/42", {

    method: "DELETE"

});

09. fetch()

The browser provides the Fetch API for making HTTP requests. 

const response =
    await fetch("/api/students");

const data =
    await response.json();

Very Important: HTTP Errors

A common beginner mistake is assuming that fetch() rejects for every HTTP error. By default, a response such as 404 or 500 still produces a Response object. Your code should check response.ok. 

const response =
    await fetch("/api/students");

if(!response.ok){

    throw new Error(
        `HTTP error: ${response.status}`
    );

}

const data =
    await response.json();
Professional pattern:

Request → check response.ok → parse response → update state.

11. Async / Await

Network requests take time. JavaScript uses asynchronous APIs so the browser can continue handling other work while the request is pending. 

async function loadStudents(){

    const response =
        await fetch("/api/students");

    if(!response.ok){

        throw new Error(
            "Request failed"
        );

    }

    const data =
        await response.json();

    return data;
}

Try / Catch / Finally

async function loadStudents(){

    try{

        const response =
            await fetch("/api/students");

        if(!response.ok){
            throw new Error(
                "Failed to load students"
            );
        }

        const data =
            await response.json();

        return data;

    }catch(error){

        console.error(error);

    }finally{

        console.log("Request finished");

    }

}
Async mental model:

Start request → Wait → Receive response → Validate → Parse JSON → Update React state.

Object → JSON

JSON → JavaScript

const object =

13. Loading, Error & Success States

A professional data-fetching UI should not display only the final data. Users need feedback while the request is happening and when something goes wrong.

⏳

Loading

The request is currently in progress.

❌

Error

The request failed or the response was not usable.

✓

Success

The request completed and usable data is available.

React State Model

const [data, setData] =
    useState([]);

const [loading, setLoading] =
    useState(true);

const [error, setError] =
    useState(null);

Complete Example

useEffect(() => {

    async function loadData(){

        try{

            setLoading(true);
            setError(null);

            const response =
                await fetch("/api/students");

            if(!response.ok){
                throw new Error(
                    "Failed to fetch data"
                );
            }

            const result =
                await response.json();

            setData(result);

        }catch(error){

            setError(error.message);

        }finally{

            setLoading(false);

        }

    }

    loadData();

}, []);

HTTP headers carry additional information about a request or response.

Content-Type

Authorization

17. POST Requests in React

POST requests are commonly triggered by user actions such as submitting a form. 

async function createStudent(student){

    const response =
        await fetch("/api/students", {

            method: "POST",

            headers: {
                "Content-Type":
                    "application/json"
            },

            body:
                JSON.stringify(student)

        });

    if(!response.ok){

        throw new Error(
            "Failed to create student"
        );

    }

    return response.json();
}

Using It from a Form

async function handleSubmit(event){

    event.preventDefault();

    try{

        const created =
            await createStudent({
                name,
                course
            });

        console.log(
            "Created:",
            created
        );

    }catch(error){

        console.error(error);

    }

}
Professional architecture:

Form → validate → event handler → API request → response → update state → UI feedback.

18. API Authentication Basics

Authentication answers: "Who are you?"

Authorization answers: "What are you allowed to do?"

Authentication

Verifies the identity of a user or client.

Examples include login credentials, sessions, access tokens and identity-provider systems.

Authorization

Determines whether an authenticated user has permission to perform an action.

Example: a normal student should not automatically have admin permissions.

Bearer Token Example

const response =
    await fetch("/api/profile", {

        headers: {

            Authorization:
                `Bearer ${token}`

        }

    });
Important:

Authentication is primarily enforced by the backend. Hiding a button in React does not prevent a malicious client from sending a request directly to the API.

19. Environment Variables

Environment variables can be used to configure applications differently across development, testing and production.

Example

const API_URL =
    import.meta.env.VITE_API_URL;

Example Environment File

VITE_API_URL=https://api.example.com
CRITICAL SECURITY RULE

Frontend environment variables are not automatically secret. If a value is bundled into a browser application, users can generally inspect it.

Therefore, never put private database passwords, private API secrets, server master keys, or other credentials that must remain confidential into frontend code.

SAFE ARCHITECTURE
React public client
→
Backend private logic
→
Secret server-side only

20. API Security Basics

Frontend developers must understand the security boundary between browser code and server code.

🔐 HTTPS

Use HTTPS in production so network communication is encrypted in transit.

🛡️ Server Validation

Never trust data simply because it came from your React application. Validate it on the server.

🔑 Protect Secrets

Keep private API keys and credentials on trusted server infrastructure.

👤 Authorization

Check permissions on the backend for every protected operation.

📦 Validate Responses

Do not blindly assume an API always returns the expected structure.

🚦 Rate Limiting

Backend services can limit excessive requests to reduce abuse and protect resources.

What NOT to Do

// ❌ Do NOT expose private secrets

const SECRET_KEY =
    "my-super-private-server-key";

Better Architecture

// React

fetch("/api/ai", {
    method: "POST",

    body: JSON.stringify({
        prompt
    })
});

The backend can then communicate with the protected third-party service using its private credentials.

Golden rule:

Anything shipped to the browser should be considered observable by the user. Frontend code is not a secure place for secrets.

21. Complete React Data-Fetching Pattern

Here is a reusable foundation for many React applications. 

import {
    useEffect,
    useState
} from "react";

function Students(){

    const [students, setStudents] =
        useState([]);

    const [loading, setLoading] =
        useState(true);

    const [error, setError] =
        useState(null);


    useEffect(() => {

        async function loadStudents(){

            try{

                setLoading(true);
                setError(null);

                const response =
                    await fetch(
                        "/api/students"
                    );

                if(!response.ok){

                    throw new Error(
                        `HTTP ${response.status}`
                    );

                }

                const data =
                    await response.json();

                setStudents(data);

            }catch(error){

                setError(
                    error.message
                );

            }finally{

                setLoading(false);

            }

        }

        loadStudents();

    }, []);


    if(loading){

        return <p>
            Loading students...
        </p>;

    }


    if(error){

        return <p>
            Error: {error}
        </p>;

    }


    return (

        <div>

            <h2>
                Students
            </h2>

            {students.map(student => (

                <article
                    key={student.id}
                >

                    <h3>
                        {student.name}
                    </h3>

                    <p>
                        {student.course}
                    </p>

                </article>

            ))}

        </div>

    );
}

22. Common API Mistakes

❌ Forgetting response.ok

A 404 or 500 response does not automatically make fetch reject. Check the response status.

❌ Forgetting response.json()

The Response object is not the parsed data. Parse the response body when it contains JSON.

❌ No loading state

Users need feedback while network operations are pending.

❌ No error state

Networks fail. Servers fail. APIs change. Your UI must handle failure.

❌ Hardcoding secrets

Never assume a frontend variable is secret just because it came from an environment file.

❌ Fetching on every render

Incorrect Effect dependencies can create repeated requests or loops.

❌ Ignoring stale requests

When parameters change quickly, consider cancellation and race conditions so older responses do not incorrectly overwrite newer data.

❌ Trusting frontend validation

Client validation improves user experience but server-side validation is still required.
