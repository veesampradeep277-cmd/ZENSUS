useRef() & DOM References

Learn how React refs connect components to DOM elements, store mutable values without re-rendering, access previous values, control timers, measure elements, and expose DOM APIs safely.

1. What is useRef()?

A persistent container for a value that survives renders.

useRef() is a React Hook that lets you create a mutable reference object whose value persists for the lifetime of a component instance.

Core idea:
useRef() gives you an object with a single property: current.
Basic Syntax
import { useRef } from "react";

const myRef = useRef(initialValue);

// Read
myRef.current;

// Update
myRef.current = newValue;

Unlike state, changing ref.current does not cause React to render the component again.

2. The useRef Mental Model

Understand refs as persistent containers.

Render Component runs
→
useRef() Persistent object
→
current Mutable value
→
No Re-render UI stays stable
Important: The ref object itself remains the same between renders. Its current property can change.

3. Ref Objects

What exactly does useRef() return?

Ref Object
const countRef = useRef(0);

console.log(countRef);

// { current: 0 }

countRef.current++;

console.log(countRef.current);

// 1

Initial Value

The value passed to useRef() becomes the initial value of current.

Persistent Identity

React keeps the same ref object between renders.

Mutable

You can modify current without creating a new ref.

No Automatic Render

Changing current does not trigger a component re-render.

4. Accessing DOM Elements

The most common use of refs.

React normally manages the DOM for you. Sometimes, however, you need to directly access a DOM element—for example, to focus an input, measure an element, scroll to a position, or control browser APIs.

Accessing an Input
import { useRef } from "react";

function App() {

    const inputRef = useRef(null);

    function focusInput() {
        inputRef.current.focus();
    }

    return (
        <>
            <input ref={inputRef} />

            <button onClick={focusInput}>
                Focus
            </button>
        </>
    );
}
Flow: React renders the input → ref is attached to the DOM node → inputRef.current points to that node → JavaScript can call DOM APIs.

6. Storing Mutable Values

Refs are useful when a value must persist but does not need to update the UI.

A ref can store values such as IDs, DOM nodes, timers, external objects, or other mutable information.

Persistent Mutable Value
const renderCount = useRef(0);

renderCount.current++;

console.log(
    "Render count:",
    renderCount.current
);
Do not use a ref simply because it is easier than state. If the value affects what the user sees, state is usually the appropriate choice.

7. useRef vs State

One of the most important distinctions in React.

Feature useState useRef
Stores value Yes Yes
Persists between renders Yes Yes
Changing value triggers render? Yes No
Designed for UI data? Yes Usually no
Can access DOM? Not directly Yes
Mutable container? No — state should be updated through setter Yes — current is mutable
Rule of thumb:

If changing the value should update the screen → use state.
If the value should persist but changing it should NOT update the screen → consider ref.

9. Previous Values

Refs can remember a value from an earlier render.

A common pattern is storing the previous value in a ref and updating the ref after the component has rendered.

Previous Value Pattern
const previousValue = useRef();

useEffect(() => {
    previousValue.current = value;
}, [value]);

console.log(
    "Previous:",
    previousValue.current
);
Concept:

Current render → read previous ref → UI renders → effect runs → ref stores current value → next render can read it as previous.

10. Timer References

Store timer IDs without putting them into UI state.

setInterval with useRef
const timerRef = useRef(null);

function startTimer() {

    timerRef.current = setInterval(() => {
        console.log("Running...");
    }, 1000);

}

function stopTimer() {

    clearInterval(timerRef.current);
    timerRef.current = null;

}
A timer ID is an excellent ref candidate because the ID needs to survive renders, but changing it does not need to update the UI.

11. DOM Measurements

Refs can access browser layout information.

Sometimes an application needs the dimensions or position of an element. A ref can point to the DOM element, after which browser measurement APIs can be used.

Measuring an Element
const boxRef = useRef(null);

function measureBox() {

    const rect =
        boxRef.current.getBoundingClientRect();

    console.log(rect.width);
    console.log(rect.height);
    console.log(rect.top);
    console.log(rect.left);

}

Real-world uses: tooltips, popovers, dropdown positioning, drag-and-drop, scroll-based interfaces, responsive visual components, and custom editors.

12. Avoiding Unnecessary Re-renders

Refs can store information that should not drive the UI.

Imagine an application receives hundreds of events. You might want to remember some internal information without causing the component to render every time.

Example
const lastMousePosition = useRef({
    x: 0,
    y: 0
});

function handleMouseMove(event) {

    lastMousePosition.current = {
        x: event.clientX,
        y: event.clientY
    };

}
This does NOT mean refs are a general-purpose replacement for state. If the mouse position needs to appear in the UI, state may be required.

13. Forwarding Refs

Allowing a parent to interact with a child DOM element.

Sometimes a parent component needs access to a DOM element rendered inside a child component.

Modern React Ref Prop Pattern
function TextInput({ ref }) {

    return (
        <input
            ref={ref}
            placeholder="Enter text"
        />
    );

}

function App() {

    const inputRef =
        useRef(null);

    return (
        <>

            <TextInput ref={inputRef} />

            <button
                onClick={() =>
                    inputRef.current?.focus()
                }
            >
                Focus Child Input
            </button>

        </>
    );

}
React version note:
In modern React, refs can be passed as a prop to function components. Older React code commonly uses forwardRef() for this pattern.
Traditional forwardRef Pattern
const TextInput =
    forwardRef(function TextInput(props, ref) {

        return (
            <input ref={ref} />
        );

    });

14. Common useRef() Mistakes

Knowing when NOT to use a ref is just as important.

Mistake 1 — Expecting a re-render 
const count = useRef(0);

count.current++;

// UI does not automatically update.
Mistake 2 — Using refs for normal UI state

If the user sees the value and the screen must update when it changes, state is generally the correct tool.

Mistake 3 — Reading DOM refs too early

A DOM ref is populated after React commits the element to the DOM. Do not assume ref.current points to a DOM node during the initial render.

Mistake 4 — Forgetting nullability 
// Unsafe if the element does not exist
inputRef.current.focus();

// Safer when null is possible
inputRef.current?.focus();
Mistake 5 — Mutating the DOM unnecessarily

React should remain the primary owner of the UI. Use refs for imperative operations that React cannot naturally express.

Mistake 6 — Reading or writing refs during rendering

Avoid using ref mutations as part of the component's rendering logic. Refs are primarily for event handlers, Effects, and imperative interactions.

15. When Should You Use useRef()?

A practical decision guide.

Need UI to update?

Use useState().

Need DOM access?

Use useRef().

Need a timer ID?

A ref is usually appropriate.

Need previous value?

A ref + effect can store it.

Need dimensions?

Use a DOM ref and measurement APIs.

Need shared state?

Consider state, reducer, context, or another state solution.

16. Complete Real-World Example

Search box that automatically receives focus.

SearchBox.jsx
import { useEffect, useRef } from "react";

function SearchBox() {

    const searchRef =
        useRef(null);

    useEffect(() => {

        searchRef.current?.focus();

    }, []);

    return (
        <div>

            <h2>Search ZENSUS</h2>

            <input
                ref={searchRef}
                placeholder="Search lessons..."
            />

        </div>
    );
}

export default SearchBox;
This is a realistic pattern: after the component mounts, the input automatically receives keyboard focus.
