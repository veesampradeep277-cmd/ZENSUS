Component Communication

How React components exchange information using Props, Callback Functions, Shared State, children, Context, and Events — from simple parent-child communication to scalable application architecture.

🧠 Why Component Communication Matters

React applications are built from components. Real applications rarely contain isolated components. Components need to exchange information, notify one another, share state, and coordinate UI behavior.

1. Parent → Child Communication

The most fundamental communication pattern in React is passing data from a parent component to a child through props.

Parent State
→
Props
→
Child

Example

function App() {
  const username = "Pradeep";

  return <Profile name={username} />;
}

function Profile({ name }) {
  return <h2>Welcome, {name}</h2>;
}

Here, App owns the value and passes it to Profile. The child receives the value through its props.

Important: Props are read-only from the receiving component's point of view. A child should not mutate its props.

2. Props — The Main Communication Channel

Props are values passed from a parent to a child. They can contain strings, numbers, booleans, arrays, objects, functions, React elements, and more. 

function App() {

  const student = {
    name: "Pradeep",
    course: "React"
  };

  return (
    <StudentCard
      name={student.name}
      course={student.course}
      active={true}
    />
  );
}

function StudentCard({ name, course, active }) {

  return (
    <div>
      <h2>{name}</h2>
      <p>Course: {course}</p>
      <p>Status: {active ? "Active" : "Inactive"}</p>
    </div>
  );
}

Props Can Carry Different Types

Function

3. Child → Parent Communication

React does not provide a direct “send state upward” mechanism. Instead, the parent gives the child a function. The child calls that function when something happens.

Parent
↓
Callback Prop
↓
Child
Child Event
→
Callback
→
Parent State Update

Example

function App() {

  const [message, setMessage] = useState("");

  function handleMessage(newMessage) {
    setMessage(newMessage);
  }

  return (
    <>
      <Child onMessage={handleMessage} />
      <p>{message}</p>
    </>
  );
}

function Child({ onMessage }) {

  return (
    <button onClick={() => onMessage("Hello Parent!")}>
      Send Message
    </button>
  );
}
Remember: The child does not directly modify the parent's state. It requests a change by calling a callback provided by the parent.

4. Callback Functions

A callback prop is simply a function passed from one component to another so that the receiving component can notify the component that owns the logic. 

function Parent() {

  function handleDelete(id) {
    console.log("Delete:", id);
  }

  return <Child onDelete={handleDelete} />;
}

function Child({ onDelete }) {

  return (
    <button onClick={() => onDelete(42)}>
      Delete
    </button>
  );
}

Data Can Travel Up Through Arguments

Child Input
→
Callback(value)
→
Parent State

This is why callbacks are often described as a communication bridge. The function travels down as a prop, while information can travel back up when the child calls that function with arguments.

5. Sibling Communication

Two sibling components should generally not try to communicate by directly accessing each other's state. Instead, move the shared state to their closest common parent.

Common Parent
Sibling A
Sibling B

Architecture

function App() {

  const [message, setMessage] = useState("");

  return (
    <>
      <Sender onSend={setMessage} />
      <Receiver message={message} />
    </>
  );
}
Pattern: Sibling A → Common Parent State → Sibling B

6. Shared Parent State

When multiple components need to coordinate around the same piece of information, the common parent can own that state.

Interactive Sibling Communication

Waiting for Component A... 
function App() {

  const [message, setMessage] = useState("");

  return (
    <Parent>
      <Sender onSend={setMessage} />
      <Receiver message={message} />
    </Parent>
  );
}

This is the same fundamental principle as lifting state up. The state belongs to the lowest common ancestor that needs to coordinate it.

7. Communication Through State

State itself is not “sent” between components. Instead, the component that owns state renders children with values derived from that state.

State Owner
→
Render
→
Child Props

When the owner updates its state, React renders again and the new values flow down to the relevant children.

8. The children Prop

React automatically provides content placed between a component's opening and closing tags through the special children prop. 

function Card({ children }) {

  return (
    <div className="card">
      {children}
    </div>
  );
}

function App() {

  return (
    <Card>
      <h2>React Course</h2>
      <p>Learn component communication.</p>
    </Card>
  );
}

Visual Model

Content
→
children
→
Wrapper Component
Key idea: children is useful for composition. The wrapper decides where the supplied content is rendered.

Real-World Uses

Modal

Put arbitrary content inside a reusable modal.

Card

Reuse the same container around different content.

Layout

Build reusable page structures.

Panel

Allow consumers to control panel contents.

9. Context

Context provides a way to make a value available to components deeper in a component tree without manually passing that value through every intermediate component.

Context Provider
Layout
Navbar
Dashboard

A deeply nested component can read the context value when it is within the corresponding provider.

Example

const ThemeContext = createContext(null);

function App() {

  return (
    <ThemeContext.Provider value="dark">
      <Dashboard />
    </ThemeContext.Provider>
  );
}

function Dashboard() {
  return <Toolbar />;
}

function Toolbar() {

  const theme = useContext(ThemeContext);

  return <p>Theme: {theme}</p>;
}

When Context Helps

Theme

Light/dark theme information.

Authentication

Current user information available across a tree.

Language

Application-wide locale or translation configuration.

Settings

Configuration shared by many descendants.

Important: Context is not automatically a replacement for every form of state management. Use it when many components in a tree need access to the same value and prop passing becomes cumbersome.

10. Event Communication

Events are often the trigger that starts communication between components. A user interacts with a child, the child invokes a callback, and the owner updates state.

User Click
→
Child Event
→
Callback
→
State Update
→
Re-render

Example

function Parent() {

  const [count, setCount] = useState(0);

  function increase() {
    setCount(c => c + 1);
  }

  return (
    <>
      <CounterButton onIncrease={increase} />
      <p>Count: {count}</p>
    </>
  );
}

function CounterButton({ onIncrease }) {

  return (
    <button onClick={onIncrease}>
      Increase
    </button>
  );
}
The child owns the interaction, while the parent owns the state.

11. One-Way Data Flow

React follows a one-way data-flow model. Data generally flows from a component that owns it down through props to descendants.

State
↓
Parent
↓
Child
↓
Grandchild

When a child needs to influence state owned higher in the tree, it uses a callback supplied through props.

Child Event
↑
Callback
↑
State Owner

The Complete Mental Model

State Owner → Props Down → User Event → Callback Up → State Update → Re-render → Props Down

This pattern gives React applications predictable data flow. Instead of arbitrary components changing each other's state directly, ownership remains explicit.

15. Practical Example — Shopping Cart

function App() {

  const [cart, setCart] = useState([]);

  function addToCart(product) {
    setCart(currentCart => [
      ...currentCart,
      product
    ]);
  }

  return (
    <>
      <ProductList onAddToCart={addToCart} />
      <Cart items={cart} />
    </>
  );
}

function ProductList({ onAddToCart }) {

  return (
    <ProductCard
      product={{ id: 1, name: "Laptop" }}
      onAddToCart={onAddToCart}
    />
  );
}

function ProductCard({ product, onAddToCart }) {

  return (
    <button onClick={() => onAddToCart(product)}>
      Add {product.name}
    </button>
  );
}

function Cart({ items }) {

  return <p>Items in cart: {items.length}</p>;
}
Communication chain:

↓
ProductList / Parent callback
↓
App updates cart state
↓
Cart receives updated items
↓
React renders the new UI

16. Common Component Communication Mistakes

❌ Mistake 1 — Mutating Props 
props.name = "New Name";

Props should be treated as read-only by the receiving component.

❌ Mistake 2 — Calling a Callback During Render 
<button onClick={handleClick()}>

This invokes the function immediately. Usually you want to pass the function: 

<button onClick={handleClick}>
❌ Mistake 3 — Duplicating Shared State

If two components independently maintain copies of the same concept, those values can become inconsistent.

❌ Mistake 4 — Direct Sibling Access

Sibling components should normally coordinate through their common parent rather than trying to access each other's internal state.

❌ Mistake 5 — Using Context for Everything

Context can reduce prop passing, but excessive Context usage can make dependencies harder to see and can cause broader updates than necessary.

❌ Mistake 6 — Making Everything Global

Keep state local when only one component needs it. Lift it when coordination requires it.

❌ Mistake 7 — Confusing Props With State

Props are inputs received from a parent. State is data managed by a component using React state mechanisms.

17. Communication Decision Guide

Question Use
Does a parent need to give data to a child? Props
Does a child need to notify its parent? Callback prop
Do siblings need synchronized information? Shared state in common parent
Do you want reusable nested content? children
Do many descendants need the same value? Context may help
Only one component needs the state? Keep it local

20. Quick Quiz

1. What is the standard way to pass data from a parent to a child?

Props are the standard parent-to-child communication mechanism.

2. How can a child notify a parent that an event occurred?

The parent passes a callback function and the child invokes it when appropriate.

3. What is a common solution when two siblings need shared state?

Shared state can be lifted to the closest common parent that needs to coordinate it.

4. What does the special children prop represent?

The children prop represents the nested React content supplied to the component.

5. What problem can Context help reduce?

Context can make values available to descendants without manually forwarding them through every intermediate component.

6. Which statement best describes React's typical data-flow model?

React generally uses one-way data flow, with values moving down through props.

7. What should you generally do when a child needs to request a parent-owned state change?

A callback gives the child a controlled way to notify the component that owns the state.
