2. Weather API

An API allows your React application to communicate with an external service.

Request

React sends information such as the city name to the weather service.

Server

The weather provider processes the request and retrieves weather information.

Response

The API returns structured JSON data.

React UI

React reads the response and renders the information. 

// Example request concept

GET https://api.example.com/weather
?city=Vijayawada
&units=metric
&appid=YOUR_API_KEY
Important: Never assume an API response always has the fields you expect. Production applications should validate responses and handle missing data.

11. Environment Variables

API configuration should not be scattered throughout your source code.

Vite example

// .env

VITE_WEATHER_API_KEY=your_api_key_here
// React

const API_KEY =
import.meta.env.VITE_WEATHER_API_KEY;
Security lesson: A Vite variable beginning with VITE_ is exposed to client-side code after the application is built. Therefore, do not treat it as a secret merely because it is stored in .env.

For sensitive production credentials, use a backend/server-side proxy or another architecture where the secret remains on the server.

13. Custom Weather Hook

A custom hook can centralize loading, error and API state. 

function useWeather() {

```
const [weather, setWeather] =
    useState(null);

const [loading, setLoading] =
    useState(false);

const [error, setError] =
    useState(null);

const searchWeather =
    async (city) => {

        setLoading(true);
        setError(null);

        try {

            const result =
                await getWeather(city);

            setWeather(result);

        } catch {

            setError(
                "Weather unavailable"
            );

        } finally {

            setLoading(false);
        }
    };

return {
    weather,
    loading,
    error,
    searchWeather
};
```

}

Now the page does not need to know all the details of the request lifecycle. It simply calls searchWeather().

17. Common Mistakes

❌ Fetching Directly Everywhere

Scattering API calls throughout components makes the application difficult to maintain.

❌ No Loading State

Users cannot tell whether their request is still processing.

❌ No Error State

A failed request can leave the dashboard looking broken or empty.

❌ Trusting API Data

External responses can be missing fields or have unexpected values.

❌ Exposing Secrets

Client-side environment variables are not automatically secret.

❌ Unnecessary Requests

Do not repeatedly call the API for every tiny input change unless that behavior is intentional.

18. Production-Level Improvements

Debouncing

Useful when implementing search-as-you-type functionality.

AbortController

Cancel outdated requests when a newer request replaces them.

Caching

Avoid repeatedly requesting the same city when appropriate.

Geolocation

Allow users to request weather for their current coordinates.

Forecast

Extend the project with multi-day weather predictions.

Accessibility

Use labels, semantic controls, keyboard navigation and readable contrast.

21. Quick Quiz

1. What is the purpose of a weather API?
It provides weather information to an application through HTTP requests.
2. Why do we need a loading state?
Because network requests take time and the UI should communicate that work is in progress.
3. Why should API logic be separated from UI components?
It improves separation of concerns, maintainability and testability.
4. What does response.ok indicate?
It indicates whether the HTTP response has a successful status.
5. Are VITE_ environment variables secret?
No. Vite exposes VITE_ variables to client-side code. Sensitive secrets should remain on a server.
6. What are the major states of an API-driven UI?
Typically idle, loading, success and error.
