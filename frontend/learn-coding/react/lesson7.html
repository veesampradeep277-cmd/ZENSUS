Event Handling

Learn how React listens to user interactions, executes event handlers, works with event objects, controls forms and understands event propagation.

01. Events in React

An event is something that happens in an application because of an action or activity.

Examples include:

  • Clicking a button
  • Typing inside an input
  • Submitting a form
  • Moving the mouse
  • Pressing a keyboard key
  • Entering or leaving an element

👆 Mouse Events

Mouse interactions such as clicking, entering and leaving elements.

⌨️ Keyboard Events

React can respond to keyboard actions such as key presses.

📝 Form Events

Forms use events to react to typing, submission and changes.

🔄 UI Events

Events allow a component to respond dynamically to the user.

Core idea:

An event is the bridge between what the user does and how your React application responds.

02. React Event System

React provides a consistent event-handling model for components. You attach event handlers directly to JSX elements using event props. 

<button onClick={handleClick}>
    Click Me
</button>

React uses camelCase event names such as onClick and onChange.

HTML vs React:

03. onClick

onClick runs a function when an element is clicked. 

function handleClick(){
    console.log("Button clicked");
}

function App(){

    return (
        <button onClick={handleClick}>
            Click Me
        </button>
    );
}

04. onChange

onChange is commonly used with form controls. It allows React to respond when the value of an input changes. 

function App(){

    const [name, setName] = useState("");

    return (
        <input
            value={name}
            onChange={(event) =>
                setName(event.target.value)
            }
        />
    );
}

Typical use cases:
  • Login forms
  • Search boxes
  • Registration forms
  • Filters
  • Live validation

05. onSubmit

The onSubmit event runs when a form is submitted. 

function handleSubmit(event){

    event.preventDefault();

    console.log("Form submitted");
}

<form onSubmit={handleSubmit}>

    <input />

    <button type="submit">
        Submit
    </button>

</form>

Interactive Form

Why use preventDefault()?

Traditional browser form submission can reload or navigate the page. React applications often prevent that default behavior and handle the form using JavaScript.

08. Passing Functions

React expects an event handler function. You normally pass the function reference rather than immediately calling it. 

function handleClick(){
    console.log("Clicked");
}

<button onClick={handleClick}>
    Click
</button>
Common mistake: 
<button onClick={handleClick()}>

This calls the function while React is rendering instead of waiting for the click.

Correct: 
<button onClick={handleClick}>

When you need arguments

function greet(name){
    console.log("Hello", name);
}

<button onClick={() => greet("Pradeep")}>
    Greet
</button>

09. Event Handler Functions

An event handler is a function that contains the logic React should execute when an event occurs. 

function handleLogin(){

    console.log("Login button clicked");

}

function Login(){

    return (
        <button onClick={handleLogin}>
            Login
        </button>
    );
}
Professional habit:

Give handlers meaningful names such as:

  • handleSubmit
  • handleLogin
  • handleChange
  • handleDelete
  • handleKeyDown

11. Synthetic Events

React provides a normalized event interface so event handling can behave consistently across supported environments.

CONCEPTUAL EVENT LAYER
Browser native event
→
React Event normalized interface
→
Your Handler application logic

This means developers can work with React's event API rather than writing browser-specific event handling for every component.

Student takeaway:

You do not need to memorize browser internals to use React events effectively. Focus first on the React event names, handler functions and event object.

12. Arguments in Event Handlers

Sometimes an event handler needs both the event object and your own data. 

function handleDelete(id, event){

    console.log("Deleting:", id);

}

<button
    onClick={(event) =>
        handleDelete(101, event)
    }
>
    Delete
</button>

Another common pattern

function handleUser(id){

    console.log(id);

}

<button
    onClick={() => handleUser(25)}
>
    Open User
</button>
Remember:

Use an arrow function when you need to supply your own arguments.

13. Preventing Default Behavior

Browsers have built-in behaviors for many events. React allows you to prevent those behaviors using event.preventDefault(). 

function handleSubmit(event){

    event.preventDefault();

    // custom React logic

}

Examples

  • Preventing a form from reloading the page
  • Preventing a link from navigating
  • Creating custom interactions
Important distinction:

preventDefault() prevents the browser's default action. It does not stop the event from propagating through the DOM.

14. Event Propagation

Event propagation describes how an event travels through the DOM tree.

THREE-PHASE EVENT MODEL
Capture outer → inner
→
Target actual element
→
Bubble inner → outer

The two major propagation phases students should understand are:

⬇️ Capturing

The event travels from an outer ancestor toward the target.

⬆️ Bubbling

The event travels from the target back through its ancestors.

16. Event Capturing

Capturing happens before the event reaches its target. The event travels from the outer ancestor toward the target.

Remember:

onClickCapture handles the capturing phase. Regular onClick participates in the bubbling phase.

18. Common Event Mistakes

❌ Calling instead of passing 

onClick={handleClick()}

This executes during rendering.

Correct: onClick={handleClick}

❌ Wrong event name 

onclick={handleClick}

React uses camelCase:

onClick

❌ Forgetting event object 

function handleChange(){

    console.log(event.target.value);

}

Pass the event parameter explicitly.

❌ Forgetting preventDefault 

function submit(event){

    // form may perform
    // its default action

}

Use event.preventDefault() when appropriate.

❌ Mutating state inside events 

items.push(newItem);

Use the state setter and immutable updates.

❌ Confusing propagation

Remember that preventing the default browser action and stopping event propagation are different concepts.
