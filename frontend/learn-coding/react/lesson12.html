Component Lifecycle & Effects

Understand how React components are created, updated and removed, how Effects participate in that lifecycle, and why modern React focuses on synchronization rather than old class lifecycle terminology.

01. Component Lifecycle

A React component has a lifetime. It can enter the UI, respond to changes, and eventually leave the UI.

MODERN REACT LIFECYCLE
Mount Component appears
→
Update Props / state change
→
Update More changes
→
Unmount Component removed
PHASE 01

Mounting

The component is added to the UI for the first time.

PHASE 02

Updating

Props or state change, causing React to render the component again.

PHASE 03

Unmounting

The component is removed from the UI and its active Effect synchronizations are cleaned up.

02. Mounting

Mounting happens when React creates a component instance in the render tree and commits its UI to the DOM. 

function Profile(){

    return (
        <div>
            <h2>Pradeep</h2>
        </div>
    );

}
MOUNTING SEQUENCE
Component render
→
React commit
→
DOM UI appears
→
Effect if declared

Mount Effect

useEffect(() => {

    console.log("Effect setup");

}, []);

An empty dependency array means the Effect has no reactive dependencies. For a normally mounted component, its setup happens after the initial commit and its cleanup runs when the component is removed.

03. Updating

A component updates when its state changes, its parent passes different props, or another relevant input causes it to render again. 

const [count, setCount] =
    useState(0);

return (
    <button
        onClick={() =>
            setCount(count + 1)
        }
    >
        {count}
    </button>
);
UPDATE SEQUENCE
User Action click
→
setState() state changes
→
Render new UI calculation
→
Commit DOM update
→
Effect if dependencies changed

04. Unmounting

Unmounting happens when React removes a component from the rendered tree.

For example, conditional rendering can cause a component to disappear. 

{
    showProfile &&
    <Profile />
}

Unmounting is not the same as hiding an element with CSS. If a component remains mounted but is visually hidden, its lifecycle has not ended.

05. Lifecycle in Modern React

Older React tutorials often teach lifecycle methods such as:

  • componentDidMount()
  • componentDidUpdate()
  • componentWillUnmount()

Those methods belong to class components. Modern React primarily uses function components and Hooks.

Older Class Model

componentDidMount()

componentDidUpdate()

componentWillUnmount()

Modern Function Model

useEffect(() => {

    // setup

    return () => {

        // cleanup

    };

}, [dependencies]);
Modern React idea:

Instead of thinking "Which lifecycle method should I put this code in?", think "What external system does this component need to synchronize with, and when should that synchronization change?"

06. Effects and Lifecycle

Effects are connected to the lifecycle, but an Effect is not simply a collection of lifecycle events.

EFFECT + LIFECYCLE
Mount initial commit
→
Effect Setup synchronize
→
Dependency Changes if applicable
→
Cleanup old synchronization
→
New Setup new synchronization
→
Unmount final cleanup
Key distinction:

A component can render many times without an Effect necessarily re-running. Whether an Effect re-runs depends on its dependency array.

07. Cleanup

Cleanup allows an Effect to stop or reverse the external synchronization created by its previous setup. 

useEffect(() => {

    const connection =
        connectToServer();

    return () => {

        connection.disconnect();

    };

}, []);

① Effect setup

Connection is created.

② Component remains active

The connection continues to be synchronized.

③ Dependency changes or component unmounts

The existing synchronization needs to stop.

④ Cleanup

The connection is disconnected.

Typical cleanup operations:
  • clearInterval()
  • clearTimeout()
  • removeEventListener()
  • unsubscribe from subscriptions
  • disconnect WebSockets
  • disconnect external libraries

08. Dependency Changes

Dependencies determine when an Effect's synchronization needs to be re-established.

Effect Behavior
useEffect(fn) Runs after every completed render.
useEffect(fn, []) No reactive dependencies.
useEffect(fn, [roomId]) Runs when roomId changes, in addition to initial setup.

Example

useEffect(() => {

    const connection =
        connect(roomId);

    return () => {

        connection.disconnect();

    };

}, [roomId]);
DEPENDENCY CHANGE
roomId = 101
→
Setup
→
roomId = 202
→
Cleanup
→
New Setup

09. Mount Effects

An Effect with no reactive dependencies is often used when a component needs to establish an external synchronization for its lifetime. 

useEffect(() => {

    const subscription =
        subscribe();

    return () => {

        subscription.unsubscribe();

    };

}, []);
Typical examples:
  • Subscribe when a component becomes active.
  • Register a browser listener.
  • Initialize an external integration.
  • Start an external resource that belongs to the component.
Don't overuse [].

If the Effect actually depends on a changing value, hiding that dependency by using [] can produce stale or incorrect behavior.

10. Update Effects

An Effect with dependencies can synchronize again when those dependencies change. 

useEffect(() => {

    document.title =
        `User ${userId}`;

}, [userId]);

11. Unmount Cleanup

When a component is unmounted, React runs the cleanup for its active Effect. 

useEffect(() => {

    const timer =
        setInterval(
            updateClock,
            1000
        );

    return () => {

        clearInterval(timer);

    };

}, []);

→

Unmount
→

→

12. Strict Mode

React Strict Mode is a development-only tool that helps identify certain problems in React applications. 

import { StrictMode } from "react";

createRoot(
    document.getElementById("root")
).render(

    <StrictMode>
        <App />
    </StrictMode>

);

Development

React may intentionally perform extra setup/cleanup cycles for Effects in development to help reveal code that is not resilient to being started and stopped correctly.

Production

This development-only Strict Mode behavior does not mean your production application continuously mounts and unmounts components in the same way.

Important debugging lesson:

If an Effect appears to run twice while developing with Strict Mode, don't immediately add a flag to suppress the second run. First make the Effect's setup and cleanup correctly mirror each other.

Good synchronization pattern

useEffect(() => {

    const connection =
        createConnection();

    connection.connect();

    return () => {

        connection.disconnect();

    };

}, []);

The cleanup makes the setup reversible, which is exactly what robust Effects need.

13. Effect Synchronization

The most useful modern mental model is synchronization.

SYNCHRONIZE — DON'T MEMORIZE LIFECYCLES
React State roomId = 42
→
Effect setup
→
External System connected to room 42

roomId changes 42 → 99
→
Cleanup disconnect 42
→
New Setup connect 99
Think like this:

"The component is currently synchronized with room 42."

"When roomId becomes 99, stop synchronizing with 42 and start synchronizing with 99."

14. Avoiding Unnecessary Effects

Not every calculation or user interaction requires an Effect.

❌ Unnecessary Effect

const [fullName,
    setFullName] =
    useState("");

useEffect(() => {

    setFullName(
        firstName +
        " " +
        lastName
    );

}, [firstName,lastName]);

✅ Derived Value

const fullName =
    firstName +
    " " +
    lastName;

Another example

// ❌ Don't use an Effect
// for a button click

useEffect(() => {

    saveForm();

}, [submitted]);

If the action happens because the user clicked Submit, the event handler is usually the appropriate place for the action. 

// ✅ Event handler

function handleSubmit(){

    saveForm();

}
Rule:

If the logic is caused by a specific user interaction, start by considering an event handler. If the logic synchronizes with an external system because the component is currently in a particular state, consider an Effect.

15. Common Lifecycle Mistakes

❌ Thinking every render is an update effect

A component can render again without every Effect necessarily needing to re-run. Dependencies determine synchronization.

❌ Forgetting cleanup

Timers, listeners, subscriptions and connections can continue doing work after the synchronization should have ended.

❌ Using empty dependencies incorrectly

Using [] when the Effect reads changing reactive values can result in stale behavior.

❌ Fighting Strict Mode

Don't hide development-only Effect behavior with arbitrary flags. Make setup and cleanup correctly mirror each other.

❌ Treating CSS hiding as unmounting

display:none hides an element but does not necessarily remove the React component from the tree.

❌ Putting event actions into Effects

A button click, form submission or keyboard action often belongs in an event handler rather than an Effect.

❌ Copying old class lifecycle code mentally

Modern React is better understood through rendering, synchronization, dependencies and cleanup.

❌ Assuming cleanup only happens on unmount

Cleanup also happens before an Effect's new setup when its dependencies change.

16. Lifecycle Cheat Sheet

Concept What it means
Mount Component is added to the rendered tree.
Update Component renders again because relevant inputs changed.
Unmount Component is removed from the rendered tree.

Dependency change Old synchronization may need cleanup and a new setup.
Cleanup Stops or reverses the previous synchronization.
