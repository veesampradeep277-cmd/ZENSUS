01. What is useEffect()?

useEffect() is a React Hook used to synchronize a component with something outside React's rendering process.

Examples include browser APIs, network requests, timers, subscriptions, event listeners and third-party libraries. 

import { useEffect } from "react";

useEffect(() => {

    // effect code

});
THE BASIC REACT EFFECT MODEL
Render React calculates UI
→
Commit DOM is updated
→
Effect external synchronization
→
External System browser / API / timer
Important mental model:

Don't think of useEffect() as "code that runs after every render". Think of it as a mechanism for synchronizing React with an external system when its dependencies change.

02. What is a Side Effect?

A side effect is work that interacts with something outside the pure calculation of the component's UI.

Examples

  • Fetching data from an API
  • Starting a timer
  • Adding a browser event listener
  • Changing the document title
  • Connecting to a WebSocket
  • Subscribing to an external data source
  • Controlling a third-party library

Pure rendering vs side effect

function User({ name }){

    // Pure rendering
    return <h1>Hello {name}</h1>;

}

Rendering calculates what the UI should look like. It should not perform unrelated external operations during rendering. 

useEffect(() => {

    document.title =
        "ZENSUS Dashboard";

});

Changing the browser tab title is an external interaction, so an effect can be appropriate.

03. Why Do We Need Effects?

React rendering should remain predictable. Components describe UI from their current props and state.

But applications still need to communicate with systems that React doesn't control.

REACT + EXTERNAL WORLD
React state + props
→
useEffect() synchronization
→
External World API / browser / timer
Think of useEffect as a bridge.

React owns rendering. External systems live outside React. An Effect can synchronize the two.

04. Effect Syntax

Basic form

useEffect(() => {

    // effect logic

}, [dependencies]);

Effect with cleanup

useEffect(() => {

    // setup

    return () => {

        // cleanup

    };

}, [dependencies]);
Remember:

The function passed to useEffect() may optionally return a cleanup function.

05. Dependency Array

The dependency array tells React which reactive values the effect depends on.

No dependency array

useEffect(fn)
The effect runs after every completed render.

Empty array

useEffect(fn, [])
The effect does not re-run because of component re-renders. For a mounted component, this means setup on mount and cleanup on unmount.

Dependencies

useEffect(fn, [id])
The effect re-runs when the dependency changes.

Dependency Array Simulator

No array Every render
[] Mount / cleanup
[userId] When userId changes

06. Empty Dependency Array

An empty dependency array means the effect has no reactive dependencies. 

useEffect(() => {

    console.log(
        "Component mounted"
    );

    return () => {

        console.log(
            "Component unmounted"
        );

    };

}, []);
Important:

Don't interpret [] as a universal "run exactly once" command. It means the effect doesn't depend on changing reactive values. In development, React Strict Mode can intentionally run setup and cleanup an extra time to help detect bugs.

07. Effect with Dependencies

Suppose a component displays information about a selected user. The effect may need to synchronize with that particular user. 

const [userId, setUserId] =
    useState(1);

useEffect(() => {

    fetch(`/api/users/${userId}`);

}, [userId]);
DEPENDENCY CHANGE
userId = 1 initial value
→
Effect runs
→
userId = 2 dependency changed
→
Effect runs again
Key idea:

The effect does not run because "something happened". It re-runs because a dependency used by the effect changed.

08. Effect Without Dependencies

useEffect(() => {

    console.log(
        "Runs after every render"
    );

});

This is valid, but it should be used intentionally. If the effect updates state on every render, it can easily create a render loop.

Danger pattern: 
useEffect(() => {

    setCount(count + 1);

});

Every render runs the effect, the effect updates state, the state causes another render, and the cycle continues.

09. API Requests

Fetching remote data is one of the most common examples of synchronizing a component with an external system. 

useEffect(() => {

    async function loadUser(){

        const response =
            await fetch(
                `/api/users/${userId}`
            );

        const data =
            await response.json();

        setUser(data);

    }

    loadUser();

}, [userId]);

Professional API states

const [status, setStatus] =
    useState("idle");

const [data, setData] =
    useState(null);

const [error, setError] =
    useState(null);

10. Timers

Timers are external browser systems. If an effect starts one, cleanup should normally stop it. 

useEffect(() => {

    const timer =
        setInterval(() => {

            console.log("Tick");

        }, 1000);

    return () => {

        clearInterval(timer);

    };

}, []);

11. Event Listeners

Browser event listeners are another common external system. 

useEffect(() => {

    function handleResize(){

        console.log(
            window.innerWidth
        );

    }

    window.addEventListener(
        "resize",
        handleResize
    );

    return () => {

        window.removeEventListener(
            "resize",
            handleResize
        );

    };

}, []);

Resize Listener Demo

Resize your browser window
Listener waiting...
Why cleanup?

Without removing the listener, a component that repeatedly mounts and unmounts can leave subscriptions behind and cause unnecessary work or stale behavior.

12. Synchronizing with External Systems

This is the most important conceptual purpose of Effects.

Examples of external systems

  • Browser APIs
  • Network connections
  • WebSocket connections
  • Timers
  • Event listeners
  • Media players
  • Map libraries
  • Charts
  • Third-party widgets
SYNCHRONIZATION MODEL
React State source of UI data
→
Effect synchronization logic
→
External System outside React
↺
Cleanup disconnect
Examples:

If a React component controls a video player, an effect can synchronize the player's play/pause state with React state.

If a component subscribes to a WebSocket, an effect can establish the connection and cleanup can close it.

13. Cleanup Functions

Cleanup reverses or disconnects work created by the effect. 

useEffect(() => {

    const connection =
        connect();

    return () => {

        connection.disconnect();

    };

}, []);
⚡

Setup

Start timer, subscribe, connect, add listener or create external resource.

🧹

Cleanup

Stop timer, unsubscribe, disconnect or remove listener.

EFFECT LIFECYCLE
Setup effect starts
→
External System active
→
Dependency Changes or unmount
→
Cleanup old synchronization ends
→
New Setup if effect still applies
Very important:

When dependencies change, React runs the previous cleanup before running the new setup. When the component unmounts, React runs the cleanup for the last setup.

14. Common useEffect() Mistakes

❌ Missing dependency

useEffect(() => {

    fetchUser(userId);

}, []);

If the effect uses a reactive value such as userId, its dependency needs to be considered.

❌ Setting state every render

useEffect(() => {

    setCount(count + 1);

});

This can continuously trigger renders.

❌ Forgetting cleanup

useEffect(() => {

    window.addEventListener(
        "resize",
        handleResize
    );

}, []);

Subscriptions and listeners usually need cleanup.

❌ Using Effect for derived data

const [fullName,setFullName] =
    useState("");

useEffect(() => {

    setFullName(
        first + " " + last
    );

}, [first,last]);

If a value can be calculated directly from existing state/props, you often don't need an Effect.

❌ Effect for simple calculations

useEffect(() => {

    setTotal(price * quantity);

}, [price, quantity]);

A derived value can often simply be: const total = price * quantity;

❌ Ignoring race conditions

If multiple requests can overlap, an older response may arrive after a newer request. Production applications need an appropriate cancellation or stale-result strategy.

❌ Treating useEffect as a lifecycle checklist

Thinking only in terms of "componentDidMount/componentDidUpdate" can hide the more useful concept: synchronization with an external system.

❌ Putting everything inside useEffect

Effects are not a replacement for event handlers, normal calculations, or state management. Use them when synchronization with an external system is actually needed.

15. Infinite Loops

One of the most important problems to understand is an Effect that continuously updates state.

The Render → Effect → State Loop

State Update
causes Render

Render → Effect → setState() → Render → Effect → setState()...

Problem example

function Counter(){

    const [count,setCount] =
        useState(0);

    useEffect(() => {

        setCount(count + 1);

    });

}

Why does it happen?

INFINITE LOOP
Render
→
Effect
→
setState()
↻
Render
Better approach:

Before adding an Effect, ask: "Am I synchronizing with something outside React?"

If the answer is no, you may not need an Effect.

16. Do I Actually Need an Effect?

Effect Decision Framework

Calculating a value from props/state? Usually NO
Responding to a button click? Usually Event Handler
Fetching/synchronizing external data? Often YES
Adding browser subscription? YES
Starting external timer? YES
ZENSUS rule:

Don't ask: "Where can I use useEffect?"

Ask: "What external system am I synchronizing with?"

17. useEffect() Cheat Sheet

Code Meaning
useEffect(fn) Runs after every completed render.
useEffect(fn, []) No reactive dependencies; setup on mount and cleanup on unmount for a mounted component.
useEffect(fn, [id]) Runs after initial setup and when id changes.
return cleanup Stops or reverses the synchronization created by the effect.
