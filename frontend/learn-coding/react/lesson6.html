State & useState()

Learn how React components remember information, respond to user interactions, update their UI, and manage changing data using state.

01. What is State?

State is data that belongs to a React component and can change over time. When state changes, React updates the component's UI so that what the user sees stays synchronized with the latest data.

Simple definition:
State is a component's memory — information that React remembers between renders.

🧠 Component Memory

A normal local variable does not persist reliably across React renders. State does.

🔄 Dynamic UI

When state changes, React renders the component again using the new state.

👆 User Interaction

Buttons, forms, toggles, counters and menus commonly depend on state.

📦 Component-Owned Data

State is generally used for information that can change during the component's lifetime.

Real-world example

Think about a shopping cart. The number of products in the cart changes when the user clicks Add to Cart. That changing number can be represented using state.

02. Props vs State

Props and state are both important React concepts, but they solve different problems.

Feature Props State
Source Passed from parent Managed by component
Can component directly change it? ❌ No ✅ Yes, through setter
Purpose Pass information Store changing information
Example <User name="Pradeep" /> const [count,setCount]
Change causes render? Parent passing new props can cause render State update causes render
Think of it this way:
Props are information a component receives. State is information a component remembers and manages.

03. Why Do We Need State?

Without state, interactive React applications would be extremely difficult to build.

🔢 Counters

Track likes, quantity, score, views and counts.

🌙 Dark Mode

Remember whether the interface is currently light or dark.

📝 Forms

Store values typed into inputs.

📂 Menus

Track whether dropdowns, modals or navigation panels are open.

04. useState()

useState() is a React Hook that lets a functional component create and manage state. 

import { useState } from 'react';

function Counter() {

    const [count, setCount] = useState(0);

    return (
        <button>
            {count}
        </button>
    );
}

The basic structure

const [state, setState] = useState(initialValue);

state

The current value stored by React.

setState

The function used to request a state update.

initialValue

The value used when the component initializes.

useState

React Hook responsible for creating the state variable and setter.

Important: You normally should not directly modify the state variable. Use its setter function.

05. State Declaration

A state variable is commonly declared using array destructuring. 

const [name, setName] = useState("Pradeep");

const [age, setAge] = useState(19);

const [isLoggedIn, setIsLoggedIn] = useState(false);

Why two values?

ARRAY DESTRUCTURING
useState(0) returns two values
→
count current value
+
setCount update function

06. Initial State

The argument passed to useState() becomes the initial state. 

const [count, setCount] = useState(0);

const [name, setName] = useState("Pradeep");

const [loggedIn, setLoggedIn] = useState(false);

const [skills, setSkills] = useState([]);
Initial state is used during initialization. After that, the setter is used to update the state.

07. State Variable

The first value returned by useState() is the state variable. 

const [score, setScore] = useState(0);

Here:

  • score → current state
  • setScore → state update function
  • 0 → initial value

08. State Setter

The setter function tells React that the state should be updated. 

const [count, setCount] = useState(0);

setCount(10);

After the update, React schedules a new render using the updated state.

Never do this: 
count = 10;
Use: 
setCount(10);

09. Updating State

State is updated by calling its setter. 

const [count, setCount] = useState(0);

// Increase
setCount(count + 1);

// Set a specific value
setCount(100);

// Decrease
setCount(count - 1);

10. State Re-rendering

One of the most important ideas in React is that updating state causes the component to render again.

WATCH A STATE UPDATE
Current State
0
Render #1

Every time you click the button, the state value changes. React then renders the component again so the displayed value matches the new state.

User clicks
→
setCount()
→
React schedules update
→
UI updates
Important: Re-rendering does not mean React destroys the entire page and creates everything again. React compares the result and updates the necessary DOM parts.

12. Functional State Updates

When the next state depends on the previous state, the recommended approach is the functional updater. 

setCount(prevCount => prevCount + 1);

Here prevCount represents the previous state value.

FUNCTIONAL UPDATE
Previous State 5
→
Function prev + 1
→
New State 6

Why use it?

It is especially useful when several updates depend on the previous value. 

// Better when each update depends on previous state

setCount(prev => prev + 1);
setCount(prev => prev + 1);
setCount(prev => prev + 1);
Rule: If your new state depends on the old state, prefer the functional updater.

13. Multiple State Variables

A component can have multiple independent state variables. 

const [name, setName] = useState("");

const [age, setAge] = useState(19);

const [isOnline, setIsOnline] = useState(true);

name

Stores a person's name.

age

Stores the person's age.

isOnline

Stores whether the user is online.

Independent Updates

Each setter updates its corresponding state.

You can also group related values inside an object, but separate state variables are often easier when the values change independently.

14. State Immutability

React state should be treated as immutable. Instead of modifying an existing object or array directly, create a new value and pass that new value to the setter.

❌ Mutate Existing Array

items.push("React");

Changes the existing array.

→

✅ Create New Array

setItems([
 ...items,
 "React"
]);

Creates a new array.

Object example

// ❌ Avoid
user.age = 20;

// ✅ Better
setUser({
    ...user,
    age: 20
});

Array example

// ❌ Avoid
skills.push("React");

// ✅ Better
setSkills([...skills, "React"]);
Core idea: Don't modify the existing state value. Create a new value and give it to React through the setter.

15. Common State Mistakes

❌ Mistake 1 — Direct mutation

count = count + 1;

Use setCount(count + 1) instead.

❌ Mistake 2 — Mutating arrays

items.push("New Item");

Use setItems([...items, "New Item"]).

❌ Mistake 3 — Mutating objects

user.name = "Alex";

Use the spread operator and setter.

❌ Mistake 4 — Ignoring previous state

setCount(count + 1);

This is fine for many simple situations, but when multiple updates depend on previous state, use: 

setCount(prev => prev + 1);

❌ Mistake 5 — Calling hooks conditionally

// ❌ Don't do this

if (loggedIn) {
    const [name, setName] = useState("");
}

Hooks should be called at the top level of the component.

❌ Mistake 6 — Expecting immediate state changes

setCount(count + 1);

console.log(count);

The logged value may still represent the current render's state. State updates are scheduled rather than behaving like ordinary variable assignments.

16. Complete Counter Example

Here is a small but complete React component using state. 

import { useState } from "react";

function Counter() {

    const [count, setCount] = useState(0);

    function increase() {
        setCount(prev => prev + 1);
    }

    return (
        <div>

            <h2>Count: {count}</h2>

            <button onClick={increase}>
                Increase
            </button>

        </div>
    );
}

export default Counter;
What happens?

1. Component starts with count = 0.
2. User clicks the button.
3. setCount() requests an update.
4. React renders the component again.
5. The UI displays the new count.
