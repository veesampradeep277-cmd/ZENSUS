Redux Toolkit

Learn how professional React applications manage complex global state using Redux Toolkit — from Store, Actions and Reducers to createSlice(), async operations and Redux DevTools.

01 — FOUNDATION

What is Redux?

Redux is a predictable state management library commonly used with React. It provides a centralized place called the store where application state can be maintained and updated through a predictable flow.

🗄️

Centralized State

Important application state can live in one centralized store instead of being scattered across many components.

🔄

Predictable Updates

State changes happen through actions and reducers following a defined data flow.

🐛

Debuggable

Redux DevTools can help developers inspect dispatched actions and state changes.

02 — WHY STATE MANAGEMENT?

Why Do We Need State Management?

Small applications can often manage state using React's useState() and useContext(). As applications grow, many components may need access to the same data.

03 — CORE ARCHITECTURE

Redux Architecture

Redux follows a unidirectional data flow. Components dispatch actions, reducers calculate the next state, and the store contains the resulting state.

04 — STORE

Store

The Redux store is the centralized container that holds the application's Redux state.

store.js import { configureStore } from '@reduxjs/toolkit'; export const store = configureStore({ reducer: { counter: counterReducer } });

Think of the Store Like a Central Database

Components don't directly modify the Redux state. They dispatch actions, and reducers determine how state should change.

05 — ACTIONS

Actions

An action is an object describing something that happened. It normally contains a type and may contain additional information in payload.

const action = { type: 'counter/increment' }; const actionWithPayload = { type: 'counter/add', payload: 5 };

The action does not directly modify the state. It describes the event that the reducer should handle.

06 — REDUCERS

Reducers

A reducer determines how the state should change when an action is dispatched.

Store Save state
UI Re-render
function counterReducer(state, action) { if (action.type === 'counter/increment') { return state + 1; } return state; }

08 — READING STATE

Selectors

A selector is a function used to retrieve specific data from Redux state. In React Redux, useSelector() allows a component to read state from the store.

const count = useSelector( state => state.counter.value );

Why Selectors?

Instead of giving every component access to the entire state object, a component can select only the data it needs.

10 — STORE CONFIGURATION

configureStore()

configureStore() creates the Redux store and provides useful development defaults.

import { configureStore } from '@reduxjs/toolkit'; export const store = configureStore({ reducer: { counter: counterReducer } });

Multiple Slices

const store = configureStore({ reducer: { auth: authReducer, courses: coursesReducer, cart: cartReducer, notifications: notificationReducer } });
11 — CREATE SLICE

createSlice()

One of Redux Toolkit's most important APIs is createSlice(). It combines a slice name, initial state and reducer functions. It also generates action creators automatically.

createSlice() Transformation

Initial State value: 0
+
Reducers increment()
+
createSlice() Redux Logic
→
Actions Generated
import { createSlice } from '@reduxjs/toolkit'; const counterSlice = createSlice({ name: 'counter', initialState: { value: 0 }, reducers: { increment: state => { state.value += 1; }, decrement: state => { state.value -= 1; }, incrementByAmount: (state, action) => { state.value += action.payload; } } }); export const { increment, decrement, incrementByAmount } = counterSlice.actions; export default counterSlice.reducer;

Important Concept

Redux Toolkit uses Immer internally, which allows reducer logic to use mutating-looking syntax while producing immutable state updates safely.

12 — ASYNC REDUX

createAsyncThunk()

Applications frequently need to fetch data from APIs. Redux Toolkit provides createAsyncThunk() for common asynchronous workflows.

export const fetchUsers = createAsyncThunk( 'users/fetchUsers', async () => { const response = await fetch( '/api/users' ); return response.json(); } );

Async State

{ data: [], status: 'idle', error: null }

A common application pattern is to represent states such as idle, loading, succeeded and failed.

16 — DEBUGGING

Common Redux Mistakes

❌ Direct State Mutation

Do not manually mutate Redux state outside the supported reducer logic.

❌ Huge Global State

Not every piece of local component state needs to be placed in Redux.

❌ Poor Slice Organization

Group related state and reducers into meaningful feature slices.

❌ Ignoring Async States

API-driven state should account for loading, success and failure states.
