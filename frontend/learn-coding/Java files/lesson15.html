What is an Exception?

Understanding the basic concept

Definition

An exception is an unwanted or unexpected event that occurs during program execution and disrupts the normal flow of the program.

For example, imagine a program trying to divide one number by zero:

Example.java 
public class Example {

    public static void main(String[] args) {

        int a = 10;
        int b = 0;

        int result = a / b;

        System.out.println(result);
    }
}
Output
Exception in thread "main" java.lang.ArithmeticException: / by zero

Real-World Analogy

Think of an exception like a sudden roadblock. Your journey is going normally, but an unexpected problem blocks the road. Exception handling provides another safe route instead of stopping the entire journey.

try-catch

The foundation of exception handling

The try block contains code that may produce an exception. The catch block handles that exception.

TryCatchExample.java 
public class TryCatchExample {

    public static void main(String[] args) {

        try {

            int result = 10 / 0;

            System.out.println(result);

        } catch (ArithmeticException e) {

            System.out.println(
                "Cannot divide by zero"
            );
        }

        System.out.println("Program continues...");
    }
}
Output
Cannot divide by zero Program continues...

Multiple catch Blocks

Handling different exceptions

A single try block can have multiple catch blocks. Each catch block handles a different type of exception.

MultipleCatch.java 
public class MultipleCatch {

    public static void main(String[] args) {

        try {

            int[] numbers = {10, 20, 30};

            System.out.println(numbers[5]);

        } catch (ArithmeticException e) {

            System.out.println(
                "Arithmetic problem"
            );

        } catch (ArrayIndexOutOfBoundsException e) {

            System.out.println(
                "Invalid array index"
            );
        }
    }
}

Remember

When multiple catch blocks are used, more specific exceptions should generally be placed before broader exception types.

10

finally Block

Code that should execute after handling

The finally block is used for cleanup operations. It normally executes whether an exception occurs or not.

FinallyExample.java 
public class FinallyExample {

    public static void main(String[] args) {

        try {

            int result = 10 / 2;

            System.out.println(result);

        } catch (ArithmeticException e) {

            System.out.println("Error occurred");

        } finally {

            System.out.println(
                "Finally block executed"
            );
        }
    }
}

Typical Use

finally is commonly associated with cleanup, such as closing resources when appropriate.

throw Keyword

Explicitly creating an exception

The throw keyword is used to explicitly throw an exception from your program.

ThrowExample.java 
public class ThrowExample {

    public static void main(String[] args) {

        int age = 15;

        if (age < 18) {

            throw new IllegalArgumentException(
                "Age must be 18 or above"
            );
        }

        System.out.println("Eligible");

    }
}

throws Keyword

Declaring possible exceptions

The throws keyword is used in a method declaration to indicate that a method may throw one or more exceptions.

ThrowsExample.java 
import java.io.*;

public class ThrowsExample {

    static void readFile()
            throws IOException {

        FileReader file =
            new FileReader("data.txt");

        file.close();
    }

    public static void main(String[] args)
            throws IOException {

        readFile();
    }
}

Nested try Blocks

Handling exceptions inside another try

NestedTry.java 
public class NestedTry {

    public static void main(String[] args) {

        try {

            System.out.println("Outer try");

            try {

                int result = 10 / 0;

                System.out.println(result);

            } catch (ArithmeticException e) {

                System.out.println(
                    "Inner exception handled"
                );
            }

        } catch (Exception e) {

            System.out.println(
                "Outer exception handled"
            );
        }
    }
}

Exception Propagation

How exceptions move through method calls

If an exception is not handled in the current method, it can propagate back through the calling methods until a suitable handler is found.

methodC()
→
Exception
→
methodB()
→
methodA()
Propagation.java 
public class Propagation {

    static void methodC() {

        int result = 10 / 0;
    }

    static void methodB() {

        methodC();
    }

    static void methodA() {

        methodB();
    }

    public static void main(String[] args) {

        try {

            methodA();

        } catch (ArithmeticException e) {

            System.out.println(
                "Exception handled in main"
            );
        }
    }
}

Custom Exceptions

Creating your own exception class

Java allows programmers to create custom exceptions when built-in exceptions do not clearly represent an application's business rule.

CustomException.java 
class AgeException extends Exception {

    public AgeException(String message) {

        super(message);
    }
}


public class CustomException {

    static void checkAge(int age)
            throws AgeException {

        if (age < 18) {

            throw new AgeException(
                "Age must be 18 or above"
            );
        }

        System.out.println(
            "You are eligible."
        );
    }


    public static void main(String[] args) {

        try {

            checkAge(16);

        } catch (AgeException e) {

            System.out.println(
                e.getMessage()
            );
        }
    }
}
Output
Age must be 18 or above

Exception Handling Best Practices

Write professional Java code

Catch Specific Exceptions

Prefer specific exception types instead of catching everything with Exception.

Do Not Ignore Exceptions

Avoid empty catch blocks that hide important problems.

Use Meaningful Messages

Error messages should help developers understand the problem.

Keep try Blocks Small

Put only the risky code inside the try block.

Use finally for Cleanup

Use appropriate cleanup mechanisms for resources.

Do Not Overuse Exceptions

Exceptions should represent exceptional situations, not ordinary control flow.

18

Common Mistakes

Mistakes beginners frequently make

!

Catching Exception everywhere

Catching a very broad exception can hide the actual problem.

!

Empty catch block

Never silently ignore an exception without a valid reason.

!

Wrong catch order

A broader exception should not appear before a more specific subclass in incompatible catch structures.

!

Using exceptions for normal flow

Exceptions should not replace ordinary conditional logic.

Interview Questions

Questions you should be able to answer

1. What is exception handling? +

Exception handling is a mechanism used to handle runtime problems so that the normal flow of the application can be controlled.

2. Difference between throw and throws? +

throw explicitly creates and throws an exception, while throws declares exceptions that a method may pass to its caller.

3. What is finally? +

finally is a block normally used for code that should execute after the try/catch processing, especially cleanup-related work.

4. Checked vs unchecked exception? +

Checked exceptions are checked by the compiler, while unchecked exceptions are RuntimeException subclasses and occur during runtime.

5. Can we create custom exceptions? +

Yes. A programmer can create a custom exception by extending an appropriate exception class such as Exception or RuntimeException.
