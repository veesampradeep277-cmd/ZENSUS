Why do we need file handling?

Variables and arrays live in memory. Files allow information to survive the program.

🧠

Without files

Data stored in normal variables exists during program execution. When the program terminates, that in-memory data is normally lost.

📁

With files

Data can be stored in persistent storage and loaded again when the program runs in the future.

Core idea: RAM is temporary working space. A file provides persistent storage that your program can access through C's standard I/O library.

Real-world examples

Roll number, name and marks can be stored permanently.

🧾

Applications can keep records of operations and events.

fopen() and fclose()

The two operations you must understand first.

Opening a file

#include <stdio.h>

int main(void)
{
    FILE *fp = fopen("data.txt", "r");

    if (fp == NULL)
    {
        perror("fopen");
        return 1;
    }

    printf("File opened successfully.\n");

    fclose(fp);

    return 0;
}

Understanding the statement

1
FILE *fp

Declares a pointer that will refer to the C library's stream object associated with the opened file.

2
fopen("data.txt", "r")

Requests the C library to open data.txt in read mode.

3
if (fp == NULL)

Opening may fail because the file does not exist, permission is denied, the path is invalid, or another system error occurs.

4
fclose(fp)

Closes the stream and releases associated resources. Check its return value when close errors matter.

Golden rule: Never assume fopen() succeeded. Always check for NULL.
🎛️

File Opening Modes

Choosing the correct mode is one of the most important file-handling skills.

Mode Purpose Must exist? Truncates? Write position
r Read Yes No Beginning
w Write No Yes Beginning
a Append No No End
r+ Read + Write Yes No Beginning initially
w+ Read + Write No Yes Beginning
a+ Read + Append No No Writes at end
Danger: Opening an existing file with "w" truncates its previous contents.

Binary variants

Add b when binary mode is desired:

rb

Read binary data.

wb

Write binary data.

ab

Append binary data.

Similarly, rb+, wb+ and ab+ provide update modes.

Character I/O — fputc() and fgetc()

Read and write one character at a time.

fputc()

fputc() writes one character to a stream. 

FILE *fp = fopen("message.txt", "w");

if (fp == NULL)
{
    perror("fopen");
    return 1;
}

fputc('H', fp);
fputc('i', fp);
fputc('\n', fp);

fclose(fp);

fgetc()

fgetc() reads one character from a stream. Its return type is int, not char. 

FILE *fp = fopen("message.txt", "r");

if (fp == NULL)
{
    perror("fopen");
    return 1;
}

int ch;

while ((ch = fgetc(fp)) != EOF)
{
    putchar(ch);
}

fclose(fp);
Why int? fgetc() must be able to represent every possible unsigned-char value plus the special EOF value. A plain char may not be able to represent EOF distinctly.

Line and String I/O

Use fgets() and fputs() when working with text lines.

fgets()

fgets(buffer, size, fp) reads at most size - 1 characters and adds a null terminator when successful. If a newline is encountered within the limit, the newline is retained. 

char line[100];

if (fgets(line, sizeof line, fp) != NULL)
{
    printf("%s", line);
}

fputs()

fputs() writes a string to a stream. It does not automatically add a newline. 

fputs("Welcome to ZENSUS\n", fp);
Remember: fgets() can keep the newline, while fputs() does not create one for you.

Safe line-reading pattern

char name[50];

printf("Enter name: ");

if (fgets(name, sizeof name, stdin) != NULL)
{
    /* name may contain '\n' */
}

EOF — End of File

One of the most common interview and beginner traps.

EOF is a special integer value returned by input functions such as fgetc() when the end of input is reached or an input failure occurs.

EOF is not a character stored inside your file. It is an indicator returned by an input operation.

Correct reading loop

int ch;

while ((ch = fgetc(fp)) != EOF)
{
    putchar(ch);
}

❌ The common wrong pattern

while (!feof(fp))
{
    ch = fgetc(fp);
    putchar(ch);
}

Why is this wrong? The EOF indicator generally becomes set after an input operation attempts to read past the available input. Therefore, testing feof() before performing the read does not tell you that the next read will succeed.

Animated EOF sequence

1. fgetc() → 'A'
2. fgetc() → 'B'
3. fgetc() → 'C'
4. fgetc() → EOF
✓ Loop condition fails → stop safely

feof(), ferror(), clearerr()

feof()

Tests whether the stream's EOF indicator is set.

ferror()

Tests whether the stream's error indicator is set.

clearerr()

Clears the EOF and error indicators for the stream.

perror()

FILE *fp = fopen("missing.txt", "r");

if (fp == NULL)
{
    perror("Unable to open file");
    return 1;
}

perror() prints the supplied message followed by a description corresponding to the current errno.

Random Access — fseek(), ftell(), rewind()

Move the stream position instead of always reading from the beginning.

File position indicator

A stream has a current file position. As data is read or written, this position changes.

Interactive file cursor

Current position: 0

fseek()

fseek(fp, 0, SEEK_SET);  /* beginning */

fseek(fp, 5, SEEK_SET);  /* 5 positions from beginning */

fseek(fp, 2, SEEK_CUR);  /* move relative to current position */

fseek(fp, 0, SEEK_END);  /* move toward end */

ftell()

long position = ftell(fp);

if (position == -1L)
{
    perror("ftell");
}

rewind()

rewind(fp);
Remember: rewind() moves the stream back to the beginning and clears its EOF and error indicators.

Random access flow

OPEN fopen()
→
POSITION fseek()
→
CHECK ftell()
→
READ / WRITE operation
Portability note: File-position operations have special rules for text streams. Do not assume every value returned by ftell() is a universally meaningful byte offset for arbitrary text files. Binary streams are generally the clearer setting for byte-oriented positioning.

Text Files vs Binary Files

Two important ways to represent persistent data.

📄 Text File

Data is represented as characters according to a textual format. Humans can usually inspect it with a text editor.

1 0 1 , P r a

💾 Binary File

Data is handled as bytes. It can be compact and efficient, but its representation may not be human-readable.

0x65 0x00 0x2A 0x7F 0x19
Feature Text Binary
Human-readable Usually yes Usually no
Typical functions fprintf, fgets, fputs fread, fwrite
Easy manual editing Yes No
Portability Often easier when format is well-defined Depends heavily on defined binary format

fwrite()

struct Student
{
    int roll;
    char name[50];
    float cgpa;
};

struct Student s = {101, "Pradeep", 8.63f};

FILE *fp = fopen("students.dat", "wb");

if (fp == NULL)
{
    perror("fopen");
    return 1;
}

if (fwrite(&s, sizeof s, 1, fp) != 1)
{
    perror("fwrite");
}

fclose(fp);

fread()

struct Student s;

FILE *fp = fopen("students.dat", "rb");

if (fp == NULL)
{
    perror("fopen");
    return 1;
}

if (fread(&s, sizeof s, 1, fp) == 1)
{
    printf("%d %s %.2f\n",
           s.roll,
           s.name,
           s.cgpa);
}

fclose(fp);
Important binary-file warning: Writing a raw C structure with fwrite() is convenient, but it does not automatically create a portable file format. Structure padding, alignment, integer/float representation, byte order and pointer members can differ between systems.

Return value of fread / fwrite

Both functions return the number of elements successfully transferred — not simply the number of bytes. 

size_t count = fread(array,
                     sizeof array[0],
                     10,
                     fp);

if (count != 10)
{
    /* inspect feof() or ferror() */
}

Useful File Functions

Know these for practical programming and interviews.

rewind()

Move to the beginning and clear stream indicators.

remove()

Requests removal of a file. Returns zero on success.

rename()

Changes a file name/path as supported by the system.

fflush()

Flushes buffered output for an output/update stream.

ferror()

Checks the stream error indicator.

clearerr()

Clears EOF and error indicators.

Do not use: fflush(stdin) as a standard C technique for clearing keyboard input. Its behavior for an input stream is not defined by the C standard.

Complete Text File Example

Create → write → close → reopen → read → close.

CREATE w
→
WRITE fprintf()
→
CLOSE fclose()
→
READ fgets() 
#include <stdio.h>

int main(void)
{
    FILE *fp;
    char line[100];

    /* Write */
    fp = fopen("notes.txt", "w");

    if (fp == NULL)
    {
        perror("notes.txt");
        return 1;
    }

    fprintf(fp, "C File Handling\n");
    fprintf(fp, "ZENSUS Learning Platform\n");
    fprintf(fp, "Lesson 13\n");

    if (fclose(fp) != 0)
    {
        perror("fclose");
        return 1;
    }

    /* Read */
    fp = fopen("notes.txt", "r");

    if (fp == NULL)
    {
        perror("notes.txt");
        return 1;
    }

    while (fgets(line, sizeof line, fp) != NULL)
    {
        printf("%s", line);
    }

    if (ferror(fp))
    {
        perror("Reading failed");
    }

    fclose(fp);

    return 0;
}

Updating and Deleting Text Records

Why temporary files are commonly used.

Text records may have variable lengths. Directly replacing one record can be difficult if the replacement changes the record's size. A common approach is:

1
Open the original file for reading.
2
Open a temporary file for writing.
3
Read records from the original file one by one.
4
Write unchanged or modified records into the temporary file.
5
Close both streams.
6
Replace the original using remove() and rename(), checking every operation.
This rewrite strategy is especially common for simple educational record systems. Production databases normally provide much stronger indexing, transactions and concurrency mechanisms.

Useful when the filename should be supplied by the user.

Common Mistakes

These mistakes appear frequently in exams, interviews and projects.

❌ Forgetting NULL check

Calling file functions after fopen() failed can lead to undefined behavior. Always check the returned pointer.

❌ Using "w" accidentally

w can truncate an existing file. Use a mode that matches your intention.

❌ Storing fgetc() in char

Use int so that every unsigned-char value and EOF can be represented.

❌ while(!feof(fp))

EOF is detected through the attempted read. Put the input operation directly in the loop condition.

❌ Forgetting fclose()

Properly close streams and check close errors where appropriate.

❌ Ignoring return values

File operations can fail. Check return values for important operations.

❌ scanf("%s") for names with spaces

%s stops at whitespace. Use fgets() when spaces should be accepted.

❌ Raw struct portability assumption

fwrite() of a struct does not automatically create a portable binary format.

🛡️

Professional File-Handling Practices

Write code that survives real inputs and real failures.

1. Check every important operation

Check fopen(), fread(), fwrite(), fseek(), fclose() and other relevant return values.

2. Bound your input

Use fixed buffer sizes carefully and avoid overflowing arrays.

3. Validate file contents

Never assume a file contains valid data just because it exists.

4. Choose a clear format

For interoperable data, define the text or binary format explicitly.

5. Handle errors separately

Distinguish EOF from actual stream errors using feof() and ferror().

6. Close resources

Close streams when finished, especially in long-running programs.

Challenge: Count lines, words and characters

#include <stdio.h>
#include <ctype.h>

int main(void)
{
    FILE *fp = fopen("input.txt", "r");

    if (fp == NULL)
    {
        perror("input.txt");
        return 1;
    }

    int ch;
    long characters = 0;
    long lines = 0;
    long words = 0;
    int in_word = 0;

    while ((ch = fgetc(fp)) != EOF)
    {
        characters++;

        if (ch == '\n')
            lines++;

        if (isspace((unsigned char)ch))
        {
            in_word = 0;
        }
        else if (!in_word)
        {
            in_word = 1;
            words++;
        }
    }

    if (ferror(fp))
    {
        perror("Read error");
        fclose(fp);
        return 1;
    }

    printf("Characters: %ld\n", characters);
    printf("Words:      %ld\n", words);
    printf("Lines:      %ld\n", lines);

    fclose(fp);

    return 0;
}

Complete C Program

#include <stdio.h>

#define FILE_NAME "students.txt"

struct Student
{
    int roll;
    char name[50];
    float cgpa;
};

void addStudent(void)
{
    struct Student s;

    FILE *fp = fopen(FILE_NAME, "a");

    if (fp == NULL)
    {
        perror(FILE_NAME);
        return;
    }

    printf("\nEnter roll number: ");
    scanf("%d", &s.roll);

    printf("Enter name: ");
    scanf(" %49[^\n]", s.name);

    printf("Enter CGPA: ");
    scanf("%f", &s.cgpa);

    if (fprintf(fp, "%d|%s|%.2f\n",
                s.roll,
                s.name,
                s.cgpa) < 0)
    {
        perror("Write error");
    }
    else
    {
        printf("Student saved successfully.\n");
    }

    if (fclose(fp) != 0)
    {
        perror("Close error");
    }
}

void viewStudents(void)
{
    FILE *fp = fopen(FILE_NAME, "r");

    if (fp == NULL)
    {
        perror(FILE_NAME);
        return;
    }

    int roll;
    char name[50];
    float cgpa;

    printf("\n---------------------------------------\n");
    printf("%-8s %-20s %-8s\n",
           "Roll", "Name", "CGPA");
    printf("---------------------------------------\n");

    while (fscanf(fp, "%d|%49[^|]|%f",
                  &roll,
                  name,
                  &cgpa) == 3)
    {
        printf("%-8d %-20s %-8.2f\n",
               roll, name, cgpa);
    }

    if (ferror(fp))
    {
        perror("Read error");
    }

    fclose(fp);
}

void searchStudent(void)
{
    FILE *fp = fopen(FILE_NAME, "r");

    if (fp == NULL)
    {
        perror(FILE_NAME);
        return;
    }

    int target;
    int roll;
    char name[50];
    float cgpa;
    int found = 0;

    printf("\nEnter roll number: ");
    scanf("%d", &target);

    while (fscanf(fp, "%d|%49[^|]|%f",
                  &roll,
                  name,
                  &cgpa) == 3)
    {
        if (roll == target)
        {
            printf("\nStudent Found!\n");
            printf("Roll : %d\n", roll);
            printf("Name : %s\n", name);
            printf("CGPA : %.2f\n", cgpa);

            found = 1;
            break;
        }
    }

    if (!found)
    {
        printf("\nStudent not found.\n");
    }

    fclose(fp);
}

int main(void)
{
    int choice;

    do
    {
        printf("\n====================================\n");
        printf("     STUDENT FILE MANAGEMENT\n");
        printf("====================================\n");

        printf("1. Add Student\n");
        printf("2. View Students\n");
        printf("3. Search Student\n");
        printf("4. Add Another Student\n");
        printf("5. Exit\n");

        printf("\nEnter choice: ");
        scanf("%d", &choice);

        switch (choice)
        {
            case 1:
                addStudent();
                break;

            case 2:
                viewStudents();
                break;

            case 3:
                searchStudent();
                break;

            case 4:
                addStudent();
                break;

            case 5:
                printf("Goodbye!\n");
                break;

            default:
                printf("Invalid choice.\n");
        }

    } while (choice != 5);

    return 0;
}

Time Complexity Perspective

File I/O performance depends on the storage system, but algorithmic patterns still matter.

Operation Typical algorithmic view Important note
Sequential read O(n) Must inspect data sequentially when searching without an index.
Search in text records O(n) Each record may need to be examined.
Append Conceptually near end-position access Actual cost depends on buffering and filesystem/storage.
Random access Positioning can be efficient Actual physical cost depends on the underlying storage.
