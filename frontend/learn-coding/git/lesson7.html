Merging Branches & Resolving Conflicts

Learn how to combine changes from different Git branches, understand fast-forward and three-way merges, identify merge conflicts, and safely resolve them.

1. What Is Merging?

Git merge is the process of combining the changes from one branch into another branch.

For example, suppose you created a branch called feature-login and finished building the login feature.

You can merge that work into main.

main Existing code
+
feature-login New feature
→
main Combined code
Simple definition: Merging combines the history and changes of one branch into another branch.

2. Why Do We Merge Branches?

Branches are useful because developers can work independently. But eventually, completed work needs to become part of the main project.

Feature Development

Build a new feature separately and merge it when ready.

Bug Fixes

Fix a problem on a separate branch and bring the fix into the main code.

Team Collaboration

Different developers can work on different branches and later combine their work.

3. Fast-Forward Merge

A fast-forward merge happens when the target branch has not received any new commits after the feature branch was created.

Before the merge

main: A ─── B
feature: A ─── B ─── C ─── D

Here, main is still pointing to B while the feature branch has moved forward to D.

Commands

git switch main
git merge feature

Git can simply move the main pointer forward.

main: A ─── B ─── C ─── D
No additional merge commit is required in a typical fast-forward merge.

4. Three-Way Merge

A three-way merge is needed when both branches have new commits after they diverged.

For example:

A ─── B ───┬──
           main: C
           feature: D

Git compares the common ancestor with the changes made on both branches.

If Git can combine the changes automatically, it creates a merge result.

Key idea: Fast-forward means one branch simply moves forward. Three-way merging combines two lines of development that have diverged.

5. The git merge Command

The basic syntax is: 

git merge branch-name

The important rule is:

Switch to the branch that should receive the changes, then run git merge.

Example: 

git switch main
git merge feature-login

This means:

  • Move to main.
  • Take the changes from feature-login.
  • Combine them into main.

6. Complete Branch Merge Workflow

Here is a simple feature development workflow.

1 main
→
2 Create branch
→
3 Develop
→
4 Commit
→
5 Merge

Example

git switch main

git switch -c feature-login

# Make changes

git add .

git commit -m "Add login feature"

git switch main

git merge feature-login
Result: The login feature is now part of the main branch.

7. What Is a Merge Conflict?

A merge conflict occurs when Git cannot automatically determine which changes should be kept.

This often happens when two branches modify the same part of the same file differently.

Simple example

Suppose main contains: 

Welcome to ZENSUS

A feature branch changes it to: 

Welcome to ZENSUS Learning Platform

Meanwhile, main changes the same line to: 

Welcome to ZENSUS Academy

Git cannot safely decide which sentence the developer wants. A conflict occurs.

A merge conflict is not a Git failure.
It means Git needs a human to decide how the conflicting changes should be combined.

8. Understanding Conflict Markers

When Git finds a conflict, it places special markers inside the affected file.

Example Conflict
<<<<<<<  HEAD Welcome to ZENSUS Academy ======= Welcome to ZENSUS Learning Platform >>>>>>>  feature-login

The markers tell you which changes came from where.

Marker Meaning
<<<<<<< HEAD Current branch's version
======= Separates the two versions
>>>>>>> feature-login Incoming branch's version
You must remove the conflict markers before completing the merge.

9. How to Resolve a Merge Conflict

Resolving a conflict means manually deciding what the final file should contain.

Step 1 — Identify the conflicted file

git status

Git will show files that have conflicts.

Step 2 — Open the file

Open the conflicted file in your editor.

Step 3 — Choose the correct content

You can:

  • Keep the current branch's version.
  • Keep the incoming branch's version.
  • Combine both changes manually.

Example resolved version

Welcome to ZENSUS Learning Platform

The conflict markers should now be removed.

Step 4 — Stage the resolved file

git add filename

Step 5 — Complete the merge

git commit

Depending on the merge situation and Git version, Git may prepare a merge commit message for you.

Basic conflict flow:

Merge → Conflict → Edit → Remove markers → git add → Complete merge

10. Aborting a Merge

Sometimes you start a merge and realize that you need to stop and return to the state before the merge.

If the merge is still in progress, you can use: 

git merge --abort
Use this when you want to cancel the current merge instead of resolving it.

After aborting, you can review your branches and decide how to proceed.

11. Checking the Repository After a Conflict

After resolving conflicts, use: 

git status

If all conflicts have been resolved and the affected files have been staged, Git should no longer report them as unmerged.

You can then complete the merge. 

git add .
git commit

View the resulting history

git log --oneline --graph --all

12. Fast-Forward vs Three-Way Merge

Feature Fast-Forward Three-Way
Branches diverged? No Yes
New merge commit? Usually no Usually yes
History Linear Shows combined history
Conflict possible? Generally no Yes
The important beginner concept is not memorizing the internal algorithm. Understand that Git can merge automatically when changes do not conflict, but it may need your help when different changes affect the same content.

13. Common Merge Mistakes

Mistake 1 — Merging into the wrong branch

Before running merge, check: 

git branch

Make sure the * is next to the branch that should receive the changes.

Mistake 2 — Ignoring a conflict

Do not randomly delete conflict markers. Understand both versions before deciding what the final code should be.

Mistake 3 — Forgetting git add

After resolving a conflict, Git needs to know that the file has been resolved. 

git add filename

Mistake 4 — Accidentally keeping incorrect code

Always test the application after resolving important conflicts.

Mistake 5 — Panicking when Git reports a conflict

Conflicts are a normal part of collaborative development. Read the conflict, understand both changes, choose the correct result, stage it, and complete the merge.

18. Lesson Takeaway

Merging is how Git combines work from different branches. Understanding conflicts is an essential skill for real-world development and team collaboration.

  • git merge branch combines a branch into the current branch.
  • Always switch to the branch that should receive the changes before merging.
  • A fast-forward merge can simply move a branch pointer forward.
  • A three-way merge combines diverged development histories.
  • A merge conflict happens when Git cannot safely decide which conflicting changes to keep.
  • Conflict markers show the competing versions.
  • Resolve the file manually, remove the markers, and test the result.
  • Use git add after resolving conflicts.
  • Use git merge --abort if you need to cancel an in-progress merge.
  • Use git status to understand the current state of a merge.
