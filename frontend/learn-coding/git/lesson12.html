Issues, Projects & GitHub Collaboration

Learn how teams use GitHub Issues to track work, GitHub Projects to organize tasks, and collaboration features to plan, discuss, develop, review, and deliver software together.

1. What Are GitHub Issues?

A GitHub Issue is a place for a repository to track a task, bug, feature request, question, improvement, or other piece of work.

Issues help a team remember what needs to be done and provide a shared place for discussion.

🐛 Bug Reports

Record problems found in the application.

✨ Features

Track new functionality that should be developed.

📝 Tasks

Break project work into manageable pieces.

💡 Ideas

Discuss possible improvements and future work.

❓ Questions

Ask project-related questions and document answers.

📚 Documentation

Track documentation improvements and missing content.

3. Issue Workflow

Report Create issue
→
Plan Assign & label
→
Develop Create branch
→
Review Open PR
→
Close Complete work

An issue can therefore represent the larger piece of work, while a branch and pull request can contain the actual code changes needed to complete it.

4. Labels, Assignees & Milestones

Labels

Labels help categorize issues so developers can quickly understand their type or priority.

Bug

Something is not working as expected.

Feature

New functionality is being requested.

Documentation

Documentation needs to be added or updated.

Assignees

An assignee is a person responsible for working on an issue.

Milestones

A milestone groups related issues and pull requests toward a larger objective, such as a release.

5. What Are GitHub Projects?

GitHub Projects provides a way to organize and visualize repository work.

Teams can use project views to understand what is planned, what is currently being worked on, and what has been completed.

📋 Plan

Organize upcoming work and priorities.

🔄 Track

Follow the current state of tasks.

📊 Visualize

Use project views to understand progress.

Simple idea:

Issues describe the work.
Projects organize the work.
Pull Requests implement and review code changes.

7. GitHub Collaboration

GitHub collaboration combines several tools rather than relying on Git commands alone.

Issues Plan work
→
Branches Isolate changes
→
Pull Requests Review changes
→
Project Track progress

Example

Suppose a team wants to add a student search feature.

  1. Create an issue describing the feature.
  2. Assign the issue to a developer.
  3. Create a feature branch.
  4. Develop and commit the feature.
  5. Push the branch to GitHub.
  6. Open a pull request.
  7. Review the code.
  8. Merge the pull request.
  9. Mark the issue as completed.

8. Working as a Team

A
Alex — Backend Developer API, database, authentication
S
Sam — Frontend Developer UI, forms, dashboard
R
Ravi — Reviewer Code review and testing

Good team workflow

  • Keep tasks visible through issues or project planning.
  • Give each task a clear owner when appropriate.
  • Use branches for separate changes.
  • Use pull requests for review.
  • Communicate through issue and PR discussions.
  • Keep important branches protected according to team policy.

9. Connecting Issues with Pull Requests

Issues and pull requests can be connected so the team can understand which code change addresses which piece of work.

GitHub supports keywords such as: 

Fixes #24

Closes #24

Resolves #24

When used appropriately in a pull request or commit message, these keywords can connect the work to the referenced issue.

Example:

Issue #24:
"Add student search"

Pull request description:
Fixes #24

11. Collaboration Best Practices

Clear Issues

Write enough information for another developer to understand the task.

Small Tasks

Break large features into smaller manageable pieces.

Meaningful Branches

Use descriptive branch names related to the work.

Focused PRs

Keep pull requests focused on a clear change.

Useful Discussions

Use issue and PR comments to document decisions.

Keep Work Updated

Communicate progress and update project tracking.

12. Common GitHub Collaboration Mistakes

Mistake Problem Better Approach
Vague issue title Team cannot quickly understand the task. Use a clear, specific title.
No issue description Requirements are unclear. Explain the problem and expected result.
Huge PR Difficult to review. Break work into focused changes.
No task tracking Work can become difficult to coordinate. Use Issues and Projects where appropriate.
Unclear ownership Team members may duplicate work. Assign responsibility when useful.

16. Lesson Takeaway

GitHub provides more than just remote code hosting. Its collaboration features help teams plan, discuss, implement, review, and track software work.

  • Issues track bugs, tasks, features, questions, and improvements.
  • Labels categorize and organize issues.
  • Assignees identify people responsible for work.
  • Milestones group work toward larger objectives.
  • GitHub Projects help organize and visualize project work.
  • Branches isolate development work.
  • Pull Requests allow code changes to be proposed and reviewed.
  • Issues and pull requests can be connected using references such as Fixes #24.
  • Good collaboration requires clear communication, focused tasks, useful reviews, and visible progress.
