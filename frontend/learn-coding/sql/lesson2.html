02 — Database

What is a Database?

A database is an organized collection of data that allows information to be stored, searched, updated and managed efficiently.

Simple definition: A database is a structured place where related information is stored so that applications can efficiently access and manage it.
📚

Without Database

Information may be scattered across files, spreadsheets, documents and folders, making searching and updating difficult.

🗄️

With Database

Related information can be organized into tables and retrieved efficiently using queries.

⚡

Fast Access

Database systems provide mechanisms such as indexes and query optimization to retrieve data efficiently.

Real-world examples

🏦

Bank

Customers, accounts, transactions and loans.

🛒

E-Commerce

Products, users, orders, payments and delivery.

🎓

College

Students, faculty, courses, marks and attendance.

07 — Keys

Understanding Database Keys

Keys help identify records and connect related tables.

🔑

Primary Key

Uniquely identifies each row in a table. It cannot contain NULL values.

🔗

Foreign Key

A column or set of columns that references a key in another table to establish a relationship.

🧩

Composite Key

A key formed using two or more columns together.

⭐

Candidate Key

A minimal set of attributes capable of uniquely identifying a row.

Primary Key Example

SQL 
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100),
    department VARCHAR(50)
);

Foreign Key Example

SQL 
CREATE TABLE departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(100)
);

CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100),
    department_id INT,

    FOREIGN KEY (department_id)
    REFERENCES departments(department_id)
);

13 — Normalization

Database Normalization

Normalization is a database design technique used to organize data and reduce unnecessary duplication and update anomalies.

Beginner idea: Instead of storing the same information repeatedly, we try to divide data into logically related tables.
1️⃣

1NF

First Normal Form focuses on atomic values and avoiding repeating groups in a relational design.

2️⃣

2NF

Builds on 1NF and addresses partial dependency for designs involving composite keys.

3️⃣

3NF

Builds on 2NF and removes inappropriate transitive dependencies between non-key attributes.

Example

Student Department Department Head
101 - Pradeep CSE Dr. Rao
102 - Anil CSE Dr. Rao
103 - Rahul ECE Dr. Kumar
If department information is repeated for every student, changing the department head can require multiple updates. A normalized design can separate department information into its own table.
14 — Transactions

What is a Database Transaction?

A transaction is a logical unit of database work that should be handled according to the database system's transaction rules.

▶️ BEGIN
→
💳 Operations
→
✅ COMMIT
OR
↩️ ROLLBACK
⚛️

Atomicity

A transaction's operations are treated as a unit: they all succeed or the transaction is rolled back.

✔️

Consistency

A successful transaction should preserve defined database integrity rules.

👥

Isolation

Concurrent transactions are controlled so that intermediate states are handled appropriately.

💾

Durability

Once committed, changes are intended to survive normal system failures according to the DBMS guarantees.

Transaction example 
START TRANSACTION;

UPDATE accounts
SET balance = balance - 500
WHERE account_id = 101;

UPDATE accounts
SET balance = balance + 500
WHERE account_id = 202;

COMMIT;
15 — Constraints

Database Constraints

Constraints are rules applied to data to help maintain integrity.

🔑

PRIMARY KEY

Uniquely identifies rows.

🚫

NOT NULL

Prevents a column from containing NULL.

🎯

UNIQUE

Enforces uniqueness according to the DBMS rules.

📏

CHECK

Requires a condition to be satisfied.

🔗

FOREIGN KEY

Maintains referential relationships between tables.

📦

DEFAULT

Supplies a default value when one is not explicitly provided.

SQL constraints 
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(150) UNIQUE,
    age INT CHECK (age >= 16),
    city VARCHAR(50) DEFAULT 'Guntur'
);
16 — Performance Preview

What is an Index?

An index is a database structure that can help the DBMS find rows more efficiently for suitable queries.

Real-world analogy: A book's index helps you find a topic without reading every page. A database index can similarly help locate rows without scanning every row in suitable situations.
Create an index 
CREATE INDEX idx_student_name
ON students(name);

Benefit

Can significantly improve suitable read/search operations.

Trade-off

Indexes consume storage and can add overhead to inserts, updates and deletes.

Important

More indexes are not automatically better. Index design depends on workload and query patterns.

18 — Common Mistakes

Beginner Mistakes to Avoid

❌ Database = DBMS

They are related but not identical. Database is the data/structure; DBMS is software that manages it.

❌ Row = Column

A row represents a record. A column represents an attribute/property.

❌ Primary Key = Foreign Key

A primary key identifies rows in its own table. A foreign key establishes a reference to another table's key.

❌ One giant table

Poor design can cause duplication and update anomalies. Related tables are often separated appropriately.

❌ Ignoring NULL

NULL represents missing/unknown information and has special behavior in SQL comparisons.

❌ Adding indexes everywhere

Indexes improve some reads but have storage and write costs.

19 — Interview Preparation

Interview Questions

These are common database fundamentals questions asked in SQL and software interviews.

A database is an organized collection of data designed so that information can be stored, accessed, updated and managed efficiently.
A DBMS is software that provides mechanisms for storing, retrieving, modifying, securing and managing data in databases.

A foreign key is a column or set of columns used to reference a key in another table and establish referential relationships.
Normalization is a database design approach that organizes data to reduce unnecessary redundancy and update anomalies.

22 — Exam Preparation

5-Mark Answer: Database & DBMS

A database is an organized collection of related data that can be stored, accessed and managed efficiently. A Database Management System (DBMS) is software used to manage databases.


The major functions of a DBMS include data storage, retrieval, security, concurrency control, transaction management and recovery. Examples include MySQL, PostgreSQL, Oracle Database, Microsoft SQL Server and SQLite.

23 — 10-Mark Answer

Database Fundamentals — Complete Answer

Definition

A database is an organized collection of related information. A DBMS is software that manages this information and provides controlled access to it.


Major Components

A relational database contains tables consisting of rows and columns. Keys identify records and establish relationships between tables. Constraints help maintain data integrity.


Relationships

The major relationship types are one-to-one, one-to-many and many-to-many.


Normalization

Normalization organizes data into suitable related tables and helps reduce unnecessary redundancy and update anomalies.


Transactions

Transactions allow database operations to be handled as logical units. The ACID properties are Atomicity, Consistency, Isolation and Durability.
