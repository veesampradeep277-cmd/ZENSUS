Core Concept

Why do we need GROUP BY?

A normal SELECT works with individual rows. GROUP BY allows SQL to treat multiple rows as one logical group.

Think of GROUP BY like sorting students into classrooms.

Suppose a college has 1,000 students from CSE, ECE, EEE and Mechanical. Instead of analyzing every student separately, we can group them by department and calculate statistics for each department.

1,000 Rows Raw Data
→
GROUP BY Department
→
4 Groups CSE / ECE / EEE / MECH
→
Aggregate COUNT / AVG / SUM
→
Summary One row per group

Syntax

The basic GROUP BY syntax

Basic SQL 
SELECT column_name,
       AGGREGATE_FUNCTION(column_name)
FROM table_name
GROUP BY column_name;
Important rule:

When using GROUP BY, every selected column that is not inside an aggregate function generally needs to appear in the GROUP BY clause. Exact rules can vary for some database systems, but this is the safest rule to learn.

Example 
SELECT department,
       COUNT(*) AS total_students
FROM students
GROUP BY department;

Core Tools

GROUP BY + Aggregate Functions

GROUP BY becomes especially powerful when combined with aggregate functions.

#

COUNT()

Counts rows or non-NULL values depending on the expression.

Σ

SUM()

Calculates the total of numeric values.

μ

AVG()

Calculates the average of numeric values.

↓

MIN()

Finds the smallest value in each group.

↑

MAX()

Finds the largest value in each group.

◎

COUNT(DISTINCT)

Counts unique non-NULL values.

SELECT department,

       SUM(marks) AS total_marks,

       AVG(marks) AS average_marks,

       MIN(marks) AS lowest_marks,

Important Detail

COUNT(*) vs COUNT(column)

COUNT(*)

Counts rows, including rows where individual columns contain NULL. 

SELECT department,
       COUNT(*) AS total
FROM students
GROUP BY department;

COUNT(column)

Counts non-NULL values in that particular column. 

SELECT department,
       COUNT(phone) AS phones
FROM students
GROUP BY department;
Filtering Before Grouping

GROUP BY with WHERE

WHERE filters individual rows before GROUP BY creates groups.

FROM Get rows
→
WHERE Filter rows
→
GROUP BY Create groups
→
Aggregate Calculate
Example 
SELECT department,
       AVG(marks) AS average_marks
FROM students
WHERE marks >= 80
GROUP BY department;
💡
Remember:

WHERE asks: "Which rows should participate?" GROUP BY asks: "How should those remaining rows be grouped?"

Group Filtering

GROUP BY with HAVING

HAVING filters groups after aggregation has taken place.

WHERE

  • Filters individual rows.
  • Usually comes before GROUP BY.
  • Cannot directly filter an aggregate result at the same query level.

HAVING

  • Filters groups.
  • Comes after GROUP BY.
  • Works naturally with aggregate expressions.
HAVING example 
SELECT department,
       AVG(marks) AS average_marks
FROM students
GROUP BY department
HAVING AVG(marks) >= 85;
Think of it this way:

WHERE filters students. HAVING filters departments.

Advanced Grouping

GROUP BY multiple columns

You can group by more than one column. SQL creates a group for each unique combination of those column values. 

SELECT department,
       city,
       COUNT(*) AS total_students

FROM students

GROUP BY department, city;
Example:

GROUP BY department, city does NOT mean "first make department groups and then separately make city groups." It creates groups based on the combination: (department, city).

Sorting Group Results

GROUP BY + ORDER BY

After calculating group summaries, ORDER BY can sort the resulting groups.

       AVG(marks) AS average_marks

FROM students

GROUP BY department

ORDER BY average_marks DESC;

Advanced SQL

Conditional aggregation with CASE

GROUP BY can be combined with CASE to calculate multiple conditional statistics. 

SELECT department,

       COUNT(*) AS total_students,

       SUM(
           CASE
               WHEN marks >= 80 THEN 1
               ELSE 0
           END
       ) AS high_scorers

FROM students

GROUP BY department;
Real-world use:

This technique is commonly used in dashboards and reports to calculate categories such as passed students, failed students, active users, completed orders and high-value customers.

Expressions

GROUP BY expressions

You can group using expressions or database-supported functions. 

SELECT
    CASE
        WHEN marks >= 90 THEN 'Excellent'
        WHEN marks >= 75 THEN 'Good'
        ELSE 'Needs Improvement'
    END AS performance,

    COUNT(*) AS students

FROM students

GROUP BY
    CASE
        WHEN marks >= 90 THEN 'Excellent'
        WHEN marks >= 75 THEN 'Good'
        ELSE 'Needs Improvement'
    END;
NULL Handling

How does GROUP BY handle NULL?

Important:

GROUP BY generally places rows having NULL in the grouping column into the same group. NULL represents missing or unknown data; it is not the same as an empty string or zero. 

SELECT city,
       COUNT(*) AS total_students

FROM students

GROUP BY city;
DISTINCT + GROUPING

GROUP BY and DISTINCT

DISTINCT

Removes duplicate combinations from the selected result. 

SELECT DISTINCT department
FROM students;

GROUP BY

Creates groups, usually so that aggregate calculations can be performed per group. 

SELECT department,
       COUNT(*)
FROM students
GROUP BY department;
Real-World SQL

GROUP BY with JOIN

GROUP BY is extremely common when analyzing related tables. 

SELECT
    d.department_name,
    COUNT(s.student_id) AS total_students

FROM students s

JOIN departments d
    ON s.department_id = d.department_id

GROUP BY d.department_name;
🚀
Interview pattern:

JOIN + GROUP BY + COUNT/SUM/AVG + HAVING + ORDER BY is one of the most important SQL combinations for data-analysis and backend interviews.

Advanced Concepts

Beyond basic GROUP BY

ROLLUP

Some databases support ROLLUP to generate hierarchical subtotals and grand totals. 

GROUP BY ROLLUP(department, city)

CUBE

Some database systems support CUBE for multiple combinations of grouping dimensions. 

GROUP BY CUBE(department, city)

GROUPING SETS

Allows explicitly specifying multiple grouping levels in a single query in systems that support it. 

GROUP BY GROUPING SETS(
    (department),
    (city),
    ()
)

Window Functions

Window functions calculate values across related rows without collapsing them into one row per group. 

AVG(marks)
OVER(PARTITION BY department)
Important Difference

GROUP BY vs Window Functions

GROUP BY

  • Collapses rows into groups.
  • Usually returns one row per group.
  • Perfect for summaries and reports.

Window Function

  • Does not collapse the original rows.
  • Calculates across related rows.
  • Useful for rankings, running totals and comparisons.

Real-World Query Patterns

GROUP BY patterns you should know

1. Count employees per department 
SELECT department,
       COUNT(*) AS employee_count
FROM employees
GROUP BY department;
2. Total sales per product 
SELECT product_id,
       SUM(quantity * price) AS total_sales
FROM orders
GROUP BY product_id;
3. Average salary by department 
SELECT department,
       AVG(salary) AS average_salary
FROM employees
GROUP BY department;
4. Departments with more than 10 employees 
SELECT department,
       COUNT(*) AS employee_count
FROM employees
GROUP BY department
HAVING COUNT(*) > 10;
5. Highest average salary first 
SELECT department,
       AVG(salary) AS average_salary
FROM employees
GROUP BY department
ORDER BY average_salary DESC;
Avoid These

Common GROUP BY mistakes

❌ Forgetting GROUP BY

Selecting a non-aggregated grouping column alongside an aggregate generally requires GROUP BY.

❌ Confusing WHERE and HAVING

WHERE filters rows. HAVING filters groups.

❌ Grouping the wrong columns

Adding extra columns to GROUP BY can create smaller groups than intended.

❌ Ignoring NULL

COUNT(column) ignores NULL values, while COUNT(*) counts rows.

❌ Expecting original rows

GROUP BY normally collapses rows into one output row per group.

❌ Forgetting ORDER BY

GROUP BY does not guarantee a particular output order. Use ORDER BY when ordering matters.

Exam Preparation

5-Mark Answer — GROUP BY

Definition:

GROUP BY is an SQL clause used to divide rows into groups based on one or more columns. It is commonly used with aggregate functions such as COUNT(), SUM(), AVG(), MIN() and MAX() to produce summary information for each group. 

SELECT department,
       COUNT(*) AS total_students,
       AVG(marks) AS average_marks
FROM students
GROUP BY department;

The query groups students according to department and calculates the number of students and average marks for every department.

Interview Preparation

GROUP BY Interview Questions

1. What is GROUP BY?

GROUP BY divides rows into groups based on one or more columns, usually so aggregate calculations can be performed for each group.

2. Can GROUP BY be used without aggregate functions?

Yes. A GROUP BY query can be used to produce unique combinations of grouping columns, although DISTINCT is often clearer when no aggregation is required.

3. What is the difference between WHERE and HAVING?

WHERE filters individual rows before grouping. HAVING filters groups after grouping and aggregation.

4. Can we use multiple columns in GROUP BY?

Yes. GROUP BY department, city creates groups based on unique department-city combinations.

5. What does COUNT(*) count?

COUNT(*) counts rows. It does not ignore a row merely because some of its columns contain NULL.

6. What does COUNT(column) do?

COUNT(column) counts non-NULL values in that column.

7. Can GROUP BY be combined with ORDER BY?

Yes. ORDER BY can sort the grouped result, for example by an aggregate such as AVG(salary) DESC.

8. Why can't we normally use aggregate conditions in WHERE?

WHERE operates before grouping and aggregation at the logical query level. HAVING is designed to filter aggregated groups.

9. What happens to NULL grouping values?

Rows with NULL in the grouping column are generally placed into the same NULL group.

10. GROUP BY vs window functions?

GROUP BY generally collapses rows into groups, whereas window functions calculate across related rows while preserving the individual rows.

Rapid Revision

GROUP BY in 60 seconds

GROUP BY creates groups of rows sharing the same values.


COUNT() → number of rows/non-NULL values

SUM() → total

AVG() → average

MIN() → smallest

MAX() → largest


WHERE → filters rows before grouping

HAVING → filters groups after grouping

ORDER BY → sorts the final result 

SELECT department,
       COUNT(*) AS total,
       AVG(marks) AS average_marks

FROM students

WHERE marks >= 60

GROUP BY department

HAVING COUNT(*) >= 2

ORDER BY average_marks DESC;
