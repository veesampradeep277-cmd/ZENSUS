What Are SQL Constraints?

Rules that control what data is allowed in a table.

A constraint is a rule enforced by the database to maintain the correctness, consistency and integrity of data.

Instead of trusting every application to validate every input, we can place important rules directly in the database.

💡 Core Idea

Constraints act like a safety layer around your database. They prevent invalid data from entering or violating important relationships.

1. NOT NULL Constraint

Make sure a value is provided.

The NOT NULL constraint prevents a column from containing NULL.

CREATE TABLE 
CREATE TABLE students (
    student_id INT,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(150)
);

Here, name must have a non-NULL value when a row is inserted.

❌ This can fail 
INSERT INTO students (student_id, name)
VALUES (101, NULL);
NULL ≠ Empty String

NULL means "unknown / missing / not provided" in SQL. An empty string such as '' is a value and is not automatically the same as NULL.

🔐

2. UNIQUE Constraint

Prevent duplicate values.

A UNIQUE constraint ensures that duplicate non-NULL values are not stored in the constrained key.

UNIQUE COLUMN 
CREATE TABLE students (
    student_id INT,
    email VARCHAR(150) UNIQUE
);

Two students should not have the same email address.

Named UNIQUE Constraint

NAMED CONSTRAINT 
CREATE TABLE students (
    student_id INT,
    email VARCHAR(150),

    CONSTRAINT uq_student_email
        UNIQUE (email)
);
⭐ Professional Practice

Naming important constraints makes schema maintenance, migrations and error diagnosis easier.

🔑

3. PRIMARY KEY

The identity of a row.

A primary key uniquely identifies each row in a table.

PRIMARY KEY 
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100),
    email VARCHAR(150)
);

Primary Key Properties

  • Uniquely identifies rows.
  • Cannot contain NULL.
  • A table has one primary key constraint.
  • The key can contain one or multiple columns.
  • A primary key can be referenced by foreign keys.

Primary Key

  • Identifies the row.
  • Unique.
  • Not NULL.
  • One primary-key constraint per table.

UNIQUE

  • Enforces uniqueness.
  • NULL behavior is DBMS-dependent.
  • Multiple UNIQUE constraints can exist.
  • Does not mean "row identity" by itself.
🧱

Composite Primary Key

A primary key made from multiple columns.

Sometimes one column is not enough to uniquely identify a row. Multiple columns can be combined.

COMPOSITE KEY 
CREATE TABLE enrollments (
    student_id INT,
    course_id INT,
    enrolled_on DATE,

    PRIMARY KEY (student_id, course_id)
);

A student can enroll in many courses, and a course can have many students. The combination of student_id and course_id identifies an enrollment.

Example

(101, 501) and (101, 502) are different enrollments, but (101, 501) cannot be inserted twice.

🔗

4. FOREIGN KEY

Connect related tables and protect referential integrity.

A foreign key creates a relationship between a child table and a referenced key in another table.

FOREIGN KEY 
CREATE TABLE departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(100)
);

CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100),
    department_id INT,

    FOREIGN KEY (department_id)
        REFERENCES departments(department_id)
);
departments
Parent
→
department_id
Referenced Key
→
students
Child

Referential Integrity

A foreign key prevents a child row from referring to a nonexistent referenced key, subject to the specific NULL and referential-action rules of the database.

❌ Invalid relationship 
INSERT INTO students
(student_id, name, department_id)
VALUES
(101, 'Pradeep', 999);

If department 999 does not exist in the referenced table, the insert can be rejected by the foreign key.

✓

5. CHECK Constraint

Enforce business rules at the database level.

A CHECK constraint requires a row to satisfy a specified condition.

CHECK 
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    age INT CHECK (age >= 17),
    marks DECIMAL(5,2) CHECK (marks BETWEEN 0 AND 100)
);

More Examples

BUSINESS RULES 
salary DECIMAL(10,2)
    CHECK (salary > 0)

quantity INT
    CHECK (quantity >= 0)

status VARCHAR(20)
    CHECK (status IN ('ACTIVE', 'INACTIVE'))

discount DECIMAL(5,2)
    CHECK (discount BETWEEN 0 AND 100)
Important

CHECK support and enforcement details can vary among database systems and versions. For production schemas, verify the behavior of your target DBMS.

⚙️

6. DEFAULT Constraint

Automatically supply a value when one is omitted.
DEFAULT 
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    name VARCHAR(100),
    city VARCHAR(50) DEFAULT 'Guntur',
    status VARCHAR(20) DEFAULT 'ACTIVE'
);

If an INSERT does not supply a value for city or status, the database can use the defined defaults.

INSERT 
INSERT INTO students (student_id, name)
VALUES (101, 'Pradeep');

Conceptually, the row receives the default city and status.

🏗️

Combining Multiple Constraints

Real database columns often have more than one rule.
PROFESSIONAL TABLE DESIGN 
CREATE TABLE students (
    student_id INT
        CONSTRAINT pk_students
        PRIMARY KEY,

    name VARCHAR(100)
        CONSTRAINT nn_student_name
        NOT NULL,

    email VARCHAR(150)
        CONSTRAINT uq_student_email
        UNIQUE,

    age INT
        CONSTRAINT chk_student_age
        CHECK (age >= 17),

    city VARCHAR(50)
        DEFAULT 'Guntur',

    department_id INT,

    CONSTRAINT fk_student_department
        FOREIGN KEY (department_id)
        REFERENCES departments(department_id)
);
PRIMARY KEY NOT NULL UNIQUE CHECK DEFAULT FOREIGN KEY
🏷️

Named Constraints

Give constraints meaningful names.
NAMED CONSTRAINTS 
CREATE TABLE employees (

    employee_id INT,

    email VARCHAR(150),

    salary DECIMAL(10,2),

    department_id INT,

    CONSTRAINT pk_employee
        PRIMARY KEY (employee_id),

    CONSTRAINT uq_employee_email
        UNIQUE (email),

    CONSTRAINT chk_employee_salary
        CHECK (salary > 0),

    CONSTRAINT fk_employee_department
        FOREIGN KEY (department_id)
        REFERENCES departments(department_id)

);

Modify an existing table.

Add FOREIGN KEY

Add CHECK

CHECK 
ALTER TABLE students
ADD CONSTRAINT chk_student_marks
CHECK (marks BETWEEN 0 AND 100);
⚠️ Existing Data Matters

Adding a constraint can fail if existing rows violate the new rule. Always inspect and clean existing data before applying restrictive constraints.

🗑️

Dropping Constraints

Remove a named constraint when necessary.
DROP CONSTRAINT 
ALTER TABLE students
DROP CONSTRAINT uq_student_email;
DBMS Difference

Exact ALTER TABLE syntax differs across MySQL, PostgreSQL, SQL Server, Oracle and other systems. Always check the syntax for your target DBMS.

🔗

Foreign Key Referential Actions

What happens when parent rows are updated or deleted?

Foreign keys can specify actions for changes to referenced rows.

CASCADE

Propagate the parent UPDATE or DELETE to matching child rows.

SET NULL

Set the foreign-key value to NULL when the parent changes, where the column allows NULL.

SET DEFAULT

Set the child value to its default where supported and applicable by the DBMS.

RESTRICT / NO ACTION

Prevent or defer the parent change when dependent rows would violate referential integrity, depending on DBMS behavior.

REFERENTIAL ACTION 
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    department_id INT,

    CONSTRAINT fk_student_department
        FOREIGN KEY (department_id)
        REFERENCES departments(department_id)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);
⚠️ Use CASCADE Carefully

Cascading deletes can remove many dependent rows. Use them only when that behavior matches the business relationship.

PRIMARY KEY vs UNIQUE

One of the most common interview questions.

PRIMARY KEY

  • Represents the table's chosen row identifier.
  • Cannot contain NULL.
  • One primary-key constraint per table.
  • Can consist of multiple columns.
  • Can be referenced by foreign keys.

UNIQUE

  • Enforces uniqueness.
  • NULL handling varies by DBMS.
  • Multiple UNIQUE constraints can exist.
  • Can be composite.
  • Can provide a candidate key for references.
🔑

PRIMARY KEY

Identifies a row in its own table.

Real-World Example — College Database

See how constraints work together.
COLLEGE DATABASE 
CREATE TABLE departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(100) NOT NULL UNIQUE
);

CREATE TABLE students (
    student_id INT PRIMARY KEY,

    name VARCHAR(100)
        NOT NULL,

    email VARCHAR(150)
        UNIQUE,

    age INT
        CHECK (age >= 17),

    city VARCHAR(50)
        DEFAULT 'Guntur',

    department_id INT,

    CONSTRAINT fk_student_department
        FOREIGN KEY (department_id)
        REFERENCES departments(department_id)
);

SQL Constraints


            

                Constraints are rules enforced by a relational database to
                preserve data integrity and prevent invalid information from
                being stored. They are an important part of database design.
            


            
1. NOT NULL


            

                Ensures that a column must contain a non-NULL value.
            


            
2. UNIQUE


            

                Ensures uniqueness for the constrained key.
            


            
3. PRIMARY KEY


            

                Uniquely identifies every row and cannot contain NULL.
            


            
4. FOREIGN KEY


            

                Maintains referential integrity between related tables.
            


            
5. CHECK


            

                Enforces a specified logical condition on row values.
            


            
6. DEFAULT


            

                Provides a value when an INSERT omits a column value.

Interview Questions


                    

                        Questions you should answer confidently.
                    


                


            


            
1. What is a constraint?


            

                A rule enforced by the database to maintain data integrity.
            


            
2. What is a primary key?


            

                A key chosen to uniquely identify rows in a table.
            


            
3. Can a primary key contain NULL?


            

                No.
            


            
4. Can a table have multiple primary keys?


            

                A table has one primary-key constraint, although that key
                can contain multiple columns.
            


            
5. Can a table have multiple UNIQUE constraints?


            

                Yes.
            


            
6. What is a foreign key?


            

                A column or set of columns that references a key in another
                table to enforce referential integrity.
            


            
7. Primary key vs foreign key?


            

                The primary key identifies rows in its own table. The foreign
                key references a key in another table.
            


            
8. What is a composite key?


            

                A key consisting of multiple columns.
            


            
9. What is CHECK?


            

                CHECK enforces a condition on row values.
            


            
10. What is DEFAULT?


            

                DEFAULT supplies a value when an INSERT does not provide one
                for the column.
            


            
11. What happens if a foreign key references a nonexistent value?


            

                Normally the database rejects the operation because it would
                violate referential integrity, unless the relationship and
                operation allow NULL or another valid referenced state.
            


            
12. What is ON DELETE CASCADE?


            

                It causes matching dependent rows to be deleted when the
                referenced parent row is deleted.

Professional Database Design Principles


                    

                        Constraints are part of schema design, not decoration.
                    


                


            


            


                


                    1. Protect important data

                    

                        Put critical integrity rules in the database.
                    


                


                


                    2. Use meaningful names

                    

                        Named constraints are easier to maintain.
                    


                


                


                    3. Choose keys carefully

                    

                        Select stable, appropriate identifiers.
                    


                


                


                    4. Model relationships explicitly

                    

                        Use foreign keys where referential integrity is required.
                    


                


                


                    5. Validate existing data

                    

                        Check old rows before adding restrictive constraints.
                    


                


                


                    6. Test destructive actions

                    

                        Especially when using CASCADE.
