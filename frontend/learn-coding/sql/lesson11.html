What Is a Subquery?

A query inside another query.

A subquery is a SQL query written inside another SQL statement.

The inner query produces a value, a list of values, a table, or an existence result that the outer query can use.

Inner Query
Find information
→
Result
Value / Set / Table
→
Outer Query
Make final decision

Basic Syntax

BASIC SUBQUERY 
SELECT column_name
FROM table_name
WHERE column_name >
      (
          SELECT column_name
          FROM another_table
          WHERE condition
      );
💡 Think of it like this

First ask a smaller question: "What is the average mark?" Then ask the larger question: "Who scored above that average?"

⚙️

How a Subquery Works

Visualize the relationship between inner and outer queries.
Inner Query 
SELECT AVG(marks)
FROM students;
Result → 76.5
→
Outer Query 
SELECT name
FROM students

Final Students

The exact physical execution strategy is controlled by the database optimizer. The inner-query → outer-query model is a useful way to understand the SQL logic, but the database may rewrite or optimize the statement internally.

Subquery in WHERE

One of the most common applications.

Suppose we want students who scored above the average mark.

ABOVE AVERAGE 
SELECT name, marks
FROM students
WHERE marks > (
    SELECT AVG(marks)
    FROM students
);

How to Think About It

  1. Calculate the average marks.
  2. The subquery returns one value.
  3. Compare every student's marks with that value.
  4. Return students whose marks are greater.
Interview Pattern ⭐

"Find employees/students/products above the average" is a very common subquery problem.

📋

IN with Subqueries

Use IN when the inner query produces a set of values.

IN checks whether a value belongs to a set returned by the subquery.

IN 
SELECT name
FROM students
WHERE department IN (
    SELECT department
    FROM departments
    WHERE location = 'Hyderabad'
);
Find departments

⚠️

The NOT IN + NULL Trap

One of the most important SQL interview concepts.

NOT IN can behave unexpectedly if the subquery returns NULL.

POTENTIAL PROBLEM 
SELECT name
FROM students
WHERE department_id NOT IN (
    SELECT department_id
    FROM departments
);

If the inner result contains NULL, comparisons can become UNKNOWN because SQL uses three-valued logic:

TRUE FALSE UNKNOWN
🚨 Safer Pattern

When checking that no matching row exists and NULLs are possible, NOT EXISTS is often a safer and clearer choice.

✅

EXISTS

Ask a yes/no question: does at least one matching row exist?

EXISTS checks whether the subquery returns at least one row.

EXISTS 
SELECT c.customer_id, c.name
FROM customers c
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.customer_id
);
Outer Customer 
Customer #101
?
Inner Orders 
Any order
for #101?
YES → keep row
Important

With EXISTS, the actual selected value inside the subquery usually does not matter. The database is testing whether a matching row exists. That is why SELECT 1 is commonly written.

🚫

NOT EXISTS

Find rows for which no matching row exists.
NO ORDERS 
SELECT c.customer_id, c.name
FROM customers c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.customer_id
);

This asks: "For this customer, is there no matching order?"

Great interview pattern ⭐

"Find customers who never ordered", "employees with no projects", and "students with no submissions" are classic NOT EXISTS problems.

🔄

Correlated Subqueries

The inner query references the current row of the outer query.

A correlated subquery depends on a value from the outer query.

Consider this classic problem:

Find employees whose salary is greater than the average salary of their own department.
CORRELATED SUBQUERY 
SELECT e.employee_name, e.salary
FROM employees e
WHERE e.salary > (
    SELECT AVG(e2.salary)
    FROM employees e2
    WHERE e2.department_id = e.department_id
);

Why Is It Correlated?

Notice this condition:

CORRELATION CONDITION 
e2.department_id = e.department_id

The inner query uses e.department_id, which comes from the outer query.

Outer Employee
→
Get Department
→
Calculate Dept Average
→
Compare Salary
⚠️ Performance Note

A correlated subquery can be expensive conceptually because it depends on outer rows. Modern optimizers can transform many such queries, so never assume the literal nested structure equals the physical execution plan.

1️⃣

Scalar Subqueries

A scalar subquery produces a single value.
SCALAR SUBQUERY 
SELECT name,
       marks,
       (
           SELECT AVG(marks)
           FROM students
       ) AS average_marks
FROM students;

The average is calculated as a single value and can appear beside every student.

Important Rule

A scalar subquery must return at most one value in contexts that require a scalar. If it returns multiple rows, most database systems raise an error.

📊

Subquery in SELECT

Use a scalar subquery to calculate an additional value.
SELECT SUBQUERY 
SELECT
    e.employee_name,
    (
        SELECT d.department_name
        FROM departments d
        WHERE d.department_id = e.department_id
    ) AS department_name
FROM employees e;
Design Tip

This can work, but a JOIN is often clearer when you simply need related columns from another table.

🧱

Subquery in FROM — Derived Table

Treat the result of a subquery like a temporary table.
DERIVED TABLE 
SELECT department_id, avg_salary
FROM (
    SELECT
        department_id,
        AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department_id
) AS dept_stats
WHERE avg_salary > 60000;
Employees
→
GROUP BY
Department averages
→
Derived Table
→
Filter
Alias

A derived table normally needs an alias, such as dept_stats, in many SQL database systems.

📈

Subquery with HAVING

Compare group-level results with another aggregate.
HAVING + SUBQUERY 
SELECT department_id
FROM employees
GROUP BY department_id
HAVING AVG(salary) > (
    SELECT AVG(salary)
    FROM employees
);

The outer query calculates average salary per department. The subquery calculates the overall company average.

Only departments whose average is greater than the company average are returned.

⚖️

ANY, SOME and ALL

Compare one value against a set of values.

ANY / SOME

ANY means the comparison is true for at least one value in the subquery. SOME is a synonym in SQL systems that support it.

ANY 
SELECT employee_name, salary
FROM employees
WHERE salary > ANY (
    SELECT salary
    FROM employees
    WHERE department_id = 10
);

This means the salary is greater than at least one salary returned by the inner query.

ALL

ALL 
SELECT employee_name, salary
FROM employees
WHERE salary > ALL (
    SELECT salary
    FROM employees
    WHERE department_id = 10
);

This means the salary must be greater than every salary returned by the inner query.

ANY

Comparison succeeds for at least one value.

Think: "one or more"

ALL

Comparison must succeed for every value.

Think: "every one"
🪆

Nested Subqueries

A subquery can contain another subquery.
NESTED SUBQUERY 
SELECT name
FROM students
WHERE department IN (
    SELECT department
    FROM departments
    WHERE location IN (
        SELECT city
        FROM campuses
        WHERE active = 1
    )
);
Readability Warning

Nested subqueries are powerful, but too many levels can become difficult to maintain. Consider a CTE or JOIN when it makes the logic clearer.

✏️

Subqueries with INSERT, UPDATE and DELETE

Subqueries are not limited to SELECT statements.

INSERT ... SELECT

INSERT 
INSERT INTO top_students (student_id, name)
SELECT student_id, name
FROM students
WHERE marks >= (
    SELECT AVG(marks)
    FROM students
);

UPDATE

UPDATE 
UPDATE employees
SET salary = salary * 1.10
WHERE department_id IN (
    SELECT department_id
    FROM departments
    WHERE location = 'Hyderabad'
);

DELETE

DELETE 
DELETE FROM customers c
WHERE NOT EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.customer_id = c.customer_id
);
⚠️ Production Rule

Always test the corresponding SELECT condition before running UPDATE or DELETE in a real database.

🔀

Subquery vs JOIN

Both can solve overlapping problems, but they communicate different ideas.

Subquery

  • Good for nested logic.
  • Natural for "above average" questions.
  • EXISTS expresses existence clearly.
  • Can isolate a calculation.

JOIN

  • Excellent for combining related tables.
  • Often easier to read for multi-table retrieval.
  • Useful when columns from both tables are needed.
  • Can be easier to optimize and reason about.

Example

SUBQUERY 
SELECT name
FROM students
WHERE department_id IN (
    SELECT department_id
    FROM departments
    WHERE location = 'Hyderabad'
);
JOIN 
SELECT s.name
FROM students s
JOIN departments d
    ON s.department_id = d.department_id
WHERE d.location = 'Hyderabad';

Neither form is universally "faster." The database optimizer, indexes, statistics, data distribution and query shape all matter. Use EXPLAIN or your database's execution-plan tools when performance matters.

🧠

Subqueries vs CTEs

CTEs can make complex multi-step SQL easier to read.

A Common Table Expression uses the WITH clause to give a named result a logical name.

CTE VERSION 
WITH dept_stats AS (
    SELECT
        department_id,
        AVG(salary) AS avg_salary
    FROM employees
    GROUP BY department_id
)

SELECT department_id, avg_salary
FROM dept_stats
WHERE avg_salary > 60000;
When CTEs help

Use a CTE when a query has multiple logical steps or when naming an intermediate result makes the SQL much easier to understand.

🪟

Subqueries vs Window Functions

An important advanced SQL decision.

A correlated subquery can sometimes be replaced by a window function when you want to compare each row with a group-level value while keeping all rows.

CORRELATED SUBQUERY IDEA 
SELECT
    e.employee_name,
    e.salary
FROM employees e
WHERE e.salary > (
    SELECT AVG(e2.salary)
    FROM employees e2
    WHERE e2.department_id = e.department_id
);

Another approach in systems supporting window functions:

WINDOW FUNCTION 
SELECT employee_name, salary
FROM (
    SELECT
        employee_name,
        salary,
        AVG(salary) OVER (
            PARTITION BY department_id
        ) AS dept_avg
    FROM employees
) x
WHERE salary > dept_avg;
Key Difference

A normal aggregate reduces rows. A window function can calculate a group statistic while retaining individual rows.

Subquery Performance

Write correct SQL first, then measure performance.
1. Index important columns

Especially columns used for filtering and correlation.

2. Use EXPLAIN

Inspect the actual execution plan when performance matters.

3. Avoid unnecessary nesting

A simpler JOIN, CTE or window function may communicate the intent better.

4. Select only required columns

Avoid unnecessary SELECT * in intermediate queries.

5. Correlation matters

Correlated logic can be expensive depending on the optimizer and data.

6. Don't guess performance

Two logically equivalent queries can have different plans depending on the database.

Common Mistakes

                    

                        Avoid these mistakes in exams, interviews and projects.
                    

                


            


            


                

                    ❌ Scalar returns multiple rows
                    

                        A scalar comparison such as = expects a single value.
                    

                


                

                    ❌ NOT IN with NULL
                    

                        NULL can produce UNKNOWN results.
                    

                


                

                    ❌ Missing correlation condition
                    

                        A correlated query needs the correct relationship
                        between inner and outer rows.
                    

                


                

                    ⚠️ Wrong column type with IN
                    

                        The compared expression and returned values should
                        be compatible.
                    

                


                

                    ⚠️ Using aggregate directly in WHERE
                    

                        Aggregates often require a subquery, GROUP BY/HAVING,
                        window function or another appropriate structure.
                    

                


                

                    ⚠️ Over-nesting
                    

                        Too many nested levels can make SQL hard to maintain.
                    

                


                

                    ℹ️ Confusing EXISTS
                    

                        EXISTS checks whether rows exist; it is not primarily
                        about returning the inner query's selected value.
                    

                


                

                    ℹ️ Missing derived-table alias
                    

                        Many SQL systems require an alias for a subquery in FROM.

Interview Questions

                    

                        Questions you should be able to answer confidently.
                    

                


            


            
1. What is a subquery?

            

                A query embedded inside another query.
            


            
2. What is a scalar subquery?

            

                A subquery that produces a single value in a scalar context.
            


            
3. What is a correlated subquery?

            

                A subquery that references one or more values from the outer query.
            


            
4. IN vs EXISTS?

            

                IN compares a value with a set of returned values. EXISTS
                tests whether at least one matching row exists. The best
                choice depends on the semantics, NULL behavior and database
                optimizer.
            


            
5. Why is NOT EXISTS often safer than NOT IN?

            

                NOT IN can produce unexpected results when the subquery contains
                NULL because of SQL's three-valued logic.
            


            
6. What happens if a scalar subquery returns multiple rows?

            

                In most database systems, the statement fails because a scalar
                context expects at most one value.
            


            
7. Can subqueries be used in INSERT, UPDATE and DELETE?

            

                Yes. Subqueries can be used in conditions and INSERT ... SELECT
                patterns.
            


            
8. Subquery or JOIN?

            

                Choose based on the problem. JOIN is often natural for retrieving
                related columns; subqueries can be clearer for nested conditions
                and existence tests.
            


            
9. What is a derived table?

            

                A subquery placed in the FROM clause and treated as a relational
                result that can be queried by the outer statement.
            


            
10. Can a subquery contain another subquery?

            

                Yes. This is called nesting.
