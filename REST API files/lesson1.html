Introduction to REST APIs

Learn how applications communicate with each other using APIs, HTTP requests, responses, JSON, endpoints, and REST principles. This lesson builds the foundation for the complete REST API course.

01 · FOUNDATION

What is an API?

API stands for Application Programming Interface. It provides a way for one software application to communicate with another software application.

A

Application

A program such as a website, mobile app, desktop application, or backend service.

I

Interface

A defined way that allows software systems to interact with each other.

Simple definition: An API is a bridge that allows different software applications to exchange data and functionality.
02 · WHY APIs?

Why Do Applications Need APIs?

Modern applications rarely work completely alone. They often need data or services from other applications.

☁

Access Data

A frontend can request information from a backend server.

🔗

Connect Applications

Web applications, mobile applications, and other services can communicate.

⚙

Reuse Services

One backend service can provide data to multiple applications.

🚀

Build Modern Systems

APIs are used in e-commerce, banking, social media, AI applications, and more.

03 · REST

What is a REST API?

REST stands for Representational State Transfer. It is an architectural style for designing web APIs.

REST API in simple words

A REST API allows applications to communicate over the web using standard HTTP methods and resources.

Remember: REST is not a programming language. REST is an architectural style used to design APIs.

05 · CLIENT & SERVER

Client and Server

💻 Client

  • Sends requests
  • Requests data or actions
  • Displays the response
  • Examples: React app, mobile app

🖥 Server

  • Receives requests
  • Processes application logic
  • Communicates with database
  • Sends a response
06 · REQUEST & RESPONSE

Request and Response

REST API communication is based on a request-response model.

📤 Request

The client sends a request to the server asking for data or asking the server to perform an operation.

→

📥 Response

The server processes the request and sends data or a result back to the client.

Example HTTP Request 
GET /api/students/101/ HTTP/1.1
Host: example.com
Example Response 
HTTP/1.1 200 OK

{
    "id": 101,
    "name": "Pradeep",
    "course": "REST API"
}
07 · DATA EXCHANGE

JSON and Data Exchange

REST APIs commonly use JSON to exchange structured data between applications.

student.json 
{
    "id": 101,
    "name": "Pradeep",
    "age": 21,
    "course": "Computer Science",
    "active": true
}
Why JSON? JSON is lightweight, easy for humans to read, and easy for programming languages to process.
08 · ENDPOINTS

API Endpoints

An endpoint is a specific URL through which a client can access an API resource.

GET
https://example.com/api/students/
GET
https://example.com/api/students/101/
Think of an endpoint as an address. The client uses that address to communicate with a particular API resource.
09 · HTTP METHODS

Common HTTP Methods

HTTP methods describe the operation that the client wants the server to perform.

GET Retrieve data
POST Create data
PUT / PATCH Update data
DELETE Remove data
These methods will be studied in detail in the upcoming REST API lessons.
10 · ARCHITECTURE

REST Architecture Principles

01

Client-Server

Client and server have separate responsibilities.

02

Stateless

Each request should contain the information needed to process it.

03

Uniform Interface

APIs use consistent ways to access and manipulate resources.

04

Resources

Data is represented as resources such as users, products, or students.

05

Cacheable

Responses can be cached when appropriate to improve performance.

06

Layered System

A client does not need to know every internal server component.
