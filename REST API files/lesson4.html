HTTP Methods & Requests

Learn how applications send requests to APIs using HTTP. Understand GET, POST, PUT, PATCH and DELETE, along with URLs, parameters, headers and request bodies.

01

What is HTTP?

HTTP stands for Hypertext Transfer Protocol.

It is the communication protocol commonly used when clients and servers communicate over the web.

Client
→
HTTP Request
→
Server
→
HTTP Response
Simple idea:

HTTP defines the rules for sending requests and receiving responses between applications.
02

What is an HTTP Request?

An HTTP request is a message sent by a client to a server asking the server to perform an operation or provide information.

For example, a frontend application may ask an API for a list of students.

GET https://api.example.com/students/
Method GET
URL /students/
Headers Content-Type: application/json
03

HTTP Request Structure

An HTTP request can contain several important parts.

1️⃣

Method

Defines the intended operation such as GET or POST.

🔗

URL

Identifies the resource being accessed.

📋

Headers

Carry metadata about the request.

📦

Body

Carries data sent to the server when required.

Example Request 
POST /api/students/ HTTP/1.1
Host: api.example.com
Content-Type: application/json

{
    "name": "Pradeep",
    "course": "REST API"
}
04

HTTP Methods

HTTP methods tell the server what kind of operation the client intends to perform.

GET

Read Data

Retrieve information from the server.

POST

Create Data

Submit data to create a new resource.

PUT

Replace Data

Replace the current representation of a resource.

PATCH

Partial Update

Modify selected parts of an existing resource.

DELETE

Remove Data

Request removal of a resource.

05

GET — Retrieve Data

The GET method is used to retrieve information from a server.

GET Request 
GET /api/students/

The server might respond with:

JSON Response 
[
    {
        "id": 1,
        "name": "Pradeep",
        "course": "Python"
    },
    {
        "id": 2,
        "name": "Rahul",
        "course": "REST API"
    }
]
Remember:

GET is normally used when the client wants to read data.
06

POST — Create Data

The POST method is commonly used to submit data for creating a new resource.

POST Request 
POST /api/students/

Content-Type: application/json

{
    "name": "Pradeep",
    "course": "REST API",
    "age": 21
}

The server processes the submitted data and may create a new student.

Example response:

201 Created
07

PUT — Replace a Resource

The PUT method is commonly used when the client sends a complete new representation for an existing resource.

PUT Request 
PUT /api/students/101/

Content-Type: application/json

{
    "name": "Pradeep Kumar",
    "course": "Django",
    "age": 22
}
Think of PUT as:

"Here is the new representation of this resource."
08

PATCH — Partial Update

The PATCH method is used when only part of an existing resource needs to be changed.

PATCH Request 
PATCH /api/students/101/

Content-Type: application/json

{
    "course": "Django"
}

Only the specified field needs to be changed.

Simple difference:

PUT → Replace the resource representation.

PATCH → Partially modify the resource.
09

DELETE — Remove a Resource

The DELETE method is used to request deletion of a resource.

DELETE Request 
DELETE /api/students/101/

The server processes the request and may remove the resource.

Important:

DELETE operations can permanently remove data. Always implement appropriate authorization and validation on real applications.
10

URL Parameters

A path parameter identifies a specific resource.

Collection 
GET /api/students/
Specific Resource 
GET /api/students/101/

Here, 101 identifies a specific student.

/students/
+
101
=
Student #101
11

Query Parameters

Query parameters are commonly used for filtering, searching, sorting or pagination.

Filtering 
GET /api/students/?course=python
Searching 
GET /api/students/?search=pradeep
Pagination 
GET /api/students/?page=2
Path vs Query:

/students/101/ → identifies a particular resource.

/students/?course=python → applies a filter or other query condition to the collection.
12

HTTP Headers

Headers carry additional information, called metadata, about the request.

Content-Type

Describes the format of the request body.

application/json

Accept

Indicates formats the client can handle.

application/json

Authorization

Carries authentication credentials such as a bearer token.

Example Headers 
Content-Type: application/json
Accept: application/json
Authorization: Bearer YOUR_TOKEN
13

Request Body

The request body contains data sent to the server. It is commonly used with POST, PUT and PATCH requests.

JSON Request Body 
{
    "name": "Pradeep",
    "email": "pradeep@example.com",
    "course": "REST API"
}

The server reads this data and validates it before performing the requested operation.

Lesson Takeaway

  • HTTP is a protocol used for communication between clients and servers.
  • An HTTP request contains information such as a method, URL, headers and, when needed, a body.
  • GET is commonly used to retrieve resources.
  • POST is commonly used to create resources.
  • PUT is commonly used to replace a resource representation.
  • PATCH is commonly used for partial updates.
  • DELETE is used to request removal of a resource.
  • Path parameters identify specific resources.
  • Query parameters are useful for filtering, searching and pagination.
  • Headers carry metadata such as content type and authorization.
  • The request body carries data sent to the server when required.
