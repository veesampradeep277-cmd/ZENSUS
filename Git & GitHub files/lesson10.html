Cloning & Forking Repositories

Learn how to copy GitHub repositories to your computer, understand the difference between cloning and forking, and use both workflows to work with existing projects.

1. What Is Cloning?

Cloning means creating a local copy of an existing Git repository.

When you clone a repository, Git downloads the repository's files, commit history, branches, and remote-tracking information to your computer.

GitHub Remote Repository
→
git clone Download Repository
→
Computer Local Repository

Basic command 

git clone https://github.com/username/project.git
Simple definition:

git clone = "Give me a local working copy of this Git repository."

2. Why Do We Clone Repositories?

Start Existing Projects

Download a project that already exists on GitHub instead of creating it from scratch.

Team Development

Clone a shared repository and start contributing to the project.

Learn Projects

Download open-source projects and study their code.

3. How git clone Works

Suppose a GitHub repository is available at: 

https://github.com/example/student-management.git

You can clone it using: 

git clone https://github.com/example/student-management.git

Git normally creates a directory using the repository name. 

student-management/

You can then enter the directory: 

cd student-management

Clone into a custom folder 

git clone https://github.com/example/student-management.git my-project

Here, Git creates the local repository inside my-project.

4. What Do You Get After Cloning?

A clone gives you much more than just a ZIP file containing source code.

Working Files

The actual project files you can open and modify.

Git History

Existing commits and repository history.

Remote Connection

Usually configured with the remote named origin. 

cd student-management

git status

git remote -v

The git remote -v command lets you see the configured remote URLs.

5. Clone Using HTTPS or SSH

GitHub can provide different URLs for accessing a repository.

HTTPS 

git clone https://github.com/username/project.git

SSH 

git clone git@github.com:username/project.git
Method Example Common Use
HTTPS https://github.com/... Easy to start with
SSH git@github.com:... Convenient for configured developer environments

A typical workflow after cloning is:

7. What Is Forking?

A fork is a GitHub feature that creates your own copy of another user's repository under your GitHub account.

Original Repository Alice/project
→
Fork Your GitHub Account
→
Your Repository YourName/project

Forking happens on GitHub. It is not a Git command like git clone.

Important distinction:

Clone creates a local copy on your computer.
Fork creates a separate repository under your GitHub account.

8. Clone vs Fork

📥 Clone

  • Creates a local copy.
  • Happens using Git.
  • Used to get a repository onto your computer.
  • Usually keeps a remote named origin.
  • Common for working with repositories you can access directly.

🍴 Fork

  • Creates a GitHub repository under your account.
  • Happens through GitHub.
  • Common when contributing to repositories where you do not have direct write access.
  • Your fork is separate from the original repository.
  • You can then clone your fork to your computer.
Feature Clone Fork
Where? Your computer GitHub account
Main action Copies repository locally Creates your GitHub copy
Git command? Yes No
Typical command git clone GitHub Fork button

9. When Should You Clone or Fork?

Clone Directly

Use cloning when you have the required access to work directly with the repository.

Fork First

Fork a repository when you need your own GitHub copy, especially for contributing to projects where you do not have direct write access.

Fork + Clone

A common open-source workflow is: fork on GitHub, then clone your fork locally.

10. Fork → Clone → Work → Push

Imagine you want to contribute to an open-source project.

1 Fork original repository
→
2 Clone your fork
→
3 Create changes
→
4 Commit
→
5 Push

Clone your fork 

git clone https://github.com/yourname/project.git

cd project

Make a change 

git add .
git commit -m "Improve documentation"
git push origin main

After pushing, your changes are available in your fork on GitHub.

11. The Upstream Remote

In a fork-based workflow, you commonly work with two remotes:

  • origin → your fork
  • upstream → original repository
Original upstream
→
Your Fork origin

Add the original repository as upstream 

git remote add upstream https://github.com/original-owner/project.git

Check your remotes 

git remote -v

Get updates from upstream 

git fetch upstream
Remember:

origin is usually your fork.
upstream usually refers to the original repository you forked from.

12. Keeping a Fork Updated

Suppose the original project has received new commits. You may want to bring those changes into your local copy.

First fetch the original repository: 

git fetch upstream

You can then inspect the branches: 

git branch -a

A common next step is to integrate the upstream branch into your local branch using your team's preferred merge or rebase workflow.

The exact command sequence for synchronizing a fork can vary depending on your branch structure and whether your team uses merge or rebase. Understand the history before rewriting commits.

13. Common Mistakes

Wrong Repository URL

Always copy the repository URL carefully from GitHub.

Cloning Inside Wrong Folder

Check your current directory before running git clone.

Confusing Fork and Clone

A fork is a GitHub copy. A clone is a local copy.

Pushing to Wrong Remote

Run git remote -v before pushing if you are unsure where your changes will go.

Forgetting Upstream

In fork workflows, remember that origin and upstream serve different purposes.

Treating GitHub as Git

Git is the version-control system. GitHub is a hosting and collaboration platform.

14. Command Summary

Command Purpose

git remote -v Show remote URLs
git remote add upstream URL Add the original repository as upstream
git fetch upstream Download changes from the upstream remote
git branch -a Show local and remote-tracking branches
git push origin main Push local main to your origin remote

18. Lesson Takeaway

Cloning and forking are two important ways to work with existing GitHub projects.

  • git clone creates a local copy of an existing repository.
  • A clone contains the project files and Git history.
  • Cloning can use HTTPS or SSH URLs.
  • A GitHub fork creates your own repository copy under your GitHub account.
  • Forking is especially common when contributing to projects where you do not have direct write access.
  • A common open-source workflow is: Fork → Clone → Work → Commit → Push.
  • In a fork workflow, origin commonly refers to your fork.
  • upstream commonly refers to the original repository.
  • git fetch upstream can retrieve updates from the original repository.
  • Always check git remote -v when you are unsure where your changes will be pushed.
