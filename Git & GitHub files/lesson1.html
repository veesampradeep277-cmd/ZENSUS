Introduction to Git & GitHub

Learn what Git and GitHub are, why developers use them, how version control works, how repositories track code, and how Git connects your local projects to GitHub.

01

What is Git?

Git is a distributed version control system used to track changes in files and source code.

It allows developers to save different versions of their work, compare changes, recover previous versions, create branches, and collaborate safely with other developers.

Simple Definition

Git = A tool that tracks changes in your project.

Example

Imagine you are developing a Python project. You change your code today, make another change tomorrow, and accidentally break something. Without version control, finding the old working version can be difficult.

With Git, you can record meaningful versions of your project and move back through its history when necessary.

Project
→
Changes
→
Git
→
History

03

What is Version Control?

Version control is a system for recording and managing changes made to files over time.

Example Timeline

Version 1
Initial Code
→
Version 2
Login Added
→
Version 3
Dashboard Added
→
Version 4
Bug Fixed

Each meaningful point in the project's history can be recorded. Git calls these saved points commits.

Three Major Benefits

  1. Track: Know what changed.
  2. Compare: Compare different versions.
  3. Recover: Return to previous states when appropriate.
04

Why is Git Called Distributed?

Git is a distributed version control system. Each developer can have a complete copy of the repository, including its history.

Developer A
💻 Local Repository
↔
☁️ Shared Repository
↔
Developer B
💻 Local Repository

Developers can work locally and synchronize changes when required.

Key idea: Git does not require you to be continuously connected to the internet to make commits and manage your local project history.
05

What is GitHub?

GitHub is a platform for hosting Git repositories and supporting collaboration around software projects.

It provides online repositories where developers can store, share and collaborate on code.

Simple Definition

Git = version control tool

GitHub = online platform built around Git repositories

GitHub Provides Features Such As

☁️

Repositories

Host project code online.

🔀

Pull Requests

Propose and review changes.

🐛

Issues

Track bugs, tasks and improvements.

⚙️

Actions

Automate workflows such as testing and deployment.

06

Git vs GitHub

Git GitHub
Version control system Platform for Git repositories
Runs on your computer Primarily accessed online
Tracks project history Hosts and shares repositories
Works locally Supports remote collaboration
Command-line/tool Web platform + services
Important: Git and GitHub are not the same thing. You can use Git without GitHub.

The Four Important Ideas

  • Working directory: where you edit your files.
  • Staging area: where you prepare selected changes.
  • Local repository: where Git stores committed history.
  • Remote repository: a shared repository hosted elsewhere.
08

What is a Repository?

A repository, commonly called a repo, is a project managed by Git.

It contains your project files along with Git's information about the project's history.

Example Project

Project Structure 
student-management/
│
├── app.py
├── students.py
├── database.py
├── requirements.txt
├── README.md
│
└── .git/
    └── Git repository data
The .git directory is created when Git initializes a repository. It contains Git's internal repository information.

Two Common Types

Local Repository

Stored on your computer.

Remote Repository

Hosted on a remote service such as GitHub.

09

How Git Tracks Changes

Suppose you start with:

app.py 
print("Hello World")

Later you change it to:

app.py 
print("Hello ZENSUS")

Git can identify that the file changed.

Git Status

Terminal 
$ git status

modified: app.py

This tells you that Git has detected a modification.

Git does not automatically commit every change. You decide which changes should become part of a commit.
10

What is a Commit?

A commit is a recorded snapshot of selected project changes.

Think of a Commit Like a Checkpoint

Write Code
→
Test Code
→
Commit
→
Checkpoint

Example Commit

Git 
$ git add app.py

$ git commit -m "Add welcome message"

[main 7ac31d2] Add welcome message
 1 file changed

Good Commit Message

Example 
git commit -m "Add student registration form"

Bad Commit Messages

Avoid vague messages 
git commit -m "changes"
git commit -m "update"
git commit -m "asdf"
A useful commit message should tell another developer what changed.

Git & GitHub for Collaboration

Git becomes especially useful when multiple developers work on the same project.

👨‍💻
Developer A
↘
☁️
GitHub
↙
👩‍💻
Developer B

Typical Team Workflow

  1. Clone the repository.
  2. Create or switch to a working branch.
  3. Make changes.
  4. Check the changes.
  5. Stage the changes.
  6. Commit the changes.
  7. Push the branch.
  8. Create a pull request.
  9. Review the changes.
  10. Merge the approved work.

Branches and pull requests will be covered in detail in later lessons.

Important Git Commands
