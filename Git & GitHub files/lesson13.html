GitHub Actions & Basic CI/CD

Learn how GitHub Actions automates development tasks, how CI/CD works, how workflow files are written, and how a repository can automatically build, test, and validate code whenever changes are made.

1. What Is Automation?

Automation means using software to perform repetitive tasks automatically instead of doing them manually.

In software development, teams repeatedly perform tasks such as:

🧪 Testing

Run automated tests whenever code changes.

🔨 Build

Automatically build an application or package.

🔍 Quality Checks

Run linting, formatting, or static analysis.

🚀 Deployment

Automatically deliver software to an environment.

Simple idea:

Instead of saying:
"Every time someone pushes code, a developer should manually run all tests."

Automation says:
"When code is pushed, run the tests automatically."

2. What Is CI/CD?

CI means Continuous Integration.

CD can mean Continuous Delivery or Continuous Deployment, depending on the workflow.

Continuous Integration

Developers frequently integrate code changes into a shared repository and automated checks validate those changes.

Continuous Delivery

Software is kept in a state where it can be released when the team decides to deploy it.

Continuous Deployment

Changes that pass the required pipeline can be automatically deployed.

CI/CD Flow

Code Developer changes code
→
Push Send changes to GitHub
→
Build Prepare application
→
Test Run automated checks
→
Deploy Release if configured

3. What Is GitHub Actions?

GitHub Actions is GitHub's automation platform. It allows you to create workflows that run when specified events happen in a repository.

A workflow can automatically:

  • run tests
  • build applications
  • check code quality
  • create packages or artifacts
  • perform deployment tasks
  • execute scheduled maintenance tasks
Important: GitHub Actions does not replace Git.

Git manages version history.
GitHub hosts and collaborates around repositories.
GitHub Actions automates tasks around the repository.

4. What Is a Workflow?

A workflow is an automated process defined using a YAML file.

GitHub Actions workflow files are stored inside: 

.github/workflows/

For example: 

.github/
└── workflows/
    └── python-ci.yml

Workflow Structure

1
Name Workflow identity
2
Trigger When it runs
3
Jobs Units of work
4
Steps Commands/actions
5
Runner Machine executing work

5. Events & Triggers

A workflow needs to know when it should run. The event configuration determines that.

Trigger Meaning Example
push Run when commits are pushed. Validate new code.
pull_request Run when a pull request event occurs. Test proposed changes.
workflow_dispatch Allow a workflow to be started manually. Manual deployment or test.
schedule Run according to a schedule. Periodic maintenance. 
on:
  push:
  pull_request:

This configuration tells GitHub to run the workflow for push and pull request events.

6. Jobs & Steps

A workflow contains one or more jobs. Each job contains one or more steps.

Workflow Entire automation
→
Job Unit of work
→
Step Individual action

Example 

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Get the code
        uses: actions/checkout@v4

      - name: Run tests
        run: npm test
Keyword Meaning
jobs Defines jobs in the workflow.
runs-on Selects the runner environment.
steps Lists actions or commands executed by the job.
uses Uses an existing GitHub Action.
run Executes a shell command.

7. What Is a Runner?

A runner is the machine that executes the steps of a GitHub Actions job.

For example: 

runs-on: ubuntu-latest

Common GitHub-hosted runner families include Linux, Windows, and macOS environments.

Linux

Common choice for web applications and backend testing.

Windows

Useful for Windows-specific applications and tooling.

macOS

Useful when workflows require Apple development environments.

8. YAML Basics

GitHub Actions workflows are normally written using YAML.

YAML uses indentation to represent structure. 

name: Example Workflow

on:
  push:

jobs:
  test:
    runs-on: ubuntu-latest

    steps:
      - name: Say hello
        run: echo "Hello from GitHub Actions"
Be careful with indentation.

YAML structure depends heavily on indentation. Incorrect spacing can cause a workflow configuration error.

Important YAML Ideas

  • Key-value pairs use key: value.
  • Nested content uses indentation.
  • Lists commonly use -.
  • Strings can often be written without quotes, depending on their content.
  • Keep indentation consistent.

9. Your First CI Workflow

Suppose we have a Node.js project and want GitHub to run tests whenever code is pushed or a pull request is opened.

Step 1 — Create the directory 

.github/workflows/

Step 2 — Create a workflow file

For example: 

.github/workflows/ci.yml

Step 3 — Add the workflow 

name: Node.js CI

on:
  push:
  pull_request:

jobs:
  test:

    runs-on: ubuntu-latest

    steps:

      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Node.js
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install dependencies
        run: npm ci

      - name: Run tests
        run: npm test

What Happens?

1
Push code Developer pushes a commit to GitHub.
2
GitHub detects the event The push matches the workflow trigger.
3
Runner starts GitHub provides the configured execution environment.
4
Dependencies install The project dependencies are installed.
5
Tests run Automated tests check the code.

10. Python CI Example

GitHub Actions can also be used for Python projects.

A simple workflow can install Python, install dependencies, and run tests. 

name: Python CI

on:
  push:
  pull_request:

jobs:

  test:

    runs-on: ubuntu-latest

    steps:

      - name: Checkout repository
        uses: actions/checkout@v4

      - name: Setup Python
        uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Install dependencies
        run: |
          python -m pip install --upgrade pip
          pip install -r requirements.txt

      - name: Run tests
        run: pytest
Why this is useful: Every push or pull request can automatically check whether the Python project still passes its tests.

11. Secrets & Sensitive Information

CI/CD workflows sometimes need sensitive values such as:

  • API keys
  • deployment credentials
  • database passwords
  • access tokens

Sensitive values should not be hard-coded directly into workflow files or source code.

Using a Secret 

env:
  API_KEY: ${{ secrets.API_KEY }}
Security rule: Never commit passwords, private keys, access tokens, or other sensitive credentials directly into a repository.

12. Understanding Workflow Results

After a workflow runs, GitHub shows whether the jobs and steps succeeded or failed.

Result Meaning
Success Required workflow steps completed successfully.
Failure One or more required steps failed.
Cancelled The workflow execution was stopped.
Skipped A job or step did not run because its conditions were not met.

Why CI Failure Matters

A failed test workflow can provide an early signal that a change needs attention before it is merged or released.

13. Actions vs Commands

A workflow step can use an existing action or execute a shell command.

Type Example Purpose
Action uses: actions/checkout@v4 Reuse a packaged automation component.
Command run: pytest Execute a shell command.
Think of it this way:

uses → use an existing action.
run → execute your command.

14. Common GitHub Actions Mistakes

Mistake Problem Better Approach
Wrong YAML indentation Workflow may not parse correctly. Check indentation carefully.
Wrong workflow location GitHub will not treat the file as a workflow. Use .github/workflows/.
Missing checkout Job may not have the repository files available. Use actions/checkout when needed.
Hard-coded secrets Sensitive information can be exposed. Use GitHub secrets or appropriate secure configuration.
Wrong runtime version Tests may fail because the environment differs. Configure the required runtime version explicitly.
Testing only locally Local and CI environments can differ. Keep automated CI checks consistent with project needs.

19. Lesson Takeaway

GitHub Actions allows developers to automate repetitive development tasks directly from their GitHub repositories.

  • Automation reduces repetitive manual work.
  • CI automatically validates integrated code changes.
  • CD extends automation toward reliable delivery or deployment.
  • GitHub Actions executes automated workflows.
  • Workflow files are normally stored inside .github/workflows/.
  • A workflow contains jobs, and jobs contain steps.
  • uses invokes an existing action, while run executes a command.
  • Runners provide the environment in which jobs execute.
  • Secrets should be handled securely rather than hard-coded.
