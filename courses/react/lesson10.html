02. Forms in React

React applications usually need more control over form values. Instead of letting the DOM be the only source of truth, React can store the current input value inside component state. 

import { useState } from "react";

function LoginForm(){

    const [email, setEmail] =
        useState("");

    return (

        <input
            type="email"
            value={email}
            onChange={event =>
                setEmail(event.target.value)
            }
        />

    );

}
Core idea:

The input displays state, and user actions update that state.

03. Controlled Components

A controlled input is an input whose value is controlled by React state. 

const [name, setName] = useState("");

<input
    value={name}
    onChange={e =>
        setName(e.target.value)
    }
/>
CONTROLLED COMPONENT LOOP
User Types interaction
→
onChange event
→
setState() update
→
Render React
↺
Input new value
React State
""
Rendered Input
<input value={state} />
Think of it like this:

State → Input
State determines what the user sees.

Input → State
User interaction updates the state.

04. Input State

Each form control can have its own state, or multiple fields can share one object state.

Separate state variables

const [name, setName] = useState("");
const [email, setEmail] = useState("");
const [age, setAge] = useState(0);

Object state

const [form, setForm] = useState({

    name: "",
    email: "",
    age: ""

});

For larger forms, an object can make the form data easier to organize.

06. Number Inputs

HTML gives us type="number", but remember that event.target.value is still received as a string. 

const [age, setAge] = useState("");

function handleAgeChange(e){

    setAge(e.target.value);

}

If you need a number for calculations, convert it explicitly. 

const numericAge =
    Number(age);
Common mistake:

Don't assume every value from an HTML input is automatically a JavaScript number.

11. Multiple Inputs

A professional form usually contains many fields. A common pattern is to keep all values inside one object. 

const [form, setForm] = useState({

    name: "",
    email: "",
    password: ""

});

function handleChange(e){

    const { name, value } =
        e.target;

    setForm(prev => ({

        ...prev,

        [name]: value

    }));

}

Why [name]: value?

The square brackets create a computed property name. It allows one handler to update different fields dynamically. 

name = "email"

{
    ...form,
    [name]: value
}

↓ becomes

{
    ...form,
    email: value
}
Professional pattern:

One handleChange() function can manage many text-like inputs when each input has a meaningful name.

13. preventDefault()

By default, a traditional HTML form submission can cause browser navigation/reload behavior. React applications commonly prevent that default behavior and handle submission in JavaScript. 

function handleSubmit(e){

    e.preventDefault();

    // React handles submission here

}
Important distinction:

preventDefault() prevents the browser's default action. It does not stop event propagation.

14. Form Validation

Validation checks whether the submitted data satisfies your rules before you process it.

Simple validation

function validate(){

    const errors = {};

    if(!form.name.trim()){

        errors.name =
            "Name is required";

    }

    if(!form.email.includes("@")){

        errors.email =
            "Enter a valid email";

    }

    return errors;

}

Typical validation pipeline

VALIDATION PIPELINE
Input raw data
→
Validate rules
→
Errors? yes / no
→
Submit valid data

15. Error Messages

Good forms don't simply say "invalid". They tell users what needs to be fixed. 

const [errors, setErrors] =
    useState({});

...

{errors.email && (

    <p className="error">
        {errors.email}
    </p>

)}

Good Error

"Password must contain at least 8 characters."

Poor Error

"Invalid input."

UX principle:

Validation should guide the user toward a correction instead of merely telling them something went wrong.

17. Dynamic Forms

A dynamic form changes its fields based on user interaction. Examples include adding multiple skills, education entries, addresses or project records.

Example: Dynamic Skills

const [skills, setSkills] =
    useState([""]);

function addSkill(){

    setSkills(prev => [
        ...prev,
        ""
    ]);

}

function updateSkill(index, value){

    setSkills(prev =>
        prev.map((skill, i) =>
            i === index
                ? value
                : skill
        )
    );

}

function removeSkill(index){

    setSkills(prev =>
        prev.filter(
            (_, i) => i !== index
        )
    );

}

19. Common Form Mistakes

❌ Forgetting value

<input
    onChange={handleChange}
/>

This doesn't make the input controlled. A controlled text input normally connects value with state.

❌ Wrong checkbox property

checked={accepted}

onChange={e =>
    setAccepted(e.target.value)
}

For a checkbox, use e.target.checked.

❌ Forgetting preventDefault()

function handleSubmit(e){

    // missing

}

If you intend to handle the submission entirely in React, prevent the browser's default submit behavior.

❌ Mutating form state

form.name = "Pradeep";

Don't directly mutate React state. Use the setter.

❌ Number assumption

const age =
    e.target.value;

Input values arrive as strings. Convert when your application needs a number.

❌ Missing name attributes

<input
    value={form.email}
/>

If you use a generic multi-input handler based on e.target.name, the input needs a matching name.

❌ Over-validating too early

Showing aggressive errors on every keystroke can create a poor user experience. Choose validation timing intentionally.

❌ Treating client validation as security

Users can bypass browser-side JavaScript. Important validation must also happen on the server.
