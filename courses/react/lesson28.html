1. Frontend vs Backend

A modern web application is usually divided into multiple layers. React normally handles the user interface while the backend handles business logic, authentication, APIs and data access.

Frontend

The frontend is the part of the application that runs in the user's browser. React is commonly used to create this layer.

  • UI components
  • Forms
  • Buttons
  • Navigation
  • Client-side state
  • API requests
  • Displaying backend data

Backend

The backend runs on a server and processes requests from the frontend. It controls application logic and communicates with databases.

  • Business logic
  • Authentication
  • Authorization
  • REST APIs
  • Database operations
  • Validation
  • Security
Important idea:

React should not normally connect directly to a production database. The frontend communicates with a backend API, and the backend communicates with the database.

2. REST API Architecture

REST stands for Representational State Transfer. A REST API exposes resources through URLs and uses HTTP methods to perform operations.

GET

Retrieve data from the server.

POST

Create new data.

PUT / PATCH

Update existing data.

DELETE

Remove data.

Request

Information sent by the client.

Response

Information returned by the server.

Example API endpoints

POST    /api/users

PUT     /api/users/42

What is an endpoint?

An endpoint is a specific URL through which the frontend communicates with a backend operation.

For example: 

https://api.example.com/api/users

4. Connecting React to a Backend

React can communicate with a backend using browser networking APIs such as fetch or libraries such as Axios.

Basic fetch request

React component
import { useEffect, useState } from "react";

function Users() {

    const [users, setUsers] = useState([]);

    useEffect(() => {

        fetch("http://localhost:5000/api/users")
            .then(response => response.json())
            .then(data => {
                setUsers(data);
            });

    }, []);

    return (
        <div>

            {users.map(user => (
                <p key={user.id}>
                    {user.name}
                </p>
            ))}

        </div>
    );
}

export default Users;

The important sequence is:

fetch() Send request
→
Backend Process request
→
JSON Return response
→
React State Update UI

5. Fetching Data

Fetching means requesting information from a backend server. Because network requests are asynchronous, React applications must handle the request lifecycle.

Modern async/await approach

GET request
async function loadUsers() {

    const response = await fetch(
        "http://localhost:5000/api/users"
    );

    const data = await response.json();

    console.log(data);
}

Checking response status

Important production pattern
async function loadUsers() {

    const response = await fetch(
        "http://localhost:5000/api/users"
    );

    if (!response.ok) {
        throw new Error("Failed to load users");
    }

    const data = await response.json();

    return data;
}
Why check response.ok?

fetch() does not automatically reject its promise for normal HTTP error responses such as 404 or 500. You should check the response status before treating the response as successful.

6. Sending Data to Backend

Frontend applications often send user-entered information to a backend. POST requests are commonly used when creating new resources.

POST request
async function createUser(user) {

    const response = await fetch(
        "http://localhost:5000/api/users",
        {
            method: "POST",

            headers: {
                "Content-Type": "application/json"
            },

            body: JSON.stringify(user)
        }
    );

    if (!response.ok) {
        throw new Error("Could not create user");
    }

    return await response.json();
}

Why JSON.stringify()?

JavaScript objects must be serialized into a JSON string before being sent as a JSON request body. 

const user = {
    name: "Pradeep",
    email: "student@example.com"
};

JSON.stringify(user);

7. CRUD Operations

CRUD represents the four fundamental data operations performed by most applications.

CREATE POST
READ GET
UPDATE PUT / PATCH
DELETE DELETE

Complete CRUD example

API service functions
const API = "http://localhost:5000/api/users";


export async function getUsers() {

    const response = await fetch(API);

    if (!response.ok)
        throw new Error("Failed to fetch users");

    return response.json();
}


export async function createUser(user) {

    const response = await fetch(API, {

        method: "POST",

        headers: {
            "Content-Type": "application/json"
        },

        body: JSON.stringify(user)
    });

    if (!response.ok)
        throw new Error("Failed to create user");

    return response.json();
}


export async function updateUser(id, user) {

    const response = await fetch(`${API}/${id}`, {

        method: "PUT",

        headers: {
            "Content-Type": "application/json"
        },

        body: JSON.stringify(user)
    });

    if (!response.ok)
        throw new Error("Failed to update user");

    return response.json();
}


export async function deleteUser(id) {

    const response = await fetch(`${API}/${id}`, {

        method: "DELETE"
    });

    if (!response.ok)
        throw new Error("Failed to delete user");

    return response.json();
}

8. Authentication

Authentication determines whether a user is logged in. Authorization determines what an authenticated user is allowed to access.

Authentication

"Who are you?"

Example:

  • Email + password
  • Session
  • Access token
  • OAuth

Authorization

"What are you allowed to do?"

Example:

  • Student
  • Instructor
  • Admin

Typical login flow

Login Form React
→
POST /login API
→
Backend Verify credentials
→
Token / Session Authentication

Sending an authenticated request

const response = await fetch(
    "http://localhost:5000/api/profile",
    {
        headers: {
            Authorization: `Bearer ${token}`
        }
    }
);
Security principle:

Never place database passwords, private API keys, or server secrets inside React client-side code. Anything shipped to the browser can potentially be inspected by users.

9. API Services

Instead of putting fetch logic inside every component, applications can create a dedicated service layer.

src/
├── components/
├── pages/
├── services/
│ ├── api.js
│ ├── userService.js
│ └── authService.js
├── hooks/
├── context/
└── App.jsx

userService.js

const API_URL =
    import.meta.env.VITE_API_URL;


export async function getUsers() {

    const response = await fetch(
        `${API_URL}/users`
    );

    if (!response.ok) {
        throw new Error("Unable to load users");
    }

    return response.json();
}

Using the service inside React

import { useEffect, useState } from "react";
import { getUsers } from "./services/userService";

function Users() {

    const [users, setUsers] = useState([]);

    useEffect(() => {

        getUsers()
            .then(setUsers)
            .catch(console.error);

    }, []);

    return (
        <div>
            {users.map(user => (
                <p key={user.id}>
                    {user.name}
                </p>
            ))}
        </div>
    );
}

10. Environment Variables

Environment variables allow configuration values to be separated from application source code.

Vite example

.env
VITE_API_URL=http://localhost:5000/api
React
const API_URL =
    import.meta.env.VITE_API_URL;

Important:

Frontend environment variables are not automatically secret. Values exposed to browser code can be discovered by inspecting the built application. Server-only secrets must stay on the backend.

11. CORS

CORS stands for Cross-Origin Resource Sharing. It controls whether a browser allows frontend JavaScript from one origin to access resources from another origin.

React Request
localhost:5173 Frontend
↔
localhost:5000 Backend

Why can this happen?

During development, your React development server and backend may run on different origins, such as different ports. The browser applies its same-origin security rules.

Backend solution concept

Express example
import cors from "cors";

app.use(cors({
    origin: "http://localhost:5173"
}));
Remember:

CORS is primarily a browser security mechanism. It is not the same thing as authentication or authorization.

12. Error Handling

Network requests can fail for many reasons: server errors, invalid input, unavailable networks, authentication failures or incorrect URLs.

try / catch / finally
async function loadUsers() {

    try {

        setLoading(true);
        setError("");

        const response = await fetch(
            "/api/users"
        );

        if (!response.ok) {
            throw new Error(
                `HTTP Error: ${response.status}`
            );
        }

        const data = await response.json();

        setUsers(data);

    } catch (error) {

        setError(error.message);

    } finally {

        setLoading(false);

    }
}

Error categories

400

Bad request or invalid input.

401

Authentication required or failed.

403

Request is not permitted.

404

Requested resource was not found.

500

Server-side failure.

Network Error

Connection could not be completed.

13. Loading States

Users should receive feedback while asynchronous operations are in progress.

Loading...
→
Data Loaded
or
Request Failed

React state pattern

const [loading, setLoading] = useState(false);
const [error, setError] = useState(null);
const [data, setData] = useState([]);


async function loadData() {

    try {

        setLoading(true);
        setError(null);

        const response =
            await fetch("/api/users");

        if (!response.ok) {
            throw new Error("Request failed");
        }

        const result =
            await response.json();

        setData(result);

    } catch (err) {

        setError(err.message);

    } finally {

        setLoading(false);

    }
}

14. Backend Response Handling

A backend commonly returns JSON together with an HTTP status code. React needs to interpret both the status and response body.

Example successful response

{
    "success": true,
    "message": "Users loaded successfully",
    "data": [
        {
            "id": 1,
            "name": "Pradeep"
        },
        {
            "id": 2,
            "name": "Rahul"
        }
    ]
}

React handling

const response = await fetch("/api/users");

const result = await response.json();

if (!response.ok) {
    throw new Error(
        result.message || "Request failed"
    );
}

setUsers(result.data);
Good API design:

Use predictable response structures so frontend components can reliably handle success, errors and returned data.

    ↓

Rows returned

    ↓

    ↓

    ↓

Why not connect React directly to the database?

Security

Database credentials must not be exposed to browsers.

Business Logic

Validation and application rules belong on the server.

Authorization

The backend can control which operations a user may perform.

Abstraction

The frontend can consume an API without knowing database details.

18. Common Mistakes

01 — Hard-coding API URLs everywhere

Create a central API configuration or service layer.

02 — Not checking response.ok

A fetch request can resolve even when the server returns an HTTP error status.

03 — Forgetting JSON.stringify()

When sending JSON request bodies, serialize the JavaScript object.

04 — Ignoring loading state

Users need feedback while asynchronous requests are running.

05 — Exposing backend secrets

Never put database passwords or private server credentials into browser code.

06 — Confusing CORS with authentication

CORS controls browser cross-origin access; authentication identifies users.

07 — Putting every API request inside components

A service layer can improve reuse, organization and maintainability.

08 — Direct database access from React

Use a backend layer to protect credentials and enforce application logic.
