2. Registration

Registration allows a new user to create an account. 

const handleRegister = async (formData) => {

```
const response =
    await fetch("/api/auth/register", {

        method: "POST",

        headers: {
            "Content-Type":
                "application/json"
        },

        body: JSON.stringify(formData)
    });

if (!response.ok) {
    throw new Error(
        "Registration failed"
    );
}

return response.json();
```

};

Name

User's display name or profile information.

Email

Usually used as the account identifier.

Password

Sent securely over HTTPS and handled by the server.

Server Validation

The backend must validate all registration data.

Critical: Never store plain-text passwords in your React application or database. Password hashing belongs on the backend.

4. Logout

Logout ends the authenticated session and returns the user to a public state. 

const logout = async () => {

```
await fetch("/api/auth/logout", {
    method: "POST",
    credentials: "include"
});

setUser(null);
```

};
Logout should clear the application's authenticated state. Depending on the authentication architecture, the server may also invalidate or expire the session.

5. Authentication State

React needs a reliable source of truth for whether a user is authenticated. 

const AuthContext = createContext(null);

function AuthProvider({ children }) {

```
const [user, setUser] =
    useState(null);

const [loading, setLoading] =
    useState(true);

const value = {
    user,
    setUser,
    loading
};

return (
    <AuthContext.Provider value={value}>
        {children}
    </AuthContext.Provider>
);
```

}

Typical Authentication State

State Meaning
user = null No authenticated user is known.
user = object User is authenticated.
loading = true Application is checking the existing session.
error Authentication operation failed.

6. Protected Routes

A protected route should only render its content for an authenticated user. 

function ProtectedRoute({ children }) {

```
const { user, loading } =
    useAuth();

if (loading) {
    return <Loading />;
}

if (!user) {
    return <Navigate to="/login" />;
}

return children;
```

}
Request Route
→
Checking Auth
→
Authenticated?

YES Dashboard
or
NO Login
Route protection in the frontend improves user experience, but it is not a security boundary. The backend must enforce authorization for protected data and operations.

8. User Profile

Profile information should normally come from the authenticated user's account data. 

async function getProfile() {

```
const response =
    await fetch("/api/users/me", {
        credentials: "include"
    });

if (!response.ok) {
    throw new Error(
        "Unable to load profile"
    );
}

return response.json();
```

}
Use an endpoint such as /api/users/me when the backend needs to determine the currently authenticated user from the session rather than trusting a user ID supplied by the browser.

10. Token Handling

Modern authentication can use sessions or token-based approaches.

Session Cookie

The browser sends a cookie with requests and the server maintains session state.

JWT Access Token

A signed token can represent claims that the server verifies.

Refresh Token

Can be used in architectures that issue short-lived access tokens.

There is no universal "best" token-storage method for every architecture. For browser applications, HttpOnly Secure cookies are commonly used to reduce JavaScript access to session credentials, while cookie-based authentication also requires appropriate CSRF defenses. 
// Cookie-based request example

const response = await fetch("/api/dashboard", {
credentials: "include"
});
Important: Do not casually put long-lived sensitive authentication credentials into localStorage. If malicious JavaScript executes in the origin, JavaScript-readable storage can be accessed by that code.

11. Error Handling

Authentication errors should be handled deliberately.

Situation User Experience
Invalid credentials Show a generic sign-in failure.
Email already registered Explain that the account already exists.
Network failure Ask the user to retry.
Session expired Return the user to authentication flow.
Server error Show a friendly temporary-error message. 
try {

```

```

} catch (error) {

```
setError(
    "Unable to sign in. Check your details and try again."
```

Avoid revealing unnecessary information such as whether a particular email address exists in your database when that information could assist account enumeration.

The initial loading state is important. Without it, an application may briefly render a login page before discovering that the user already has a valid session.

13. Production Considerations

🔒 HTTPS Use encrypted transport for authentication traffic.
🧂 Password Hashing Passwords must be securely hashed on the server.
🍪 Secure Cookies Use appropriate Secure, HttpOnly and SameSite settings where cookies are used.
🛡️ CSRF Protection Cookie-based authentication needs an appropriate CSRF defense strategy.
⏱️ Session Expiration Sessions should have an appropriate lifetime and revocation strategy.
🚦 Rate Limiting Login and registration endpoints should be protected against abuse.
📋 Server Validation Never trust validation performed only in React.
🧹 Sensitive Logs Do not log passwords, tokens or unnecessary personal data.
Remember: React is a client. It cannot enforce backend security by itself. Every protected API endpoint must independently verify authentication and authorization.

18. Common Mistakes

❌ Frontend-Only Authentication

Hiding a button or route does not secure backend data.

❌ Plain-Text Passwords

Passwords must never be stored as plain text.

❌ Trusting User IDs

The server must derive identity from trusted authentication context.

❌ No Session Check

Refreshing the application can incorrectly make a user appear logged out.

❌ Exposing Tokens

Be deliberate about where browser authentication credentials are stored.

❌ Ignoring Logout

Logout must update both client authentication state and the appropriate server session.

20. Quick Quiz

1. What is authentication?
Authentication verifies who a user is.
2. What is authorization?
Authorization determines what an authenticated user is allowed to access or perform.
3. Why do we need Protected Routes?
They control what UI an unauthenticated user can access, improving application flow. Backend authorization is still required for real security.
4. Why should passwords never be stored in React?
React runs in the browser and is not a secure place to store server-side password records. Password handling and hashing belong on the backend.
5. Why is an initial authentication loading state useful?
It prevents the application from making routing decisions before it has finished checking the existing session.
6. Is frontend route protection enough to secure an API?
No. Every protected backend endpoint must independently authenticate the request and enforce authorization.
