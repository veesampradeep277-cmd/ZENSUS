1. What is useCallback()?

useCallback() is a React Hook that caches a function definition between renders until its dependencies change.

Core idea: useCallback does not make the function itself magically faster. It can preserve the function's reference identity.
const handleClick = useCallback(() => { console.log("Button clicked"); }, []);

The function is created normally on the first render. On later renders, React can return the same cached function when the dependency array has not changed.

What does it NOT do?

❌ Does not stop parent rendering

The component containing useCallback can still render normally.

❌ Does not automatically improve everything

Adding useCallback everywhere can make code more complex without producing a meaningful performance benefit.

✅ Preserves function identity

Its major purpose is maintaining a stable function reference when appropriate.

2. Function References & Function Identity

To understand useCallback, you must understand that JavaScript functions are objects/values with identity. Two separately created functions are different references even when their code looks identical.

const first = () => console.log("Hello"); const second = () => console.log("Hello"); console.log(first === second); // false

Why? Because JavaScript created two different function objects.

3. Re-rendering in React

A React component can re-render when its state changes, its parent renders, or other reactive inputs change. A re-render means React executes the component function again.

State Changes
→
Component Executes
→

→

→
React Reconciles
function App() { ``` const [count, setCount] = useState(0); const handleClick = () => { console.log("clicked"); }; return ( <button onClick={handleClick}> {count} </button> ); ``` }

Every time App renders, the function expression assigned to handleClick is evaluated again.

Important: A new function reference does not automatically mean the browser will perform an expensive DOM update. React still compares the resulting UI. The performance concern becomes especially relevant when a function is passed as a prop to a memoized child.

5. React.memo

Before understanding useCallback + React.memo, understand what React.memo does.

const Child = React.memo(function Child({ onClick }) { ``` return ( <button onClick={onClick}> Click </button> ); ``` });

React.memo lets React skip rendering a child when its props are considered equal to their previous values.

Important: React.memo is about skipping unnecessary component renders based on props. It does not prevent the parent from rendering.

With useCallback

Because handleClick keeps the same reference while its dependencies are unchanged, a memoized Child can skip rendering when its other props also remain unchanged.

7. Dependency Array

The dependency array tells React when the cached callback should be considered out of date.

const handleClick = useCallback(() => { ``` console.log(userId); ``` }, [userId]);

If userId remains the same, React can reuse the callback reference. If userId changes, React creates a new callback that captures the new value.

Do not choose dependencies simply because you want fewer re-creations. Dependencies should represent the reactive values used by the callback. Incorrect dependencies can create stale values or incorrect behavior.

9. Performance Optimization

useCallback is an optimization tool, not a default requirement for every event handler.

Potential Benefit

Stable callback references can help memoized children avoid unnecessary renders when the callback is passed as a prop.

Potential Cost

React must track the callback and dependencies. Additional memoization also adds conceptual complexity.

Measure First

Optimization should be based on actual rendering behavior and performance evidence rather than automatically adding hooks everywhere.

Optimization chain

Expensive UI
→
Frequent Parent Renders
→
Callback Prop Changes
→
Memoized Child Re-renders
→
Investigate
→
Optimize
Professional rule: Do not think “useCallback = faster React.” Think: “Can a stable function reference prevent unnecessary work in this specific component tree?”

10. When to Use useCallback()

Good situations

  • A callback is passed to a child wrapped with React.memo.
  • The child is expensive to render.
  • The parent renders frequently.
  • The callback is used as a dependency where stable identity matters.
  • Profiling or analysis shows that callback identity is contributing to unnecessary work.

11. When NOT to Use useCallback()

Usually unnecessary

  • A tiny component has a simple button handler.
  • The callback is not passed to a memoized child.
  • The child is inexpensive to render.
  • There is no measurable performance issue.
  • You are adding it everywhere just because it is a React performance Hook.
Situation useCallback? Reason

12. Common useCallback() Mistakes

Mistake 1 — Using it everywhere

const handleA = useCallback(() => {}, []); const handleB = useCallback(() => {}, []); const handleC = useCallback(() => {}, []); const handleD = useCallback(() => {}, []);
Memoizing every function is not automatically a performance improvement. It can make the code harder to understand without meaningful benefit.

Mistake 2 — Forgetting dependencies

const handleClick = useCallback(() => { ``` console.log(count); ``` }, []);

If the callback needs the current count, an empty dependency list can cause the callback to retain an outdated captured value.

A dependency array is not a “performance setting.” It describes the values that determine when the callback needs to change.

Mistake 3 — Expecting useCallback to stop the parent render

useCallback stabilizes a callback reference. It does not stop the component that owns the callback from rendering.

Mistake 4 — Forgetting React.memo

If a child is not memoized and is rendered normally by a parent, stabilizing a callback prop may not produce the expected child-render optimization.

Mistake 5 — Confusing useCallback and useMemo

Hook What is cached? Typical purpose
useMemo A calculated value Avoid repeating an expensive calculation
useCallback A function reference Keep callback identity stable
// useMemo → caches a value const result = useMemo(() => calculate(data), [data]); // useCallback → caches a function const handle = useCallback(() => doSomething(data), [data]);

17. Quick Quiz

Test whether you understand the underlying mechanism instead of memorizing the syntax.

1. What does useCallback primarily preserve?
Answer: B — useCallback can preserve a function reference while its dependencies remain unchanged.
2. Why can a new callback cause a memoized child to render?
Answer: B — a newly created function is a different reference, so the callback prop can be considered changed.
3. What does React.memo primarily optimize?
Answer: C — React.memo allows a component to skip rendering when its props are unchanged according to its comparison.
4. Which statement is correct?
Answer: C — stable callback identity can matter when functions are passed to memoized children or used in other identity-sensitive situations.
5. What should dependencies represent?
Answer: B — dependencies describe the reactive values that the callback uses and that determine when its captured values may need updating.
6. Which situation usually does NOT justify useCallback by itself?
Answer: C — simple local handlers often gain little from memoization and may become unnecessarily complex.
