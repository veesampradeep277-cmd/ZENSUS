Lifting State Up
One Source of Truth

Learn how React components share information by moving state to their nearest common parent, passing values through props, passing event handlers downward, and allowing sibling components to communicate without directly talking to each other.

Sibling A
↘
Common Parent State
↙

1. Shared State

Sometimes two or more components need to work with the same piece of information. When that happens, keeping separate copies of the state can cause the UI to become inconsistent.

Example problem

Imagine a temperature converter with two components:

Temperature Input A

Stores Celsius.

Temperature Input B

Stores Fahrenheit.

Problem

Both need to stay synchronized.

If multiple components need to coordinate around the same state, ask: Which component should own that state?

Shared state means

A value is needed by more than one part of the component tree and those parts must stay consistent when the value changes.

2. The State Ownership Problem

React state belongs to the component where the Hook is called. A child cannot directly reach into a sibling's local state.

Parent
↓
Child A
↔
Child B

Suppose Child A owns:

const [count, setCount] = useState(0);

Child B cannot simply do:

// ❌ Child B cannot directly access Child A's local state count
Sibling components do not directly access each other's local state. React's data flow is primarily from parent to child through props.

The architectural question

Who needs the state?
If multiple siblings need it, their nearest common parent is often the appropriate place to own it.

3. What Is Lifting State Up?

Lifting state up means moving state from a child component into their closest common parent so that the parent can coordinate the shared value.

Child A
Owns state
↑
Common Parent
Owns state
↓
Child B
Receives state

Before lifting

Parent │ ├── Child A │ └── count state │ └── Child B └── needs count

After lifting

Parent │ ├── count state │ ├── Child A │ └── receives count + setter │ └── Child B └── receives count + setter
Core principle: Move state upward until it is owned by the lowest common ancestor that needs to coordinate that state.

4. Parent State

Once state is lifted, the parent becomes the owner of the shared value.

function Parent() { ``` const [count, setCount] = useState(0); return ( <> <ChildA count={count} /> <ChildB count={count} setCount={setCount} /> </> ); ``` }

The parent owns the state because both children need to participate in the same state.

5. Passing State Through Props

Once state lives in the parent, the parent can pass the current value to children through props.

function Parent() { ``` const [name, setName] = useState("Pradeep"); return ( <Profile name={name} /> ); ``` }

The child receives:

function Profile({ name }) { ``` return ( <h2>Hello {name}</h2> ); ``` }
Data flow: Parent State → Props → Child

Props are read-only from the receiving component's perspective. The child should not mutate the prop directly.

6. Passing Setter Functions

A child sometimes needs to request a change to state owned by its parent. The parent can pass a state setter or, often preferably, a purpose-specific callback function.

Passing the setter

function Parent() { ``` const [count, setCount] = useState(0); return ( <Child count={count} setCount={setCount} /> ); ``` }

Child calls it

function Child({ count, setCount }) { ``` return ( <button onClick={() => setCount(value => value + 1) } > {count} </button> ); ``` }

Often better — pass a purpose-specific callback

function Parent() { ``` const [count, setCount] = useState(0); const increment = () => setCount(value => value + 1); return ( <Child count={count} onIncrement={increment} /> ); ``` }
A semantic callback such as onIncrement can make the child's responsibility clearer and prevent the child from knowing unnecessary details about how the parent stores its state.

7. Sibling Communication

Sibling communication is one of the most important reasons for lifting state.

Sibling A
↓
Common Parent
State + Handler
↓
Sibling B

Notice that A and B are not directly communicating. The parent coordinates the communication.

Example

function Parent() { ``` const [message, setMessage] = useState(""); return ( <> <Sender onSend={setMessage} /> <Receiver message={message} /> </> ); ``` }
function Sender({ onSend }) { ``` return ( <button onClick={() => onSend("Hello from Sender") } > Send Message </button> ); ``` }
function Receiver({ message }) { ``` return ( <p>{message}</p> ); ``` }

Sibling A → Callback → Parent State → Props → Sibling B

8. Controlled Components

A controlled component is a component whose important input value is controlled by React state.

Controlled input

function App() { ``` const [name, setName] = useState(""); return ( <input value={name} onChange={event => setName(event.target.value) } /> ); ``` }
User Types

onChange

Parent State

The React state becomes the source of truth for the controlled value.

9. State Synchronization

Lifting state helps prevent multiple independent copies of the same concept from drifting apart.

Problem — duplicated state

// ❌ Two components independently track the same concept ChildA: const [selected, setSelected] = useState(false); ChildB: const [selected, setSelected] = useState(false);

Now one component can change while the other remains unchanged.

Better architecture

// Parent owns one source of truth const [selected, setSelected] = useState(false);
One state value → multiple consumers → synchronized UI.

10. Practical Example — Temperature Converter

Let's build a classic example where two inputs must stay synchronized.

Parent component

function Calculator() { ``` const [temperature, setTemperature] = useState(""); const [scale, setScale] = useState("c"); const handleCelsiusChange = value => { setTemperature(value); setScale("c"); }; const handleFahrenheitChange = value => { setTemperature(value); setScale("f"); }; return ( <> <TemperatureInput scale="c" temperature={ scale === "c" ? temperature : toCelsius(temperature) } onTemperatureChange={ handleCelsiusChange } /> <TemperatureInput scale="f" temperature={ scale === "f" ? temperature : toFahrenheit(temperature) } onTemperatureChange={ handleFahrenheitChange } /> </> ); ``` }

Why does this work?

Celsius Input
→
Parent State
→
Fahrenheit Input

The parent owns the state and calculates the value needed by each child. There is no need for the two inputs to directly modify each other.

Interactive Temperature Architecture

One State → Two Views
Celsius Component
0 °C
Fahrenheit Component
32 °F

Both views are derived from the parent's shared temperature state.

Real-world examples

Shopping Cart

Cart state can be owned by a common parent and displayed by product, summary, and checkout components.

Search + Results

Search input updates parent state, while results receive that value.

Dashboard Filters

A filter component changes shared state while charts and tables consume it.

↓

↑

This creates a predictable cycle:

State → Props → UI → User Event → Callback → State Update → Re-render

Understanding this cycle is one of the most important steps toward understanding React architecture.

12. When Should You Lift State?

Situation Recommended Approach
Only one component needs the state Keep it local
Parent and child need the state Consider putting it in the parent
Two siblings need the same state Lift it to their common parent
Many distant components need it Consider Context or a state-management solution
State belongs to a server/cache layer Consider an appropriate server-state/data-fetching architecture
Do not automatically move every piece of state to the top of the application. Keeping state as local as practical usually makes components easier to understand and maintain.

13. Common Mistakes

Mistake 1 — Keeping duplicate state

// ❌ Same concept stored independently ChildA: const [value, setValue] = useState(0); ChildB: const [value, setValue] = useState(0);

If both must always represent the same concept, this can create synchronization problems.

Mistake 2 — Trying to access sibling state directly

// ❌ Sibling A's state is not directly available in Sibling B SiblingB: console.log(siblingAState);

Move the shared state into their common parent instead.

Mistake 3 — Mutating props

// ❌ Props should not be mutated props.count = 10;

Mistake 4 — Passing the setter unnecessarily

A child should receive only the capabilities it actually needs. A purpose-specific callback can provide a clearer component interface.

// Often clearer

Mistake 5 — Lifting too far

If state is used by only one small component, moving it all the way to App-level state can create unnecessary complexity and prop passing.

Mistake 6 — Confusing state sharing with prop drilling

Lifting state and prop drilling are related but not identical. Lifting determines where state lives. Prop drilling describes passing props through intermediate components that may not need the data themselves.

14. State Ownership Decision Guide

One Component Keep state local
→
Sibling Components Lift to common parent
→
Many Distant Components Consider Context / state architecture
Golden rule:
Keep state at the lowest level that can reasonably coordinate every component that needs it.

15. Cheat Sheet

Shared State

State needed by multiple components.

State Owner

Component responsible for storing and updating the state.

Lifting State

Move state to a common parent.

Props Down

Parent passes state values to children.

Callbacks Up

Child invokes a parent-provided function to request an update.

Single Source of Truth

Avoid unnecessary duplicated copies of the same state.

16. Quick Quiz

1. What does “lifting state up” mean?
Answer: B — Lifting state means moving shared state to the closest common parent that needs to coordinate it.
2. How does data normally flow from a parent to a child?
Answer: A — Parents pass data to children through props.
3. How can a child request a parent state update?
Answer: B — The parent can pass a setter or, often more clearly, a purpose-specific callback.
4. How do sibling components usually communicate through lifted state?
Answer: B — The common parent coordinates the state and passes the result to both siblings.
5. What is the source of truth in a controlled input?
Answer: B — In a controlled input, React state controls the input value.
6. Should every state value be lifted to App?
Answer: B — Keep state local when only one component needs it. Lift it when multiple components need to coordinate around it.
7. Which pattern best describes lifted state?
Answer: A — State values generally flow down through props, while child events can invoke callbacks supplied by the parent.
