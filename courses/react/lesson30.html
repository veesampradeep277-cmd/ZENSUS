1. Development vs Production

The environment used while developing an application is different from the environment used by real users.

Development

  • Developer-friendly error messages
  • Fast refresh
  • Source files are actively transformed
  • Debugging is easier
  • Development server is running
  • Frequent code changes

Production

  • Optimized application assets
  • Minified JavaScript and CSS
  • Static assets can be cached
  • Production environment variables
  • Real users access the application
  • Performance and reliability matter
Important:

A development server is designed for development. Deployment normally uses the production build generated by the project's build tool.

2. What Is a Production Build?

A production build converts your application's source code into files that can be served to users.

From Source Code to Production Website
React Source JSX + CSS + Assets
→
Build Tool Transform
→
Optimization Bundle + Minify
→
dist/ Production Files

Why build?

Browsers need optimized files that can be efficiently downloaded and executed. Modern React projects use build tools to transform development source code into deployable assets.

3. `npm run build`

The exact build command is defined by the project's package scripts.

Terminal
$ npm run build

✓ Production build completed

package.json

package.json 
{
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  }
}

When you execute `npm run build`, npm looks inside the project's scripts section and executes the configured build command.

Previewing the production build

$ npm run preview
Preview the generated production build locally.
Development vs preview:

`npm run dev` starts the development workflow. `npm run preview` lets you inspect the generated production build locally before deploying it.

5. Environment Variables

Applications often need configuration that changes between development and production.

DEVELOPMENT 
VITE_API_URL=http://localhost:5000/api
PRODUCTION 
VITE_API_URL=https://api.example.com

Reading a Vite environment variable

const API_URL =
    import.meta.env.VITE_API_URL;

fetch(`${API_URL}/users`);
Security rule:

Frontend environment variables should not be treated as secret storage. Values exposed to client-side code can generally be discovered by users. Private credentials should remain on the backend.

8. SPA Routing

React applications commonly behave as Single Page Applications (SPAs).

Example routes

/
 /about
 /courses
 /dashboard
 /profile

In an SPA, client-side routing can change the displayed view without performing a complete document navigation for every route.

The refresh problem

Suppose the application is deployed and a user directly opens: 

https://example.com/dashboard

The hosting server must know that the application should serve the SPA entry document for that route. Otherwise, the server may return a 404 response even though `/dashboard` is a valid React route.

SPA fallback concept

/dashboard User opens route
→
Host Receives request
→
index.html SPA entry
→
React Router Resolves route
Deployment lesson:

A React application's routing configuration and the hosting platform's rewrite/fallback configuration need to work together.

12. Build Optimization

Production applications should avoid sending unnecessary work to the browser.

Code Splitting

Load application code in smaller chunks instead of sending everything immediately.

Lazy Loading

Load certain routes or components only when they are needed.

Image Optimization

Use appropriately sized and compressed images.

Tree Shaking

Build tools can remove unused portions of modules when supported by the module/build setup.

Minification

Production builds can reduce JavaScript and CSS size.

Caching

Static assets can be cached to reduce repeated downloads.

Lazy loading example

import {
    lazy,
    Suspense
} from "react";

const Dashboard =
    lazy(() =>
        import("./Dashboard")
    );

function App() {

    return (

        <Suspense
            fallback={
                <p>
                    Loading dashboard...
                </p>
            }
        >

            <Dashboard />

        </Suspense>
    );
}

13. Production Debugging

A deployment can succeed while the application still contains runtime or configuration problems.

1
Check the browser console

Look for JavaScript errors, failed requests and other client-side diagnostics.

2
Check the Network panel

Inspect API requests, status codes, request URLs and response data.

3
Check environment configuration

Confirm that the production application is using the intended API endpoint and configuration.

4
Check routing

Test direct navigation and page refreshes on nested routes.

5
Check the deployed build

Reproduce the problem using the production build rather than assuming the development server behaves identically.

Common production problems

Blank page

Possible causes include JavaScript runtime errors, incorrect asset paths, routing configuration or environment configuration.

API not working

Check the production API URL, CORS configuration, authentication and Network tab responses.

404 after refresh

Check the hosting provider's SPA rewrite/fallback configuration.

Works locally but not online

Compare environment variables, URLs, build configuration and server behavior.

14. Deployment Checklist

Use this checklist before considering a React application production-ready.

✓ Application runs correctly in development.
✓ Production build completes successfully.
✓ Production build has been previewed/tested.
✓ Production environment variables are configured.
✓ No private secrets are exposed in frontend code.
✓ API endpoints point to the correct production backend.
✓ CORS configuration has been verified where applicable.
✓ Loading, empty and error states work.
✓ Authentication works in production.
✓ All important routes have been tested.
✓ Direct URL navigation works.
✓ Refreshing nested SPA routes works.
✓ HTTPS is enabled.
✓ Images and static assets load correctly.
✓ Production debugging tools have been checked.
✓ Application performance has been reviewed.

15. Quick Quiz

1. What command commonly generates a production build in a Vite React project?
A. npm start-build
B. npm run build
C. npm production
D. react deploy
Answer: B — npm run build executes the project's configured build script.
2. What is commonly contained in the Vite production output directory?
A. Only JSX source files
B. Deployable HTML, JavaScript, CSS and related assets
C. Only package.json
D. Only node_modules
Answer: B — The production output contains the assets needed to serve the built application.
3. Why can an SPA route sometimes return 404 after refreshing the page?
A. React cannot create components
B. The hosting server may not be configured to serve the SPA entry document for that route
C. CSS always causes 404 errors
D. npm deletes the route
Answer: B — The hosting layer needs appropriate fallback/rewrite behavior for client-side routes.
4. What is HTTPS primarily used for?
A. Making React components
B. Protecting communication between client and server
C. Creating databases
D. Installing npm packages
Answer: B — HTTPS uses TLS to protect network communication.
5. Which item should NOT be placed in frontend code as a secret?
A. Public API base URL
B. Application title
C. Private database password
D. UI configuration
Answer: C — Private database passwords belong on the server, not in browser-delivered code.
6. Why is code splitting useful?
A. It can reduce the amount of JavaScript loaded initially
B. It removes the need for React
C. It creates database tables
D. It disables routing
Answer: A — Code splitting can allow application code to be loaded in smaller chunks when needed.
