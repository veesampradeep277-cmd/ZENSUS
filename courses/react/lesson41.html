Adding a todo follows a simple controlled-input workflow.

→

→

→

Add Todo Logic App.jsx 
function addTodo(text) { const trimmedText = text.trim(); if (!trimmedText) { return; } const newTodo = { id: crypto.randomUUID(), text: trimmedText, completed: false }; setTodos(currentTodos => [ ...currentTodos, newTodo ]); }
Common Mistake Do not directly mutate the existing todos array. Prefer creating a new array with the new item.

6. Delete Todo

Deletion removes the todo whose ID matches the requested item.

Delete Logic App.jsx 
function deleteTodo(id) { setTodos(currentTodos => currentTodos.filter(todo => todo.id !== id ) ); }
Why filter()? filter() creates a new array containing only the items that satisfy the condition. The matching ID is therefore excluded.

7. Complete Todo

Completing a todo changes its completed state without changing the other fields.

Toggle Completion App.jsx 
function toggleTodo(id) { setTodos(currentTodos => currentTodos.map(todo => { if (todo.id === id) { return { ...todo, completed: !todo.completed }; } return todo; }) ); }
map() vs filter() Use map() when you need to transform an item while keeping the collection. Use filter() when you need to remove items.

8. Edit Todo

Editing updates only the selected todo.

Edit Logic App.jsx 
function editTodo(id, newText) { const trimmedText = newText.trim(); if (!trimmedText) { return; } setTodos(currentTodos => currentTodos.map(todo => todo.id === id ? { ...todo, text: trimmedText } : todo ) ); }

9. Filter Todos

Filtering should normally derive the visible list from the original todo state.

Filtered Todos App.jsx 
const filteredTodos = todos.filter(todo => { if (filter === "active") { return !todo.completed; } if (filter === "completed") { return todo.completed; } return true; });
ALL

All

Shows every todo.

A

Active

Shows incomplete todos.

C

Completed

Shows completed todos.

Important State Principle Do not create separate state such as allTodos, activeTodos and completedTodos unless there is a specific reason. These values can be derived from the main todos state.

10. Local Storage

React state normally disappears when the page is refreshed. localStorage allows this project to persist todos in the browser.

React State
→
JSON.stringify()
→
localStorage

Saving Todos

Persist State App.jsx 
useEffect(() => { localStorage.setItem( "zensus-todos", JSON.stringify(todos) ); }, [todos]);

Loading Todos

Initial State App.jsx 
const [todos, setTodos] = useState(() => { const saved = localStorage.getItem("zensus-todos"); return saved ? JSON.parse(saved) : []; });
Important localStorage stores strings, not JavaScript arrays or objects. That is why JSON.stringify() is used when saving and JSON.parse() when reading. Also remember that browser storage is not a secure place for passwords, private keys or other secrets.

15. Quick Quiz

Check your understanding of the Todo project.

1. Why does each todo need a unique ID?
A stable ID lets the application identify and update or delete the correct todo and provides a stable key when rendering the list.
2. Which array method is useful for removing a todo by ID?
filter() can create a new array that excludes the todo with the matching ID.
3. Which array method is useful for toggling the completed property?
map() can create a new array while replacing only the matching todo.
4. Why is JSON.stringify() used with localStorage?
localStorage stores string values, so JavaScript objects or arrays must be serialized into a string before storing them.
5. Why should filtered todos usually be derived instead of stored separately?
The filtered list can be calculated from the source todos and current filter, which avoids maintaining duplicate state that can become inconsistent.
6. What is one important thing to test after implementing localStorage?
Refresh the page and verify that previously saved todos are restored correctly.
