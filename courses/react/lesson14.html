React Hooks

A complete guide to the Hooks system — from useState and useEffect to Context, Reducer, Refs, Memoization and Custom Hooks. Learn not only how Hooks work, but when they should and should not be used.

01. What are Hooks?

Hooks are special React functions that let function components use React features such as state, Effects, context, refs and performance optimizations.

Before Hooks were introduced, many stateful or lifecycle-related patterns commonly relied on class components. Hooks made it possible to organize these capabilities inside function components.

THE REACT HOOKS TOOLBOX
useState

Stores component state.

useEffect

Synchronizes with external systems.

useContext

Reads context without prop drilling.

useReducer

Manages complex state transitions.

useRef

Stores mutable values and references DOM nodes.

useMemo

Caches a calculated value.

useCallback

Caches a function reference.

Custom Hooks

Reuse stateful logic across components.

Composition

Combine Hooks to build reusable behavior.

02. Why Hooks?

Hooks allow related behavior to stay together inside function components and make reusable stateful logic easier to extract.

Without reusable Hook logic

  • Repeated state logic
  • Repeated Effects
  • Repeated event handling
  • Logic becomes harder to share

With Hooks

  • State can live in function components
  • Effects can synchronize external systems
  • Reusable logic can become Custom Hooks
  • Related behavior can be organized together
Important:

Hooks are not a replacement for every React feature. They are a mechanism for using and composing React capabilities inside function components.

03. Rules of Hooks

Hooks follow strict rules. These rules allow React to associate Hook calls with the correct component state across renders.

1️⃣

Call Hooks at the Top Level

Do not call Hooks inside loops, conditions, nested functions or arbitrary blocks.

2️⃣

Only Call Hooks from React Functions

Call Hooks from React function components or Custom Hooks.

❌ Incorrect

function Profile({ isLoggedIn }){

    if(isLoggedIn){

        const [name, setName] =
            useState("");

    }

    return <div>Profile</div>;
}

✅ Correct

function Profile({ isLoggedIn }){

    const [name, setName] =
        useState("");

    if(!isLoggedIn){

        return <p>
            Please login
        </p>;

    }

    return <h1>
        {name}
    </h1>;
}
Why?

React relies on the consistent order of Hook calls between renders. Changing that order can cause React to associate state with the wrong Hook.

04. useState

useState allows a component to store information that can change over time and trigger a re-render when updated. 

const [count, setCount] =
    useState(0);
USESTATE FLOW
Initial State 0
→

→
Re-render component runs
→
New UI count changed

useState Visualizer

Every state update causes React to schedule a new render.

0

Functional Updates

setCount(prevCount =>
    prevCount + 1

Use a functional update when the next state depends on the previous state, especially when multiple updates may be queued.

05. useEffect

useEffect is used to synchronize a component with an external system such as a network connection, browser API, timer, subscription or other system outside React's rendering process. 

useEffect(() => {

    const connection =
        createConnection();

    connection.connect();

    return () => {

        connection.disconnect();

    };

}, []);
EFFECT LIFECYCLE
Render
→
Effect synchronize
→
External System
→
Cleanup when needed
Key idea:

Do not use Effects simply because you want to calculate something during rendering. Effects are primarily for synchronizing with systems outside React.

06. useContext

Context allows components to read values provided by a parent without passing those values through every intermediate component as props.

Creating Context

import {
    createContext,
    useContext
} from "react";

const ThemeContext =
    createContext("light");

Providing Context

function App(){

    return (

        <ThemeContext.Provider
            value="dark"
        >

            <Dashboard />

        </ThemeContext.Provider>

    );
}

Reading Context

function Dashboard(){

    const theme =
        useContext(ThemeContext);

    return (
        <p>
            Current theme:
            {theme}
        </p>
    );
}
CONTEXT FLOW
Provider value
→
Component A
→
Component B
→
useContext() read value
Context is not automatically global state.

Context provides a way to make values available to a subtree. State management still depends on where and how the state is stored.

07. useReducer

useReducer is useful when state transitions are more complex or when multiple updates are naturally represented as actions. 

const initialState = {
    count: 0
};

function reducer(state, action){

    switch(action.type){

        case "increment":

            return {
                ...state,
                count:
                    state.count + 1
            };

        case "decrement":

            return {
                ...state,
                count:
                    state.count - 1
            };

        default:

            return state;
    }

}

Using the Reducer

const [state, dispatch] =
    useReducer(
        reducer,
        initialState
    );

Dispatching an Action

dispatch({
    type: "increment"
});
REDUCER MENTAL MODEL
UI Event
→
dispatch(action)
→
Reducer state + action
→
New State
→
UI
Think:

useState → simple state updates
useReducer → structured state transitions and actions

08. useRef

useRef returns a mutable object whose current property persists across renders. Updating it does not by itself trigger a re-render. 

const inputRef =
    useRef(null);

DOM Reference

function SearchBox(){

    const inputRef =
        useRef(null);

    function focusInput(){

        inputRef.current.focus();

    }

    return (

        <>

            <input ref={inputRef} />

            <button
                onClick={focusInput}
            >
                Focus
            </button>

        </>

    );
}

Mutable Value

const renderCount =
    useRef(0);

renderCount.current++;

useState

Changing state schedules a re-render. 

setValue(newValue);

useRef

Changing current does not itself schedule a re-render. 

ref.current =
    newValue;
Common useRef uses:
  • Focusing an input
  • Referencing a DOM element
  • Storing an interval ID
  • Keeping a mutable value between renders
  • Interacting with browser APIs or imperative libraries

09. useMemo

useMemo lets React cache the result of a calculation between renders until its dependencies change. 

const filteredStudents =
    useMemo(() => {

        return students.filter(
            student =>
                student.course ===
                selectedCourse
        );

    }, [
        students,
        selectedCourse
    ]);
Dependencies unchanged

React can reuse the previously calculated value.

→
Dependency changed

React recalculates the memoized value.

Do not memoize everything.

Memoization adds complexity. A calculation should be expensive enough or have another clear reason to justify caching it.

10. useCallback

useCallback caches a function definition between renders until its dependencies change. 

const handleSelect =
    useCallback((id) => {

        setSelectedId(id);

    }, []);

Why Function Identity Matters

Every time a component renders, a normal function expression creates a new function value. 

const handleClick = () => {
    console.log("clicked");
};

When passing callbacks to memoized child components or using a callback as a dependency, function identity can matter.

useMemo

Caches a calculated value. 

const result =
    useMemo(
        calculate,
        [a,b]
    );

useCallback

Caches a function. 

const fn =
    useCallback(
        () => doSomething(),
        [a]
    );
Memory trick:

Memo → value
Callback → function

11. Custom Hooks

A Custom Hook is a JavaScript function whose name starts with use and which can call other Hooks.

Example: useOnlineStatus

import {
    useEffect,
    useState
} from "react";

function useOnlineStatus(){

    const [isOnline, setIsOnline] =
        useState(
            navigator.onLine
        );

    useEffect(() => {

        function handleOnline(){
            setIsOnline(true);
        }

        function handleOffline(){
            setIsOnline(false);
        }

        window.addEventListener(
            "online",
            handleOnline
        );

        window.addEventListener(
            "offline",
            handleOffline
        );

        return () => {

            window.removeEventListener(
                "online",
                handleOnline
            );

            window.removeEventListener(
                "offline",
                handleOffline
            );

        };

    }, []);

    return isOnline;
}

Using the Custom Hook

function Status(){

    const isOnline =
        useOnlineStatus();

    return (

        <p>

            {isOnline
                ? "Online"
                : "Offline"}

        </p>

    );
}
Component Needs online status
Custom Hook useOnlineStatus()
useState Stores status
useEffect Listens to browser
Result Reusable logic
Important:

Custom Hooks share logic, not the same state instance. Each component calling a Custom Hook gets its own Hook state unless the Hook connects to some shared external source.

12. Hook Composition

Hook composition means combining multiple Hooks to create a reusable piece of behavior.

Example

function useSearch(){

    const [query, setQuery] =
        useState("");

    const [results, setResults] =
        useState([]);

    useEffect(() => {

        // Fetch or calculate
        // results here

    }, [query]);

    return {
        query,
        setQuery,
        results
    };
}

The component consuming the Hook does not need to know how the state, Effect and data logic are internally organized. 

function SearchPage(){

    const {
        query,
        setQuery,
        results
    } = useSearch();

    return (
        // UI
    );
}

+
useEffect
+
useMemo
→
Custom Hook
→

13. Hook Dependencies

Some Hooks accept dependency arrays. Dependencies tell React which values the Hook's calculation or Effect depends on.

useEffect Dependency Example

useEffect(() => {

    console.log(
        "Room changed:",
        roomId
    );

}, [roomId]);
Initial render

The Effect runs after the component commits.

→
roomId changes

React runs cleanup from the previous Effect, then runs the new Effect.

Dependency Array Patterns

Pattern Meaning
useEffect(fn) Runs after every committed render.
useEffect(fn, []) Runs after the initial commit; in development Strict Mode, React may perform an additional setup/cleanup cycle to help detect bugs.
useEffect(fn, [value]) Runs after the initial commit and when value changes.
Do not treat dependencies as a random performance switch.

The dependency list should reflect the reactive values used by the Effect or calculation. If you are fighting the dependency list, first reconsider the structure of the code.

15. Common Hook Mistakes

❌ Calling Hooks inside if

Hook call order must remain consistent between renders.

❌ Calling Hooks inside loops

Do not dynamically change the order or number of Hook calls.

❌ Using useEffect for derived data

If a value can be calculated directly from existing props/state during render, an Effect may be unnecessary.

❌ Using useMemo everywhere

Memoization is an optimization, not a default requirement.

❌ Confusing useRef with state

Changing ref.current does not trigger a re-render.

❌ Ignoring dependencies

Incorrect dependency handling can create stale values, repeated Effects or synchronization bugs.

❌ Custom Hook with no reusable logic

Do not create Custom Hooks merely to rename a few lines. Extract behavior that is meaningfully reusable.

❌ Treating Context as global everything

Context is a delivery mechanism for values through a component tree, not a universal replacement for all state management.
