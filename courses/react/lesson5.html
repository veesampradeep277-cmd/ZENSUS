01 — Core Concept

What are Props?

Props are inputs passed to a React component. They allow a parent component to provide information to a child component.

Think of Props as Component Inputs

A normal JavaScript function can receive arguments: 

function greet(name) {
    return "Hello " + name;
}

greet("Pradeep");

React components can receive information in a similar conceptual way, but the data is passed through JSX attributes.

React Example

function Student(props) {

```
return (
    <h2>
        Hello {props.name}
    </h2>
);
```

}

function App() {

```
return (
    <Student
        name="Pradeep"
    />
);
```

}

Here, name is a prop passed from App to Student.

Remember: Props are data supplied to a component by its parent.
02 — Why Props?

Why Do We Need Props?

♻ Reuse

The same component can display different data.

📦 Customization

Parents can configure how a child component behaves or appears.

🔗 Communication

Props establish a common parent-to-child data flow.

🧩 Composition

Small components become flexible building blocks.

📊 Dynamic UI

The same UI structure can represent different data.

🛠 Maintainability

Component structure and data can remain separated.

04 — Passing Props

Passing Props

Props are passed to components using JSX attributes. 

function App() {

    return (
        <Student
            name="Pradeep"
            course="CSE"
        />
    );
}

The child receives two props:

name → "Pradeep"
course → "CSE"
05 — Receiving Props

Receiving Props

A function component receives props through its function parameter. 

function Student(props) {

    return (
        <div>
            <h2>{props.name}</h2>
            <p>{props.course}</p>
        </div>
    );
}

React provides the component with an object containing the props.

Pattern: Parent passes props → React supplies the props object → child reads properties from that object.
06 — Props Object

The Props Object

If several props are passed, the component receives them together through the props object. 

function Course(props) {

    console.log(props);

    return (
        <article>
            <h2>{props.title}</h2>
            <p>{props.level}</p>
        </article>
    );
}

Conceptually, the object contains entries such as: 

{
    title: "React",
    level: "Beginner"
}
07 — Destructuring

Destructuring Props

Instead of repeatedly writing props.name, you can destructure the properties you need directly in the function parameter.

Without Destructuring

function Student(props) {

```
return (
    <>
        <h2>
            {props.name}
        </h2>

        <p>
            {props.course}
        </p>
    </>
);
```

}

With Destructuring

function Student({ name, course }) {

```
return (
    <>
        <h2>
            {name}
        </h2>

        <p>
            {course}
        </p>
    </>
);
```

}
Destructuring is JavaScript syntax. React does not require it, but it often makes components cleaner when only a few props are needed.

10 — String Props

String Props

Strings can be passed directly using quoted JSX attributes. 

<CourseCard
    title="React Fundamentals"
    level="Beginner"
/>

The child can read: 

function CourseCard({ title, level }) {

    return (
        <>
            <h2>{title}</h2>
            <span>{level}</span>
        </>
    );
}
11 — Number Props

Number Props

JavaScript expressions are placed inside curly braces. That is how numbers and other non-string values are passed. 

<CourseCard
    lessons={17}
    progress={65}
/>
function CourseCard({ lessons, progress }) {

    return (
        <p>
            {lessons} lessons • {progress}% complete
        </p>
    );
}
Writing lessons="17" passes the text string "17". Writing lessons={17} passes the JavaScript number 17.
12 — Boolean Props

Boolean Props

Boolean props represent a true/false configuration. 

<Button disabled={true} />

<Course premium={false} />

For boolean props, JSX also supports the shorthand: 

<Button disabled />

This is equivalent to passing true for that prop.

13 — Array Props

Array Props

Arrays are useful when a component needs a collection of values. 

const courses = [
    "Python",
    "React",
    "SQL"
];

function App() {

    return (
        <CourseList
            courses={courses}
        />
    );
}
function CourseList({ courses }) {

    return (
        <ul>
            {courses.map(course => (
                <li key={course}>
                    {course}
                </li>
            ))}
        </ul>
    );
}
14 — Object Props

Object Props

Objects are useful when multiple related values belong together. 

const student = {
    name: "Pradeep",

<StudentCard

15 — Function Props

Function Props

Functions can also be passed as props. This allows a child component to invoke behavior supplied by its parent. 

function App() {

    function handleStart() {
        console.log("Course started");
    }

    return (
        <StartButton
            onStart={handleStart}
        />
    );
}
function StartButton({ onStart }) {

    return (
        <button
            onClick={onStart}
        >
            Start Learning
        </button>
    );
}
Parent defines function
→
Function passed as prop
→
Child calls it
This pattern is important because it allows child UI components to trigger behavior owned by a parent.
16 — JSX as Props

Passing JSX as Props

Props can contain React elements or other renderable values. This enables flexible component composition. 

function Card({ header }) {

    return (
        <section>
            {header}
            <p>
                Course content goes here.
            </p>
        </section>
    );
}

function App() {

    return (
        <Card
            header={
                <h2>React Fundamentals</h2>
            }
        />
    );
}

This lets the parent decide what JSX should appear in a particular slot of the child component.

17 — Children

When content is placed between a component's opening and closing tags, React makes that content available through the special children prop. 

function Card({ children }) {

            {children}

18 — Read Only

Props Are Read-Only

A component should treat the props it receives as read-only. A child should not directly modify the props object supplied by its parent. 

function Student(props) {

    // Don't do this:

    props.name = "Another Name";

    return <h2>{props.name}</h2>;
}

If a component needs to manage changing data, React state is designed for that purpose.

Parent State / Data
→
Props
→
Child Reads
Props describe data supplied to a component. They are not the component's own mutable storage mechanism.
19 — Parent-to-Child

Parent-to-Child Communication

Props establish the standard one-way data flow from parent to child.

ONE-WAY DATA FLOW

Parent

const user = { name: "Pradeep" };
user
props

Child

function Profile({ user }) { return user.name; }
For child-to-parent interactions, a common React pattern is to pass a function from the parent to the child as a prop. The child can call that function, allowing the parent to handle the resulting action.

21 — Validation

Props Validation Concepts

As applications become larger, developers may want to document and validate what kind of data a component expects.

What Should a Component Expect?

For example, a CourseCard might expect:

  • title — string
  • lessons — number
  • premium — boolean
  • course — object

Why Validation Helps

  • Catches incorrect data assumptions.
  • Documents component expectations.
  • Improves maintainability.
  • Makes reusable components easier to understand.
Modern React projects may use TypeScript for static type checking. JavaScript projects can also use runtime validation libraries or other documentation techniques depending on the project's needs.
22 — Common Mistakes

Common Props Mistakes

MISTAKE 01

Passing Number as String

<Course lessons="17" />

If the child expects a JavaScript number, use braces: 

<Course lessons={17} />
MISTAKE 02

Calling a Function Immediately

<Button
    onClick={handleClick()}
 />

This calls the function while rendering rather than passing the function itself.

MISTAKE 03

Mutating Props

// Avoid modifying props directly
props.name = "New Name";

Treat received props as read-only.

MISTAKE 04

Wrong Destructuring

function User({ username }) {
    // But parent passes name
}

The destructured property name must match the prop being supplied unless you intentionally rename it during destructuring.

MISTAKE 05

Forgetting children

function Card() {
    return <div>
        ...
    </div>;
}

If the component is designed to render nested content, remember to use the children prop.

MISTAKE 06

Overloading Props

Passing a huge collection of unrelated values into one component can be a sign that the component's responsibility or API needs reconsideration.
