Core concept

What is Abstraction?

A

Hide implementation. Show functionality.

Abstraction is the process of hiding unnecessary implementation details and exposing only the essential functionality to the user.

The user should know WHAT an operation does, without necessarily knowing HOW it is implemented.
The fundamental idea

WHAT vs HOW

This is the simplest way to remember abstraction.

WHAT

What should the system do?

The abstraction exposes the operation or capability that the user needs.

car.start()
→
HOW

How does it actually work?

The internal implementation remains hidden behind the abstraction.

fuel → engine → ignition → ECU

Why abstraction?

Why do we need it?

01

Reduce Complexity

Users work with a simple interface instead of understanding every internal operation.

02

Improve Maintainability

Internal implementation can change while the external abstraction remains stable.

03

Loose Coupling

Code can depend on a contract instead of depending directly on implementation details.

04

Reusability

Common behavior can be defined once and reused by related classes.

05

Security

Unnecessary internal details are not exposed to the user of the abstraction.

06

Flexible Design

Different implementations can satisfy the same abstraction.

Mechanism 01

Abstract Class

An abstract class is declared using the abstract keyword and cannot be instantiated directly.

Abstract class 
abstract class Animal {

    abstract void sound();

    void sleep() {
        System.out.println("Sleeping...");
    }
}
abstract class defines a class that cannot be instantiated.
sound() is an abstract method.
sleep() is a concrete method with implementation.
Concrete subclass 
class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}

class Main {
    public static void main(String[] args) {

        Dog d = new Dog();

        d.sound();
        d.sleep();
    }
}
Dog barks Sleeping...

Abstract Method

An abstract method declares what a subclass must do, without defining how it does it.

WHAT 
abstract void start();

The parent defines the required behavior.

→
HOW 
void start() {
    System.out.println(
        "Car starts"

The child defines the implementation.

Rules

Rules of Abstract Methods

01

No method body

An abstract method is declared without an implementation body.

02

Uses abstract keyword

The method declaration contains the abstract keyword.

03

Must belong to an abstract class

A normal class cannot contain an abstract method.

04

Subclass must implement

A concrete subclass must provide implementations for inherited abstract methods.

05

Override

Use @Override to clearly indicate implementation of the inherited method.

06

Abstract subclass is possible

A subclass may remain abstract instead of implementing every abstract method.

Can an Abstract Class have a Constructor?

Yes. An abstract class can have a constructor. The constructor runs when a concrete subclass object is created because the subclass constructor initializes the inherited part of the object through the superclass constructor.

Constructor example 
abstract class Vehicle {

    String brand;

    Vehicle(String brand) {
        this.brand = brand;

        System.out.println(
            "Vehicle constructor"
        );
    }

    abstract void start();
}

class Car extends Vehicle {

    Car(String brand) {
        super(brand);
    }

    @Override
    void start() {
        System.out.println(
            brand + " starts"
        );
    }
}

class Main {

    public static void main(String[] args) {

        Car c = new Car("Toyota");

        c.start();
    }
}

Mechanism 02

Interface and Abstraction

An interface defines a contract that implementing classes agree to follow. Java interfaces can contain abstract methods as well as default, static and private methods depending on the Java version and language rules.

Interface 
interface Payment {

    void pay(double amount);
}
Payment defines the behavior required from a payment implementation.
pay() describes what the implementation must provide.
Implementation 
class UPI implements Payment {

    @Override
    public void pay(double amount) {

        System.out.println(
            "Paid ₹" + amount +
            " using UPI"
        );
    }
}

Implement Multiple Interfaces

A Java class can implement more than one interface. This is one reason interfaces are useful for combining multiple behavioral contracts.

Multiple interfaces 
interface Printable {
    void print();
}

interface Scannable {
    void scan();
}

class Printer implements Printable, Scannable {

    @Override
    public void print() {
        System.out.println("Printing...");
    }

    @Override
    public void scan() {
        System.out.println("Scanning...");
    }
}

class Main {

    public static void main(String[] args) {

        Printer p = new Printer();

        p.print();
        p.scan();
    }
}

End-to-end example

Payment System using Abstraction

This example demonstrates how a real application can hide payment implementation behind a common abstraction.

PaymentSystem.java 
interface Payment {

    void pay(double amount);
}


class UPI implements Payment {

    @Override
    public void pay(double amount) {

        System.out.println(
            "Processing UPI payment..."
        );

        System.out.println(
            "Paid ₹" + amount
        );
    }
}


class CreditCard implements Payment {

    @Override
    public void pay(double amount) {

        System.out.println(
            "Processing card payment..."
        );

        System.out.println(
            "Paid ₹" + amount
        );
    }
}


class PaymentService {

    void processPayment(
        Payment payment,
        double amount
    ) {

        payment.pay(amount);
    }
}


public class Main {

    public static void main(String[] args) {

        PaymentService service =
            new PaymentService();

        Payment upi = new UPI();

        Payment card =
            new CreditCard();

        service.processPayment(
            upi,
            500
        );

        service.processPayment(
            card,
            1000
        );
    }
}
Processing UPI payment... Paid ₹500 Processing card payment... Paid ₹1000

Common Abstraction Mistakes

01

Creating an object of an abstract class

Abstract classes cannot be instantiated directly.

02

Forgetting to implement abstract methods

A concrete subclass must implement inherited abstract methods.

03

Confusing abstraction with encapsulation

They are related but solve different design problems.

04

Thinking abstract classes contain only abstract methods

Abstract classes can also contain fully implemented methods.

05

Confusing extends and implements

Classes extend classes, while classes implement interfaces.

06

Saying interfaces can never contain implementation

Modern Java interfaces can contain default, static and private methods.

Frequently Asked Questions

01 What is abstraction in Java?

Abstraction hides implementation details and exposes only essential functionality. Java provides abstract classes and interfaces for abstraction.

02 What is an abstract class?

An abstract class is declared using the abstract keyword and cannot be instantiated directly. It may contain both abstract and concrete methods.

03 What is an abstract method?

An abstract method is declared without a method body. A concrete subclass normally provides its implementation.

04 Can an abstract class have a constructor?

Yes. Abstract classes can have constructors, and the superclass constructor participates in initialization when a concrete subclass object is created.

05 Can we create an object of an abstract class?

No. An abstract class cannot be instantiated directly. A concrete subclass can be instantiated.

06 Can an abstract class contain normal methods?

Yes. An abstract class can contain concrete methods with complete implementations.

07 What is the difference between abstract class and interface?

An abstract class can contain state, constructors, concrete methods and abstract methods. A class can extend only one class. A class can implement multiple interfaces, which are primarily used to define behavioral contracts.

08 Can an interface have implemented methods?

Yes. Modern Java interfaces can contain default, static and private methods with implementations.

09 Why use abstraction?

Abstraction reduces complexity, improves maintainability, promotes flexible design and allows code to depend on contracts instead of concrete implementations.

10 What keywords are important for abstraction?

Important keywords include abstract, extends, interface and implements.
