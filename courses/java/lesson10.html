FOUNDATION

What is Object-Oriented Programming?

O

OOP = Objects + Data + Behavior

Object-Oriented Programming is a programming paradigm where software is organized around objects. An object combines its state with the behavior that operates on that state.

Simple idea: Instead of thinking only about what the program does, think about who or what performs the action.

WHY OOP?

Procedural Programming vs OOP

PROCEDURAL

Function-Centered

Programs are primarily organized around functions and procedures.

  • Focuses on functions
  • Data and behavior may be separate
  • Can become difficult to maintain at scale
  • Common in small procedural programs
OOP

Object-Centered

Programs are organized around objects that combine state and behavior.

  • Focuses on objects
  • Combines data and behavior
  • Encourages reuse
  • Useful for large applications

CONCEPT 01

Class — The Blueprint

A class defines the structure and behavior that objects created from it can have.

Student.java 
class Student {

    String name;
    int age;

    void study() {
        System.out.println(name + " is studying");
    }
}

What does this class contain?

name Field representing student state.
age Another piece of object data.
study() Method representing object behavior.

OBJECT INITIALIZATION

Constructors

Constructors are used to initialize newly created objects.

Student.java 
class Student {

    String name;
    int age;

    Student(String name, int age) {

        this.name = name;
        this.age = age;
    }
}
Main.java 
Student s =
    new Student("Pradeep", 20);

System.out.println(s.name);
System.out.println(s.age);
!
Remember

A constructor has the same name as its class and does not have a return type.

PILLAR 01

Encapsulation

Encapsulation protects an object's internal state by controlling how that state is accessed.

PRIVATE DATA balance
🔒 →
PUBLIC METHODS deposit() withdraw()
Encapsulation Example 
class BankAccount {

    private double balance;

    public void deposit(double amount) {

        if (amount > 0) {
            balance += amount;
        }
    }

    public double getBalance() {
        return balance;
    }
}
PILLAR 02

Inheritance

Inheritance allows a class to derive from another class and reuse its accessible state and behavior.

Vehicle

Inheritance Example 
class Vehicle {

    void start() {
        System.out.println("Vehicle started");
    }
}


class Car extends Vehicle {

    void drive() {
        System.out.println("Car is driving");
    }
}
✓

In Java, a class can directly extend only one class. Interfaces provide another way for a class to have multiple types.

PILLAR 03

Polymorphism

Polymorphism allows a common parent type or interface to refer to different concrete objects.

Animal
↓
Dog bark()
Cat meow()
Cow moo()
Runtime Polymorphism 
class Animal {

    void sound() {
        System.out.println("Animal sound");
    }
}


class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Bark");
    }
}


Animal a = new Dog();

a.sound();
Output: Bark
PILLAR 04

Abstraction

Abstraction focuses on what an object should do while hiding unnecessary implementation details.

WHAT

Drive a Car

The user knows how to operate the car without needing to understand every internal engine mechanism.

→
HIDDEN

Internal Mechanism

Complex implementation details can remain behind a simpler interface.

Abstract Class 
abstract class Shape {

    abstract void draw();

    void display() {
        System.out.println("Shape");
    }
}
Implementation

    @Override
    void draw() {
        System.out.println("Drawing circle");

}
CONTRACT-BASED DESIGN

Interfaces

An interface defines a contract that implementing classes agree to fulfill.

Payment.java 
interface Payment {

    void pay(double amount);
}
UPI.java 
class UPI implements Payment {

    public void pay(double amount) {

        System.out.println(
            "Paid: " + amount
        );
    }
}

AVOID THESE

Common OOP Mistakes

01

Confusing a Class with an Object

A class is the blueprint; an object is an instance created from that blueprint.

02

Making Everything Public

Unnecessary public fields expose internal state. Prefer appropriate access control.

03

Using Inheritance Everywhere

Inheritance should represent a meaningful is-a relationship. Do not use it simply to avoid writing code.

04

Forgetting @Override

Use @Override when intentionally overriding an inherited method. It helps the compiler catch signature mistakes.
