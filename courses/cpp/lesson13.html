01 · Foundation

What is Inheritance?

Inheritance allows a new class to reuse and extend an existing class.

🧬

Simple Definition

Inheritance is an OOP mechanism where a derived class acquires accessible properties and behaviors of a base class.

♻

Why use it?

  • Code reuse
  • Extension of existing functionality
  • Hierarchical design
  • Relationship modeling
  • Foundation for runtime polymorphism
Important: Inheritance should represent a meaningful "is-a" relationship. A Dog is an Animal. A Car is a Vehicle.

02 · Syntax

Inheritance Syntax

The colon specifies the base class and the inheritance mode.

Basic Syntax 
class Derived : public Base {
    // members of Derived
};

Base Class

The existing class whose accessible members can be inherited by another class.

Derived Class

The new class that extends or specializes the base class.

Example 
#include <iostream>
using namespace std;

class Vehicle {
public:
    void start() {
        cout << "Vehicle started\n";
    }
};

class Car : public Vehicle {
public:
    void drive() {
        cout << "Car is driving\n";
    }
};

int main() {

    Car c;

    c.start();
    c.drive();

    return 0;
}
03 · Access Control

public, protected and private

Understanding access control is one of the most important parts of inheritance.

Inside Base Class Base
public Base members ✓
protected Base members ✓
private Base members ✓
Inside Derived Class Derived
public Inherited access ✓
protected Inherited access ✓
private Direct access ✕
Remember: Private members of the base class are not directly accessible inside the derived class. They still belong to the base subobject and can be manipulated through appropriate base-class functions.
protected.cpp 
class Parent {

protected:
    int age = 20;

};

class Child : public Parent {

public:

    void showAge() {
        cout << age;   // allowed
    }
};

int main() {

    Child c;

    c.showAge();

    // cout << c.age; // ERROR
}
Access Transformation

Public vs Protected vs Private Inheritance

The inheritance mode controls how inherited public and protected members appear in the derived class.

Base Member public inheritance protected inheritance private inheritance
public public protected private
protected protected protected private
private Not directly accessible Not directly accessible Not directly accessible
Best beginner rule: Prefer public inheritance when modeling a true "is-a" relationship.

06 · Multilevel

Multilevel Inheritance

Inheritance can continue through multiple levels.

Person Level 1
Student Level 2
EngineeringStudent Level 3
multilevel.cpp 
class Person {

public:

    void breathe() {
        cout << "Breathing\n";
    }
};

class Student : public Person {

public:

    void study() {
        cout << "Studying\n";
    }
};

class EngineeringStudent : public Student {

public:

    void code() {
        cout << "Coding\n";
    }
};

int main() {

    EngineeringStudent e;

    e.breathe();
    e.study();
    e.code();

}
Key idea: EngineeringStudent can access accessible members from Student and, through that chain, from Person.

hybrid structure

10 · Advanced Inheritance

The Diamond Problem

One of the most important inheritance interview questions.

A Base
B Derived from A
C Derived from A
D Derived from B + C
diamond.cpp 
class A {
public:
    void show() {
        cout << "A";
    }
};

class B : public A {};

class C : public A {};

class D : public B, public C {};

int main() {

    D obj;

    // obj.show(); 
    // ERROR: ambiguous

}
Why is it ambiguous? D contains a B part and a C part. Both B and C contain their own A base subobject. Therefore D can have two A subobjects.
11 · Solution

Virtual Inheritance

Virtual inheritance makes the shared base a single virtual base subobject in the most-derived object.

virtual-inheritance.cpp 
class A {

public:

    void show() {
        cout << "A";
    }
};

class B : virtual public A {};

class C : virtual public A {};

class D : public B, public C {};

int main() {

    D obj;

    obj.show();  // OK

}
Result: D has one shared A base subobject instead of separate A subobjects through B and C.
12 · Object Construction

Constructor Order in Inheritance

Constructors execute from the base toward the derived class.

1. Base constructor
2. Derived class members initialize
3. Derived constructor body
constructor-order.cpp 
class Base {

public:

    Base() {
        cout << "Base Constructor\n";
    }
};

class Derived : public Base {

public:

    Derived() {
        cout << "Derived Constructor\n";
    }
};

int main() {

    Derived d;

}
Execution: Base constructor → Derived constructor. For more complex inheritance, virtual bases are initialized first, followed by direct bases, members in declaration order, and finally the constructor body.
Base Initialization

Calling a Base Constructor

base-constructor.cpp 
class Person {

protected:
    string name;

public:

    Person(string n)
        : name(n) {}
};

class Student : public Person {

private:
    int roll;

public:

    Student(string n, int r)
        : Person(n), roll(r) {}
};
Important: A derived constructor uses the member-initializer list to explicitly select the base constructor.
Modern C++

Constructor Inheritance with using

using-base-constructor.cpp 
class Person {

public:

    Person(string name) {
        cout << name;
    }
};

class Student : public Person {

public:

    using Person::Person;
};
Do not confuse this: using Person::Person makes base constructors available for initialization of Student objects. It does not turn constructors into ordinary inherited member functions.
Object Destruction

Destructor Order

Construction

Base → Derived


Destruction

Derived → Base

destructor-order.cpp 
class Base {

public:

    ~Base() {
        cout << "Base destroyed\n";
    }
};

class Derived : public Base {

public:

    ~Derived() {
        cout << "Derived destroyed\n";
    }
};
Rule: Destruction happens in the reverse order of construction.
13 · Member Functions

Function Overriding

A derived class can provide its own implementation of a virtual function from the base class.

override.cpp 
class Animal {

public:

    virtual void sound() {
        cout << "Animal sound\n";
    }
};

class Dog : public Animal {

public:

    void sound() override {
        cout << "Dog barks\n";
    }
};
Best practice: Use the override keyword. It tells the compiler that you intend to override a virtual base function.
Important distinction: If the base function is not virtual, a same-name function in the derived class generally hides the base function rather than providing runtime overriding.
Inheritance Control

final Keyword

final.cpp 
class Animal {

public:

    virtual void sound() final {
        cout << "Sound";
    }
};

// class Dog : public Animal {
//     void sound() override; // ERROR
// }

You can also mark a class as final to prevent further derivation. 

class Vehicle final {
};

// class Car : public Vehicle {}; // ERROR
Encapsulation

Understanding protected Members

public

Accessible from class, derived classes and external code through objects.

protected

Accessible inside the class and derived classes, but not directly through ordinary outside code.

private

Directly accessible only inside the class and its friends, not directly inside derived classes.

Design tip: Prefer private data with well-designed protected/public functions when possible. Excessive protected state can weaken encapsulation.
14 · OOP Connection

Inheritance + Polymorphism

Inheritance creates the relationship; virtual functions can provide runtime polymorphism.

runtime-polymorphism.cpp 
class Animal {

public:

    virtual void sound() {
        cout << "Animal sound\n";
    }

    virtual ~Animal() = default;
};

class Dog : public Animal {

public:

    void sound() override {
        cout << "Dog barks\n";
    }
};

class Cat : public Animal {

public:

    void sound() override {
        cout << "Cat meows\n";
    }
};

void makeSound(const Animal& a) {
    a.sound();
}

int main() {

    Dog d;
    Cat c;

    makeSound(d);
    makeSound(c);

}
Runtime polymorphism: The call to sound() is resolved according to the actual object because the function is virtual.
Interview Essential

Why should a Base Destructor often be virtual? 

class Base {

public:

    virtual ~Base() = default;
};

If a derived object may be destroyed through a base pointer, a virtual base destructor ensures the derived destructor participates correctly in destruction.

15 · Type Conversion

Upcasting and Downcasting

↑

Upcasting

Converting a derived object reference/pointer to a base class reference/pointer. 

Dog d;

Animal* a = &d;

For public inheritance, this is safe and implicit.

↓

Downcasting

Converting a base pointer/reference toward a specific derived type. 

Animal* a = &d;

Dog* dptr =
    dynamic_cast<Dog*>(a);

dynamic_cast can check the relationship when the base is polymorphic.

Warning: Downcasting should not be performed blindly. The object must actually represent the appropriate derived type.
Important Concept

Object Slicing 

class Animal {
public:
    virtual void sound() {}
};

class Dog : public Animal {
public:
    void sound() override {}
};

Dog d;

Animal a = d;   // slicing

When a derived object is copied into a base object by value, only the base subobject is retained. The derived-specific part is sliced away.

Polymorphism tip: Prefer references or pointers when you need to preserve the actual derived object behavior.

Avoid These

Common Inheritance Mistakes

❌ Accessing private base members

Derived classes cannot directly access private base members.

❌ Confusing overriding and hiding

A same-name function is not automatically runtime overriding. Use virtual + override.

❌ Ignoring diamond ambiguity

Multiple inheritance can create multiple copies of a shared base class.

❌ Unsafe downcasting

Never assume every Base object is a particular Derived object.

❌ Forgetting virtual destructor

Polymorphic base classes often need virtual destructors.

❌ Using inheritance everywhere

Not every relationship is an "is-a" relationship. Sometimes composition is better.

Design Thinking

Inheritance vs Composition

Inheritance Composition
Represents "is-a" Represents "has-a"
Car is a Vehicle Car has an Engine
Creates class hierarchy Combines independent objects
Useful for polymorphism Often gives flexible design

Mini Project

Employee Management System

Apply inheritance in a realistic C++ program.

employee-system.cpp 
#include <iostream>
#include <string>

using namespace std;

class Employee {

protected:

    string name;
    double salary;

public:

    Employee(string n, double s)
        : name(n), salary(s) {}

    virtual void display() const {

        cout << "Name: "
             << name << '\n';

        cout << "Salary: "
             << salary << '\n';
    }

    virtual ~Employee() = default;
};

class Developer : public Employee {

private:

    string language;

public:

    Developer(
        string n,
        double s,
        string lang
    )
        : Employee(n, s),
          language(lang) {}

    void display() const override {

        Employee::display();

        cout << "Language: "
             << language << '\n';
    }
};

class Manager : public Employee {

private:

    int teamSize;

public:

    Manager(
        string n,
        double s,
        int size
    )
        : Employee(n, s),
          teamSize(size) {}

    void display() const override {

        Employee::display();

        cout << "Team Size: "
             << teamSize << '\n';
    }
};

int main() {

    Developer d(
        "Rahul",
        60000,
        "C++"
    );

    Manager m(
        "Priya",
        85000,
        8
    );

    d.display();

    cout << '\n';

    m.display();

    return 0;
}
What this project teaches: inheritance, protected members, constructors, constructor initialization, overriding, virtual functions, polymorphism and virtual destructors.
