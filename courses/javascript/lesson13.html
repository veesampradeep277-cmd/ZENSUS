Remember: input is the element, while input.value is the value entered by the user.

08 · Submit Event

Understanding form submission

The submit event fires when the user submits a form.

JavaScript 
const form = document.querySelector("#myForm");

form.addEventListener("submit", function(event) {

    event.preventDefault();

    console.log("Form submitted!");

});
Why preventDefault()? Normally, submitting a form can cause the browser to navigate/reload according to the form's action. JavaScript applications often prevent that default behavior so they can validate or process the data first.

10 · Validation

Form validation

Validation checks whether user input meets your rules.

Client-side validation

  • Runs in the browser.
  • Provides fast feedback.
  • Improves user experience.
  • Can use HTML constraints and JavaScript.

Server-side validation

  • Runs on the server.
  • Must be performed for security.
  • Should never blindly trust browser input.
  • Protects backend systems and data.
Security rule: Client-side validation is for user experience, not a security boundary. Always validate important data on the server too.

13 · Validation API

checkValidity()

Form controls provide the Constraint Validation API. One useful method is checkValidity().

JavaScript 
const email = document.querySelector("#email");

if (email.checkValidity()) {
    console.log("Valid");
} else {
    console.log("Invalid");
}
14 · Custom Rules

Creating custom validation

JavaScript 
const password = document.querySelector("#password");

if (password.value.length < 8) {

    console.log("Password must contain at least 8 characters");

} else {

    console.log("Password accepted");

}
Custom validation is useful when your application has rules that HTML attributes alone cannot express.

20 · FormData

The FormData API

A powerful way to collect form fields.

JavaScript 
const form = document.querySelector("#myForm");

const data = new FormData(form);

console.log(data.get("name"));
console.log(data.get("email"));
Important: FormData uses successful form controls and their name attributes to construct key/value data.

24 · Advanced Validation

Regular expressions

Regex can help describe text patterns.

Regex is powerful, but don't try to solve every validation problem with one enormous expression. Keep validation understandable.

28 · Common Mistakes

Mistakes beginners make

❌ Forgetting preventDefault()

The browser may perform the default form submission before your JavaScript workflow.

❌ Forgetting name attributes

FormData and traditional form submission rely on successful controls and their names.

❌ Trusting client validation

Browser validation can be bypassed. Important validation belongs on the server too.

❌ Not trimming input

Users may accidentally enter leading or trailing whitespace.

❌ Using innerHTML carelessly

Never insert untrusted user input into HTML without proper sanitization.

❌ Weak error messages

Tell users exactly what they need to correct.

29 · Security

Forms and security

  • Never trust user input.
  • Validate data on the server.
  • Sanitize or safely encode output where appropriate.
  • Use HTTPS for sensitive data.
  • Use appropriate authentication and authorization.
  • Protect against CSRF where relevant.
  • Do not store passwords as plain text.
Important: JavaScript validation improves UX, but it does not make an application secure by itself.
30 · Best Practices

Professional form practices

Clear labels

Every field should communicate what information is expected.

Useful feedback

Show validation feedback close to the relevant field.

Accessible controls

Use labels, meaningful names and keyboard-friendly controls.

Prevent duplicate submits

Disable or manage the submit action while a request is being processed.

Keep validation reusable

Separate complicated validation logic into functions.

Server validation

Always validate important data again on the backend.

31 · Interview Preparation

Important interview questions

1. What is a form?

A form is a collection of controls used to collect and submit user information.

2. What does preventDefault() do?

It prevents the browser's default action for the current event.

3. Why use the name attribute?

It identifies a form control's key when form data is submitted or collected.

4. What is FormData?

A browser API for constructing key/value pairs from form controls.

5. input vs change?

Input generally fires as a value changes, while change fires when a value is committed.

6. Is client validation enough?

No. Important validation must also happen on the server.

7. What is checkValidity()?

It checks whether a form control satisfies its constraint validation rules.

8. Why use labels?

Labels improve usability and accessibility and associate descriptive text with controls.

32 · Exam Preparation

5-Mark Answer

Explain HTML forms and JavaScript form handling.

HTML forms are used to collect information from users. The <form> element contains controls such as text fields, password fields, radio buttons, checkboxes, select boxes and buttons.

JavaScript can access form controls and their values. The submit event can be handled using addEventListener(). The preventDefault() method can stop the browser's default action so that JavaScript can validate and process the data.

Forms can use built-in HTML validation and custom JavaScript validation. The FormData API can also collect form values efficiently.
