02

Using the Fetch API

JavaScript provides the Fetch API for making HTTP requests from browser-based applications.

Basic Syntax

JavaScript 
fetch("https://api.example.com/students/");

The fetch function returns a Promise representing the result of the network operation.

Simple Request

JavaScript 
fetch("https://api.example.com/students/")
    .then(response => response.json())
    .then(data => {
        console.log(data);
    })
    .catch(error => {
        console.error(error);
    });
The Fetch API can be used for GET, POST, PUT, PATCH and DELETE requests.

04

Reading the API Response

A fetch response contains information such as the HTTP status and response body.

Checking Status

JavaScript 
const response = await fetch(url);

console.log(response.status);

console.log(response.ok);

For successful HTTP responses, response.ok is generally true for status codes in the 200–299 range.

Reading JSON

JavaScript 
const data = await response.json();

console.log(data);
Important: Calling response.json() reads and parses the response body as JSON. It also returns a Promise.

Sending a POST Request

POST is commonly used when the frontend wants to create a new resource.

Request

HTTP 
POST /students/

{
    "name": "Pradeep",
    "email": "pradeep@example.com",
    "age": 21,
    "course": "REST API"
}

JavaScript

Fetch POST 
async function createStudent() {

    const student = {
        name: "Pradeep",
        email: "pradeep@example.com",
        age: 21,
        course: "REST API"
    };

    const response = await fetch(
        "https://api.example.com/students/",
        {
            method: "POST",
            headers: {
                "Content-Type": "application/json"
            },
            body: JSON.stringify(student)
        }
    );

    const data =
        await response.json();

    console.log(data);
}

Important Parts

Part Purpose
method Specifies POST
headers Describes the request body format
JSON.stringify() Converts JavaScript object to JSON text
body Contains the data sent to the API

    headers: {
        "Content-Type": "application/json",
        "Authorization": "Bearer YOUR_ACCESS_TOKEN"

Never hard-code real secret credentials into frontend source code. Browser code is visible to users.

Loading States

Network requests are not instantaneous. A good frontend should tell the user that data is being loaded.

⏳

Loading

Show a spinner, skeleton or loading message.

✓

Success

Display the returned API data.

⚠️

Error

Tell the user that the request could not be completed.

Example

JavaScript 
async function loadStudents() {

    showLoading();

    try {

        const response =
            await fetch(url);

        const data =
            await response.json();

        showStudents(data);

    }
    catch(error) {

        showError(
            "Unable to load students."
        );

    }
    finally {

        hideLoading();

    }
}
11

Handling API Errors

A fetch request can fail because of network problems, API errors, authentication issues, server failures, or other conditions.

Important Point

Fetch does not automatically reject its Promise simply because the server returned an HTTP error such as 404 or 500. The frontend should inspect response.ok or response.status.

JavaScript 
async function getStudent() {

    try {

        const response =
            await fetch(
                "https://api.example.com/students/101/"
            );

        if(!response.ok){

            throw new Error(
                `HTTP error: ${response.status}`
            );

        }

        const data =
            await response.json();

        console.log(data);

    }
    catch(error){

        console.error(
            "Request failed:",
            error
        );

    }
}

Different Error Situations

Situation Frontend Response
200 Display data
400 Show validation/request error
401 Ask user to authenticate
403 Show permission message
404 Show resource-not-found message
500 Show general server error
Network failure Show connection error

Understanding CORS

CORS stands for Cross-Origin Resource Sharing. It is a browser security mechanism that controls whether a web page from one origin can access resources from another origin.

Example

Different Origins 
Frontend

http://localhost:3000


API

http://localhost:8000

If the frontend makes a browser request to the API on another origin, the server may need to provide appropriate CORS response headers.

Important: CORS is enforced by browsers. It is not a replacement for authentication or authorization.

Typical Development Setup

React
:3000
→
CORS
→
REST API
:8000

The backend must be configured to allow the appropriate frontend origin according to the application's requirements.

The frontend then includes the appropriate credential when calling protected endpoints, according to the authentication system used by the API.

Example: Student Search

  1. User enters student ID.
  2. User clicks "Search".
  3. JavaScript reads the ID.
  4. JavaScript sends a GET request.
  5. The REST API receives the request.
  6. The backend searches the database.
  7. The API creates a JSON response.
  8. The frontend receives the response.
  9. JavaScript reads the JSON.
  10. The UI displays the student.
Complete Example 
async function searchStudent(id) {

    const response = await fetch(
        `https://api.example.com/students/${id}/`
    );

    if(!response.ok){

        throw new Error(
            "Student could not be loaded"
        );

    }

    const student =
        await response.json();

    document.getElementById("name")
        .textContent = student.name;

    document.getElementById("course")
        .textContent = student.course;

}

Lesson Takeaway

  • The frontend communicates with the backend through REST APIs, not directly with the database.
  • JavaScript's Fetch API can send HTTP requests from browser applications.
  • GET is commonly used to retrieve resources.
  • POST is commonly used to create resources.
  • PUT/PATCH can update resources.
  • DELETE removes resources.
  • JSON is commonly used to exchange structured data between frontend and backend.
  • JSON.stringify() converts JavaScript values into JSON text for a request body.
  • response.json() reads a JSON response body.
  • response.ok and response.status should be checked when handling HTTP responses.
  • Loading, success and error states make frontend API interactions clearer for users.
  • CORS controls browser access to resources on different origins.
  • Authentication information should be sent according to the API's authentication design.
  • Never place private server secrets or database credentials in browser-side JavaScript.
