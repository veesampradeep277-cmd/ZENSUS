REST Architecture & API Principles

Understand what REST means, how REST APIs are structured, how resources are represented, and the important principles that make an API simple, scalable and easy to use.

01

What is REST?

REST stands for Representational State Transfer.

REST is an architectural style used for designing networked applications and APIs.

A REST API allows applications to communicate using standard web technologies such as HTTP.

Simple definition:

REST is a way of designing APIs where applications communicate with resources using standard HTTP methods.
02

Everything is a Resource

One of the most important ideas in REST is the concept of resources.

A resource represents something that the application manages.

👨‍🎓

Students

/api/students/

📚

Courses

/api/courses/

🛒

Products

/api/products/

📦

Orders

/api/orders/

REST idea:

Instead of designing an API around actions such as /getStudents, REST commonly represents the resource as /students/ and uses HTTP methods to describe the operation.
04

Stateless Architecture

A REST API should be stateless.

This means that each request should contain the information needed by the server to process that request.

Request 1
→
Server
→
Response
Request 2
→
Server
→
Response

The server should not need to depend on hidden information from a previous request to understand the current request.

Example:

If authentication is required, the request can contain the appropriate authentication credentials or token.

REST separates the client from the server.

🎨

06

Uniform Interface

REST encourages a consistent way of interacting with resources. This makes APIs easier to understand and use.

Resource URLs

/api/students/

HTTP Methods

GET, POST, PUT, PATCH, DELETE

Representations

Usually JSON data is exchanged.

Example 
GET    /api/students/
POST   /api/students/
GET    /api/students/10/
PUT    /api/students/10/
DELETE /api/students/10/
07

Resource Representation

The actual resource and its representation are related but not necessarily the same thing.

For example, a student resource can be represented as JSON.

Student Resource 
{
    "id": 101,
    "name": "Pradeep",
    "course": "REST API",
    "active": true
}

The client receives this representation and uses it in the application interface.

09

HTTP Status Codes

REST APIs use HTTP status codes to communicate the result of a request.

200 OK

Request completed successfully.

201 Created

A new resource was created.

400 Bad Request

The request contains invalid data.

401 Unauthorized

Authentication is required or invalid.

403 Forbidden

The server understood the request but access is not allowed.

404 Not Found

The requested resource does not exist.

500 Server Error

An unexpected server-side problem occurred.

10

Important REST Principles

1

Client-Server

Keep client concerns and server concerns separated.

2

Stateless

Each request should contain the information necessary for processing it.

3

Cacheable

Responses can indicate whether they may be cached, allowing clients or intermediaries to reuse responses when appropriate.

4

Uniform Interface

Use consistent resource URLs, representations and interaction rules.

5

Layered System

A client does not necessarily know whether it is communicating directly with the final server or through intermediate layers such as proxies or gateways.

6

Code on Demand

REST includes code-on-demand as an optional constraint. A server can provide executable code to a client when appropriate.

11

Designing a Good REST API

🔗

Use Clear URLs

Prefer:
/api/students/

📋

Use HTTP Methods

Let GET, POST, PUT, PATCH and DELETE describe operations.

📦

Consistent JSON

Return predictable data structures.

⚠️

Meaningful Errors

Return useful status codes and error information.

Good Resource-Based URL 
/api/students/
 /api/students/101/
 /api/courses/
 /api/courses/5/
Avoid action-heavy URLs such as:

/getStudents
/deleteStudent
/createNewStudent

Use HTTP methods with resource-based URLs instead.

Lesson Takeaway

  • REST stands for Representational State Transfer.
  • REST is an architectural style for designing networked applications.
  • REST APIs work with resources.
  • Resources are commonly represented using URLs.
  • HTTP methods describe operations on resources.
  • REST encourages stateless communication.
  • Client and server responsibilities are separated.
  • REST APIs commonly use JSON for data exchange.
  • HTTP status codes communicate the result of requests.
  • Good REST APIs use clear, consistent and resource-oriented URLs.
