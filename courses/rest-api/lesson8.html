CRUD Operations

Learn how REST APIs create, read, update and delete data. Understand how CRUD maps to HTTP methods, how JSON is used, how database operations happen behind an API, and how to design a complete CRUD API.

01

What is CRUD?

CRUD is an acronym for four fundamental operations performed on data:

C

Create

Add new data.

R

Read

Retrieve existing data.

U

Update

Modify existing data.

D

Delete

Remove existing data.

Simple idea:

Almost every application needs to store information and allow users or other systems to manage that information. CRUD provides the basic operations required to manage that data.
02

Why CRUD Matters

Imagine a student management application. Users need to perform operations such as:

  • Add a new student.
  • View all students.
  • View one student's details.
  • Change a student's course.
  • Remove a student.

These operations map naturally to CRUD.

User
→
Frontend
→
REST API
→
Database
Important:

CRUD is not a programming language or a specific database. It is a way of describing the four basic data-management operations.
03

CRUD and HTTP Methods

REST APIs commonly map CRUD operations to HTTP methods.

CRUD HTTP Method Typical Endpoint Purpose
Create POST /students/ Create a new student
Read GET /students/ Get students
Update PUT /students/101/ Replace student 101
Update PATCH /students/101/ Partially update student 101
Delete DELETE /students/101/ Delete student 101
Remember:

CRUD describes what happens to the data. HTTP methods describe the request operation.
04

CRUD Works With Resources

In REST APIs, CRUD operations are normally performed on resources.

For our example, the resource is:

Student Resource 
/students/

A collection represents multiple students:

Student Collection 
/students/

An individual student can be identified using an ID:

Individual Student 
/students/101/
The collection endpoint and individual-resource endpoint are both important when designing CRUD APIs.
05

Create Operation

The Create operation adds a new resource. In REST APIs, this is commonly performed using the POST method.

Endpoint

POST Endpoint 
POST /students/

Request Body

JSON Request 
{
    "name": "Pradeep",
    "email": "pradeep@example.com",
    "age": 21,
    "course": "REST API"
}

What Happens?

1
Client sends POST request

The frontend sends student information as JSON.

2
API receives request

The backend receives and parses the request.

3
Validate data

The API checks whether the submitted data is valid.

4
Save to database

The backend creates a new database record.

5
Return response

The API sends the newly created resource back to the client.

Possible Response

201 Created 
{
    "id": 101,
    "name": "Pradeep",
    "email": "pradeep@example.com",
    "age": 21,
    "course": "REST API"
}

Update Operation

The Update operation changes existing data. REST APIs commonly use PUT or PATCH.

PUT

PUT is commonly used when the client sends a representation intended to replace the resource.

PUT 
PUT /students/101/

PATCH

PATCH is commonly used when the client wants to modify only part of an existing resource.

PATCH 
PATCH /students/101/

PUT Example

PUT Request Body 
{
    "name": "Pradeep",
    "email": "pradeep@example.com",
    "age": 22,
    "course": "Django"
}

PATCH Example

PATCH Request Body 
{
    "course": "Django"
}
If only the course needs to change, PATCH can send just the field that needs modification.

Example Response

Updated Student 
{
    "id": 101,
    "name": "Pradeep",
    "email": "pradeep@example.com",
    "age": 22,
    "course": "Django"
}

09

Collection vs Individual Resource

Understanding the difference between a collection and an individual resource is essential when designing CRUD APIs.

Request Meaning Typical CRUD
GET /students/ Get the student collection Read
POST /students/ Create a student in the collection Create
GET /students/101/ Get student 101 Read
PUT /students/101/ Replace student 101 Update
PATCH /students/101/ Partially update student 101 Update
DELETE /students/101/ Delete student 101 Delete
This resource-oriented design keeps the API predictable because the URL represents the resource while the HTTP method expresses the requested operation.

CRUD Status Codes

HTTP status codes tell the client what happened to the request.

Operation Common Success Status Meaning
Create 201 Created A new resource was created.
Read 200 OK The requested data was returned.
Update 200 OK The updated resource was returned.
Update 204 No Content Update succeeded without a response body.
Delete 204 No Content Resource was deleted successfully.

Common Error Responses

Status Example CRUD Situation
400 Bad Request Invalid data was submitted.
401 Unauthorized Authentication is required or failed.
403 Forbidden User is authenticated but lacks permission.
404 Not Found Requested resource does not exist.
409 Conflict Request conflicts with current resource state.
422 Unprocessable Content Request format is understood but validation fails.
500 Internal Server Error Unexpected server-side failure.

CRUD Errors and Validation

A good CRUD API should not blindly store every request. It should validate incoming data and return useful errors.

Example Invalid Create Request

Invalid JSON 
{
    "name": "",
    "email": "not-an-email",
    "age": -5
}

The server may reject this data because the fields do not satisfy the application's validation rules.

Example Error Response

400 Bad Request 
{
    "error": "Validation failed",
    "fields": {
        "name": "This field is required.",
        "email": "Enter a valid email address.",
        "age": "Age must be greater than 0."
    }
}

Resource Not Found

404 Not Found 
{
    "error": "Student not found",
    "code": "STUDENT_NOT_FOUND"
}
Important:

Never assume that the client will always send correct data. Validation belongs on the server as well as any useful client-side validation.

Practice Challenge

Design CRUD endpoints for an online course platform. The main resource is courses.

Requirements

  • Create a course.
  • Get all courses.
  • Get course 10.
  • Replace course 10.
  • Partially update course 10.
  • Delete course 10.

Expected Design

Requirement Method Endpoint
Create course POST /courses/
Get all courses GET /courses/
Get course 10 GET /courses/10/
Replace course 10 PUT /courses/10/
Update part of course 10 PATCH /courses/10/
Delete course 10 DELETE /courses/10/
Think before coding:

First identify the resource → choose the endpoint → choose the HTTP method → define the request data → define the response → define validation and errors.

Lesson Takeaway

  • CRUD stands for Create, Read, Update and Delete.
  • CRUD describes the fundamental operations performed on data.
  • POST is commonly used to create resources.
  • GET is used to retrieve resources.
  • PUT is commonly used for replacing an existing resource.
  • PATCH is commonly used for partial updates.
  • DELETE is used to remove resources.
  • JSON is commonly used to transfer CRUD request and response data.
  • A collection endpoint such as /students/ represents a resource collection.
  • An individual endpoint such as /students/101/ represents one resource.
  • Successful creation commonly returns 201 Created.
  • Successful retrieval commonly returns 200 OK.
  • Successful deletion commonly uses 204 No Content when no response body is needed.
  • Validation and error handling are important parts of a reliable CRUD API.
