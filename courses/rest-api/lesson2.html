How Applications Communicate

Learn how websites, mobile applications, servers and other software systems communicate with each other using requests, responses, HTTP and data formats such as JSON.

01

How Do Applications Communicate?

Applications often need information or services from other applications. For example, a shopping application may need payment information from a payment service.

A weather application may request weather information from a weather server. A mobile banking application may communicate with a banking server.

Application A
→
API
→
Application B
Important: Applications usually communicate by sending a request and receiving a response.
02

Client and Server

The most common communication model on the web is the client-server model.

💻

Client

The client is the application that requests information or a service.

Examples: browser, mobile app, React application.

🖥️

Server

The server receives the request, processes it and sends a response.

Examples: Django, Node.js, FastAPI backend.

Client
→
Request
→
Server
→
Response
03

What is a Request?

A request is a message sent by a client to a server asking the server to perform an operation or return information.

Method GET
URL /api/students/
Headers Authentication / Content-Type
Body Optional data

For example, a frontend application may send:

HTTP Request 
GET /api/students/
04

What is a Response?

A response is the message returned by the server after processing the request.

Status Code 200 OK
Content-Type application/json
Data Student information
HTTP Response 
{
    "id": 1,
    "name": "Pradeep",
    "course": "Django"
}
05

HTTP — The Communication Protocol

HTTP stands for HyperText Transfer Protocol. It is one of the main protocols used for communication between web clients and servers.

📤

Request

Client sends a request to the server.

⚙️

Processing

Server processes the request.

📥

Response

Server returns information to the client.

06

Communication Through the Internet

When you use a web application, the communication may travel through the internet before reaching the server.

Browser
→
Internet
→
API Server
→
Database

The server may communicate with a database, process the information, and then send a response back to the client.

07

Where Does the API Come In?

An API provides a defined way for one software application to communicate with another software application.

React App
→
REST API
→
Backend
Think of an API as a communication interface.
The frontend does not need to know exactly how the backend works. It communicates through the API's defined endpoints.
08

JSON — Data Exchange Format

Applications need a common format for exchanging data. REST APIs commonly use JSON.

JSON Data 
{
    "id": 101,
    "name": "Pradeep",
    "email": "pradeep@example.com",
    "course": "REST API"
}
🔑

Key

Example: name

📦

Value

Example: "Pradeep"

09

Real-World Example — Food Delivery

Imagine a food delivery application.

Mobile App
→
Restaurant API
→
Restaurant Data

The mobile application may request nearby restaurants. The API receives the request and returns restaurant information.

Example:

Client asks: GET /api/restaurants/

Server responds with restaurant data in JSON.
10

Frontend and Backend Communication

Modern applications often separate the frontend and backend. The REST API acts as the communication layer between them.

🎨

Frontend

React, HTML/CSS/JavaScript, mobile applications.

🔗

REST API

Defines endpoints and communication rules.

⚙️

Backend

Django, FastAPI, Node.js and other server technologies.

11

API and Database Communication

The frontend normally does not directly access the database. Instead, the API communicates with the backend, and the backend communicates with the database.

Frontend
→
REST API
→
Backend
→
Database
Important:
A properly designed application generally keeps database access inside the backend rather than exposing database credentials directly to the frontend.

13

Application Communication Example

Suppose we have a student management application. The frontend wants to display all students.

Step Action
1 User opens Student Dashboard
2 Frontend sends GET request
3 REST API receives request
4 Backend reads database
5 Backend prepares JSON
6 API sends JSON response
7 Frontend displays students
Example Endpoint 
GET /api/students/

15

Lesson Takeaway

  • Applications communicate by exchanging requests and responses.
  • The client sends a request and the server sends a response.
  • HTTP is commonly used for web communication.
  • An API provides a defined communication interface between applications.
  • REST APIs commonly exchange data using JSON.
  • Frontend applications communicate with backend systems through APIs.
  • Backend applications can communicate with databases.
  • The frontend normally should not directly access database credentials.
