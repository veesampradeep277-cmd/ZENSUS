03 SEARCHING FUNDAMENTALS

Linear Search

Linear search checks candidates one by one. It does not require sorted data.

ALGORITHM

Linear Search

START
↓
Set i = 0
↓
i < n?
NO → NOT FOUND YES ↓
Compare arr[i] with target
EQUAL → RETURN i NOT EQUAL ↓
i = i + 1
↺ Repeat
Python 
def linear_search(arr, target):

    for i in range(len(arr)):

        if arr[i] == target:
            return i

    return -1

Complexity

Best case: O(1)

Worst case: O(n)

Space: O(1)

04 BINARY SEARCH

Binary Search: Eliminate Half

Binary search works when the search space has enough order or monotonic structure to prove that an entire portion can be discarded.

½
Every decision removes approximately half of the remaining candidates.
n → n/2 → n/4 → n/8 → ... → 1
BINARY SEARCH VISUALIZER
Target: 23 Left: 0 Mid: 4 Right: 8

Start by checking the middle element.

CORE ALGORITHM

Binary Search — Closed Interval [left, right]

START
→
left = 0
right = n - 1
→
left ≤ right?
YES →
mid = left + (right-left)//2
→
Compare target & arr[mid]
== → RETURN MID < → RIGHT = MID - 1 > → LEFT = MID + 1
left > right → NOT FOUND
Canonical Python 
def binary_search(arr, target):

    left = 0
    right = len(arr) - 1

    while left <= right:

        mid = left + (right - left) // 2

        if arr[mid] == target:
            return mid

        elif arr[mid] < target:
            left = mid + 1

        else:
            right = mid - 1

    return -1

Why these updates?

left = mid + 1 means mid and everything before it are impossible.

right = mid - 1 means mid and everything after it are impossible.

left <= right checks the final remaining candidate.

06 INVARIANTS

The invariant: your binary-search safety net

An invariant is a statement that remains true before and after every iteration.

🔒 Closed Interval Invariant
01 At every iteration, [left, right] contains every index that could still be the answer.
02 Anything outside the interval has already been proven impossible.
03 When left > right, there are no candidates remaining.

What does [left, right] mean?

It means:

"These are the only positions I still believe could contain the answer."

Why is this powerful?

Every update must preserve this statement. If your update breaks it, your algorithm is wrong.

INTERVIEW FORMULA

State your invariant before coding.

"My current interval contains all possible answers. Whenever I discard a side, I have proven that side cannot contain the answer."

1

left + half the distance

2

Integer division

// 2 gives the integer midpoint.

4

Same mathematical midpoint

Condition Interval idea Typical use Important point

Important: Neither condition is universally "better." The correct condition depends on your interval definition and what your loop is designed to return.

09 BINARY SEARCH ON ANSWER ⭐

When there is no sorted array

One of the most important interview upgrades is realizing that binary search does not require an array.

?
Search the possible answers.
Example: "What is the minimum speed that can finish the work?"
01 Identify answer range
02 Pick mid
03 Check feasible(mid)
04 Prove monotonicity
05 Discard half

Step 1 — Identify answer space

Example: minimum eating speed is between 1 and max(piles).

Step 2 — Define feasibility

Create a function: feasible(x) that tells whether candidate x works.

Step 3 — Prove monotonicity

If speed 10 works, then speeds 11, 12, 13... also work.

Step 4 — Choose optimization direction

For minimum feasible value: when feasible(mid) is true, move left.

Monotonicity

Binary search needs a predictable True/False transition.

1 → F 2 → F 3 → F 4 → F 5 → T 6 → T 7 → T 8 → T

Pattern: FFFFTTTT

CLASSIC PROBLEM

Koko Eating Bananas

Find the minimum eating speed K such that all bananas can be eaten within H hours.

Search space 

lo = 1
hi = max(piles)

Feasibility 

hours = 0

for pile in piles:
    hours += ceil(pile / speed)

return hours <= H

Binary search 

def min_speed(piles, h):

    lo = 1
    hi = max(piles)
    ans = hi

    while lo <= hi:

        mid = lo + (hi-lo)//2

        if feasible(mid):

            ans = mid
            hi = mid - 1

        else:

            lo = mid + 1

    return ans
Recognition: We are not searching the piles. We are searching possible speeds.

Search in Rotated Sorted Array 
def search_rotated(nums, target):

    left = 0
    right = len(nums) - 1

    while left <= right:

        mid = left + (right-left)//2

        if nums[mid] == target:
            return mid

        if nums[left] <= nums[mid]:

            if nums[left] <= target < nums[mid]:
                right = mid - 1
            else:
                left = mid + 1

        else:

            if nums[mid] < target <= nums[right]:
                left = mid + 1
            else:
                right = mid - 1

    return -1

The reasoning

1. At least one half is sorted.

2. Identify the sorted half.

3. Ask whether the target lies inside that sorted range.

4. Keep the appropriate half.

Don't memorize the branches. Understand the invariant: one side has usable order.
11 CORRECTNESS

Why is discarding half actually safe?

Binary search is not magic. Its correctness comes from a logical proof.

Case 1 — target == arr[mid]

We found the target. Returning mid is safe.

Case 2 — target > arr[mid]

Because the array is sorted, every value before or at mid is ≤ arr[mid]. Therefore none can be the target.

Case 3 — target < arr[mid]

Because the array is sorted, every value at or after mid is ≥ arr[mid]. Therefore none can be the target.

Therefore

The discarded half contains no valid answer. Removing it preserves the invariant.

CORRECTNESS IN ONE SENTENCE

We discard only what we have proved impossible.

🔬 Loop Invariant Proof
1
Initialization

Initially, [0, n-1] contains every possible index.

2
Maintenance

After comparing with mid, we remove only a side that cannot contain the target.

3
Termination

If target is found, return it. If left > right, no candidate remains, so the target does not exist.

14 COMMON MISTAKES

Why binary search fails in interviews

01

Wrong loop condition

The condition must match your interval definition.

02

Wrong boundary update

left = mid can cause an infinite loop.

03

Forgetting duplicates

Finding the target is not enough for first/last occurrence.

04

No invariant

You must know exactly what the current interval represents.

05

Non-monotonic condition

If the predicate behaves like F T F T, ordinary binary search is invalid.

06

Wrong answer direction

Minimum feasible and maximum feasible require opposite boundary movement.

07

Incorrect answer range

In answer search, bad lower/upper bounds can eliminate the real answer.

08

Memorizing branches

Understand why the discarded side is impossible.

GOLDEN RULE

Before writing code, define:

Search space → invariant → mid → decision → discarded region → answer.
