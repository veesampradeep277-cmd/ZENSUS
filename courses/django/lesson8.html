Why Forms Are Important

Almost every real web application needs to collect information from users.

👤 Registration

Collect name, email, password and other account information.

🔐 Login

Receive username and password from a user.

📝 Feedback

Allow users to submit comments and feedback.

🛒 Products

Add product information through an administration form.

🔎 Search

Accept search keywords and return matching results.

📚 Student Portal

Register students and update their information.

Django Forms solve two major problems:

1. Collecting user input
2. Validating user input before using it
02

What is a Django Form?

A Django Form is a Python class that describes the fields a user should submit and the rules that should be applied to that submitted data.

Think of a Django Form as a bridge between:

HTML Form → User Input → Validation → Python Data

Without Django Forms

You would manually create HTML fields, read request.POST, check every value, handle errors, and repeat this logic throughout your application.

With Django Forms

Django can generate form fields, validate submitted values, report errors and provide cleaned data.

Creating Your First Django Form

Forms are usually created inside a file called forms.py.

forms.py 
from django import forms


class StudentForm(forms.Form):

    name = forms.CharField(
        max_length=100
    )

    email = forms.EmailField()

    age = forms.IntegerField()
Here:

StudentForm is your form class.
CharField accepts text.
EmailField validates email format.
IntegerField expects an integer.

06

GET vs POST

GET

Request Data

GET is commonly used when retrieving information.

Example 
/search/?q=django

Query parameters can appear in the URL.

POST

Submit Data

POST is commonly used when sending form data to the server.

Example 
username=Pradeep
email=example@email.com

POST data is not normally placed directly in the URL.

When processing forms that change data on the server, POST is generally the appropriate method.
07

request.POST

Django provides submitted POST data through request.POST.

views.py 
def student_register(request):

    if request.method == "POST":

        name = request.POST.get("name")

        email = request.POST.get("email")

        print(name)
        print(email)

    return render(
        request,
        "student_register.html"
    )
You can read POST data manually, but Django Forms are preferable for structured validation because they provide a consistent validation system.
08

is_valid()

After binding submitted data to a form, call is_valid() to run the form's validation.

views.py 
def register(request):

    if request.method == "POST":

        form = StudentForm(
            request.POST
        )

        if form.is_valid():

            print("Valid data")

    else:

        form = StudentForm()

    return render(
        request,
        "register.html",
        {"form": form}
    )
is_valid() returns True when all required validation rules pass.

Otherwise it returns False and the form contains errors.
09

cleaned_data

After form.is_valid() returns True, Django provides the validated values through cleaned_data.

Python 
if form.is_valid():

    name = form.cleaned_data["name"]

    email = form.cleaned_data["email"]

    age = form.cleaned_data["age"]

    print(name)
    print(email)
    print(age)
Important: Use cleaned_data after successful validation instead of treating raw input as validated application data.

11

Custom Validation

Sometimes built-in validation is not enough. You can write your own validation logic.

Field-specific clean method

forms.py 
from django import forms


class StudentForm(forms.Form):

    name = forms.CharField(
        max_length=100
    )

    age = forms.IntegerField()


    def clean_age(self):

        age = self.cleaned_data["age"]

        if age < 18:

            raise forms.ValidationError(
                "Student must be at least 18."
            )

        return age
A validation error raised inside a clean method is shown to the user as a form error.

Handling Form Errors

Enter a valid email address.

Django automatically stores validation errors in the form. When the form is rendered again, Django can display those errors near the relevant fields.

Checking errors 
if form.errors:

    print(form.errors)
A good form experience should clearly tell the user what needs to be corrected.
13

CSRF Protection

Django includes protection against Cross-Site Request Forgery attacks for POST forms.

Inside a Django template form, include:

template.html 
<form method="POST">

    {% csrf_token %}

    <input
        type="text"
        name="name"
    >

    <button type="submit">
        Submit
    </button>

</form>
Important: Do not forget {% csrf_token %} in normal Django POST forms.
14

ModelForm

A ModelForm is useful when a form is directly connected to a Django model.

Instead of manually defining every form field, Django can generate form fields from your model.
forms.py 
from django import forms
from .models import Student


class StudentForm(forms.ModelForm):

    class Meta:

        model = Student

        fields = [
            "name",
            "email",
            "age",
            "course"
        ]

forms.Form

General-purpose form. You define the fields yourself.

forms.ModelForm

Form connected directly to a Django model.

15

Saving a ModelForm

One major advantage of ModelForm is that a valid form can be saved directly to the database.

views.py 
def register_student(request):

    if request.method == "POST":

        form = StudentForm(
            request.POST
        )

        if form.is_valid():

            form.save()

            return redirect(
                "success"
            )

    else:

        form = StudentForm()

    return render(
        request,
        "register.html",
        {"form": form}
    )
ModelForm flow:

Model → ModelForm → User Input → Validation → save() → Database

Connecting Form with View

The view usually handles two situations:

GET

Display Empty Form

Create an unbound form and show it to the user.

POST

Process Submitted Form

Bind submitted data, validate it and process the result.

Complete View Pattern 
def register(request):

    if request.method == "POST":

        form = StudentForm(
            request.POST
        )

        if form.is_valid():

            name = form.cleaned_data["name"]

            email = form.cleaned_data["email"]

            # Process valid data here

            return redirect("success")

    else:

        form = StudentForm()

    return render(
        request,
        "register.html",
        {"form": form}
    )

Rendering a Form in a Template

A Django form can be passed to the template through the context dictionary.

register.html 
<h1>Student Registration</h1>

<form method="POST">

    {% csrf_token %}

    {{ form.as_p }}

    <button type="submit">
        Register
    </button>

</form>
{{ form.as_p }} is a convenient way to render the fields as paragraphs.

Later, you can render each field separately when you need more control over the design.

Common Mistakes

❌ Forgetting forms.py

Keep form definitions in a dedicated forms.py file for clean organization.

❌ Forgetting is_valid()

Always validate submitted form data before processing it.

❌ Reading cleaned_data too early

Use cleaned_data after successful validation.

❌ Missing csrf_token

Normal Django POST forms should include CSRF protection.

❌ Wrong request method

Check request.method before deciding how to process the form.

❌ Forgetting form context

Pass the form to the template through the context.

Golden pattern:

GET → Show empty form
POST → Bind submitted data
is_valid() → Validate
cleaned_data / save() → Process
redirect() → Finish successfully
