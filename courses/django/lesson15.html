03

Student Model

models.py

from django.db import models


class Student(models.Model):

    name = models.CharField(max_length=100)

    email = models.EmailField(unique=True)

    age = models.IntegerField()

    course = models.CharField(max_length=100)

    phone = models.CharField(max_length=15)

    profile_image = models.ImageField(
        upload_to="students/",
        blank=True,
        null=True
    )

    created_at = models.DateTimeField(
        auto_now_add=True
    )

    def __str__(self):
        return self.name

Create the database table

python manage.py makemigrations
python manage.py migrate

Example Models

from django.db import models
from django.contrib.auth.models import User


class Category(models.Model):

    name = models.CharField(max_length=100)

    def __str__(self):
        return self.name


class Post(models.Model):

    title = models.CharField(max_length=200)

    content = models.TextField()

    author = models.ForeignKey(
        User,
        on_delete=models.CASCADE
    )

    category = models.ForeignKey(
        Category,
        on_delete=models.SET_NULL,
        null=True
    )

    created_at = models.DateTimeField(
        auto_now_add=True
    )

    def __str__(self):
        return self.title


class Comment(models.Model):

    post = models.ForeignKey(
        Post,
        on_delete=models.CASCADE
    )

    author = models.ForeignKey(
        User,
        on_delete=models.CASCADE
    )

    content = models.TextField()

    created_at = models.DateTimeField(
        auto_now_add=True
    )
06

Development vs Production

DEV

Development

  • DEBUG = True
  • Local development server
  • SQLite is convenient
  • Local configuration
  • Detailed errors
PROD

Production

  • DEBUG = False
  • Production application server
  • Production database
  • Environment variables
  • HTTPS
Important: Django's development server is designed for development, not for serving a production application.
07

Production Settings

Production configuration should be separated from local development configuration. 

DEBUG = False

ALLOWED_HOSTS = [
    "your-domain.com",
    "www.your-domain.com"
]

STATIC_URL = "/static/"

STATIC_ROOT = BASE_DIR / "staticfiles"

MEDIA_URL = "/media/"

MEDIA_ROOT = BASE_DIR / "media"
Security: Never publish your real SECRET_KEY in a public repository.

Environment Variables

Sensitive and environment-specific configuration should not be hard-coded directly into your source code. 

SECRET_KEY=your-secret-key
DEBUG=False

DATABASE_NAME=production_database
DATABASE_USER=database_user
DATABASE_PASSWORD=database_password
DATABASE_HOST=database_host
DATABASE_PORT=5432
S

Security

Keep secrets outside source code.

D

Different Environments

Development and production can use different values.

C

Configuration

Change configuration without changing application logic.

13

Production Security Checklist

  • Set DEBUG = False.
  • Configure ALLOWED_HOSTS.
  • Keep SECRET_KEY private.
  • Use HTTPS.
  • Validate user input.
  • Use CSRF protection for applicable forms.
  • Keep dependencies updated.
  • Protect authentication endpoints.
  • Secure uploaded files.
  • Back up production data.
  • Monitor application errors.
Production security is a combination of application configuration, authentication, HTTPS, database security and infrastructure practices.
