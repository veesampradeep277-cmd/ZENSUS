File & Image Uploads

Learn how Django receives files from a browser, stores them on the server, saves their paths in the database, validates uploads, and displays uploaded files and images inside templates.

01

What Are File Uploads?

A file upload happens when a user selects a file on their device and sends it to a web server through a form.

Examples include:

PDF

Documents

Resumes, certificates, reports and assignments.

IMG

Images

Profile photos, product images and project pictures.

ZIP

Other Files

Archives, spreadsheets and other supported files.

02

FileField vs ImageField

Field Purpose Example
FileField Stores uploaded files PDF, DOCX, ZIP
ImageField Stores uploaded images JPG, PNG, WebP
Important: ImageField requires the Pillow image library because Django uses Pillow for image handling. 
pip install Pillow
03

MEDIA_ROOT and MEDIA_URL

Django uses two important settings for uploaded media: MEDIA_ROOT and MEDIA_URL.

DIR

MEDIA_ROOT

Defines the filesystem location where uploaded media files are stored.

URL

MEDIA_URL

Defines the URL prefix used to access uploaded media during development.

settings.py

MEDIA_URL = "/media/"

MEDIA_ROOT = BASE_DIR / "media"
project/ │ ├── manage.py ├── db.sqlite3 │ ├── media/ │ ├── documents/ │ ├── images/ │ └── profiles/ │ └── app/ ├── models.py ├── forms.py ├── views.py └── templates/
Remember: Media files are different from static files. Static files are application assets such as CSS and JavaScript; media files are generally user-uploaded content.
04

Creating FileField and ImageField

Example — Student Profile

from django.db import models

class Student(models.Model):

    name = models.CharField(
        max_length=100
    )

    resume = models.FileField(
        upload_to="resumes/"
    )

    profile_image = models.ImageField(
        upload_to="profiles/"
    )

What does upload_to mean?

The upload_to value tells Django which directory under MEDIA_ROOT should contain the uploaded file. 

upload_to="resumes/"

A file may therefore be stored under: 

media/resumes/example.pdf

An image may be stored under: 

media/profiles/student.jpg

Creating an Upload Form

Django forms can be used to create a clean upload interface.

forms.py

from django import forms
from .models import Student

class StudentForm(forms.ModelForm):

    class Meta:

        model = Student

        fields = [
            "name",
            "resume",
            "profile_image"
        ]

Why ModelForm?

A ModelForm can generate form fields from a Django model and can save submitted data back to that model.

07

multipart/form-data

This is one of the most important details when uploading files.

The HTML form must use: 

<form method="POST"
      enctype="multipart/form-data">

    {% csrf_token %}

    {{ form.as_p }}

    <button type="submit">
        Upload
    </button>

</form>
Critical: If you forget enctype="multipart/form-data", uploaded files will not be sent correctly with the form.
POST

method="POST"

Sends submitted form data to the server.

FILE

multipart/form-data

Allows files to be included in the request.

CSRF

{% csrf_token %}

Protects the POST form against CSRF attacks.

Handling Uploads in the View

The view receives normal form data through request.POST and uploaded files through request.FILES. 

from django.shortcuts import render
from .forms import StudentForm

def upload_student(request):

    if request.method == "POST":

        form = StudentForm(
            request.POST,
            request.FILES
        )

        if form.is_valid():

            form.save()

    else:

        form = StudentForm()

    return render(
        request,
        "upload.html",
        {"form": form}
    )

Understanding request.FILES

request.FILES contains uploaded files from the request. 

uploaded_file = request.FILES.get(
    "resume"
)

You can inspect basic information about the uploaded file: 

uploaded_file.name
uploaded_file.size
uploaded_file.content_type
Property Meaning
name Original filename
size File size in bytes
content_type Reported MIME/content type
For important security decisions, do not rely only on a browser-supplied filename or content type. Validate uploads on the server.

Working with ImageField

ImageField is designed specifically for image uploads.

Model

from django.db import models

class Profile(models.Model):

    name = models.CharField(
        max_length=100
    )

    photo = models.ImageField(
        upload_to="profiles/"
    )

Template

<img
    src="{{ profile.photo.url }}"
    alt="{{ profile.name }}"
    width="200"
>
Remember: ImageField stores the path/reference to the uploaded image in the model while the actual image file is stored in the configured media storage.
12

File Upload Validation

File uploads should be validated before accepting them.

SIZE

File Size

Restrict unusually large uploads where appropriate.

TYPE

File Type

Allow only file types your application actually needs.

IMG

Image Validation

Check dimensions and image validity when necessary.

Example Form Validation

from django import forms
from .models import Student

class StudentForm(forms.ModelForm):

    class Meta:

        model = Student

        fields = [
            "name",
            "resume"
        ]

    def clean_resume(self):

        file = self.cleaned_data.get(
            "resume"
        )

        if file:

            if file.size > 5 * 1024 * 1024:

                raise forms.ValidationError(
                    "File must be smaller than 5 MB."
                )

        return file
Security: Never blindly trust uploaded files. Validate what your application accepts and configure production storage and serving securely.
13

Multiple File Uploads

A form can allow users to select multiple files using the HTML multiple attribute. 

<input
    type="file"
    name="documents"
    multiple
>

In the view, multiple uploaded files can be retrieved using: 

files = request.FILES.getlist(
    "documents"
)

for file in files:

    print(file.name)
Handling multiple uploads usually requires a model design that can store each uploaded file as its own database record, rather than trying to put many files into one FileField.

File Upload Security

Upload functionality must be designed carefully because users can submit files to your application.

01

Limit File Size

Set reasonable application and server-side upload limits.

02

Validate File Types

Accept only the file formats your application needs.

03

Use Safe Storage

Configure production storage carefully instead of exposing arbitrary filesystem paths.

04

Validate Images

Make sure uploaded images are actually valid images and apply appropriate dimension or size restrictions.

Never assume a filename extension alone proves that a file is safe. Production applications should use layered validation and secure storage and serving practices.
17

Common Mistakes

01

Missing enctype

Forgetting multipart/form-data prevents files from being submitted correctly.

02

Missing request.FILES

Uploaded files must be passed from request.FILES to the form when handling uploads.

03

Forgetting Pillow

ImageField requires Pillow.

04

Wrong Media Settings

Check MEDIA_ROOT and MEDIA_URL carefully.

05

Forgetting Migrations

Model changes require makemigrations and migrate.

06

Unsafe Uploads

Never accept arbitrary files without appropriate validation and production storage controls.

Lesson Takeaway

  • Django uses FileField for general file uploads.
  • Django uses ImageField for image uploads.
  • ImageField requires Pillow.
  • MEDIA_ROOT defines the filesystem location for uploaded media.
  • MEDIA_URL defines the media URL prefix.
  • upload_to controls the upload directory beneath the media storage.
  • File upload forms need multipart/form-data.
  • Uploaded files are available through request.FILES.
  • ModelForm can simplify upload form handling.
  • Uploaded file URLs can be accessed using the field's .url.
  • File size, type and content should be validated appropriately.
  • Production applications need secure media storage and serving practices.
Core concept:

User selects file → multipart/form-data → request.FILES → Form Validation → File Storage → Database File Reference → Template → Browser
