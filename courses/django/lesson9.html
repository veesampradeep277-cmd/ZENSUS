Why Authentication Matters

A real application usually cannot give every visitor access to everything.

👤 User Accounts

Store and identify registered users.

🔐 Login

Allow users to prove their identity.

🚪 Logout

End the user's authenticated session.

Give authorized users access to management features.

Control specific actions users can perform.

02

What is Authentication?

👤

Authentication

Authentication answers:

"Who are you?"

The application verifies that a user is actually the account owner.

🔐

Example

A user enters:

  • Username
  • Password

Django checks the credentials and, when valid, authenticates the user.

03

What is Authorization?

🛡️

Authorization

Authorization answers:

"What are you allowed to do?"

A user may be logged in but still not have permission to perform every action.

Example — Student Management System
Student View Profile
Student Delete Students
Teacher Manage Grades
Admin Manage Users
04

Authentication vs Authorization

🪪

Authentication

Determines the identity of the user.

Who are you?

Example: logging in with a username and password.

🔑

Authorization

Determines what the authenticated user can access.

What can you do?

Example: only an admin can delete another user.

Easy memory trick:

Authentication = Identity
Authorization = Permission

10

authenticate()

The authenticate() function checks whether the supplied credentials correspond to a valid user.

views.py 
from django.contrib.auth import authenticate


user = authenticate(
    username="pradeep",
    password="StrongPassword123"
)


if user is not None:

    print("Valid credentials")

else:

    print("Invalid credentials")
Important:

authenticate() checks the credentials.
It does not by itself mean that the user is now logged in.
11

login()

Once the credentials are authenticated, Django's login() function associates the user with the current session.

Login View 
from django.contrib.auth import authenticate
from django.contrib.auth import login
from django.shortcuts import redirect


def user_login(request):

    if request.method == "POST":

        username = request.POST.get(
            "username"
        )

        password = request.POST.get(
            "password"
        )

        user = authenticate(
            request,
            username=username,
            password=password
        )

        if user is not None:

            login(request, user)

            return redirect("dashboard")

    return render(
        request,
        "login.html"
    )
Remember:

authenticate() → checks credentials
login() → starts authenticated session
12

logout()

Django provides logout() to end the user's authenticated session.

from django.shortcuts import redirect


def user_logout(request):

A common application flow is:

Login → Dashboard → Logout → Login Page

14

is_authenticated

Django provides request.user.is_authenticated to determine whether the current user is authenticated.

Example 
def dashboard(request):

    if request.user.is_authenticated:

        return HttpResponse(
            "Welcome to your dashboard"
        )

    return HttpResponse(
        "Please login"
    )

Authenticated

The user has successfully logged in.

Unauthenticated

The current request is not associated with a logged-in user.

15

Protected Views

A protected view is a page that should only be available to authenticated users.

Manual Protection 
def dashboard(request):

    if not request.user.is_authenticated:

        return redirect("login")

    return render(
        request,
        "dashboard.html"
    )
This works, but Django provides a cleaner decorator for protecting function-based views.
16

@login_required

The @login_required decorator redirects unauthenticated users to the configured login page.

views.py 
from django.contrib.auth.decorators import login_required


@login_required
def dashboard(request):

    return render(
        request,
        "dashboard.html"
    )
This is one of the most useful authentication tools for function-based views.

User logged in → dashboard opens
User not logged in → redirected to login

Mini Project — ZENSUS Secure Dashboard

Project Goal

Build a small Django application where users can log in, access a protected dashboard and log out.

Step 1 — Login View

views.py 
from django.contrib.auth import authenticate
from django.contrib.auth import login
from django.shortcuts import render
from django.shortcuts import redirect


def login_view(request):

    if request.method == "POST":

        username = request.POST.get(
            "username"
        )

        password = request.POST.get(
            "password"
        )

        user = authenticate(
            request,
            username=username,
            password=password
        )

        if user is not None:

            login(request, user)

            return redirect("dashboard")

    return render(
        request,
        "login.html"
    )

Step 2 — Protected Dashboard

views.py 
from django.contrib.auth.decorators import login_required


@login_required
def dashboard(request):

    return render(
        request,
        "dashboard.html"
    )

Step 3 — Logout

views.py 
from django.contrib.auth import logout


def logout_view(request):

    logout(request)

    return redirect("login")

Common Authentication Mistakes

❌ Confusing authenticate() and login()

authenticate() checks credentials; login() establishes the authenticated session.

❌ Forgetting @login_required

A page intended to be private should have appropriate access protection.

❌ Missing csrf_token

Include CSRF protection in normal POST login forms.

❌ Storing passwords manually

Use Django's authentication and password handling mechanisms.

❌ Checking only the frontend

Access control must be enforced on the server.

❌ Giving every user admin access

Use appropriate permissions and groups for different levels of access.
