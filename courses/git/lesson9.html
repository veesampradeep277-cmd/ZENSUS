GIT & GITHUB • LESSON 09

Push, Pull & Fetch

Learn how Git moves commits between your local repository and a remote repository. Understand exactly what git push, git pull, and git fetch do and when to use each command.

1. Push, Pull and Fetch — The Big Picture

In the previous lesson, you connected your local Git repository to a GitHub repository.

Now we need to move information between them.

⬆️

git push

Sends your local commits to a remote repository.

Local → Remote
⬇️

git pull

Downloads remote changes and integrates them into your current branch.

Remote → Local
🔄

git fetch

Downloads remote information without changing your current working branch.

Remote → Local Remote-Tracking
Easy memory trick:

Push = send your work.
Pull = get remote work and integrate it.
Fetch = get remote information and inspect it before integrating.

2. git push

git push sends commits from your local branch to a remote repository.

Suppose you have:

Local Commit A
Commit B
Commit C
→
GitHub Commit A
Commit B

After pushing:

Local A → B → C
→
GitHub A → B → C

Basic command 

git push

Push to a specific remote and branch 

git push origin main

Here:

  • origin = remote name
  • main = branch being pushed
Important: A normal push sends commits that exist locally but are not yet present on the remote branch, subject to Git's non-fast-forward and other safety checks.

3. Your First Push

If a local branch has not yet been connected to a remote tracking branch, you may use: 

git push -u origin main

The -u option sets the upstream tracking relationship between your current local branch and origin/main.

After this, you can usually use: 

git push
Note: If your default branch is named something other than main, use that branch name instead.

4. What Is an Upstream Branch?

An upstream branch is the remote branch that a local branch tracks.

For example:

Local main
↔
Remote origin/main

This relationship allows Git to know which remote branch should normally be used for operations such as git push and git pull.

View branch tracking information 

git branch -vv

This can show which remote-tracking branch each local branch is associated with.

5. git pull

git pull retrieves changes from a remote repository and integrates them into your current local branch.

GitHub New commits
→
Fetch Download changes
→
Integrate Update branch

Basic command 

git pull

Specify remote and branch 

git pull origin main
Conceptually, git pull performs a fetch and then integrates the fetched changes into the current branch. The integration strategy can vary depending on Git settings and options.

6. git fetch

git fetch downloads new objects and references from a remote repository without integrating those changes into your current branch.

GitHub New commits
→
Local Remote-tracking refs

Your current branch and working files are not automatically changed by the fetch itself.

Basic command 

git fetch

Fetch from a specific remote 

git fetch origin

Fetch everything from all configured remotes 

git fetch --all

7. Fetch vs Pull

Command Downloads Remote Changes Updates Current Branch Main Idea
git fetch Yes No, not by itself Inspect remote changes first
git pull Yes Yes, integrates changes Update your current branch
Practical idea: Use fetch when you want to see what changed remotely before deciding how to integrate it. Use pull when you are ready to retrieve and integrate the remote changes into your current branch.

8. Remote-Tracking Branches

When Git fetches information from a remote, it updates remote-tracking references such as: 

origin/main
origin/develop
origin/feature-login

These references represent the state of those branches as known from the remote.

Important: origin/main is not the same thing as your local main branch.

Example

Local branch main
↔
Remote-tracking origin/main
↔
Remote GitHub main

9. Inspecting Changes After Fetch

Suppose you run: 

git fetch origin

You can then compare your local branch with the remote-tracking branch. 

git log main..origin/main

This asks Git to show commits reachable from origin/main that are not reachable from your local main.

You can also inspect the differences: 

git diff main..origin/main
This is one reason git fetch is useful: you can inspect remote changes before integrating them.

10. Typical Push Workflow

When you work on your own changes, a common sequence is: 

git status
git add .
git commit -m "Add student registration"
git push
1. Edit Change files
→
2. Stage git add
→
3. Commit git commit
→
4. Push git push

11. Typical Team Workflow

In a team, other developers may push changes to the remote repository while you are working locally.

Before starting new work, a common approach is to retrieve the latest remote information and integrate appropriate changes. 

git fetch origin
git status
git pull

Then you can work on your changes: 

git add .
git commit -m "Implement login validation"
git push
Team principle: Keep your local branch synchronized with the shared remote branch according to your team's workflow.

12. What If git push Is Rejected?

A push may be rejected when the remote branch contains commits that your local branch does not contain.

For example:

Local A → B → C
↛
GitHub A → B → D

Git prevents you from simply overwriting the remote history in this situation.

You normally need to retrieve the remote changes and integrate them before pushing again. 

git pull
# resolve any conflicts if necessary
git add .
git commit
git push
The exact recovery workflow depends on the branch state, repository history, and your team's policy. Do not use force-push commands casually.

13. Force Push — Use With Care

Git also provides force-push options, such as: 

git push --force

A force push can replace remote branch history with your local history.

Warning: Force pushing can overwrite commits that other developers rely on. Avoid it on shared branches unless you understand the consequences and your team explicitly allows it.

A safer option in many situations is: 

git push --force-with-lease

It performs additional checks before forcing the update, reducing the chance of overwriting unexpected remote work.

14. Fetching All Remotes

A repository can have more than one remote.

To fetch from all configured remotes: 

git fetch --all

This is useful when a repository has multiple remote sources.

15. Important Commands

Command Purpose
git push Send local commits to the tracked remote branch
git push origin main Push local main to origin/main
git push -u origin main Push and set upstream tracking
git pull Fetch and integrate remote changes
git pull origin main Pull from origin/main
git fetch Download remote changes without integrating them into the current branch
git fetch origin Fetch from origin
git fetch --all Fetch from all configured remotes
git branch -vv View branch tracking information

19. Lesson Takeaway

Push, pull, and fetch are fundamental Git commands for communicating with remote repositories.

  • git push sends local commits to a remote.
  • git pull retrieves and integrates remote changes into the current branch.
  • git fetch downloads remote information without integrating it into the current branch.
  • origin is the conventional name for a primary remote.
  • git push -u origin main can establish upstream tracking for the first push.
  • origin/main is a remote-tracking reference, not your local main branch.
  • Fetching is useful when you want to inspect remote changes before integrating them.
  • Pushes can be rejected when the remote has commits missing from your local history.
  • Force pushing can rewrite remote history and should be used carefully.
  • A typical workflow is: edit → add → commit → push.
