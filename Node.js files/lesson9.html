What is Routing?

Routing is the process of deciding what server-side code should execute when a client requests a particular URL using a particular HTTP method.

In an Express application, routing connects a request such as GET /users to a JavaScript function that handles that request.

Browser
→
HTTP Request
→
Express Router
→
Route Handler
→
Response
Simple idea: Routing answers one important question: "Which function should handle this request?"
03

Express Route Structure

A basic Express route contains three important parts:

METHOD HTTP Method

Defines what operation the client wants to perform.

PATH URL Path

Identifies the resource or endpoint being requested.

HANDLER Callback Function

Contains the logic that runs when the route matches.

app.js 
app.get('/about', (req, res) => {
    res.send('About Page');
});

Here:

  • GET → HTTP method
  • /about → route path
  • (req, res) => { ... } → route handler
04

HTTP Methods in Express

Express provides methods such as app.get(), app.post(), app.put(), app.patch() and app.delete().

Method Typical Purpose Example
GET Retrieve data GET /users
POST Create or submit data POST /users
PUT Replace a resource PUT /users/10
PATCH Partially update a resource PATCH /users/10
DELETE Remove a resource DELETE /users/10
Important: A route is not identified by its path alone. The HTTP method is also part of the route definition.

Therefore these are different routes:

routes.js 
app.get('/users', (req, res) => {
    res.send('Get users');
});

app.post('/users', (req, res) => {
    res.send('Create user');
});
05

Creating Basic Routes

The simplest Express application can contain several routes for different pages.

server.js 
const express = require('express');

const app = express();

app.get('/', (req, res) => {
    res.send('Welcome to ZENSUS');
});

app.get('/about', (req, res) => {
    res.send('About ZENSUS');
});

app.get('/contact', (req, res) => {
    res.send('Contact Page');
});

app.listen(3000, () => {
    console.log('Server running on port 3000');
});

How it works

GET /

Returns the home page.

GET /about

Returns the about page.

GET /contact

Returns the contact page.

Unknown path

No matching route is found.

06

Route Parameters

Sometimes the value needed by the server is part of the URL itself.

For example:

Dynamic route 
app.get('/users/:id', (req, res) => {

    const userId = req.params.id;

    res.send(`User ID: ${userId}`);

});

The :id part is a route parameter. Express places its value inside req.params.

Example requests

Request req.params.id
/users/10 10
/users/25 25
/users/abc abc
Remember: Route parameters are commonly used when identifying one particular resource.
07

Query Parameters

Query parameters appear after a ? in a URL. They are commonly used for filtering, searching, sorting and pagination.

Query example 
app.get('/products', (req, res) => {

    const category = req.query.category;

    res.send(`Category: ${category}`);

});

Request:

/products?category=laptops

Result:

Category: laptops

Multiple query parameters

Multiple query values 
app.get('/products', (req, res) => {

    const category = req.query.category;
    const sort = req.query.sort;

    res.json({
        category: category,
        sort: sort
    });

});
/products?category=laptops&sort=price

An application can contain many endpoints. Keeping everything in one large file quickly becomes difficult to maintain.

/users

User-related operations.

Product-related operations.

Order-related operations.

/auth

Authentication-related operations.

09

Express Router

express.Router() creates a modular routing system. It allows related routes to be grouped together.

Step 1 — Create user routes

routes/users.js 
const express = require('express');

const router = express.Router();

router.get('/', (req, res) => {
    res.send('All Users');
});

router.get('/:id', (req, res) => {
    res.send(`User ${req.params.id}`);
});

module.exports = router;

Step 2 — Connect the router

server.js 
const express = require('express');

const app = express();

const userRoutes = require('./routes/users');

app.use('/users', userRoutes);

app.listen(3000, () => {
    console.log('Server running');
});

What happens?

/users
+
router.get('/')
=
GET /users
/users
+
router.get('/:id')
=
GET /users/10
Key idea: The path given to app.use() is combined with the path defined inside the router.
10

Dynamic Routing

Dynamic routes allow one route definition to handle many related URLs.

products.js 
app.get('/products/:productId', (req, res) => {

    const id = req.params.productId;

    res.json({
        message: 'Product requested',
        productId: id
    });

});

The same route can handle:

/products/101

productId = 101

/products/205

productId = 205

/products/500

productId = 500

Multiple parameters

Multiple parameters 
app.get('/users/:userId/orders/:orderId',
    (req, res) => {

    res.json({
        user: req.params.userId,
        order: req.params.orderId
    });

});
GET /users/15/orders/9001

Routing and Middleware

Middleware functions execute during the request-response lifecycle. They can inspect a request, modify it, perform authentication, log information, or pass control to the next middleware or route handler.

middleware example 
const logger = (req, res, next) => {

    console.log(req.method, req.url);

    next();

};

app.use(logger);

app.get('/dashboard', (req, res) => {

    res.send('Dashboard');

});
Request
→
Middleware
→
Route Handler
→
Response
Important: If middleware does not send a response and does not call next(), the request may remain unfinished.

REST API Routing

Express routing is commonly used to build REST APIs. A resource such as users can have multiple operations.

Method Endpoint Operation
GET /users Get all users
GET /users/:id Get one user
POST /users Create user
PUT /users/:id Replace user
PATCH /users/:id Update part of user
DELETE /users/:id Delete user

Example REST routes

router.get('/', (req, res) => {

Status Codes in Express Routes

Routes should return meaningful HTTP status codes so that clients understand the result of an operation.

200 OK

Request completed successfully.

201 Created

A new resource was created.

204 No Content

Successful request with no response body.

400 Bad Request

Client sent invalid data.

404 Not Found

Requested resource does not exist.

500 Server Error

An unexpected server-side error occurred.

Using status()

Status response 
app.post('/users', (req, res) => {

    // User created

    res.status(201).json({
        message: 'User created'
    });

});
17

Handling Unknown Routes

A client may request a URL for which no route exists. A common approach is to add a final middleware that returns a 404 response.

404 handler 
app.use((req, res) => {

    res.status(404).json({
        error: 'Route not found'
    });

});
Why at the end? Express processes middleware and routes in their registered order. This handler should come after the routes you want to match.
18

Common Routing Mistakes

01 Wrong HTTP Method

Defining POST while the client sends GET means the route will not match.

02 Wrong Path

/user and /users are different paths.

03 Wrong Parameter Access

Route parameters use req.params, while query parameters use req.query.

04 Wrong Router Mount

Check the path supplied to app.use().

Debugging tip: When a route does not work, first check:
HTTP method → URL path → router mount path → route parameter → middleware order.

Mini Project — User API

Let's combine the concepts and create a small REST-style user API.

server.js 
const express = require('express');

const app = express();

app.use(express.json());

const users = [
    {
        id: 1,
        name: 'Pradeep'
    },
    {
        id: 2,
        name: 'Rahul'
    }
];


// GET all users

app.get('/users', (req, res) => {

    res.json(users);

});


// GET one user

app.get('/users/:id', (req, res) => {

    const id = Number(req.params.id);

    const user = users.find(user => user.id === id);

    if (!user) {
        return res.status(404).json({
            error: 'User not found'
        });
    }

    res.json(user);

});


// CREATE user

app.post('/users', (req, res) => {

    const newUser = {
        id: users.length + 1,
        name: req.body.name
    };

    users.push(newUser);

    res.status(201).json(newUser);

});


// UPDATE user

app.patch('/users/:id', (req, res) => {

    const id = Number(req.params.id);

    const user = users.find(user => user.id === id);

    if (!user) {
        return res.status(404).json({
            error: 'User not found'
        });
    }

    user.name = req.body.name;

    res.json(user);

});


// DELETE user

app.delete('/users/:id', (req, res) => {

    const id = Number(req.params.id);

    const index = users.findIndex(user => user.id === id);

    if (index === -1) {
        return res.status(404).json({
            error: 'User not found'
        });
    }

    users.splice(index, 1);

    res.json({
        message: 'User deleted'
    });

});


app.listen(3000, () => {
    console.log('User API running on port 3000');
});

API Structure

Request Purpose
GET /users Get all users
GET /users/1 Get user 1
POST /users Create user
PATCH /users/1 Update user 1
DELETE /users/1 Delete user 1
Architecture takeaway: Routing provides the structure that connects API endpoints to the application logic behind them.

Interview Questions

Routing is the process of determining which server handler should execute for a specific HTTP method and URL path.
req.params contains values captured from route parameters such as /users/:id. req.query contains query-string values such as /users?role=admin.
express.Router() creates a modular router object that can group related routes and then be mounted into the main Express application.
HTTP methods communicate the intended operation of a request. GET is generally used for retrieval, POST for creation or submission, PUT for replacement, PATCH for partial updates and DELETE for removal.
If no route or middleware handles the request, the application needs appropriate fallback handling. A common pattern is a final 404 middleware.
Express processes registered middleware and routes in order. Therefore, the order in which routes and middleware are declared can affect which handler receives a request.
