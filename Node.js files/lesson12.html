02 • Fundamentals

What Is a Database?

A database is a system used to store, organize, manage, and retrieve data efficiently.

Imagine an application such as an online shopping website. It needs to remember users, products, orders, payments, reviews, and many other pieces of information.

If this information were stored only in JavaScript variables, it would disappear when the server stops.

Important Idea Variables store data temporarily in memory. A database provides persistent storage so data can survive application restarts.
💾

Persistent

Data remains available even after the Node.js process stops.

🔎

Searchable

Applications can efficiently find specific records.

📈

Scalable

Databases can handle large amounts of application data.

Without a Database

server.js 
let users = [
  { name: "Asha", email: "asha@example.com" },
  { name: "Ravi", email: "ravi@example.com" }
];

This works temporarily, but when the server restarts, the data stored in the variable is lost.

With a Database

The Node.js application sends data to a database. The database stores the information and returns it whenever the application asks.

03 • Database Types

SQL vs NoSQL

Databases are commonly divided into two broad categories: relational databases and NoSQL databases.

📊

SQL / Relational

Data is generally organized into tables containing rows and columns.

  • Tables
  • Rows
  • Columns
  • Relationships
  • Structured schemas
  • SQL queries

Examples: PostgreSQL, MySQL, Microsoft SQL Server, Oracle Database.

🍃

NoSQL / Document

Data can be stored as flexible documents rather than traditional rows and columns.

  • Documents
  • Collections
  • Flexible structure
  • Document-oriented data
  • JSON-like representation

Example: MongoDB.

Concept SQL MongoDB
Structure Tables Collections
Record Row Document
Field Column Field
Query language SQL MongoDB query/document operations
Schema Usually strongly defined Flexible document structure
Do not think "NoSQL" means "no structure." MongoDB allows flexible document structures, but good applications still define and validate the shape of their data.
04 • MongoDB

What Is MongoDB?

MongoDB is a document-oriented NoSQL database. Instead of storing application records as traditional table rows, MongoDB stores them as documents inside collections.

MongoDB documents look similar to JSON when represented in application code, although MongoDB internally uses a binary representation called BSON.

Simple Mental Model Database → Collection → Document → Field → Value
🗃️

Database

Container for related collections.

📁

Collection

Group of related documents.

📄

Document

Individual record containing fields and values.

What Is BSON?

BSON means Binary JSON. MongoDB uses BSON internally because it supports additional data types and efficient processing beyond ordinary JSON.

What Is ObjectId?

MongoDB commonly uses an ObjectId as the unique identifier for a document.

MongoDB document 
{
  "_id": ObjectId("66a123456789abcdef123456"),
  "name": "Asha",
  "email": "asha@example.com"
}

The _id field uniquely identifies the document within its collection.

08 • Mongoose

What Is Mongoose?

Mongoose is an Object Data Modeling library for MongoDB and Node.js.

It provides a convenient way to define the structure of application data, validate values, create models, and perform database operations.

📐

Schema

Defines the expected structure and rules for documents.

🧠

Model

Provides an interface for interacting with a MongoDB collection.

✅

Validation

Helps ensure application data follows defined rules.

Important MongoDB itself is the database. Mongoose is a Node.js library that helps your application work with MongoDB.

09 • Connection

Connecting Node.js to MongoDB

Step 1 — Create a Node.js Project

Terminal 
mkdir mongodb-app
cd mongodb-app

npm init -y

Step 2 — Install Dependencies

Terminal 
npm install express mongoose dotenv

Here:

  • express → creates the backend API.
  • mongoose → communicates with MongoDB.
  • dotenv → loads environment variables.

Step 3 — Connection Code

server.js 
const express = require("express");
const mongoose = require("mongoose");

const app = express();

app.use(express.json());

mongoose
  .connect("mongodb://127.0.0.1:27017/schoolDB")
  .then(() => {
    console.log("MongoDB connected");
  })
  .catch((error) => {
    console.error("MongoDB connection failed:", error);
  });

  console.log("Server running on port 3000");
});

10 • Schema

Mongoose Schema

A Mongoose Schema describes the structure of documents that your application expects.

For example, a user might have:

  • name
  • email
  • age
  • role
models/User.js 
const mongoose = require("mongoose");

const userSchema = new mongoose.Schema({
  name: String,
  email: String,
  age: Number,
  role: String
});

module.exports = userSchema;

Schema with Validation

User schema 
const userSchema = new mongoose.Schema({
  name: {
    type: String,
    required: true,
    trim: true
  },

  email: {
    type: String,
    required: true,
    unique: true,
    lowercase: true
  },

  age: {
    type: Number,
    min: 18
  },

  role: {
    type: String,
    enum: ["student", "admin", "teacher"],
    default: "student"
  }
});

Common Mongoose Schema Types

Type Example Purpose
String name: String Text
Number age: Number Numbers
Boolean active: Boolean True/false
Date createdAt: Date Date/time
Array skills: [String] List of values
ObjectId userId: mongoose.Schema.Types.ObjectId Document reference
11 • Model

Mongoose Model

A Model is created from a schema. It provides methods for interacting with a MongoDB collection.

User.js 
const mongoose = require("mongoose");

const userSchema = new mongoose.Schema({
  name: String,
  email: String,
  age: Number
});

const User = mongoose.model("User", userSchema);

module.exports = User;
Remember This Relationship Schema defines the structure → Model uses the schema → Model communicates with the MongoDB collection.
12 • Create

Creating Documents

To add a new document, you can use create() or create an instance and call save().

Using create()

Create user 
const user = await User.create({
  name: "Asha",
  email: "asha@example.com",
  age: 21
});

console.log(user);

Using save()

save() 
const user = new User({
  name: "Ravi",
  email: "ravi@example.com",
  age: 22
});

await user.save();
What happens? Mongoose validates the document according to the schema and then sends the operation to MongoDB.

14 • Update

Updating Documents

Mongoose provides several update methods.

findByIdAndUpdate()

Update user 
const updatedUser = await User.findByIdAndUpdate(
  userId,
  {
    age: 22
  },
  {
    new: true,
    runValidators: true
  }
);

console.log(updatedUser);

new: true tells Mongoose to return the updated document rather than the old version.

runValidators: true ensures schema validators are applied during this update operation.

Updating Multiple Documents

updateMany() 
await User.updateMany(
  { role: "student" },
  { $set: { active: true } }
);
15 • Delete

Deleting Documents

Delete One

findByIdAndDelete() 
const deletedUser = await User.findByIdAndDelete(userId);

console.log(deletedUser);

Delete Many

deleteMany() 
await User.deleteMany({
  active: false
});
Be Careful Delete operations permanently remove documents unless your application has a separate backup or soft-delete strategy.
16 • Data Quality

Validation & Error Handling

Validation ensures that incoming data follows the rules expected by your application.

Validation example 
const userSchema = new mongoose.Schema({
  name: {
    type: String,
    required: [true, "Name is required"],
    minlength: 2,
    maxlength: 50
  },

  email: {
    type: String,
    required: [true, "Email is required"],
    unique: true
  },

  age: {
    type: Number,
    min: [18, "Age must be at least 18"]
  }
});

Express Error Handling

Controller example 
app.post("/api/users", async (req, res) => {
  try {
    const user = await User.create(req.body);

    res.status(201).json(user);
  } catch (error) {
    res.status(400).json({
      message: error.message
    });
  }
});
Never trust client data. Data sent from a browser or API client should be validated before being stored or used.
17 • Relationships

Relationships Between Documents

Real applications often contain related data.

For example:

  • A user can have many orders.
  • A student can enroll in many courses.
  • A product can have many reviews.

ObjectId Reference

Order schema 
const orderSchema = new mongoose.Schema({
  product: {
    type: mongoose.Schema.Types.ObjectId,
    ref: "Product",
    required: true
  },

  quantity: {
    type: Number,
    required: true
  }
});

populate()

Mongoose can use populate() to replace referenced ObjectIds with related documents.

populate() 
const orders = await Order.find()
  .populate("product");
Concept MongoDB does not require every relationship to be represented like a traditional SQL foreign key. Applications can model relationships using references or embedded documents depending on the use case.

Complete User CRUD API

The following example connects Express, Mongoose, MongoDB, validation, and REST API operations into one small application.

Project Structure

Project

├── models/
│   └── User.js
│
├── .env

User Model

models/User.js 
const mongoose = require("mongoose");

const userSchema = new mongoose.Schema(
  {
    name: {
      type: String,
      required: true,
      trim: true
    },

    email: {
      type: String,
      required: true,
      unique: true,
      lowercase: true
    },

    age: {
      type: Number,
      min: 18
    }

  }
);

Complete Server

server.js 
require("dotenv").config();

const express = require("express");
const mongoose = require("mongoose");

const User = require("./models/User");

const app = express();

app.use(express.json());

/* =========================
   DATABASE CONNECTION
========================= */

mongoose
  .connect(process.env.MONGODB_URI)
  .then(() => {
    console.log("MongoDB connected");
  })
  .catch((error) => {
    console.error("Database connection error:", error);
  });

/* =========================
   CREATE
========================= */

app.post("/api/users", async (req, res) => {
  try {
    const user = await User.create(req.body);

    res.status(201).json(user);
  } catch (error) {
    res.status(400).json({
      message: error.message
    });
  }
});

/* =========================
   READ ALL
========================= */

app.get("/api/users", async (req, res) => {
  try {
    const users = await User.find();

    res.status(200).json(users);
  } catch (error) {
    res.status(500).json({
      message: "Failed to fetch users"
    });
  }
});

/* =========================
   READ ONE
========================= */

app.get("/api/users/:id", async (req, res) => {
  try {
    const user = await User.findById(req.params.id);

    if (!user) {
      return res.status(404).json({
        message: "User not found"
      });
    }

    res.status(200).json(user);
  } catch (error) {
    res.status(400).json({
      message: "Invalid user ID"
    });
  }
});

/* =========================
   UPDATE
========================= */

app.patch("/api/users/:id", async (req, res) => {
  try {
    const user = await User.findByIdAndUpdate(
      req.params.id,
      req.body,
      {
        new: true,
        runValidators: true
      }
    );

    if (!user) {
      return res.status(404).json({
        message: "User not found"
      });
    }

    res.status(200).json(user);
  } catch (error) {
    res.status(400).json({
      message: error.message
    });
  }
});

/* =========================
   DELETE
========================= */

app.delete("/api/users/:id", async (req, res) => {
  try {
    const user = await User.findByIdAndDelete(req.params.id);

    if (!user) {
      return res.status(404).json({
        message: "User not found"
      });
    }

    res.status(200).json({
      message: "User deleted successfully"
    });
  } catch (error) {
    res.status(400).json({
      message: "Invalid user ID"
    });
  }
});

/* =========================
   SERVER
========================= */

app.listen(3000, () => {
  console.log("Server running on port 3000");
});
What you have built You now have a real REST-style backend that persists user data in MongoDB instead of keeping it only inside JavaScript memory.

21 • Querying

Useful Mongoose Query Patterns

Sorting

sort() 
const users = await User.find()
  .sort({ age: -1 });

-1 means descending order and 1 means ascending order.

Limit Results

limit() 
const users = await User.find()
  .limit(10);

Select Specific Fields

select() 
const users = await User.find()
  .select("name email");

Chaining Queries

Mongoose query 
const users = await User.find({
  age: { $gte: 18 }
})
.sort({ age: -1 })
.limit(10)
.select("name email age");
22 • Performance

Indexes

An index helps MongoDB locate matching documents more efficiently for supported queries.

For example, if your application frequently searches users by email, an index can be useful.

Schema index 
const userSchema = new mongoose.Schema({
  name: String,

  email: {
    type: String,
    required: true,
    unique: true
  }
});
Trade-off Indexes can improve reads, but they also consume storage and can add overhead to writes. Index only fields that benefit from your actual query patterns.

24 • Debugging

Common MongoDB & Mongoose Mistakes

❌ Forgetting express.json()

Then JSON request bodies may not be available through req.body.

❌ Wrong MongoDB URI

Verify the hostname, port, database name, credentials, and network configuration.

❌ Not handling errors

Database operations are asynchronous and can fail. Use proper try/catch or centralized error handling.

❌ Trusting client input

Always validate and sanitize application data before storing it.

❌ Ignoring indexes

Large datasets can make repeated queries expensive without appropriate indexes.

❌ Hard-coding secrets

Keep database credentials and connection strings outside source code.

25 • Interview Preparation

MongoDB & Mongoose Interview Questions

MongoDB is a document-oriented NoSQL database that stores data as BSON documents inside collections.
A collection is a group of MongoDB documents. It is roughly comparable to a table in a relational database, although the underlying data model is different.
A document is an individual record stored in a MongoDB collection. It contains fields and values.
Mongoose is a Node.js library that provides schemas, models, validation, and convenient database operations for MongoDB.
A schema describes the structure and rules for documents. A model is created from the schema and provides an interface for interacting with a MongoDB collection.
ObjectId is a BSON type commonly used by MongoDB as a unique identifier for documents.
populate() allows Mongoose to replace referenced ObjectIds with related documents when the relationship is defined using refs.
find() returns matching documents, findOne() returns one matching document, and findById() looks up a document using its identifier.
Environment variables keep configuration and sensitive connection information outside the application source code.
SQL databases organize data primarily into relational tables, while MongoDB uses collections of document-oriented records. Each model has different strengths and design patterns.
