02 • Concept

What Is a Module?

A module is a reusable piece of code that can be imported into another file.

📄
user.js User logic
→
📦
Export Share functionality
→
📥
Import Use functionality
→
🚀
app.js Main application
Modules help us break a large application into smaller, reusable and maintainable pieces.
03 • Why Modules?

Why Do We Need Modules?

❌ Without Modules

  • Everything is inside one huge file
  • Hard to maintain
  • Hard to test
  • Code becomes difficult to reuse
  • Team development becomes harder

✓ With Modules

  • Code is separated logically
  • Functions can be reused
  • Easier debugging
  • Easier testing
  • Better project architecture

05 • CommonJS

CommonJS Modules

CommonJS is a traditional module system widely used in Node.js applications.

📤 Exporting

// math.js

function add(a, b) {
    return a + b;
}

function multiply(a, b) {
    return a * b;
}

module.exports = {
    add,
    multiply
};

📥 Importing

// app.js

const math = require("./math");

console.log(math.add(10, 20));
console.log(math.multiply(5, 4));

09 • Modern JavaScript

ES Modules

Modern JavaScript provides import/export syntax for modules.

📤 export

// math.js

export function add(a, b) {
    return a + b;
}

export function multiply(a, b) {
    return a * b;
}

📥 import

// app.js

import {
    add,
    multiply
} from "./math.js";

console.log(add(10, 20));
ES Modules use import and export, while CommonJS commonly uses require() and module.exports.
10 • Comparison

CommonJS vs ES Modules

CommonJS

  • require()
  • module.exports
  • Traditional Node.js module style
  • Common in older Node.js projects
const fs = require("fs");

module.exports = {
    hello
};

ES Modules

  • import
  • export
  • Standard JavaScript module syntax
  • Common in modern applications
import fs from "fs";

export {
    hello
};
11 • ES Module Configuration

Using "type": "module"

One common way to tell Node.js to interpret .js files as ES modules. 

{
    "name": "module-demo",
    "version": "1.0.0",
    "type": "module",
    "scripts": {
        "start": "node app.js"
    }
}
With "type": "module", regular .js files in that package are interpreted using ES module semantics.

19 • Interview Preparation

Node.js Modules Interview Questions

A module is a reusable unit of code that can be loaded into another part of an application.
CommonJS is a module system commonly associated with Node.js. It uses require() to load modules and module.exports to expose values.
module.exports defines the value that a CommonJS module makes available to code that imports it.
require() is the CommonJS mechanism used to load another module into the current file.
Built-in modules are modules supplied by Node.js itself, such as fs, path, os, http and events.
require() is commonly associated with CommonJS, while import/export are the standard ES Module syntax.

21 • Challenge

Build Your Own Math Module

🚀 Challenge

Create two files:

math-app/ ├── math.js └── app.js

Your math.js should export:

  • add()
  • subtract()
  • multiply()
  • divide()

Then import those functions inside app.js and print their results. 

// math.js

function add(a, b) {
    return a + b;
}

function subtract(a, b) {
    return a - b;
}

function multiply(a, b) {
    return a * b;
}

function divide(a, b) {
    return a / b;
}

module.exports = {
    add,
    subtract,
    multiply,
    divide
};


// app.js

const math = require("./math");

console.log(math.add(10, 5));
console.log(math.subtract(10, 5));
console.log(math.multiply(10, 5));
console.log(math.divide(10, 5));
