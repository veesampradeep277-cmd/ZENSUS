What is Express.js?

A lightweight web framework for Node.js.

Express.js is a web framework built for Node.js. It provides a simpler and more organized way to create web servers, APIs and backend applications.

Node.js already provides the built-in http module. However, when applications become larger, manually checking URLs, HTTP methods, headers and request bodies can become repetitive.

Express provides convenient abstractions for these common tasks. Instead of manually implementing everything with http.createServer(), developers can define routes such as:

Express route 
app.get('/about', (req, res) => {
  res.send('About ZENSUS');
});
Important: Express does not replace Node.js. Express runs on top of Node.js and uses Node's underlying capabilities.
+

Why Use Express.js?

From low-level HTTP handling to cleaner application development.

Without Express

With the Node.js HTTP module, you often need to manually inspect the URL and method.

node:http 
if (req.method === 'GET'
    && req.url === '/users') {
  // handle request
}

With Express

Express gives routing methods that directly represent the HTTP method and path.

Express 
app.get('/users', (req, res) => {
  // handle request
});

Major Benefits

  • Simple routing system.
  • Middleware support.
  • Convenient request and response APIs.
  • Easy JSON API development.
  • Static file serving.
  • Large ecosystem of middleware packages.
  • Good foundation for REST APIs.
  • Works naturally with Node.js asynchronous programming.

Installing Express.js

Set up Express inside a Node.js project.

Step 1 — Create a project

Terminal 
mkdir express-demo
cd express-demo
npm init -y

The npm init -y command creates a package.json file containing project metadata.

Step 2 — Install Express

Terminal 
npm install express

Express is added as a project dependency and will appear in package.json.

Project Structure

Recommended beginner structure 
express-demo/
│
├── node_modules/
├── package.json
├── package-lock.json
└── server.js
Tip: Do not manually edit files inside node_modules. NPM manages installed packages for you.

Your First Express Server

The basic building block of an Express application.

server.js 
const express = require('express');

const app = express();

app.get('/', (req, res) => {
  res.send('Hello from ZENSUS!');
});

app.listen(3000, () => {
  console.log('Server running at http://localhost:3000');
});

Understanding Every Line

Code Meaning
require('express') Loads the Express package.
express() Creates an Express application object.
app.get() Creates a route that responds to GET requests.
req Contains information about the incoming request.
res Used to send a response back to the client.
res.send() Sends content as the HTTP response.
app.listen() Starts the server listening on a port.
Run it: Save the file as server.js, then run node server.js. Open http://localhost:3000 in your browser.

Routing in Express

Define what your server should do for different URLs.

A route defines how an application responds when a client requests a particular HTTP method and URL path.

Client Browser / App
→
HTTP Request GET /about
→
Express Router Find matching route
→
Handler Run callback
→
Response Send result

Basic Route Syntax

Route syntax 
app.METHOD(PATH, HANDLER);

For example:

server.js 
app.get('/', (req, res) => {
  res.send('Home Page');
});

app.get('/about', (req, res) => {
  res.send('About Page');
});

app.get('/contact', (req, res) => {
  res.send('Contact Page');
});
Each URL can have its own route handler. This makes an Express application much easier to organize than manually checking req.url for every request.

Request & Response Objects

The two most important objects inside an Express route handler.

The Request Object — req

The req object represents the incoming HTTP request. It gives your application access to information sent by the client.

Property Purpose Example
req.method HTTP method used by the request. GET
req.url Requested URL. /users
req.params Route parameters. { id: "10" }
req.query Query string values. { page: "2" }
req.headers Request metadata. Content-Type
req.body Parsed request body when body-parsing middleware is enabled. { name: "Alex" }

The Response Object — res

The res object is used by your server to send a response to the client.

Common response methods 
res.send('Hello');

res.json({
  message: 'Success'
});

res.status(404).send('Not Found');

res.status(201).json({
  message: 'Created'
});

Route Parameters & Query Parameters

Extract dynamic information from URLs.

Route Parameters

A route parameter is a dynamic part of the URL.

Route parameter 
app.get('/users/:id', (req, res) => {

  console.log(req.params.id);

  res.send(`User ID: ${req.params.id}`);
});

Requesting /users/25 produces: 

req.params.id

25

Multiple Parameters

app.get('/users/:userId/posts/:postId',
  (req, res) => {

    console.log(req.params.userId);
    console.log(req.params.postId);

  }
);

Query Parameters

Query parameters appear after ? in a URL. 

GET /products?category=books&page=2

Express makes them available through req.query.

app.get('/products', (req, res) => {

  console.log(req.query.category);
  console.log(req.query.page);

  res.json(req.query);
});

Route Parameter

/users/25

Usually identifies a specific resource.

Query Parameter

/users?page=2

Usually controls filtering, sorting or pagination.

MW

Middleware

The most important Express concept after routing.

Middleware is a function that runs during the request-response cycle.

Middleware can inspect or modify the request and response, perform logging, authenticate users, parse data, handle errors, or pass control to the next middleware or route handler.

1
Request Client sends request
2
Logger Record request
3
Auth Check access
4
Route Run handler
5
Response Return result

Basic Middleware

Logger middleware 
app.use((req, res, next) => {
  console.log(req.method, req.url);

  next();
});
Why is next() important? If middleware does not send a response and does not call next(), the request may remain waiting.

Middleware With a Route

const logger = (req, res, next) => {
  console.log(`Request: ${req.method} ${req.url}`);
  next();
};

app.use(logger);

app.get('/dashboard', (req, res) => {
  res.send('Dashboard');
});

JSON & Request Body Parsing

Receive structured data from clients.

APIs frequently receive data as JSON. Express provides built-in middleware for parsing JSON request bodies.

Enable JSON parsing 
app.use(express.json());

Now a client can send:

{
  "name": "Alex",
  "email": "alex@example.com",
  "course": "Node.js"
}

And Express makes it available through req.body.

POST route 
app.post('/students', (req, res) => {

  console.log(req.body);

  res.status(201).json({
    message: 'Student created',
    student: req.body
  });

});
Remember: express.json() parses incoming JSON. It does not automatically validate that the data is correct for your business rules. Validation is a separate responsibility.

Express + Node.js Event-Driven Architecture

Connect this lesson to the previous HTTP and event-loop concepts.

Express does not change the event-driven nature of Node.js. Express runs on Node's HTTP server and provides a higher-level programming model for handling requests.

Incoming Request HTTP event
→
Node.js HTTP server
→
Express Middleware + routing
→
Handler Your code
→
Response Client receives data
Key connection: Node.js provides the runtime and underlying HTTP/event mechanisms. Express provides convenient application-level abstractions such as routing and middleware.

Mini Project — Student REST API

Combine Express routing, JSON and HTTP methods.

Let's create a small API that manages students. The example uses an in-memory array, so data will disappear when the server restarts.

Complete Server

server.js 
const express = require('express');

const app = express();
const PORT = 3000;

app.use(express.json());

let students = [
  {
    id: 1,
    name: 'Alex',
    course: 'Node.js'
  },
  {
    id: 2,
    name: 'Sam',
    course: 'Python'
  }
];

// GET all students
app.get('/students', (req, res) => {
  res.json(students);
});

// GET one student
app.get('/students/:id', (req, res) => {

  const id = Number(req.params.id);

  const student = students.find(
    student => student.id === id
  );

  if (!student) {
    return res.status(404).json({
      message: 'Student not found'
    });
  }

  res.json(student);
});

// CREATE student
app.post('/students', (req, res) => {

  const newStudent = {
    id: students.length + 1,
    name: req.body.name,
    course: req.body.course
  };

  students.push(newStudent);

  res.status(201).json(newStudent);
});

// DELETE student
app.delete('/students/:id', (req, res) => {

  const id = Number(req.params.id);

  const index = students.findIndex(
    student => student.id === id
  );

  if (index === -1) {
    return res.status(404).json({
      message: 'Student not found'
    });
  }

  students.splice(index, 1);

  res.status(204).send();
});

app.listen(PORT, () => {
  console.log(
    `Server running at http://localhost:${PORT}`
  );
});

API Endpoints

Method Endpoint Purpose
GET /students Return all students.
GET /students/:id Return one student.
POST /students Create a student.
DELETE /students/:id Delete a student.

Example POST Body

{
  "name": "Priya",
  "course": "Express.js"
}
Production note: This example stores students in memory. Real applications normally persist data in a database such as PostgreSQL, MongoDB or another appropriate database.

Error Handling

Handle failures instead of leaving clients without useful responses.

404 Route Handling

app.use((req, res) => {
  res.status(404).json({
    error: 'Route not found'
  });
});

Error-Handling Middleware

Express error-handling middleware has four parameters: err, req, res, next. 

app.use((err, req, res, next) => {

  console.error(err);

  res.status(500).json({
    error: 'Internal server error'
  });

});
Important: Never expose sensitive implementation details, secrets, database credentials or internal stack traces to normal production clients.

Common Express.js Mistakes

Problems beginners frequently encounter.

Forgetting express.json()

If JSON body parsing is needed but the middleware is not enabled, req.body may not contain the expected data.

Forgetting next()

Middleware that neither responds nor calls next() can prevent the request from continuing.

Wrong HTTP Method

A GET route does not automatically handle POST requests to the same path.

Wrong Parameter

For /users/:id, the value is available through req.params.id.

Not Returning After Error

After sending an error response inside a branch, return when necessary to avoid continuing execution.

No Input Validation

Never assume client input is valid simply because the JSON format is correct.

S

Basic Express Security Practices

Good habits when moving from tutorials to real applications.

  • Validate and sanitize user-controlled input where appropriate.
  • Do not expose passwords, API keys or secrets in source code.
  • Use HTTPS for production applications.
  • Use authentication and authorization where required.
  • Return appropriate HTTP status codes.
  • Do not expose detailed internal errors to clients.
  • Keep dependencies updated and review security advisories.
  • Apply rate limiting and other protections when appropriate for the application.
Remember: Express gives you a web framework, not automatic security. Security must be designed into the application.

Q

Interview Questions

Important Express.js questions for technical interviews.

Express.js is a web framework for Node.js that provides convenient APIs for routing, middleware, request handling, responses and building web applications and APIs.

Middleware is a function that participates in the request-response cycle. It can inspect or modify request and response objects, perform logic and either end the response or pass control using next().

req.params contains values captured from route parameters such as /users/:id. req.query contains values from the query string such as /users?page=2.

It is built-in middleware that parses incoming JSON request bodies and makes the parsed object available through req.body when the request contains an appropriate JSON payload.

PUT is generally used to replace the representation of a resource, while PATCH is generally used to apply a partial update. Exact API behavior depends on the application's design.

Node.js provides the runtime and low-level capabilities used to build the server. Express runs on Node.js and provides a higher-level framework for routing, middleware and web APIs.

When middleware does not finish the response, next() passes control to the next matching middleware or route handler. Without it, the request may not continue.

Practical Coding Challenge

Build a simple Express product API.

Your Task

Create an Express server on port 3000 with the following routes:

  1. GET /products — return all products.
  2. GET /products/:id — return one product.
  3. POST /products — create a product.
  4. DELETE /products/:id — delete a product.

Use express.json() so POST requests can receive JSON data.

Solution 
const express = require('express');

const app = express();

app.use(express.json());

let products = [
  { id: 1, name: 'Laptop', price: 60000 },
  { id: 2, name: 'Keyboard', price: 2500 }
];

app.get('/products', (req, res) => {
  res.json(products);
});

app.get('/products/:id', (req, res) => {

  const id = Number(req.params.id);

  const product = products.find(
    item => item.id === id
  );

  if (!product) {
    return res.status(404).json({
      message: 'Product not found'
    });
  }

  res.json(product);
});

app.post('/products', (req, res) => {

  const product = {
    id: products.length + 1,
    name: req.body.name,
    price: req.body.price
  };

  products.push(product);

  res.status(201).json(product);
});

app.delete('/products/:id', (req, res) => {

  const id = Number(req.params.id);

  products = products.filter(
    product => product.id !== id
  );

  res.status(204).send();
});

app.listen(3000, () => {
  console.log('Server running on port 3000');
});
