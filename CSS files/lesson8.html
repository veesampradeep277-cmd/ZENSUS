CSS LESSON 08

CSS Display

Learn how CSS decides whether an element behaves as a block, inline element, flex container, grid container, hidden element, or another layout type.

1. What is the display property?

The display property determines how an element participates in layout.

Every HTML element has a default display behavior. CSS allows us to change that behavior. 

p {
    display: block;
}

span {
    display: inline;
}

.container {
    display: flex;
}

.gallery {
    display: grid;
}
Think of display as a layout instruction.

It answers questions such as:
• Should this element start on a new line?
• Can neighboring content sit beside it?
• Should its children be arranged using Flexbox?
• Should its children be arranged using Grid?
• Should the element participate in layout at all?

2. Normal Flow

Before learning individual display values, understand normal flow.

In normal document flow, block-level elements generally participate vertically while inline content flows within lines.

Important: Display is not just about appearance. It changes how an element participates in layout.

3. display: block

A block-level box normally starts on a new line and can occupy available horizontal space within its containing block. 

.box {
    display: block;
}

Common block-level elements

<div>
<p>
<h1> ... <h6>
<section>
<article>
<header>
<footer>
<nav>

Width and height 

.box {
    display: block;

    width: 300px;
    height: 150px;
}

Width and height can generally be applied as expected to block-level boxes.

4. display: inline

Inline elements participate within a line of text instead of automatically starting a new line. 

span {
    display: inline;
}
This is normal text with an inline element inside the sentence.
Important difference: Inline elements do not behave like block boxes. Width and height do not generally work in the same way as they do for block-level boxes.

5. display: inline-block

inline-block combines useful characteristics of inline and block-level behavior. 

.card {
    display: inline-block;

    width: 140px;
    height: 80px;
}

Multiple inline-block elements can appear on the same line while still accepting width and height.

Box 1
Box 2
Box 3
Historical note: Inline-block was widely used for horizontal layouts before Flexbox and Grid became the preferred tools for many modern layout problems.

6. display: none vs visibility: hidden

Normal
I occupy space.
Visibility Hidden
I am invisible.
Display None
I am removed from layout.

display: none 

.element {
    display: none;
}

The element does not generate a box in the layout.

visibility: hidden 

.element {
    visibility: hidden;
}

The element is invisible but its layout space is generally preserved.

Do not treat display: none and visibility: hidden as interchangeable. They can have different layout and accessibility consequences.

7. display: flex

Setting display: flex creates a flex container. Its direct children become flex items. 

.container {
    display: flex;
}

Flexbox is designed primarily for arranging items along one main axis, with powerful alignment and distribution controls.

    display: flex;

8. display: grid

Setting display: grid creates a grid container. Grid is designed for two-dimensional layouts involving rows and columns. 

.container {
    display: grid;

    grid-template-columns:
        repeat(3, 1fr);

    gap: 20px;
}

Flex vs Grid: Flexbox is often useful for one-dimensional arrangements. Grid is especially useful for two-dimensional row/column layouts.

9. display: contents

display: contents causes the element's own box to disappear while its children can participate in the surrounding layout. 

.wrapper {
    display: contents;
}
This is an advanced feature. It should not be used simply because it "removes a wrapper." Always consider the semantic and accessibility implications of changing how an element participates in layout.

10. display: flow-root

display: flow-root establishes a new block formatting context.

One practical use is containing floated descendants. 

.container {
    display: flow-root;
}
Float
This container establishes its own block formatting context. The parent can contain the floated child without relying on an old clearfix hack.

11. Table Display Values

CSS also provides table-related display values. 

display: table;

display: table-row;

display: table-cell;

display: table-caption;

These values make an element participate in a table-like formatting context.

For normal application layouts, modern Flexbox and Grid are usually clearer choices. Table display values are still useful when you specifically need table-like formatting behavior.

12. Display and Width / Height

One of the most common beginner mistakes is assuming width and height behave identically for every display type.

Display Width / Height Behavior
block Width and height can generally be controlled.
inline Does not behave like a normal block box for width/height.
inline-block Width and height can be controlled.
flex Creates a flex formatting context for children.
grid Creates a grid formatting context for children.

13. Inline Whitespace

Inline and inline-block layouts can be affected by whitespace in the HTML source. 

<span>One</span>
<span>Two</span>

A source newline or space between inline-block elements can contribute visible whitespace.

This is one reason modern layouts often use Flexbox instead of relying on inline-block spacing tricks.

14. Responsive Display

Display values can change at different breakpoints. 

.navigation {
    display: flex;
}

@media (max-width: 700px) {

    .navigation {
        display: block;
    }

}

Another common pattern is changing a desktop navigation into a mobile menu.

Professional principle: Responsive design is not only about shrinking elements. Sometimes the layout model itself should change.

17. Common Mistakes

❌ Using inline when you need width and height 

.button {
    display: inline;
    width: 200px;
}

If you need a box-like inline element, consider inline-block or a modern layout approach.

❌ Using display: none for everything

Hiding an element visually, removing it from layout, and making it inaccessible to interaction are not necessarily the same requirement.

❌ Using inline-block for complex layouts

Flexbox and Grid are generally easier to reason about for modern responsive layouts.

❌ Confusing display with visibility 

display: none;

visibility: hidden;

These produce different layout behavior.

❌ Thinking display controls everything

Display controls an element's layout participation and formatting context, but positioning, sizing, overflow, alignment and other properties also influence the final result.

19. Professional Display Cheat Sheet

Value Core Idea Typical Use
block Block-level participation Sections, containers, paragraphs
inline Flows within text Text-level content
inline-block Inline + box dimensions Small legacy-style horizontal components
none No generated box Conditional UI
flex Flex formatting context One-dimensional layouts
grid Grid formatting context Rows and columns
contents Element's own box is not generated Advanced layout cases
flow-root New block formatting context Containing floats / isolation
table Table-like formatting Specialized table layouts

🧠 ZENSUS Mental Model

BLOCK → "Put me in the block flow."

INLINE → "Let me flow with text."

INLINE-BLOCK → "Let me sit inline but behave like a box."

NONE → "Do not generate my layout box."

FLEX → "Arrange my children along flexible axes."

GRID → "Arrange my children using rows and columns."

FLOW-ROOT → "Create an independent block formatting context."

🎯 Final Concept

The display property is one of the most important concepts in CSS because it determines the fundamental layout behavior of an element.

Once you understand display, the transition into Positioning → Flexbox → Grid → Responsive Design becomes much easier.
